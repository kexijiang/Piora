# Intelligent UI 第三阶段方案 v3.1

2026-10-31 | 重新设计与可行性分析 | 实施依据，不是完成报告

## 1. 这次调整的结论

第三阶段交付可生成、可操作、可保存并能继续讨论的小程序。保留第一、二阶段的组件界面，为模拟、教学、空间操作和轻量小游戏增加可编程输出。仍由设置中的 Intelligent UI Beta 开关控制，默认关闭；普通对话只连接通用输出接口。

本版基于 OpenIntelligentUI 本地提交 `8391a94`、Piora 当前工作树及已有第三阶段原型重新梳理。它替代 v3.0 的实施安排；v3.0 文档与 PDF 保留为历史快照。范围仍是三个交付阶段，3A 至 3E 是第三阶段内部步骤。

### 相比 v3.0 的具体变化

| 调整 | 目的 |
| --- | --- |
| 先交付一条完整使用流程；3B 与 3C 的最小保存能力一起接入 | 生成后必须能操作、刷新恢复、继续追问，不能把独立运行的演示当作产品完成 |
| 分开记录不可变的发布内容和可更新的操作状态 | 保存参数不能破坏原工具回执；历史分支能够读取当时的状态 |
| 明确三维拾取、相机状态、动态列表和布局预览的能力差距 | “能画立方体”不足以证明可以生成可交互的三维教学 |
| 初次生成与历史恢复均默认暂停，用户点击播放 | 减少意外动画；单步、复位和减少动画偏好具有统一语义 |
| 用统一的能力契约维护工具说明、校验和开发示例 | 减少模型按常规浏览器写代码、实际运行时却不支持的失败 |
| 分开记录触发正确、生成可运行、结果正确和产品流程通过 | 不用编译通过率或截图美观替代真实可用性 |

### 从参考项目采用什么

采用自由布局、CSS 先就绪再显示预览、预览与最终实例分离、共享主题以及按用户任务选择表达方式。参考项目通过 Websandbox 执行生成的浏览器脚本，并提供有限宿主桥；其[架构说明][R1]明确指出，iframe 内控件变化不会自动同步给智能体，会话检查点也使用进程内存。

Piora 保留现有 AgentSession、模型、工具权限和会话系统；无需引入 CopilotKit 的整套运行服务、Python/LangGraph 或其[路由方案][R2]中的额外 Jev 分类请求。HTML/CSS 作为创作输入，计算脚本进入独立 VM；需要的宿主动作沿用 Piora 已登记能力。此取舍会增加协议与渲染适配工作，但能与现有分支、草稿和保存规则连接。

## 2. 产品边界与触发方案

模型在当前回答中结合完整可用上下文选择形式。用户无需知道组件名、工具名或“生成交互页面”等暗号。缺失会影响结论的规则时先澄清；用户明确要求文字时尊重要求。

| 用户需求 | 输出与判断理由 |
| --- | --- |
| “这两个方案哪个便宜？” | 数据齐全就直接回答；一次比较无需生成界面 |
| “人数不确定，我想换着看看。” | 组件界面，现有输入和计算足够表达 |
| “这个算法到底怎么一步步做的？” | 小程序，步骤、单步与回退到初始状态帮助理解 |
| “让我拖一下三角形，看看面积变化。” | 小程序，需要空间事件与几何计算 |
| “把这个立方体转一转，再展开。” | 三维小程序，实际完成面邻接与展开关系 |
| “规则还没定，先做个提成工具。” | 先澄清影响结果的规则；不能把虚构规则藏进默认值 |
| “为什么我刚才选的方案更贵？” | 读取已保存状态解释；没有新交互需求就不重新生成 |

### 具体接入方式

Beta 开启时，宿主向当前模型公布两份互补能力说明：组件工具 `piora_render_ui_plan` 与小程序工具 `piora_render_mini_app`。前者面向结构化输入、比较与筛选；后者面向时间演化、空间交互、显式状态或组件表达式无法完成的计算。普通回答和澄清沿用原路径，不要求先调用路由工具。

工具说明共享回答形式原则，各自仅声明自身支持的协议；现有组件说明里的“不可执行 JavaScript”必须限定在组件路径，避免与小程序能力冲突。设备不支持三维时，宿主通过能力信息告知模型并在执行时复核；静态替代需明确说明。

触发是语义判断，不能由关键词、任务长度或模型自报置信度保证正确。保留多轮对话、明确拒绝 UI、已有输出追问和缺事实任务的评估，分别记录漏触发、误触发与形式选择错误。两种形式都合理的样本单列，不强制判成唯一答案。

### 与原对话解耦

通用 `answer-output` 登记 kind、版本、工具、预览、渲染、保存门禁、复制及导出适配器。组件继续使用 `intelligent-ui`；小程序使用独立 `mini-app` / version 1。具体模块置于 `lib/mini-app/`、`components/mini-app/` 与专用 extension。

ChatWindow 和 useAgentSession 只提供已有会话身份、运行取消与通用输出槽；不得散布小程序协议判断。关闭 Beta 后停止现有实例，撤销工具能力，保留可读快照；已有小程序历史不会自动执行。关闭状态下不加载 QuickJS、Three.js 或小程序样式。

## 3. 统一计划、两种视图、独立计算

```text
用户意图 + 上下文 + 当前能力
  -> 当前回答模型选择文字 / 澄清 / 组件 / 小程序
  -> MiniAppPlan1 -> 编译 -> 隔离试运行 -> 候选发布
  -> MiniAppHost
       文档视图：HTML/CSS 展示树、SVG、表单与文本
       场景视图：Canvas / Three.js 的可信绘制适配器
       计算：Worker 内 QuickJS/WASM
       宿主：状态保存、暂停/停止、权限动作与恢复
```

计划包含用途与假设、输入及其含义、有限状态 schema、HTML/CSS 文档、视口、计算程序和初始文字快照。宿主生成身份、摘要、版本、令牌及资源预算。模型不指定包版本、远程依赖、文件权限或运行时选项。

### 程序接口

```text
init(inputs, ctx)                  -> 初始 JSON 状态
reduce(state, event, ctx)          -> 交互后的 JSON 状态
advance(state, fixedDt, ctx)       -> 下一时间步的 JSON 状态
project(state, inputs, ctx)        -> Frame + 当前文字结果
```

状态显式保存，禁止依赖隐藏全局变量。ctx 提供宿主控制的 tick、输入和可恢复随机源；project 为纯投影，不推进时间、不取随机数。图形、指标、动态说明和保存快照来自同一次投影，降低“图表更新了，文字仍在说旧结果”的风险。公式本身正确与否仍需独立检查。

### 表达能力与必要补齐

| 能力 | 实现约定 |
| --- | --- |
| 自由布局 | 解析 HTML/CSS 为允许的展示树，使用主题令牌；不直接插入生成 HTML。受控属性和 SVG 绑定不执行表达式 |
| 动态内容 | 标量绑定与 Canvas 图元已有原型；新增受限重复列表契约，固定子模板、标量字段绑定、稳定 key，展开后仍计入 400 节点总预算 |
| 操作 | 数字、选择、勾选、按钮、拖动、键盘、单步与播放按任务组合。数值上下限是执行约束，应与业务假设分开说明 |
| 三维 | 可信适配器创建基础几何与网格，执行有界变换。补齐宿主拾取、旋转/缩放及标准事件，不能假定现有网格绘制已覆盖这些能力 |
| 视图状态 | 持久的相机视角与选择对象纳入显式状态；临时悬停可以不保存。投影从保存状态重建相同关系 |
| 可访问性 | 拖动有键盘或数值替代；场景提供文字结果；焦点、对比度、窄屏和减少动画共用宿主规则 |

这些能力是通用原语，不建立预算、旅行、几何等业务模板分支。动态列表与三维交互协议在接入前冻结并补对应校验；当前原型尚未实现它们。首版不支持任意 npm 包、远程资产、生成着色器或无限粒子。标准 Three.js 场景对象也不直接暴露给生成程序。

## 4. 从生成到可用：预览、修复和视觉

### 有明确边界的生成流程

流式输入只在相关字段闭合且通过同一编译器时产生预览。CSS、输入声明与布局依赖未齐全时显示占位；供应商没有可用参数增量时等待最终对象。预览不能执行模型程序、保存状态或调用动作，三维视口仅显示占位，不创建 WebGL 上下文。

完整计划进行语法、schema、绑定、资源校验，再由独立服务器 Worker 执行 init、project 和有界步进试运行。恢复终态仅 project，不能为了验证强行多走一步。试运行只筛查结构及初步运行错误，不证明所有用户输入或业务计算正确。

候选工具结果进入会话文件后，发布协调器核对当前运行、分支、完整 turn_end 工具回执和内容摘要；磁盘确认后才登记为可使用版本。正式实例从已发布内容创建并默认暂停。恢复失败保留旧版本与快照，不把预览升级成“已保存”。

### 让模型更容易一次生成正确

工具 transport schema、编译器与能力说明维护同一份受版本控制的契约；测试校验说明中的示例能编译并运行。通用辅助说明包含事件格式、输入绑定、投影、固定时间步和有限图形原语，不把某个业务测试答案塞进提示词。

错误返回稳定代码、字段路径、实际原因与允许修复的范围。默认沿用同一 PromptRun 的 3 次接纳尝试、1 次模型纠错、首次尝试后 60 秒窗口；组件与小程序共用预算，切换工具或模型回退不会重置。统一诊断字段，避免新增小程序错误绕过现有接纳逻辑。

状态冲突、用户取消、权限拒绝和设备能力不足不进入模型重写循环。超预算保留失败原因和旧输出，必要时给文字解释。长程序是否需要调整时间预算由开发样本数据决定，调整后记录策略版本并重新对照，不能默默无限重试。

### 视觉职责分配

Piora 提供外壳、标题区、内边距、控件基础样式、焦点、状态与动作按钮；模型决定内容层级、布局和场景。主题和字号变化通过可信消息同步到隔离视图，图形调色板与文字对比度同样跟随主题。滑块只适合有意义的连续区间，步骤演示优先播放/单步，几何优先拖动，离散选项优先按钮或选择器。

初始内容、生成中、保存中、保存失败、暂停、停止和不可用应有一致外观。界面显示“已保存”必须来自真实确认；不能仅靠防抖计时器结束就切换标签。旧版组件布局和动态说明继续回归，第三阶段不得再次丢失第一阶段已有的留白和对齐。

## 5. 状态与后续对话：单独设计持久记录

发布记录保存计划、程序摘要、来源及工具回执，提交后不可变。操作状态使用独立记录，包含 publicationId、branch/entry 锚点、stateRevision、输入、JSON state、rng、tick、运行时版本和文字摘要。保存操作不改写原工具结果，也不改变发布回执的哈希。

### 写入与恢复顺序

用户操作后先更新本地计算，再把待保存状态写入具有独立 draftId 的本机恢复记录；服务端保存按会话写锁检查分支、发布版本和 expectedStateRevision。相同 requestId 幂等，旧版本写入返回冲突，保留双方草稿，禁止最后写入者静默覆盖。

服务端核对状态 schema，并用同一程序重新 project，生成权威保存摘要；不能信任客户端上送的结论。此检查验证状态格式和投影一致性，不证明每一步都由真实点击产生，也不构成任何外部动作授权。

成功以磁盘提交回执为准，客户端仅删除该 requestId 对应的已确认草稿。响应丢失时查询回执再重试。动画按有界间隔合并检查点，不逐帧写盘；暂停、离开输出和追问触发有界 flush，不依赖 beforeunload。保存失败保留本机恢复副本，并显示最近确认的检查点。

### 分支、追问与版本更新

| 情况 | 必须满足的规则 |
| --- | --- |
| 继续追问 | 发送前通过通用保存门禁；上下文只引用确认的状态版本、参数含义、假设和结果。失败时显示恢复选项，不悄悄发送旧状态 |
| 历史导航、fork、复制 | 每次状态提交带会话分支锚点；读取目标祖先可见的最新记录。不能只存一份全局“最新状态” |
| 多窗口或分支切换 | 原实例 epoch 失效，取消保存和迟到回复；已落盘记录不可由旧实例撤销 |
| 新版程序 | 同任务新候选通过校验后，在原运行结束后展示差异；涉及含义、单位、schema 或程序变化时明确确认，不自动套用旧 state |
| 迁移 | 同含义同单位的兼容输入可预填；状态默认重新 init。确需转换时使用单独受限迁移、再次校验和投影；失败保留原版本与草稿 |
| 回收站和导出 | 删除/恢复关联发布与状态记录；导出参数、结果、版本及静态快照，HTML 会话导出不自动执行生成代码 |

## 6. 外部动作与停止

输入、键盘和拖动只改变本地业务状态。读取参数、另存结果等已登记动作由外层宿主按钮执行，复用现有权限、取消、幂等与执行回执；生成脚本和 iframe 消息不能授权写文件。动作开始前确认保存状态，服务端重新核对分支、目标与版本。

暂停停止时间推进；停止撤销当前执行资格、终止 Worker、释放视图资源并忽略迟到消息。停止后的恢复从最近确认状态开始，不承诺保存卡死瞬间的数据；Worker.terminate 不等待任务收尾。[R4] 关闭 Beta 立即停止；重新开启和刷新均默认暂停。

## 7. 执行限制、可行性与当前证据

QuickJS/WASM 提供脚本内存限制与中断能力，Worker 提供外部终止路径。[R3] 固定可信渲染器位于 opaque-origin iframe，使用限权 sandbox、CSP 和专用 MessageChannel；模型只提交展示树和帧数据。主窗口继续保持 Electron 隔离，特权入口校验消息发送方。[R5]

iframe 不等于独立进程，VM 内存上限也不是整机或 GPU 上限。HTML/CSS 展开、SVG 路径、消息复制、绘图命令和 GPU 资源都要独立约束。依赖固定版本并随应用分发，离线不需要 CDN。

| 原型当前限制 | 接入后的处理 |
| --- | --- |
| 计划 256 KiB、程序 64 KiB、状态 256 KiB | 在反序列化、编译和传输边界分别限制；模型不能修改上限 |
| VM 堆 32 MiB、WASM 64 MiB | 保留真实内存增长限制；另测 Worker 和主窗口整体资源趋势 |
| 初始化 200 ms、单步 8 ms、每秒计算 200 ms | 用目标设备校准；超时暂停并显示原因，不无限延长或偷偷减少模拟精度 |
| 30 fps、500 ms watchdog、事件队列 128 | 连续指针移动可以合并，离散事件不能静默丢弃；隐藏和失焦按交互语义暂停 |
| 400 文档节点、2,000 绘图指令、200 网格、50,000 三角形 | 编译后与每帧都检查；有界帧确认和背压，避免宿主排队耗尽资源 |

以上是当前原型配置，不是实测性能承诺。每个聊天视图至多一个小程序持续运行；历史输出惰性创建实例，卸载后释放 Worker、监听器和 GPU。遇到无 WebGL、超预算或旧运行时版本时显示快照及原因，不把静态替代记作完整交互成功。

### 对实际代码的判断

| 已有证据 | 仍需证明 |
| --- | --- |
| 编译器、QuickJS Worker、Canvas/Three.js 和消息边界已有原型 | 实际 Next 开发桌面中的 Worker/WASM 资源装载，原生 GPU 与发布包兼容性 |
| 日志记录上次 mini-app 测试 29/29 通过 | 该记录不是本轮重新运行；夹具通过不等于聊天产品闭环通过 |
| 通用输出适配器已有代码，当前仅登记旧组件 | 新工具、前端 Surface、持久保存和动作尚未完成产品接入 |
| 候选发布日志已有完整回执验证 | 操作状态历史、迁移确认、分支副本与草稿恢复仍需实现 |

总体可行。主要不确定性已经从“能否画出来”转到模型契约负担、恢复语义、真实设备资源和任务正确性。最小完整流程应优先暴露这些问题；以真实用例和独立结果核对决定能力是否开放，不以原型数量推算完成度。本轮不承诺工期或生成成功率。

## 8. 实施顺序与每步交付物

保留 3A 至 3E 的范围，调整依赖关系：3B 的内部开发可以接入工具，但面向用户开放之前必须连同 3C 的最小保存、读取、追问门禁一起完成。之后补齐 3C 的完整分支、迁移、动作和恢复矩阵。最终完成口径仍覆盖全部范围。

| 步骤 | 实际工作及用户可见结果 | 完成证据 |
| --- | --- | --- |
| 3A 基础边界 | 复用现有编译、计算与渲染原型，补布局预览不创建 GPU、关闭开关撤销实例等缺口 | 资源与取消故障测试，旧组件回归；当前已完成部分基础验证 |
| 3B 首条完整流程 | 登记新工具和共同预算；预览、发布读取、Surface、基础保存及追问。生成一个可操作的教学小程序并刷新恢复 | 真实聊天 UI 完成生成、操作、磁盘确认、刷新和追问；模型可用性单独记录 |
| 3C 完整状态与动作 | 独立状态历史、并发冲突、草稿、迁移确认、fork/复制/回收站/导出、既有权限动作 | 故障和恢复矩阵；旧版本继续可读，结果不明不重复执行 |
| 3D 复杂能力与泛化 | 动态列表、完整空间/三维事件、模拟、持续交互；主题、字号、无障碍、性能与模型评估 | 教学/模拟、持续交互、三维各至少一项贯穿产品流程，使用独立计算核对 |
| 3E 收尾与综合验收 | 整合三个阶段的回归及成果文档，再执行此前推迟的 CI 和人工语义验收 | 明确开发完成、待验收、失败和已验收；发布单独处理 |

三维能力已经列入 3B/3C 的协议设计和状态存储，3D 负责完成表现与验证，避免到最后才发现状态无法承载视角或面选择。重复列表同样先冻结绑定协议，后补完整渲染和泛化证据。

### 模块级落点

`lib/answer-output-catalog.ts`、generation/persistence 适配器及 `components/answer-output-renderers.tsx` 承接通用登记。`extensions/piora-mini-app.ts` 连接当前模型与同一 PromptRun；第一方扩展清单按 Beta 决定加载。

`lib/mini-app/` 保留协议、编译器、VM、事件、帧与候选日志，新增独立状态服务和恢复适配。`components/mini-app/` 提供只读 Preview 与正式 Surface。读取走既有通用 answer-output API；状态、迁移和动作接口独立置于会话作用域，全部复核当前会话所有权，不能只信任 URL 或前端传来的身份。

每一步记录改动、验证命令、实际结果、首次失败与修复、未覆盖项，并输出同内容 PDF。计划文件不当作成果报告。开发不运行 next build，不本地构建发布包；必要测试夹具可编译。提交、推送和发布继续遵循仓库同步与 GitHub Actions 规则。

## 9. 验证方案与方案自审

真实模型使用用户指定的 DeepSeek V4.1，沿用 `deepseek/deepseek-flash` 配置，并记录实际返回的模型标识；不使用 V4 Pro，不在失败后静默替换模型。先用开发样本诊断，再运行冻结的封存任务；人工语义验收和完整 CI 仍在三个阶段开发后进行。

沿用 48 个任务的初始设计：16 个小程序、12 个组件、12 个直接回答、4 个澄清、4 个能力缺口；32 个开发、16 个封存，每例 3 次。按任务族与交互组合隔离，而非只换措辞。封存样本一旦用于修改提示词或程序，必须降为开发样本并补充新的封存任务。

| 验证层 | 记录内容 |
| --- | --- |
| 触发 | 是否需要 UI、组件或小程序是否合适、是否遗漏必要澄清；支持范围内未调用仍计失败 |
| 生成 | 首次可运行、预算内最终可运行、修复次数、首个预览与最终可用耗时、超时与降级 |
| 语义 | 数学/物理/业务结果、假设与单位、操作目的是否实现；不能用模型自报结果作为正确答案 |
| 产品 | 操作、保存、刷新、追问、取消、分支、动作权限、草稿恢复及主题表现 |

### 复杂任务如何证明做对

三角形拖动用独立鞋带公式核对面积；排序逐步演示检查顺序及元素多重集不变；概率模拟固定种子回放并做多种子统计；键盘小游戏核对规则、碰撞、计分和暂停后的状态；立方体展开检查面邻接、边长、面重叠及还原关系。旋转截图不能代替三维关系正确。

桌面自测复用现有隔离生命周期，通过真实 UI 执行操作，接口只用于准备和核对。故障矩阵覆盖残缺流、错误绑定、死循环、超大状态、消息洪泛、伪造消息、关闭 Beta、取消后迟到、发布中断、保存响应丢失、多窗口、迁移失败和旧分支写入。保存前后动态文字与数值一致性保留第二阶段已知问题的回归。

### 自审结论与保留风险

最容易出现的设计错误是“能执行即完成”“只有一份最新状态”“静态三维截图算交互”以及“预览提前执行”。本版分别用完整流程验收、分支状态历史、空间事件与独立几何检查、纯布局预览处理。具体实现仍需相应证据。

风险仍包括长协议降低模型首轮成功率、8 ms 预算在低性能设备上过紧、原生 GPU 与软件渲染差异、迁移含义不明确以及生成公式错误。前两项在开发样本中调整版本化契约和预算；后几项依赖目标环境与独立核对。不能因为修复困难就降低断言、排除失败或把三维悄悄降为二维。

本次完成的是源码核对和方案自审，并非独立人员 Review、重新运行产品测试或完成第三阶段。现有成果边界见 [第三阶段进展](intelligent-ui-phase3-progress.md)。后续仍需完成全部 3A 至 3E，才能给出第三阶段完成结论。
