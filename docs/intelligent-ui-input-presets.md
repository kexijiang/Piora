# Intelligent UI 参数预设

2026-11-02 | 实现增量，完整第三阶段仍在开发

计划可在 `inputPresets` 中声明最多 16 个 `{id,label,values}`。每个预设至少提供一个已有输入的合法值；值沿用原输入的类型、范围、文本长度及选项约束。声明后必须在全局文档中放置唯一的 `<button data-preset="id"></button>`。按钮的文字与无障碍标签来自预设的 label，不使用独立 data-event 或嵌套绑定。数据行模板内不能放置全局预设。

该能力用于归零、恢复默认或切换有限示例。宿主将 values 合并到当前参数中，未列出的值保持当前值；不能把默认值重新覆盖到其他参数上。可以同时设置数值、开关、文本和选项。例：`{id:"zero",label:"角度归零",values:{pitch:0,yaw:0,roll:0}}`。

原生点击只发送 `{type:"input-preset",id}`。宿主查找当前计划，拒绝额外 values、未知预设或未挂载的按钮；生成的程序不能用预设请求网络、文件或工具动作。只读预览、冻结输入和合成 DOM 点击均不能触发该入口。

应用过程在一个普通执行预算内完成：先更新整组输入，按输入声明顺序逐个调用原有 `reduce(state,{type:"input",id,value},ctx)`，每个处理函数看到的 `ctx.inputs` 都是完整的新参数，最后只投影一次。中间状态不会发布给 UI 或保存服务。`ctx.inputs` 仍只读；错误会保留上一个完整检查点。

预设会暂停播放，但不自动调用 init，不清除任务进度、随机种子、逻辑步数或用户镜头。需要重置业务状态时，在普通 input 处理函数中明确实现；镜头仅按已有的显式 cameraRevision 规则处理。预设不是绕过 8ms 操作预算的启动入口。

新计划使用 `mini-app-1.6` 并要求 `inputPresets` 能力；普通旧计划身份保持不变。提示、接纳、执行和发布共用能力检查。新发布程序从初始检查点分别试运行所有预设，发布结果不携带试验输入；这不能证明其他历史状态或所有组合。读取历史检查点不追加这些探测。

保存前的输入冻结会等待整个事务完成；刷新从已确认的完整输入与任务状态恢复。相关测试包含原生按钮、控件数值、选择与镜头保留、暂停播放、恢复、伪造参数及非法声明，范围和未通过事项另见分批成果报告。
