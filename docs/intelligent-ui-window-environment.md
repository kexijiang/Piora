# Intelligent UI 当前窗口环境协商

2026-11-02 | 第三阶段增量 | 不代表第三阶段整体完成

三维能力按发起消息的窗口判断。代码已实现、验证证据匹配、运行平台支持，并且当前窗口的可信渲染器实际创建和读取 WebGL2 成功时，才允许该次运行生成三维输出。窗口报告只描述可用性，不授予权限，不接纳模型声明的能力或资源路径。

## 消息到发布

1. 通用消息客户端在带有 idempotencyKey 的 `prompt` / `submit_input` 提交前调用可选输出模块。Beta 关闭时不创建探测器；探测失败仍允许普通消息继续发送。
2. 每个窗口使用独立实例，在 app 自有的隔离 iframe 中创建 WebGL2、清屏并读取像素。报告包含渲染器协议、资源摘要、实例、epoch 和递增序号。
3. 服务端将报告关联到 sessionId + submissionId。SDK 运行开始时只绑定一次，关联信息通过现有消息幂等身份传递。没有报告的运行不会因为迟到报告或另一窗口的请求获得三维能力。
4. 模型每轮上下文读取该运行的能力；当前窗口说明覆盖会话创建时的静态环境状态。原始参数接纳、工具执行、正式发布均再次核对同一绑定及当前源码证据。
5. 加载已保存三维内容时，实际承载内容的 iframe 再次探测。环境不可用时保留静态结果与检查点，不启动场景。

普通聊天只接通通用输出预检；WebGL、窗口心跳和协议均在独立 mini-app 模块中。固定 schema 组件不依赖三维报告。外部动作继续使用原有权限边界。

## 失效和恢复

报告保存在进程内，不写为永久许可。心跳间隔 15 秒，3 分钟没有有效心跳即失效，留出后台标签页计时器限速余量。当前窗口关闭、Beta 关闭、探测器或实际场景丢失图形上下文时立即请求撤销；通知丢失由过期机制兜底。

同一资源 epoch 的心跳延长现有记录；新 epoch、资源摘要变化或过期后的新报告不能恢复旧运行引用。关闭记录保留带新序号的失效标记，迟到心跳不能使旧运行复活。环境恢复后需发起新请求，重新检测并关联；不会偷偷放宽仍在执行的请求。

注册表有容量边界：128 个窗口、512 个待关联提交和 256 个运行。容量压力最多令相关运行失去三维可用性，不阻止普通聊天。后台冻结超过过期时间会保守停用该次运行的三维发布；完整原生隐藏/恢复组合仍需后续验证。

## 开发验证

- `node scripts/verify-mini-app-capabilities.mjs`：检查协议、窗口绑定、真实浏览器预检、生产环境路由、运行身份、生成与发布失效，以及既有运行器回归。证据绑定被验证源码；软件 WebGL 不等于所有硬件兼容。
- `node scripts/verify-spatial-ui-desktop.mjs`：隔离真实开发桌面，自然表达生成、对象选择、改角度、换镜头、保存、刷新及真实模型追问。固定配置名称为 DeepSeek V4.1 Flash，provider/id 为 deepseek/deepseek-flash；禁止回退。具体供应端版本仍以供应方信息为限。

完整 CI、两人独立语义验收及发布包验证仍遵循三阶段开发完成后的统一安排。
