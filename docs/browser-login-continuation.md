# 浏览器登录后的自动继续

登录交接使用当前会话的实际浏览器标签页。页面会显示出来，聊天不弹登录确认卡。普通付款或账户安全确认仍要求用户明确完成，不套用登录自动继续规则。

旧实现要求出现此前没有的头像、用户菜单或退出按钮；已经登录的页面、没有标准标记的网站会一直等待。现在通过只读 DOM 探测返回页面是否就绪、是否有可见登录/验证码输入、是否有用户标记及当前 URL，不读取密码、cookie 或存储内容。

- 每 250 毫秒检查一次，单次探测限制为 500 毫秒，页面达到 `interactive` 即可观察，不等待广告等后台资源全部加载。
- 可见密码/验证码或登录表单仍由用户操作。有用户标记、或已离开原登录页时，连续两个就绪观察便恢复。
- 无头像、无退出按钮、仍保留 `/auth` 路由或不断更新查询参数的 SPA，在没有可见登录表单且就绪持续 1.5 秒后恢复页面核对，避免无限等待。
- 聊天中的等待状态每 250 毫秒同步。以上预算为就绪后约 3 秒内恢复检测留出余量；用户实际输入、网站服务响应和后续模型生成耗时分别计算。

恢复信号表示“可以重新读取页面核对”，不表示已证明登录成功。工具返回内容和浏览器使用说明都要求先取新快照、确认目标页面状态，再执行后续操作。取消、标签关闭、过期检查与新交接身份隔离，迟到检查不能恢复已取消的任务。
