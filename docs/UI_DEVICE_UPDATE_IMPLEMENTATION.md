## 2. 鸿蒙：单工具入口与按需帮助

现有鸿蒙后端已有设备发现、租约、语义 UI 树、截图、操作验证和场景执行；问题在于 26 项工具直接注册，占用常驻上下文。现仅注册 `harmony_control`，原实现成为内部操作表。注册工具的序列化长度估算约 238 tokens（字符/4 的工程估算，实际随模型 tokenizer 不同）。

调用顺序：

1. `{"operation":"help"}` 获取精简操作目录。
2. `{"operation":"help","topic":"list_devices"}` 仅获取设备发现的参数定义。
3. `{"operation":"list_devices","input":{}}` 发现设备，然后按需查询具体操作帮助。
4. 优先语义树定位与操作后验证，只有视觉判断必要时才索取截图；批量流程使用 `run_scenario`。

分发前使用 Pi SDK 参数校验，继续沿用任务身份、租约隔离、串行执行、取消与清理。树文本上限缩至 12,000 字符/100 节点。普通编码会话默认可见该单工具；旧会话已经启用的鸿蒙操作迁移到入口，明确关闭过入口的选择不被覆盖。

本机 HDC 返回 `[Empty]`，因此本次没有完成真实设备端到端验收。连接设备并完成设备侧授权后，应验证：发现 → 读取 UI 树 → 点击/输入 → 再观察 → 取消任务释放租约。相关集成测试通过模拟设备后端覆盖调用链和错误路径。

## 3. 定时后台静默更新

入口：安装版桌面应用「设置 → 通用 → 后台静默更新」。默认关闭，默认时间 03:00，按本地时间保存。便携版/开发环境等不支持自动安装的运行方式保持不可用。

主进程每 30 秒检查计划，不依赖渲染器可见性；到时间后检查并下载更新。程序错过时间后重新运行会补检查，当天完成后不重复。失败 15 分钟后重试；下载后遇忙碌会延后，跨午夜仍保留待安装状态。修改时间或关闭开关会在后续异步步骤重新检查。

安装前要求没有运行中的任务、没有未保存/正在保存的编辑内容、电脑空闲至少 60 秒。再次读取服务端运行状态，失败时不安装；随后取得短时更新租约，阻止检查之后新任务进入。文件阻塞标识按编辑器实例分配，避免相同文件多标签相互清除。安装调用现有 Electron updater 的 `quitAndInstall(true, true)`，复用退出清理和失败恢复；手动更新行为保留。

真实覆盖安装依赖安装版、更新服务器上更高版本及有效发布产物。本机未运行真实覆盖安装；发布与安装包验收由后续 beta CI 执行。遵守仓库开发约束，没有执行 `next build`。当前旧 standalone 产物与已安装的 Next 依赖版本不同，旧产物的许可证打包校验不通过，必须在正式发布构建后重新打包及验收，不能把旧目录当成本次构建结果。

## 4. Windows 电脑控制选型与集成

| 项目 | 事实与判断 |
| --- | --- |
| [Windows-MCP](https://github.com/CursorTouch/Windows-MCP) | MIT；已有 UI Automation、鼠标键盘、截图与 stdio MCP 接口。可直接接入现有 Pi 决策循环，本次采用 |
| [Microsoft UFO](https://github.com/microsoft/UFO) | MIT；完整 Windows Agent 编排系统。能力广，但再嵌套一套 Agent 编排会增加状态与模型配置复杂度，本次不采用（架构判断） |

新增默认关闭的 `Piora Computer Control` 扩展，只注册 `computer_control`。首次需要安装 [uv](https://docs.astral.sh/uv/getting-started/installation/)，然后在「设置 → 扩展」启用扩展，检查连接，并在任务能力中启用该工具。运行环境使用 PyPI 已发布的 [windows-mcp 0.8.5](https://pypi.org/project/windows-mcp/0.8.5/) 与 Python 3.13；上游主分支的 Python 要求与该发行版不同，因此显式固定发行版。首次启动需要联网下载运行环境。

仅给后端开放 14 项 GUI 相关能力：App、DisplayInventory、Snapshot、Screenshot、Click、Type、Scroll、Move、Shortcut、Wait、WaitFor、MultiSelect、MultiEdit、Clipboard。未开放后端的 Shell、注册表、文件系统等重复能力。关闭匿名遥测；Windows 子进程隐藏启动。中文系统上游 App 启动功能有已知限制，应从当前 UI 启动或使用现有程序窗口。

工具支持 `status`、`help`、指定操作、`release`、`stop`。帮助按需返回单项 schema；文本上限 12,000 字符、最多一张有大小限制的截图。一次仅一个任务拥有控制权；异常不自动重放鼠标操作；任务结束释放运行进程。扩展关闭或紧急停止会终止自己启动的进程树；停止后需用户在设置恢复。

已真实启动固定版本后端，通过 MCP 初始化、14 项允许操作核对、Snapshot schema 获取以及停止清理。此冒烟测试没有发送鼠标键盘动作，因此不宣称所有应用的实际操控成功率已验证。可重复运行 `node scripts/verify-computer-control.mjs`。

## 5. 验证方式

- `npm run typecheck`：前端、服务端和 Electron 类型检查。
- `npm run lint`：全项目静态检查。
- `npm test`：现有全量回归与新增调度、更新租约、工具路由、电脑连接/隔离测试。
- `node scripts/audit-ui.mjs`：更新审查清单。
- `node scripts/verify-computer-control.mjs`：真实 MCP 连接冒烟，不操作桌面。
- `npm run licenses:check`：源码依赖许可证清单一致性；发布时仍需单独执行包产物校验。

发布验收还需：真实鸿蒙设备操作；安装版 Electron 设置/IPC；有更新版本时的下载、忙碌延后、静默覆盖安装和自动重启。开发服务器不具备安装版更新条件。

## 6. beta.5 初版启动动画与发布记录

新增用户需求实施为 Blender 原创 3D 短片，场景和镜头由 `scripts/blender/polaris-rover.py` 生成。Blender 5.2.1 LTS 便携版安装在当前用户的 Programs/Blender 目录，并添加开始菜单快捷方式；安装包本身只携带视频与海报，不依赖用户安装 Blender。

六轮探测车沿冰原行驶，包含车轮转动、太阳能翼板、双目导航相机、取样臂、发光裂隙、远山、极光和星空。1280×720、24 fps、8 秒、无声音。可编辑 `.blend` 场景随源码保存，构建仅附带 MP4/JPG；清单包含大小与 SHA-256 校验。

主进程直接显示本地媒体，启动文档的 CSP 禁止联网。新版本第一次启动最多保留 8 秒片头，用户可以跳过；普通启动在服务就绪后立即进入。遵循减少动态效果偏好，缺失/解码失败不阻塞启动，实际进入工作区后再保存已启动版本。运行 `node scripts/preview-startup.mjs` 可以在本机浏览器检查相同启动文档。

发布版本为 `0.4.41-beta.5`（beta.4 的旧工具名验收脚本在 CI 中失败，已修正并补充契约测试），使用现有 `v*-beta.*` 标签流程，执行类型检查、Lint、全量测试、性能预算、许可证校验、Windows 构建、安装版/便携版冒烟和更新元数据检查。源码阶段不能替代 CI 的安装包验收；发布状态以对应 GitHub Actions 运行结果为准。

## 7. PX-06 动画重制

用户选择使用新提供的 `piora_intro.py` 中的 PX-06 车型及完整分镜。当前场景设定为 2076 年、北极星方向的虚构冰岩世界，保留三维 `piora` 车身标识、六轮随地形运动、轮迹和冰尘、减速扫描，以及片尾品牌与英文副标题。正式输出为 1920×1080、30 fps、240 帧／8 秒、无音轨。

原始 ZIP 保留不动；项目副本修复了 Blender 5.2 的视频媒体类型、辉光输入、混合／数值节点、Alpha Over 插槽和单帧输出设置恢复。实际渲染发现的车身主标识与序列号重叠也已修正。可编辑场景内嵌生成代码，所有动作是烘焙关键帧，无需自动执行脚本。复现与验证方法见 `scripts/blender/README.md`。

除原有 8 项数值测试外，新增 Blender 实际场景验证：240 帧、1,440 次轮心与真实地表三角网格的接地检查；9 个镜头位置的实际车体包围盒检查；停车、片尾可见性及两侧车身文字分离检查。这些是程序化运动的验证，不是完整车辆物理仿真。

启动页按原比例完整显示影片，撤下旧的大标题与遮罩，保留右上角状态和跳过。影片正常播放结束后继续启动；初始化或解码异常有 10 秒外层上限，减少动态效果偏好与媒体错误均能提前释放等待。静态回退使用车身标识镜头，避免把开场暗帧当作海报。浏览器中已检查静音、完整 8 秒播放及默认／最小桌面窗口布局。
