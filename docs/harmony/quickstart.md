# 第一次连接和测试

1. 安装 GitHub Releases 的 Windows 桌面版。通过 DevEco Studio 安装 HarmonyOS API 26 SDK/HDC，并先运行 `devecocli auth login` 完成开发者登录。打开手机开发者选项、USB 调试，在手机确认电脑授权并保持屏幕解锁。普通用户不需要编写签名描述文件。
2. 打开右侧 Harmony 面板，选择检测到的 HDC 与手机。在“设备设置 → 连接诊断”运行只读检查。多台设备必须明确选择；Agent 的设备归属不会跟随面板选择改变。
3. 投屏缺少服务时，点击“初始化投屏服务”。程序先核对安装包所带 unsigned HAP 的来源和真机验收收据；首次初始化会在 Piora 私有缓存复制一个只含工程元数据的签名项目，并调用随包 DevEco CLI 为当前已连接手机生成或更新 debug Profile。随后程序从 DevEco 私有配置目录读取生成结果，创建并官方验签只适用于该 Profile 的私有副本。已装组件不匹配时会先卸载并确认缺席，再执行普通 `hdc install`，不使用 `-r`。登录、API 26 签名工具、有效 Profile 或手机绑定缺失时，程序会在安装命令发出前明确说明配置问题；不会尝试直接安装 unsigned HAP。
4. 投屏画面只读，可缩放、拖动查看、截图和录屏。点击或拖动画布不会向手机注入触摸，观看也不会占用设备。需要操作手机时使用 AI、应用或测试等工具；这些动作由设备队列按实际状态执行。

5. 在“应用”按名称或包标识搜索，选择查询得到的启动入口。旧系统不提供名称时显示实际包标识，不猜应用名称或 ability。
6. 在底部“工具 → 测试”选择手机应用、场景和验证内容，再运行测试；步骤预览与工程验证收在展开项内。“记录”查看媒体保存路径、通过、失败、未执行步骤及恢复条件。工具默认关闭，宽面板在侧边展开、窄面板从底部展开。新用户可先用 [测试工程](../../tests/harmony-fixture/README.md)。

原生视频不可用时，画面切换到兼容投屏并保留失败原因。可点击画面上的“重试视频”重新建立观看连接；该操作不会签名或安装组件、启动手机应用或注入输入。首次部署仍需明确点击“启用实时视频”，并在手机完成共享授权。候选普通权限组件在实际录屏开始后建立系统录屏后台通知，以便切换应用继续观看；系统取消或暂停该任务时结束共享，不自动重新请求授权。beta 标签任务用随包的同一 unsigned 输入生成私有 DevEco device-signed 副本做官方验签和专用手机门禁，随后删除该副本且不上传；桌面候选只携带 unsigned HAP 与脱敏收据。最终 beta 安装包仍须另行实机验收，未完成时不能视为通过。

Agent 推荐顺序：`harmony_control` 的 `list_devices → capabilities → discover → observe_page → act/run_scenario → verify`。已连接设备的应用操作、系统按键、安装、卸载、清数据与录屏均不再需要额外批准。面板只读观察无需控制租约。
