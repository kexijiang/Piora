# 三种音频路径

- 电脑听写：Windows 安装版内的 SenseVoiceSmall INT8 + sherpa-onnx 把电脑麦克风录音变成输入框文字；它没有给手机输入声音。
- 声学输入：选定本地 PCM16 WAV、明确的电脑输出设备、手机目标应用/窗口、监听就绪控件和精确识别文字。一个租约负责进入监听、播放、释放及结果验证。只有手机实际文字匹配才通过；播放器结束或声波动画不足以通过。
- app-test：仅自有 debug fixture 的短时认证 PCM 输入，核对手机端接收字节 hash。不会覆盖真实麦克风、第三方 App 或 ASR；生产源与生产 HAP 必须排除入口。

工作台“语音”导入不可变 WAV（8–48 kHz，单/双声道，50 ms–30 s，8 MiB 上限），列出并明确选择输出。首次选择音频、输出及目标条件后直接执行校准；成功后配置绑定设备/OS 与输出标识。设备或输出变动需重校。

按住说话先在“按键与触摸”校准足够的精确触摸时长，再选择 push-to-talk。校准的按住时长必须覆盖监听就绪、音频播放及 500 ms 尾静音预算；全程检查应用、窗口和几何，取消会停止播放并释放触摸。声学通路全局互斥，避免多手机测试互相串音。

app-test 配对使用“当前控制者 ID”，手机生成 2 分钟单次 token 和设备实例 ID。只接受 16 kHz 单声道 PCM16 的 50–250 ms 样本；其他 run、实例、过期、重放均拒绝。配对信息只填入桌面专用表单，不发送给模型。详见 [fixture](../../tests/harmony-fixture/README.md)。
