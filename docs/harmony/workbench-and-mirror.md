# 鸿蒙工作台与独立投屏

实施日期：2026-10-26。设计采用简洁原生工作台和单个独立只读投屏窗口，使用 Piora 主题和字体设置。本文描述当前实现；真机性能目标不代表已通过验收。

## 入口与功能组织

点击鸿蒙设备会展开主工作区，可返回双栏。首次发现设备时选择第一台在线设备；在线设备排在前面，同组保持发现顺序。手动选择后，刷新或新增设备不会抢走选择；断连保留设备身份。相同名称通过序列号后缀区分。

固定导航是概览、应用、文件、媒体。更多菜单按开发工具、自动化、维护分组，打开可关闭的工作标签。文件目录树只属于文件功能。工具按需加载，已经挂载的工具在切换标签时保留状态。顶部任务入口继续使用后端操作任务记录。

| 功能 | 实施落点 |
| --- | --- |
| 概览、设备选择、设置、诊断、任务入口 | `components/workspace/HarmonyPanel.tsx` |
| 应用、文件、数据库、终端、场景、语音、界面结构 | 复用 `components/workspace/harmony/WorkbenchTools.tsx` 及其子模块 |
| 日志 | 复用 `components/workspace/HarmonyLogViewer.tsx` |
| 媒体筛选、预览、定位、复制、删除 | `components/workspace/harmony/MediaHistory.tsx` |
| 独立投屏 | `app/desktop-harmony/page.tsx`、`MirrorWindow.tsx` |
| 通用结果和确认 | `components/PioraMessage.tsx`、`app/desktop-message/page.tsx` |

浏览器模式保留桌面能力说明。观看不取得输入租约，不安装、唤醒、解锁手机，不向设备发送鼠标或键盘输入。投屏组件初始化仍需显式操作。

## 窗口与缩放

`desktop/src/harmony-windows.ts` 管理单实例投屏，重复打开唤起已有窗口。主进程保存每台设备的比例、位置；本次运行的所选设备和媒体 owner 在工作台与投屏间共享。首次默认 75%，不从上次运行恢复默认设备。

100% 是当前显示器工作区扣除边距后可完整容纳的最大画面。`harmony-window-bounds.ts` 在 DIP 中计算：

```
W0/H0 = 当前画面宽高比
W = round(W0 * scale / 100)
H = round(H0 * scale / 100)
外窗宽 = W + 2
外窗高 = H + 36 + 2
```

比例为 25%、50%、75%、100%。画面和外窗一起变小，标题栏保持 36 DIP。比例不改变视频编码、截图和录屏分辨率。横竖屏或显示器变化重新计算；仅编码分辨率改变而宽高比不变时保持窗口尺寸。

Windows 非整数 DPI 下通过完整 bounds 设置、读取实际 bounds 后有界一 DIP 修正，避免连续拖动的取整误差累积。位置限制在工作区内。窗口底部没有 Piora 操作或文案；窄窗口把功能收到原生菜单，保留菜单和关闭。

最小化只暂停观看订阅，后端录屏继续。关闭和切换设备检查当前录屏：本实例拥有的录屏需确认停止保存，失败保留窗口；其他控制者的录屏继续，窗口不会擅自停止。系统录屏状态不明时先在手机停止，再取回文件。

## 桌面权限边界

`harmonyMirror` 提供打开、唤起、关闭、选设备、比例、置顶、状态事件、画面尺寸报告和原生菜单。页面不能提交任意外窗边界。

投屏发送方必须同时匹配注册的 webContents、主 frame、应用 origin 和专用路由。新窗口共享桌面认证会话，禁止任意导航、新窗口及 webview。文件定位只接受当前设备媒体历史中的路径；截图复制沿用媒体验证。通用消息窗口有单独的发送方校验，仅接受有限动作 ID，不接收执行代码或回调函数。

## 截图与通用提示

截图通过 `/api/harmony/media` 保存设备原始图片，成功后独立尝试复制。保存成功但复制失败仍显示保存成功，并提供重试复制；保存失败不产生虚假媒体条目。按钮处理中拒绝同次重复操作，设备切换后旧响应不覆盖新设备状态。

截图、录屏结果、媒体操作错误和确认统一调用 `showPioraMessage`。桌面使用约 430 DIP 独立模态窗口，复用 Piora 确认样式、主题和焦点管理；浏览器承载使用同一内容组件。无底部 Toast。自动录屏结束结果通过录屏 ID 跨窗口去重，包含到限或磁盘不足等停止原因。

## 录屏与恢复

统一策略位于 `lib/harmony/media/recording-policy.ts`：

| 项目 | 当前策略 |
| --- | --- |
| 时长 | 最长 30 分钟 |
| 原生流文件 | 2 GiB，预留 16 MiB 封装余量 |
| 帧数 | 216000 帧，与 30 分钟、最高 120 FPS 对齐 |
| 空间 | 开始检查，每 5 秒复查；低于 256 MiB 停止并尝试保存 |
| 音频 | 内置流录制不新增音轨；系统录屏文件原样保留 |
| 输出 | 流式写盘，不保留整段视频内存副本 |

Manager 是录屏状态的唯一来源。准备、录制、保存、恢复和状态不明均显式区分；请求绑定设备和 recordingId，停止幂等。UI 刷新保留桌面实例 owner，不使用每个页面新建的随机 owner。

`owned-recording.ts` 使用独立原生视频订阅。到限、方向或编码配置不兼容时收尾当前段；断流尝试保存已有可播放内容。缩放和观看最小化不影响录屏。系统录屏停止失败后的重试只取回文件，避免重复切换录屏开关。

临时 MP4 和原子写入的 JSON 恢复清单位于 Harmony 配置目录旁的 `harmony-recording-drafts`。已封装草稿保存失败后保留，可换目录重试；重启后从登记清单恢复。页面仅传恢复 ID，不传临时路径。未封装的崩溃文件明确提示无法自动恢复，保留供处理；放弃恢复需要确认，只删除对应本地草稿及记录，不删除手机相册原件。

本期不拼接不同规格视频，不承诺任意进程崩溃后的 MP4 都可播放。录屏原有设备兼容性和系统录屏支持范围仍然适用。

## 性能与验收边界

工作台不创建隐藏视频订阅。投屏优先原生链路、保留截图回退；截图请求串行且刷新间隔扣除采集耗时。坐标校验不阻塞观看。解码拥塞有界等待和恢复，不无条件丢弃 H.264 依赖帧。旧设备请求、帧和尺寸报告失效。

连接详情的 FPS 来自实际绘制计数，主机绘制耗时只统计绘制；两者都不能代替端到端延迟测量。HDC 参数响应时间也不视为视频延迟。

真实 USB 设备的 10 分钟动态画面、平均至少 24 FPS、P95 不超过 250 ms，以及真实 30 分钟录制仍需验收。2026-10-26 本地 `hdc list targets` 返回 `[Empty]`，没有把模拟视频或浏览器夹具结果记作真机通过。
