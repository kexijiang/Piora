# 当前设备运行边界

HTTP、轻量 Agent 网关与场景以 `lib/harmony/contracts/actions.ts` 为动作契约。`action-dispatcher.ts` 执行直接动作；`scenario-executor.ts` 执行有界步骤。Manager 保持 façade，集中设备 lane、lease、epoch、互斥与取消；读屏质量和几何分别位于 observation。

HDC 负责发现、文件/流和只读设备信息；Hybrid 选路，Hypium 只在独立子进程加载。父进程 PATH 不变，子进程收到固定 HDC 环境。`.harmony-worker` 通过独立 TypeScript 任务编译并被 standalone 打包验证。worker IPC 绑定协议版本、专属进程 epoch、设备、单调请求 ID 和截止时间；过期或外来请求在执行前被拒绝，取消终止其专属进程。worker 超时/崩溃后不重放效果不明的动作。

投屏默认使用内置 HDC 视频服务，旁观不会自动安装、唤醒或解锁设备。用户显式选择 HOScrcpy 时，可指定本地 dsh-hos-scrcpy 包（Java sidecar 类及 SDK jar）；Piora 独立启动 Java 进程，只在服务端连接其回环 WebSocket，将 H.264 回调转换为原有视频协议，网页仍只访问经过桌面认证的 `/api/harmony/video`。此可选模式首次开流可能由第三方 SDK 部署设备组件；缺包、启动失败或进程异常时短时冷却并回退内置投屏。SDK jar 不随 Piora 分发，其源码许可声明尚待上游补全；没有真机视频回执前不能宣称该适配已完成设备验收。

设备锁位于用户目录统一 physical serial 哈希命名空间，跨进程及品牌互斥；活 PID 不会因时间老而被抢占。退休死 owner 与建立新 owner 使用互斥 gate，无法确认的状态拒绝接单。

HDC 在线状态作为已完成设备授权的边界，不添加应用范围 grant 或单次审批。lease 只负责并发归属与取消；安装前自动导入校验过的 HAP 副本。场景 journal 保存步骤与检查点，私有输入不进入公开列表。恢复在设备 lane 内重观测，未知副作用不能自动重放。

应用管理的直接动作与场景使用同一动作目录和设备 lane。桌面及 AI 安装入口均只接受已允许工作区内的 HAP，并由控制后端冻结产物。设备文件浏览是只读能力：共享路径通过 HDC shell 查询，可调试应用沙箱通过 `shell -b` 查询；路径不允许父级跳转、控制字节或沙箱外绝对路径。实机 HDC 会丢弃 NUL 输出字节，目录条目改用 ASCII 记录/单元分隔符，跳过含分隔符的名称，并限制为 500 项；元数据每 50 项批量读取，缺失目录或缺少 `stat -c` 时返回能力错误。单文件下载通过 `file recv` 先写到目标目录内的私有临时目录，核对大小后以同卷硬链接原子发布到尚不存在的目标路径；不支持硬链接的文件系统返回错误，不暴露半成品。上传使用与安装相同的写入 fence：先冻结工作区文件，限制设备目标路径，默认拒绝覆盖与符号链接；`file send` 写入同目录随机暂存名，校验长度后再用 `mv -n/-f` 移到目标并复查，不直接向目标传输。HDC 3.1.0e 起支持非交互式 `shell -b` 和沙箱文件传输，但真机兼容性仍须逐设备验证。

应用清缓存使用 `bm clean -c -n`，与清数据使用的 `-d` 分开。应用使能/禁用仅调用 `bm enable/disable -n`，不传 user ID，按设备当前活跃用户执行。OpenHarmony 官方文档说明它仅在 root 构建可用；user 构建和设备返回未确认成功时必须报错。文档同时说明 `-u` 指定非活跃用户可能实际作用于当前活跃用户，因此面板不提供跨用户切换。开发板镜像特权通过工作区内 `install_list_capability.json` 的独立流程配置，限定 bundle 与证书 SHA-256 指纹，预览差异后要求原文件哈希一致，写入前备份，恢复也保留被替换版本并核对哈希。本地写入不代表设备已部署或重启生效。

设备交互式 Shell 使用独立的 HDC PTY，会话绑定手动 lease 与指定设备；输入和窗口尺寸操作在服务端再次校验 lease，lease 到期或关闭面板时结束子进程。输出仅经桌面认证的 SSE 发送给当前面板，不写入设备管理日志。单次命令仍经过设备 lane 并返回有界输出和退出码；交互式会话中的副作用无法逐条核验，断线时不宣称成功。

设备文件变更仅允许可写共享路径或调试沙箱的 `data/storage` 内。新建目录不自动创建父目录；删除仅针对普通文件和空目录，重命名保持在同一目录且使用 `mv -n`，每次变更后重新查询设备路径类型。符号链接不作为可变更目标；无法可靠确认结果时报错，不宣称成功。

权限编辑仅接受三位八进制模式，不支持递归、setuid/setgid/sticky、所有者或系统目录操作；设备执行 `chmod` 后用 `stat -c '%a'` 回读。目录和文件必须是普通目标，符号链接不通过类型检查。

文件名搜索在设备 lane 内按广度优先遍历，最多 5 层、80 个目录、4000 个条目、200 个匹配项或 30 秒；不进入符号链接，子目录不可读会计入跳过数。面板收藏路径按设备与沙箱保存在本机浏览器存储中。

设备文本预览在传输前限制为 2 MiB 普通文件，完整下载后核对长度。默认按 BOM 识别 UTF-8/UTF-16 LE/BE，否则按严格 UTF-8；GB18030 必须显式选择且要求编解码往返无损，拒绝 NUL 字节。保存时保留 BOM 和原有单一换行格式；混合换行须由用户明确选定统一格式。差异预览限制输入、计算时间和输出大小。AI 结果最多携带 12,000 个字符，标注设备内容不可信；面板显示完整文本。保存时要求打开时的 SHA-256 与设备当前内容匹配，新内容先经 `file send` 写入同目录独立暂存文件，再在设备 shell 中检查原文件哈希并替换，最后回读新哈希。缺少 `sha256sum` 时禁用保存；取消或无法确认时不把未知效果报为成功。

手动 Wi-Fi 调试入口要求用户在设备上先启用无线调试，再输入局域网 IPv4:端口。服务端调用 HDC `tconn` 或 `tconn ... -remove` 后读取目标列表核对；正在持有 lease 的同一设备不允许切换连接。显式断开完成后清除普通轮询的暂时缺席宽限，避免 UI 继续把已断开的设备显示在线。真实 USB/Wi-Fi 切换及版本兼容性仍需设备验证。官方命令语义参见 [OpenHarmony HDC 指南](https://gitee.com/openharmony/docs/blob/master/zh-cn/device-dev/subsystems/subsys-toolchain-hdc-guide.md)。

目录浏览按 500 项一页调用设备 Shell，逐页跳过前面的目录项后再批量读取当前页元数据；服务端只返回有界页，且检测是否有下一页。页面排序和隐藏过滤不跨页，目录在翻页期间变化时页边界可能移动。递归查找继续保持 4000 项、80 目录和 30 秒边界，不宣称无截断的全目录索引。

上传前的工作区文件冻结使用 1 MiB 分块复制，核对源文件身份、大小与修改时间，并在私有副本落盘后再逐块验证 SHA-256；整个过程不分配与文件等大的 Buffer。上传/下载的软件上限统一为 1 GiB；不超过 256 MiB 的 HDC 传输保持 120 秒超时，大于此值的传输采用 30 分钟有界超时与后台任务取消。冻结副本在单次设备调用结束后清理。1 GiB 的真实设备往返和断线行为仍须验收。

后台文件传输由 `HarmonyTransferJobs` 维护，单批最多 20 项、同设备串行，任务元数据原子写入 HDC 配置旁的私有 JSON 日志，lease 令牌只保存在进程内。上传入队时将已获准的手动 lease 原子交给任务，后台定期续租并在结算后释放，因此面板卸载不影响运行。上传仍调用同一设备写入 fence 与源文件冻结链；下载重新校验工作区目标。进程重启后未完成任务标为 `interrupted`，不自动重放可能已生效的设备写入。HDC 官方回执不承诺实时字节事件，界面仅展示已确认完成的文件数和字节数；运行中单文件的效果与取消后的设备暂存状态必须谨慎核对。上传取消后使用独立短时命令尽力清理随机暂存路径；断线时无法保证远端清理。设备“任务”页汇集传输记录与场景执行记录。

SQLite 查看器只接受工作区内已下载的普通本地文件，限制为 64 MiB，拒绝伴有 `-wal` 的文件。打开时复制到私有临时目录，后续表浏览、查询和导出均绑定该快照 ID；关闭或十分钟后清理，最多同时打开八个。独立 worker 用 `DatabaseSync({ readOnly: true, allowExtension: false })` 与 `query_only` 打开，列出普通表和视图、字段及索引。表和查询每页最多 200 行、100 列；单条 SELECT/WITH 查询最多查看前 1000 行，拒绝分号和其他语句，文本和 BLOB 单元格截断显示，浏览超时为 5 秒。CSV/JSON 导出在 worker 内逐行写入私有临时文件，限制 10 万行、64 MiB 和 30 秒，HTTP 以流返回并在完成或取消后清理。浏览器优先使用文件流写入接口，不支持时以有界 Blob 下载；CSV 文字中会触发表格公式的前缀加单引号，JSON 中大整数以字符串、BLOB 以 Base64 对象表示。设备侧数据库快照自动获取仍待实现。它不提供正在写入的设备数据库的一致性保证：主文件可能遗漏 WAL 中的事务，用户应先通过应用导出一致快照。依据 [SQLite 备份说明](https://www.sqlite.org/backup.html)和[WAL 说明](https://www.sqlite.org/wal.html)。

AI 的 `harmony_control` 中 `database` 操作复用相同快照服务；每个 AI 快照绑定当前 prompt run，任务结束即关闭。读取结果仅返回前 10 行、20 列的有限预览，数据库内容明确标为不可信；导出只能新建已获准工作区文件，失败清理未完成文件。

专用调试 HAP 可通过系统备份 API 生成一致副本；用户通过持久后台下载任务取回 `.db`/`.sqlite` 后，可从完成项打开本机只读查看器。任意第三方应用的在线数据库没有通用 HDC 一致快照接口，必须由该应用自行导出；主文件单独拷贝不能覆盖未检查点的 WAL 事务。

单次命令抽屉只供用户手动运行，不加入 AI 动作目录。命令仍需设备 lease，经过与其他写操作相同的 dispatch fence 和设备 lane；每条命令使用单独的 HDC `shell` 调用，最多 15 秒、128 KiB 输出。退出码通过每次随机生成的结束标记解析；缺失标记时结果不确认。单次命令的多标签只保留当前网页中的输出记录，可跨标签查找命令、标准输出、错误输出与失败原因并跳转；复制和粘贴均由用户显式触发，粘贴只修改草稿。工作目录和环境变量不跨单次命令保持；同页的交互式 PTY 则保留 Shell 状态。

用户定义的快捷命令按设备保存在浏览器存储，最多 20 条；旧版数组记录仍可读取。快捷项包含设备/本机目标、设备 Shell/调试沙箱范围、分组、收藏和参数模板，支持编辑及版本化 JSON 导入导出。模板占位符仅在命令引号外使用；设备参数作为 POSIX Shell 单独参数引用，本机参数限普通路径/标识符字符。选择或导入不自动执行：设备命令仅填入输入框，本机命令复制到剪贴板并打开现有本机 PTY，用户仍须检查和手动粘贴。面板不把本机命令伪装为设备 Shell。

命令兼容性依据：[OpenHarmony HDC 文档](https://github.com/openharmony/docs/blob/master/zh-cn/application-dev/dfx/hdc.md)与[Bundle Manager 文档](https://github.com/openharmony/docs/blob/master/en/application-dev/tools/bm-tool.md)。

现有 `check-runtime/check-config/check-types` 继续提供 DevEco CLI 检查。开发验证链引用 report ID、工程源指纹、用户选中 HAP hash、场景执行 ID 与按进程过滤日志；不声称读取 IDE Problems 或证明用户选中的 HAP 一定来自该源码构建。
