# 当前设备运行边界

数据库应用树将应用名称与扫描状态排在同一行；存在友好名称时才另行显示包名，长名称省略但保留悬停全文。无法扫描的原因仅在该应用展开时显示，折叠与状态通过 `aria-expanded` 和辅助描述提供给键盘及读屏。SQL 编辑区去除重复标题，筛选与复制合并，结果表格使用剩余面板高度并独立滚动。文件页预览顶部的数据库捷径仍按当前自动发现结果匹配，不要求用户手动提供数据库路径。

跨进程设备占用错误保留物理互斥，不自动终止活跃 owner 或删除锁。桌面将含有效 owner PID 的 `DEVICE_BUSY` 显示为另一个 Piora 实例正在使用设备，建议先在该实例结束操作；不在普通提示中暴露 PID。停止或清理未确认状态优先显示对应恢复指导。

场景新增只读 `capture_screenshot` 步骤，Manager 在已占用的设备队列内直接采集并保存截图，不再次嵌套排队。步骤截图与结束截图使用媒体库文件元数据，历史记录不保存图片字节或原始 UI 树；结束截图缺失或保存失败使总体结果失败，已完成步骤保持原结果。最终 UI 摘要、设备版本和采集失败原因持久保存。

每次桌面运行传入 UUID `clientRunId`，Journal 启动时重建标识索引；按设备与标识读取本次进度只访问对应记录，不每秒扫描整个目录。重复标识不能重放场景。UI 串行轮询，隐藏页面暂不读取，关闭或切换时取消；失败保留最后确认进度，恢复后不重新执行。

可选 `policy.collectLogs` 默认关闭；选中才在场景步骤与最终观察之后读取设备日志尾部，直接复用后端读接口以避免队列递归。最多 200 行，序列化正文总量限制 128 KiB，逐字段限长；超限保留较新行并标注截断。它不是严格运行时间范围内或特定应用的完整日志，UI 明示来源、时间及失败原因。日志失败不改写已验证的步骤结果；取消采集仍使当前运行中断。当前结果导出含最终快照，历史导出仅包含记录摘要、截图元数据和用户选择的日志，不包含私有输入或租约令牌。

`POST /api/harmony/scenario/preview` 只解析不超过 128 KiB 的步骤与策略，复用 `validateHarmonyScenario` 的实际运行参数校验。接口受同一桌面身份、可信请求与 JSON 边界保护，不构建设备管理器，不冻结安装包、不取得租约、不检查设备能力或派发动作；返回去重动作列表和 `deviceVerified: false`。场景编辑器显示这些边界，新增、改参数、排序、删除和修改结束截图策略都会撤销旧预览。模板与应用列表分别结算，应用读取失败保留自定义步骤；运行前再次校验，准备控制期间取消后不发送场景，运行中锁定编辑，关闭工具中止当前请求。危险应用维护步骤在运行前列出设备与实际目标，结果按动作、状态和耗时呈现并可导出。

设备截图使用独立的 `harmony.screenshot` 快捷键标识，默认 Alt+Shift+S，复用应用快捷键设置、冲突检查与持久配置；与桌面截图命令分开。Electron 接受完整键位映射但不将设备截图注册为全局快捷键或菜单动作。可见且 active 的 Harmony 面板自行匹配当前配置，设备不可截图、正在截图、输入框/终端/显式保留区域、可见模态弹窗、已处理事件、重复与输入法组合按键均不抢键；隐藏面板不处理。截图不获取人工租约，仍可在 AI 持有控制或一般工具准备期间独立采集。

HDC 的 Connected 列表只表示主机发现传输目标。目标命令返回明确的通道尚未建立、isDead 或 hChannel nullptr 协议错误时，丢弃该设备的在线信息与能力缓存，返回不含原始输出的 `hdc-channel-not-ready` 原因。参数查询出现该原因且本轮所有设备信息均不可核实时，设备状态为 unknown，不缓存为在线；下次列表读取立即重试。存在有效信息的部分查询失败，以及普通参数缺失、权限不足、未知命令不单独推断设备离线。界面保留 USB 传输证据并显示连接未确认，停止实时帧与截图/新录屏入口；提示重连、授权和刷新，不自动重启主机 HDC、解锁或派发输入，也不声称失败前的动作已撤销。

目录树浏览状态按设备与共享/应用范围写入当前网页的 sessionStorage，最多记住 256 个已展开分支、各分支显示数量、额外根目录及滚动位置，不保存设备目录内容或权限判断。路径格式与范围重新校验，坏记录或禁用的浏览器存储不影响当前浏览。重新打开先完成当前路径读取，再以最多三个并发只读请求重新核对已展开分支的第一页，不递归扫描或自动读取后续页。读取失败保留展开选择与重试；点击、方向键、滚轮、刷新或导航取消本轮恢复，旧设备/旧范围及迟到回复不能更新新树。滚动位置等本轮布局完成后恢复，不抢走当前焦点；存储写入按动画帧合并，退出前补写最后已确认的浏览状态。

设备目录树复用工作区文件树的渐进显示机制：设备页最多读取 500 项，只缓存目录节点，每分支先显示 200 个，用户可从缓存每次增加 200 个，不触发新设备读取。分支下一页有独立偏移、扫描数量与截断状态，按路径去重，不改变中间文件列表或地址。读取失败保留旧节点并原位重试，刷新与导航取消未完成页，旧回复不得追加；达到 50000 偏移限制时说明上限，已知路径仍可直达。树内独立滚动，键盘焦点用元素与路径引用管理，移动焦点不重绘文件工作区或读取设备。重试和分页按钮保持独立激活，焦点处理不滚动父节点导致鼠标抬起时按钮移位。隐藏文件页不截获当前工具快捷键；目录浏览不需要租约。

展开工作台通过显式布局状态移除文件与数据库抽屉的宽度上限，使用完整工具区域；返回双栏恢复普通布局。文件文本预览根据实际可用宽度显示原文/草稿对照，原文仅为只读采集副本，不随草稿编辑更改。保存、差异、复制与明确放弃置于编辑器前，并在编辑区域滚动时保持可见；哈希折叠显示，避免长校验值挤走操作。文件路径直达和显式打开会将预览定位到工具视口，右键选中不自动滚动。原文对照开关只改变本机视图，不触发设备读取或租约；新编辑撤销旧差异结果。本机恢复入口在宽工具区域并排显示元数据目录与恢复正文，窄面板堆叠。

文件页提供本机恢复入口，不要求设备路径仍存在。草稿库版本 2 增加独立元数据目录，旧版本正文原样保留，升级时逐条填入目录，不捏造旧记录修改时间。正文与目录在同一事务写入/删除；每页最多 50 条目录记录，单次最多检查 500 条无效/已取消项，只按选中的身份读取正文。设备前缀与完整身份同时核对，内存中的未提交副本叠加到对应设备目录，持久目录读取失败明确显示窗口内副本。分页仅列本机元数据，不调用设备接口或获取租约；只有显式核对按钮再次读取设备路径。恢复正文与采集时原文标为本机副本，缺失或无权限仍可复制。放弃时同时比较已查看的内容/时间版本和异步提交期间的版本；有新编辑则不删除，已持久放弃后通知当前编辑器清除对应副本，避免旧编辑器重新冒充保留草稿。

设备文本草稿由独立的浏览器 IndexedDB 库 `piora-harmony-file-drafts` 保存，键包含设备标识、共享/应用范围和原路径，与聊天草稿隔离。编辑事件先同步保留内存副本，再串行提交有界文本及采集时原文；重复排队的相同最新版本不重复写入，只有事务完成才能显示持久保存成功。存储失败不清空内存，尚未提交或失败的内容离开页面时提示复制；没有按年龄/数量自动删除。重新打开先恢复草稿，再只读核对设备哈希，读取失败或变化时禁用保存；实际写入仍由服务端再次比较原哈希并校验替换后的新哈希。明确放弃或已验证保存才删除草稿，持久删除失败恢复内存副本。范围/设备切换取消旧请求，旧读取不更新新视图；保存、上传及文件维护等待租约后再次检查取消，不因晚到租约继续派发。

应用页自动读取完整列表（最多 5000 项，超限报错）并按 100 项分页。系统分类只使用匹配包身份的严格布尔元数据；兼容本机 `isSystemApp/userDataClearable` 与官方 `systemApp/dataUnclearable` 字段，冲突或缺失保持未知。缺少分类时最多三个详情读取任务、两分钟限时，可中止并继续。`debug` 构建标志不等于签名类型，沙箱入口只依据明确的 `appProvisionType` 禁用发行包，其余情况按实际只读目录检查返回原因；没有自动启动。卸载/清数据保护依据设备明确字段，操作后回读详情或列表。进程只显示当前匹配包或明确进程名的采样，未观察到不构成停止证明。字段语义参见 [OpenHarmony ApplicationInfo](https://github.com/openharmony/docs/blob/master/en/application-dev/reference/apis-ability-kit/js-apis-bundleManager-applicationInfo.md)。

启动入口兼容设备 `bm dump` 返回的 `visible` 与 `exported`：至少存在一个明确的布尔 true，已声明字段均为 true，且未被明确禁用，才列为可启动入口；冲突、缺失和非布尔值不推测。启动回执错误 10106102 转为 `SCREEN_LOCKED`，保留 `dispatchState: sent` 和原始错误码，提示在手机上手动解锁后重新发起；不自动重试、唤醒或输入密码。应用操作的取消、成功与错误反馈置于页内顶部并随滚动保持可见。错误码依据 [OpenHarmony aa 工具说明](https://github.com/openharmony/docs/blob/master/zh-cn/application-dev/tools/aa-tool.md)。

`POST /api/harmony/packages` 只读预览经过桌面认证且处于允许工作区的 HAP，256 MiB 文件上限；不解包或执行内容，仅流式读取根 `module.json` 或旧格式 `config.json`，实际展开元数据最多 512 KiB。返回声明的包名、版本、模块、设备类型、权限与 SHA-256，签名固定为未验证，不暴露证书或内部路径。桌面安装提交 `expectedHash`，设备 lane 内冻结副本前核对相同字节；不匹配返回未发送的 `STALE_SNAPSHOT`，既不派发也不自动重试。安装返回后界面再读目标包版本，只有与预览一致才显示版本已核对；原安装任务的设备命令回执与这个版本观察是两个证据。Stage 包配置来源参见 [官方包结构](https://github.com/openharmony/docs/blob/master/zh-cn/application-dev/quick-start/application-package-structure-stage.md)。

兼容投屏与用户截图共用每设备私有暂存位置，仅截图采集、传输和清理在独立每设备队列中串行，不阻塞其他设备动作。完整 PNG 已读入内存后，在返回前清除本机图片及本次生成的远端图片；取消或读取失败也进入清理，远端清理使用独立 3 秒截止，不沿用已取消信号。不删除其他进程或历史图片；断线时只能尽力清理，不能承诺设备不可达时已删除，退出时另做最后清理。

日志只有打开日志页时建立已认证 HiLog SSE，关闭或设备离线结束采集。前端保留最近一万行，暂停只冻结展示副本，不停止接收；断线保留已收到内容，切换设备或显式刷新清除旧设备视图。服务端未接收数与前端超出保留上限数分别累计；清空只清除本地视图和计数，不调用设备日志清理。行按实际字体测量高度虚拟渲染，截断的正文可进入完整行详情。进程、级别、TAG、文本/正则和时间条件共同筛选；时间基于 HiLog 原始设备时钟，可填 HH:mm[:ss] 或 MM-DD HH:mm[:ss]，不猜年份、时区，允许跨午夜/年末的有界环回区间。导出只包含当前展示副本中的保留原文或其筛选结果，不补造已丢失的历史日志；暂停时新收到但未展示的内容不进入导出。

SQLite 结构与数据共用已验证的私有快照。`table_xinfo` 只排除隐藏虚拟表内部列，不排除 VIRTUAL/STORED 生成列；主键保留顺序。索引目录包含普通表的自动 UNIQUE/主键约束索引，`index_list` 提供来源和部分索引标志，`index_xinfo` 仅保留声明键，排除辅助存储列，记录排序与校对规则。表达式或 rowid 通过种类区分，不把空字段名转成字符串 `null`；表达式和条件展示 `sqlite_schema.sql` 的实际定义，不猜测其 SQL。省略目标字段的外键保留空值，由界面说明引用父表主键；表与视图都提供有界创建语句。定义最多 10,000 字符，索引目录最多 200 项、每表索引最多 100 项、每索引键最多 100 项，沿用 worker 的只读和资源边界。语义依据 [SQLite PRAGMA 文档](https://sqlite.org/pragma.html)。

设备响应样本来自既有只读 API 版本参数命令，只有退出成功、返回有效版本且耗时有限时发布；耗时包含主机 HDC 开销，不是视频延迟或吞吐评分。样本随 30 秒设备信息缓存更新，连接方式变化时重采，离线时不保留；仅增加元数据，不发额外心跳命令。界面拒绝未来、无效或超过 45 秒的样本，显示采样时间与未确认状态；顶栏保留 HDC 连接方式来源，不把未知方式猜成 USB/Wi-Fi。同名设备以序列号尾号区分，尾号重复时显示完整序列号。

安装与数据库采集的轻量结果记录由 `operation-tasks.ts` 管理，按设备列入 `/api/harmony/tasks`。直接安装、场景安装及显式投屏服务初始化共用安装记录；采集只有在双副本核验和 SQLite 快照打开后才显示完成。队列和运行状态先落盘，原子替换使用现有私有文件写入器；重启将未确认记录标为中断，只保留展示目标与结果，不自动重试。记录不含租约、SQL、原始数据库路径或快照 ID；保留的采集时间与校验方式仅是历史证据，当前查询仍需新快照。

HTTP、轻量 Agent 网关与场景以 `lib/harmony/contracts/actions.ts` 为动作契约。`action-dispatcher.ts` 执行直接动作；`scenario-executor.ts` 执行有界步骤。Manager 保持 façade，集中设备 lane、lease、epoch、互斥与取消；读屏质量和几何分别位于 observation。

普通 lease 或 owner 释放只结束其输入和自身媒体资源，等待旧设备动作结算后再重置输入并释放进程间物理锁；它不关闭被动观看与日志连接、不等待其他 GUI owner 的媒体，也不改变设备 generation。显式设备停止、离线和断连仍执行完整清理；完整停止可以立即升级尚未完成的输入清理，迟到回调不能解除新清理的 fence。不确定的输入或媒体释放继续保留对应恢复状态。

HDC 负责发现、文件/流和只读设备信息；Hybrid 选路，Hypium 只在独立子进程加载。父进程 PATH 不变，子进程收到固定 HDC 环境。`.harmony-worker` 通过独立 TypeScript 任务编译并被 standalone 打包验证。worker IPC 绑定协议版本、专属进程 epoch、设备、单调请求 ID 和截止时间；过期或外来请求在执行前被拒绝，取消终止其专属进程。worker 超时/崩溃后不重放效果不明的动作。

投屏默认使用内置 HDC 视频服务，旁观不会自动安装、唤醒或解锁设备。用户显式选择 HOScrcpy 时，可指定本地 dsh-hos-scrcpy 包（Java sidecar 类及 SDK jar）；Piora 独立启动 Java 进程，只在服务端连接其回环 WebSocket，将 H.264 回调转换为原有视频协议，网页仍只访问经过桌面认证的 `/api/harmony/video`。此可选模式首次开流可能由第三方 SDK 部署设备组件；缺包、启动失败或进程异常时短时冷却并回退内置投屏。SDK jar 不随 Piora 分发，其源码许可声明尚待上游补全；没有真机视频回执前不能宣称该适配已完成设备验收。

普通权限替代组件的可复现源码位于 `third_party/harmony-mirror`，由 `scripts/prepare-harmony-mirror.mjs` 复制到新建隔离目录后配置签名；公开源码不包含私钥、证书或签名 profile。显式初始化要求安装包声明正确包身份及前台 EntryAbility，安装后回读版本和实际可启动入口，全部吻合才启动。用户在手机点击开始共享并确认系统授权；权限拒绝不自动重试。关键帧请求不重新请求录屏授权，单个慢客户端不暂停全局编码器。原生回调通过异步 epoch 核对结束捕获，TCP 发送队列丢帧后等待关键帧再恢复。设备绑定的 debug HAP 仅用于实机测试，不能直接作为公开 beta 的发行组件；当前分发旧 HAP 的替换仍须经过发行签名与最终包验收。

设备锁位于用户目录统一 physical serial 哈希命名空间，跨进程及品牌互斥；活 PID 不会因时间老而被抢占。退休死 owner 与建立新 owner 使用互斥 gate，无法确认的状态拒绝接单。

HDC 在线状态作为已完成设备授权的边界，不添加应用范围 grant 或单次审批。lease 只负责并发归属与取消；安装前自动导入校验过的 HAP 副本。场景 journal 保存步骤与检查点，私有输入不进入公开列表。恢复在设备 lane 内重观测，未知副作用不能自动重放。

应用管理的直接动作与场景使用同一动作目录和设备 lane。桌面及 AI 安装入口均只接受已允许工作区内的 HAP，并由控制后端冻结产物。设备文件浏览是只读能力：共享路径通过 HDC shell 查询，可调试应用沙箱通过 `shell -b` 查询；路径不允许父级跳转、控制字节或沙箱外绝对路径。实机 HDC 会丢弃 NUL 输出字节，目录条目改用 ASCII 记录/单元分隔符，跳过含分隔符的名称，并限制为 500 项；元数据每 50 项批量读取，缺失目录或缺少 `stat -c` 时返回能力错误。部分 HDC 沙箱命令会再次解析并移除脚本引号，因此 `shell -b` 脚本使用无引号 ASCII 传递再在原沙箱中解释，不改变工作目录、权限或写入脚本文件；共享 shell 与文件传输参数不改写。批量 stat 失败、记录或元数据格式异常直接报错，不能返回空列表或残缺结果。单文件下载通过 `file recv` 先写到目标目录内的私有临时目录，核对大小后以同卷硬链接原子发布到尚不存在的目标路径；不支持硬链接的文件系统返回错误，不暴露半成品。上传使用与安装相同的写入 fence：先冻结工作区文件，限制设备目标路径，默认拒绝覆盖与符号链接；`file send` 写入同目录随机暂存名，校验长度后再用 `mv -n/-f` 移到目标并复查，不直接向目标传输。HDC 3.1.0e 起支持非交互式 `shell -b` 和沙箱文件传输，但真机兼容性仍须逐设备验证。

应用清缓存使用 `bm clean -c -n`，与清数据使用的 `-d` 分开。应用使能/禁用仅调用 `bm enable/disable -n`，不传 user ID，按设备当前活跃用户执行。OpenHarmony 官方文档说明它仅在 root 构建可用；user 构建和设备返回未确认成功时必须报错。文档同时说明 `-u` 指定非活跃用户可能实际作用于当前活跃用户，因此面板不提供跨用户切换。开发板镜像特权通过工作区内 `install_list_capability.json` 的独立流程配置，限定 bundle 与证书 SHA-256 指纹，预览差异后要求原文件哈希一致，写入前备份，恢复也保留被替换版本并核对哈希。本地写入不代表设备已部署或重启生效。

设备交互式 Shell 使用独立的 HDC PTY，会话绑定手动 lease 与指定设备；输入和窗口尺寸操作在服务端再次校验 lease，lease 到期或关闭面板时结束子进程。输出仅经桌面认证的 SSE 发送给当前面板，不写入设备管理日志。单次命令仍经过设备 lane 并返回有界输出和退出码；交互式会话中的副作用无法逐条核验，断线时不宣称成功。

设备文件变更仅允许可写共享路径或调试沙箱的 `data/storage` 内。新建目录不自动创建父目录；删除仅针对普通文件和空目录，重命名保持在同一目录且使用 `mv -n`，每次变更后重新查询设备路径类型。符号链接不作为可变更目标；无法可靠确认结果时报错，不宣称成功。

权限编辑仅接受三位八进制模式，不支持递归、setuid/setgid/sticky、所有者或系统目录操作；设备执行 `chmod` 后用 `stat -c '%a'` 回读。目录和文件必须是普通目标，符号链接不通过类型检查。

文件名搜索在设备 lane 内按广度优先遍历，最多 5 层、80 个目录、4000 个条目、200 个匹配项或 30 秒；不进入符号链接，子目录不可读会计入跳过数。面板收藏路径按设备与沙箱保存在本机浏览器存储中。

设备文本预览在传输前限制为 2 MiB 普通文件，完整下载后核对长度。默认按 BOM 识别 UTF-8/UTF-16 LE/BE，否则按严格 UTF-8；GB18030 必须显式选择且要求编解码往返无损，拒绝 NUL 字节。保存时保留 BOM 和原有单一换行格式；混合换行须由用户明确选定统一格式。差异预览限制输入、计算时间和输出大小。AI 结果最多携带 12,000 个字符，标注设备内容不可信；面板显示完整文本。保存时要求打开时的 SHA-256 与设备当前内容匹配，新内容先经 `file send` 写入同目录独立暂存文件，再在设备 shell 中检查原文件哈希并替换，最后回读新哈希。缺少 `sha256sum` 时禁用保存；取消或无法确认时不把未知效果报为成功。

手动 Wi-Fi 调试入口要求用户在设备上先启用无线调试，再输入局域网 IPv4:端口。服务端调用 HDC `tconn` 或 `tconn ... -remove` 后读取目标列表核对；正在持有 lease 的同一设备不允许切换连接。显式断开完成后清除普通轮询的暂时缺席宽限，避免 UI 继续把已断开的设备显示在线。真实 USB/Wi-Fi 切换及版本兼容性仍需设备验证。官方命令语义参见 [OpenHarmony HDC 指南](https://gitee.com/openharmony/docs/blob/master/zh-cn/device-dev/subsystems/subsys-toolchain-hdc-guide.md)。

目录浏览按 500 项一页调用设备 Shell，逐页跳过前面的目录项后再批量读取当前页元数据；服务端只返回有界页，且检测是否有下一页。页面排序和隐藏过滤不跨页，目录在翻页期间变化时页边界可能移动。递归查找继续保持 4000 项、80 目录和 30 秒边界，不宣称无截断的全目录索引。

上传前的工作区文件冻结使用 1 MiB 分块复制，核对源文件身份、大小与修改时间，并在私有副本落盘后再逐块验证 SHA-256；整个过程不分配与文件等大的 Buffer。上传/下载的软件上限统一为 1 GiB；不超过 256 MiB 的 HDC 传输保持 120 秒超时，大于此值的传输采用 30 分钟有界超时与后台任务取消。冻结副本在单次设备调用结束后清理。1 GiB 的真实设备往返和断线行为仍须验收。

后台文件传输由 `HarmonyTransferJobs` 维护，单批最多 20 项、同设备串行，任务元数据原子写入 HDC 配置旁的私有 JSON 日志，lease 令牌只保存在进程内。上传入队时将已获准的手动 lease 原子交给任务，后台定期续租并在结算后释放，因此面板卸载不影响运行。上传仍调用同一设备写入 fence 与源文件冻结链；下载重新校验工作区目标。进程重启后未完成任务标为 `interrupted`，不自动重放可能已生效的设备写入。HDC 官方回执不承诺实时字节事件，界面仅展示已确认完成的文件数和字节数；运行中单文件的效果与取消后的设备暂存状态必须谨慎核对。上传取消后使用独立短时命令尽力清理随机暂存路径；断线时无法保证远端清理。设备“任务”页汇集传输记录与场景执行记录。

数据库页复用设备应用列表，逐应用限量扫描标准数据库目录及有限层级的文件目录，包含应用级 files 和 base/haps 下各模块的 files；每应用最多 18 次目录读取，不进入模块缓存和资源，达到上限标记结果不完整；HDC `shell -b` 只访问已运行、使用调试签名且设备允许读取的应用沙箱。候选文件再由设备端核对 `SQLite format 3` 文件头，不能访问、扫描截断和确实没有数据库分别呈现。服务端以当前进程私有的不透明 ID 绑定设备、应用和文件，列表与后续查询接口都不接收用户输入的数据库原始路径。打开或刷新时拒绝非空、大小不明或类型不确定的 WAL 及 rollback journal；只有采集前与两份复制后均确认为零字节普通文件的 WAL 可继续，前后核对设备文件元数据并下载两份比较 SHA-256；只有验证相同且通过 SQLite `quick_check` 的副本才发布只读快照。活跃事务、加密库或无法核对一致性的文件报错，不把旧数据当成新结果。

设备快照与工作区内已下载的普通数据库共用私有只读查看器。文件上限 64 MiB；本地文件也拒绝伴有 `-wal` 的数据库。打开时复制到私有临时目录，后续表浏览、查询和导出均绑定快照 ID；关闭或十分钟后清理，最多同时打开八个。独立 worker 用 `DatabaseSync({ readOnly: true, allowExtension: false })` 与 `query_only` 打开，列出普通表、视图、字段及索引。表和查询每页最多 200 行、100 列；单条 SELECT/WITH 查询最多查看前 1000 行，拒绝分号和其他语句，文本和 BLOB 单元格截断显示，浏览超时为 5 秒。CSV/JSON 导出在 worker 内逐行写入私有临时文件，限制 10 万行、64 MiB 和 30 秒，HTTP 以流返回并在完成或取消后清理。浏览器优先使用文件流写入接口，不支持时以有界 Blob 下载；CSV 文字中会触发表格公式的前缀加单引号，JSON 中大整数以字符串、BLOB 以 Base64 对象表示。依据 [SQLite 备份说明](https://www.sqlite.org/backup.html)和[WAL 说明](https://www.sqlite.org/wal.html)。

SQL 失败保留上一份成功结果与查询草稿。Node SQLite 错误没有位置字段时，独立 worker 按需加载 SQLite WASM，用只读 `sqlite3_deserialize` 私有快照准备同一条 SQL，不执行语句；只有错误文本完全一致才采用 `sqlite3_error_offset`。UTF-8 字节位置转换成编辑器 UTF-16 偏移，界面再按 Unicode 字符显示行列；选中语句的位置加回全文起点。编辑后禁用旧定位，不完整语句或版本差异导致无位置时明确提示。解析资源固定为当前锁定的 SQLite WASM 版本，最大 128 MiB WASM 内存，仍受查询 worker 的 5 秒期限约束；ESM 和 WASM 一并放在实际 ASAR 侧目录，隔离运行测试验证无需开发目录依赖。依据 [SQLite 错误位置接口](https://sqlite.org/c3ref/errcode.html)与[只读反序列化接口](https://sqlite.org/c3ref/deserialize.html)。

AI 的 `harmony_control` 中 `database` 操作复用相同快照服务；每个 AI 快照绑定当前 prompt run，任务结束即关闭。读取结果仅返回前 10 行、20 列的有限预览，数据库内容明确标为不可信；导出只能新建已获准工作区文件，失败清理未完成文件。

专用调试 HAP 仍可通过系统备份 API 生成一致副本；用户通过持久后台下载任务取回 `.db`/`.sqlite` 后，可从完成项打开本机只读查看器。自动发现只覆盖 HDC 可读取的调试应用沙箱；任意第三方应用的在线数据库没有通用 HDC 一致快照接口。主文件单独拷贝不能覆盖未检查点的 WAL 事务，因此自动快照会拒绝这类文件，必要时仍须由应用导出一致副本。

单次命令抽屉只供用户手动运行，不加入 AI 动作目录。命令仍需设备 lease，经过与其他写操作相同的 dispatch fence 和设备 lane；每条命令使用单独的 HDC `shell` 调用，最多 15 秒、128 KiB 输出。退出码通过每次随机生成的结束标记解析；缺失标记时结果不确认。单次命令的多标签只保留当前网页中的输出记录，可跨标签查找命令、标准输出、错误输出与失败原因并跳转；复制和粘贴均由用户显式触发，粘贴只修改草稿。工作目录和环境变量不跨单次命令保持；同页的交互式 PTY 则保留 Shell 状态。

用户定义的快捷命令按设备保存在浏览器存储，最多 20 条；旧版数组记录仍可读取。快捷项包含设备/本机目标、设备 Shell/调试沙箱范围、分组、收藏和参数模板，支持编辑及版本化 JSON 导入导出。模板占位符仅在命令引号外使用；设备参数作为 POSIX Shell 单独参数引用，本机参数限普通路径/标识符字符。选择或导入不自动执行：设备命令仅填入输入框，本机命令复制到剪贴板并打开现有本机 PTY，用户仍须检查和手动粘贴。面板不把本机命令伪装为设备 Shell。

命令兼容性依据：[OpenHarmony HDC 文档](https://github.com/openharmony/docs/blob/master/zh-cn/application-dev/dfx/hdc.md)与[Bundle Manager 文档](https://github.com/openharmony/docs/blob/master/en/application-dev/tools/bm-tool.md)。

现有 `check-runtime/check-config/check-types` 继续提供 DevEco CLI 检查。开发验证链引用 report ID、工程源指纹、用户选中 HAP hash、场景执行 ID 与按进程过滤日志；不声称读取 IDE Problems 或证明用户选中的 HAP 一定来自该源码构建。

现代 DisplayManager 诊断按独立 Screen ID 记录解析，不能把后面的 Client Screen Infos 重复属性当成另一块输入屏幕。存在多条记录时必须有明确且一致的屏幕类型；只选择唯一 REAL 屏，排除已确认的 VIRTUAL 录屏显示，不根据名称推测。重复标识、类型冲突、多个真实屏幕或未知分类均拒绝坐标操作。方向同时支持 0–3 索引与 0/90/180/270 角度，矩形仍要求零原点、完整且有界。类型取值依据 [OpenHarmony screen_info.h](https://github.com/openharmony/window_window_manager/blob/master/utils/include/screen_info.h)。

物理屏几何可识别不等于编码视频已适配横竖屏。固定尺寸 H.264 与物理方向不一致时，Manager 仍拒绝对应帧的坐标映射；不能通过 CSS 旋转或放宽比例检查声称录像与设备动作已正确。

普通权限投屏组件最后一个观看连接断开时保留现有已授权采集五秒。连接恢复取消等待任务，单调 presence epoch 阻止旧任务释放新连接；持续断开才停止采集，能力销毁时立即清理等待任务和全部资源。手机明确点击开始共享时，同一会话边界取消旧停止计时器；尚未连接的请求最多等待三十秒供正常系统授权和首次连接，连接建立后恢复五秒断开清理。计时器不创建采集或请求授权。桌面刷新只重建观看连接，不重新安装组件；真实设备必须验证超过原等待期限后仍收到原生帧，以及持续断开后可明确授权恢复。

普通组件由 tagged GitHub Actions 的专用 ephemeral Windows/API26/真机 runner 在隔离目录构建。来源门禁量测源码、明确的 ohpm 锁文件、release HAP 元数据与 SHA，并绑定 repository、commit、workflow、run 和 attempt；SDK 示例 release 身份经 `localSign` 后必须再通过官方 `verify-app`/`verify-profile`，profile 限定目标 bundle、`normal`、`hos_normal_app` 且无 ACL 或 privilege capability。随后同一 HAP 必须在指定 HDC 开发手机上完成安装回读、启动、系统授权、真实 H.264 配置/关键帧/连续帧、PNG 截图及卸载缺席检查。独立签名 receipt 保存非敏感证书指纹、profile 边界和散列后的设备身份；provenance manifest 仍用 `signature: unverified` 表示来源接口本身不替代验签。四个经门禁的资源由同 run artifact 传给 Windows builder，beforeBuild 与解包后再次核对。beta tag 只产出 artifact；真正的安装包和手机验收完成后，手动 publish workflow 按 tag 和原 run ID 发布同批字节。该 job 绑定 `preview-publish` environment，仓库必须另行配置 required reviewers 才能形成批准门禁。缺少 runner、SDK、设备或证据时拒绝打包，不能退回旧 1.0.3。具体调用及边界见 `scripts/README-harmony-mirror-provenance.md`。
