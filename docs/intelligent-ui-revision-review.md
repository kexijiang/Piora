# 小程序修订确认

当 `piora_render_mini_app` 为已有 app ID 发布候选，旧版保持可用，候选停在 `awaiting_confirmation`。候选卡片提供“核对变化 / 刷新”，先暂停并保存本窗口的旧实例，再读取当前分支可见的来源状态。

输入比较使用完整声明（不含默认 value）：ID、含义、类型、标签及约束必须一致才建议保留。默认值变化不影响已保存参数；含义或范围变化使用新默认值，用户可在确认界面修改。没有隐式单位转换。新增及移除输入单独列出。

默认明确重新调用新版 init：任务内部状态、tick、随机状态和用户镜头重新开始。仅保留确认的输入，不按同名内部字段迁移进度。具有 `stateMigration` 能力的候选也可声明下述受限进度迁移，由用户另行选择；跨形式切换见独立的[组件与小程序互转协议](intelligent-ui-output-conversion.md)。

## 受限进度迁移（mini-app-1.7）

候选的 `migration` 包含 `fromPlanDigest`、`description` 和 `clock: "reset" | "preserve"`，程序另外声明 `migrate(previous, inputs, ctx)`。仅同一个 app ID 的准确来源摘要匹配才接纳，不提供按 ID 猜测或自动单位转换。未声明迁移的旧计划保持原运行时版本。

宿主上下文提供有大小限制的 `progressSource`，包含准确程序摘要、完整状态结构及确认检查点；超限时明确 `complete:false`，不能把遗漏状态当作默认值。生成说明要求仅在完整来源足以设计转换时声明迁移，具体业务正确性仍需要独立核对。

用户核对页默认选择“重新开始”，可显式改为“使用提议的进度迁移”，同时查看提议说明和时钟行为。模型说明是提议，不是校验过的业务事实。确认使用同一来源 CAS 和持久回执；来源变化、异常或结构不匹配时保留旧版，不静默改成 init。

迁移仅在服务端 Worker 的新 QuickJS 实例中执行。`previous` 是冻结的旧 inputs/state/tick/rng；宿主镜头不会传入。函数只返回新版 state，经过新版 schema、JSON 深度/节点/字节限制及投影检查，再向新版 reduce 发送 blur 以释放旧输入。clock 决定是否沿用 tick/RNG；用户镜头始终重新开始。迁移函数可使用受控随机上下文，调用后保存相应 RNG 状态。

迁移使用原有 200ms 启动额度、堆/栈限额和服务端 Worker 看门狗；同一实例不能第二次调用迁移领取额度。普通浏览器 VM 没有迁移入口。保留过程进度后仍执行原有有界步骤与交互试运行，最终只提交迁移后的起始检查点。请求保持原有 512KiB 总界限，来源计划与状态过大时明确失败，不放宽限制或悄悄丢弃字段。

## 确认与恢复

同源 GET/POST 位于 `/api/sessions/[id]/mini-app/migration`。POST 接收 toolCallId、publicationId、digest、leafId、requestId、decision、inputs，以及可选 progress 和 previewDigest。模型程序没有调用入口；真实宿主确认点击创建新运行及不可序列化授权，复用已有 session mutation ownership 和公共锁。

### 确认前的实际预演

核对页展示核对时已保存的来源摘要。用户选好输入和进度模式后，通过“预演所选变化”调用 `POST /api/sessions/[id]/mini-app/migration/preview`；GET 核对仍不执行生成代码。预演使用同一来源、输入和 Worker/QuickJS 试运行边界，不写状态、确认意图或会话项，也不建立模型运行。试运行前后都核对 Beta 修订、请求取消、当前叶节点、来源身份与候选状态，执行期间发生冲突就丢弃结果。

结果展示应用后的投影摘要，以及宿主按实际检查点计算的数据差异。详情区分新增、移除、替换和显式 null；有界列表最多 12 项、1200 字符，单值最多 256 字符，超限明确给出未展示数量，不能推断遗漏字段未变化。摘要仍来自生成程序的投影，不构成独立业务正确性证明；变化明细是结构比较，数组位置也不等同于业务对象身份。

新核对界面必须成功预演当前选择才启用确认；输入或进度模式变化会清除预演。确认附带 previewDigest，绑定候选、来源核对摘要、分支、输入、模式及完整试运行结果。服务端确认重新试运行并比对摘要，不一致则拒绝且不写意图；原有锁内 CAS 仍负责最终发布边界。预演后其他视图保存会使确认失效，用户须刷新核对再预演。

取消不要求预演。成功响应丢失或已有持久意图时，沿用原选择恢复，不重新解释选择或绕过回执。历史客户端和旧回执未携带 previewDigest 时继续走原有确认试运行及 CAS，以保持兼容；新界面不会走这条省略路径。clock 指宿主运行时钟和随机源，不能当作任务步数；任务数值看实际预演结果。

服务器在锁外进行 QuickJS 初始化或显式迁移及有界交互试运行，锁内再次核对来源版本、检查点摘要及当前叶节点。来源发生变化时拒绝旧选择，用户必须刷新核对。试运行失败不创建确认意图。Beta 切换或取消请求会撤销未完成工作。

确认先持久化精确意图，再写 `piora-mini-app-confirmation` 自定义会话项并核对磁盘回执，最后原子提交发布日志。迁移结果摘要绑定在回执内；原工具结果、原初始投影和旧程序状态保持不变。重复同一请求返回原决定，不再次初始化；不同选择不能复用已有确认身份。

读取不会自动补完中断的确认。若意图/确认项已保存但最终日志未提交，同一选择的明确重试可继续核对并完成；丢失成功响应时刷新可读取已提交结果。若来源已发生变化，则保留旧版并要求重新评估，不覆盖它。

新版只在确认项所在分支及其后代生效；确认之前的旧分支继续使用旧版。fork 仅继承分支可见且已确认的迁移，确认项的标签父链重写沿用既有 fork 证据；未确认候选在副本中不可写。保存状态、模型上下文和静态导出读取同一个确认结果。

## 开发验证

`lib/mini-app-migration.test.mjs` 验证语义比较、真实 SDK 文件与生产 API、冲突、取消、幂等、权限、旧分支/fork、中断恢复、初始化失败及摘要篡改。中断测试通过重建特定持久状态模拟断点，不宣称已执行操作系统断电测试。

`lib/mini-app-migration-browser.test.mjs` 使用真实 React Surface、Edge 原生点击、生产 API、IndexedDB、QuickJS 和 SDK 文件。HTTP 壳与确定性计数程序是夹具；未使用模型、原生 Electron 窗口或安装包。覆盖无效选择后重新核对、确认、取消、刷新及成功响应截断恢复，所有子测试失败均会使报告失败。

`lib/mini-app-progress-migration.test.mjs` 补充精确来源、能力门禁、旧版本身份、输入变化下的进度转换、时钟/RNG、旧检查点不可变、镜头隔离、按键/拖动释放、异常/死循环、普通 VM 拒绝迁移、重复启动拒绝及显式失败后选择 init。模型上下文的完整结构由真实 SDK 运行回归核对。

`lib/mini-app-migration-preview.test.mjs` 验证无写入预演、来源和输入绑定、重置与保留模式、错误摘要拒绝、过期/取消/Beta/忙碌/同源边界，以及字段删除、null 和有界省略。浏览器场景覆盖键盘预演、编辑后失效、确认响应丢失恢复、两视图冲突及窄屏深色展示；真实模型重放仍需单独记录，不由这些夹具推导通过率。
