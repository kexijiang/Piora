# Intelligent UI 宿主动作

组件和小程序共用执行与权限生命周期。小程序通过 `actions:{version:1,actions:[...]}` 声明最多 8 个动作；生成文档没有 `data-action`，VM 和渲染事件不能调用宿主文件操作。普通聊天只使用已有通用输出入口。

| kind | 字段与约束 | 结果 |
| --- | --- | --- |
| read_json_parameters | id、label、项目相对 path，扩展名 .json | 完整输入对象，经原始 JSON 及当前计划约束校验，只形成建议 |
| save_snapshot | id、label、path、format=json 或 markdown，文件扩展名匹配 | 以服务端确认的检查点创建报告；已有文件禁止覆盖 |

按钮由宿主绘制，点击先完成当前检查点保存。来源摘要绑定会话、分支、程序、状态版本及动作声明；仅线性的自动标题尾部不改变授权身份。实际文件读写由既有 `executeAnswerAction` 和权限层执行，检查会话工具能力、权限版本、当前运行及 Beta 状态。模型、沙箱或环境能力证明不能代替用户的动作请求和权限审批。

读取 JSON 后，用户再次点击“采用这些参数”才改变程序输入。服务器从确认检查点启动独立 Worker，清理临时按键，按输入声明顺序发送普通 input 事件，每个处理函数均看到完整新输入；保留 tick、RNG 和镜头，不调用 init。处理函数仍可依据业务规则改变任务状态。程序错误、超限、来源变化或取消均不提交状态。

采用动作使用确定的保存请求 ID，状态与回执原子写入；动作日志标记丢失时从回执恢复。之后再次采用同一结果只返回旧回执，不覆盖更新后的状态。写报告在执行前保存 executing；原运行消失后只显示 uncertain 并核对文件摘要，不重放写入，也不把内容一致当成该次操作成功的证明。

声明动作的计划使用 mini-app-1.8。能力表中的 registeredActions 必须具备匹配源码、平台及运行资源的证据才向普通生成开放；隔离开发配置只表示可验证实现。动作记录位于现有小程序发布旁存文件，共用会话锁及回收站生命周期。新分叉不继承原会话的动作执行资格。

界面更新只在读取到不同检查点时恢复所有已挂载实例；未变化的程序继续可用。跨原生窗口和真实模型生成仍需完整阶段验收，不能从同页两处显示的夹具推出。
