# Intelligent UI 第四阶段：可靠性与泛化

2026-11-03 · 用户确认从第三阶段迁入 · 尚未开始综合验收

第三阶段按[方案 v3.9](intelligent-ui-phase3-design-v3.9.md)交付代表任务可用的 Beta。第四阶段保持原问题、失败记录和未覆盖范围，不将范围迁移等同于修复。

2026-11-09 增补：新生成界面迁移至 [A2UI 1.0 受限组件目录](intelligent-ui-a2ui-migration.md)。第四阶段需同时覆盖旧历史与新来源的修订、迁移、动作和状态恢复，单独统计协议错误、表达深度超限、语义错误及形式选择。当前真实 Flash 样本在价格相等时仍生成了错误的比较标签，不能用工具发布成功代表业务验收通过。详见[迁移验证记录](verification/intelligent-ui-a2ui-2026-11-09.md)。完整 CI 和双人人工验收仍按原安排执行。

新增生成可靠性样本：自行车拆解连续两次真实生成未发布，最终源码样本遗漏状态字符串约束并包含不可达组件，纠错未完整修复。需要验证模型能一次定位并修完结构问题，保持现有两次尝试预算，不以复制固定自行车模板或手改模型产物替代泛化验收。另保留一次 3D 初始渲染 WATCHDOG；原样单测和后续完整能力复测通过，仍应覆盖资源竞争情形。

| 编号 | 工作 | 完成依据 |
|---|---|---|
| 4A | 自然表达的形式选择、生成成功率、重试和耗时 | 开发集包含正反例、多轮、边界；分别统计分母与失败，不以发布成功代替正确性 |
| 4B | 业务和解释可靠性 | 修复排序漏试算、三角形建议/键盘说明、量杯无效提示、棋盘排他说明等通用问题，另开新生成复测 |
| 4C | 历史与运行状态解释 | 区分程序状态、宿主播放状态及已确认变化；处理机械臂最近镜头、“同时归零”、仅凭保存差异推断点击，以及接球游戏额外称“未暂停”等问题 |
| 4D | 复杂操作组合 | 多窗口、分支、冲突、取消、响应丢失与修订、迁移、文件动作、互转组合；核对不重复副作用和可恢复状态 |
| 4E | 视觉、键盘与资源 | 深浅主题、窄窗口、焦点、减少动画、长期模拟/游戏、Worker/GPU/订阅释放与性能；三维生成物的物理假设也需独立检查 |
| 4F | 综合验收 | 完整 CI 与历史失败修复，开发集完成后固定门槛，封存集 16 题各 3 次，两人独立语义判断并复核分歧 |

48 题原计划保留，32 开发、16 封存，每题 3 次。触碰过的封存题迁入开发集并补题，模型固定 DeepSeek V4.1 Flash，不能用 Pro 或回退掩盖失败。样本取消、失败、超时、漏调用均留在分母内。

先依据完整失败清单确定优先级，避免不断重跑已经通过的样本。每次改动明确针对的错误机制、相关回归和新增独立任务；不通过弱化断言关闭问题。真正阻止基本功能或造成数据损失、权限绕过的问题应及时修复，不能仅因排入第四阶段而忽略。
