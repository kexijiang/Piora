# Intelligent UI 第三阶段重新设计

版本 v3.0 | 2026-10-31 | 方案已整理，尚未实现或验收

本文替代此前讨论中的“优先限制为二维画布”方案，作为第三阶段的实施依据。第一、二阶段保持兼容；仍然只有三个交付阶段，文中的 3A 至 3E 是第三阶段内部的实施步骤。人工语义验收和完整 CI 按用户要求留到三个阶段开发完成后，必要的开发验证继续执行。

## 1. 产品目标与范围

让用户用自然语言得到可以操作、观察和继续修改的小程序，例如概率实验、几何教学、动态过程和轻量小游戏。模型负责任务含义、布局与计算；Piora 负责设计规范、执行边界、状态、权限和恢复。普通聊天通过通用输出接口接入，实验功能关闭后继续展示可读快照。

| 回答形式 | 使用场景 | 实现路线 |
| --- | --- | --- |
| 直接回答或澄清 | 一次性结论、静态说明、关键规则缺失 | 保留现有聊天路径 |
| 组件界面 | 调参比较、筛选、结构化计算与登记动作 | 复用第二阶段 Plan2 |
| 可编程小程序 | 空间关系、连续演化、自定义操作或现有表达式不能描述的计算 | 新增 MiniAppPlan1，独立渲染与计算运行时 |

第三阶段首版包含自由布局、受控 HTML/CSS、SVG/Canvas、拖动与键盘操作、动画、受限三维场景，以及暂停、恢复、保存、追问。三维是明确的实现目标，需单独通过能力原型；失败时报告缺口，不将二维替代记成三维交付。

首版不开放任意 npm 包、生成脚本直接操作 DOM、任意网络访问、自定义 GPU 着色器、原生插件、重型三维游戏和无上限粒子模拟。约束作用于通用绘图、布局、状态和计算能力，不按“旅行、预算、教学”等业务关键词维护模板库。

### 从 OpenIntelligentUI 借鉴什么

参考项目为 CopilotKit/OpenIntelligentUI，本次检查本地提交 `8391a94c1c3939c679e40ddd7bfc08a9ef690e70`，不是对远端最新版的声明。

| 参考实现 | Piora 的取舍 |
| --- | --- |
| HTML/CSS/JS 流式生成，预览和最终运行分开 | 借鉴渐进展示；布局先编译校验，生成代码只进入计算沙箱 |
| 统一主题、SVG 与控件设计规范 | 使用 Piora 设计令牌和同一份模型说明、编译规则、渲染样式 |
| SVG、动画和 Three.js 表现能力 | 扩展到文档视图与场景视图，避免所有任务都变成滑块 |
| 独立的展示路由和窄消息桥 | 保留语义判断思路，复用 Piora 当前模型、会话和权限 |

不引入整套 CopilotKit、Python/LangGraph 或 Jev 服务。参考项目的控件状态不会自动同步到会话，检查点位于进程内存；它不能直接替代 Piora 的持久恢复、分支和授权。流式与状态行为见参考项目[架构说明][R1]。

## 2. 总体架构与接入边界

采用“一个小程序协议、两种视图、独立计算”的结构。文档视图和场景视图可以共存，使用同一份输入、状态和计算结果。

```text
自然语言与当前会话上下文
  -> 同一轮模型选择回答形式
  -> piora_render_ui_plan 或 piora_render_mini_app
  -> 通用接纳预算与候选发布流程
  -> MiniApp 编译器 / 受限试运行 / 持久提交
  -> MiniAppHost
       |-- 文档视图：受控 HTML/CSS、SVG、输入与文本
       |-- 场景视图：Canvas / Three.js 可信渲染适配器
       |-- Worker + QuickJS/WASM：生成的业务计算
       |-- 状态服务、动作服务、可读快照
```

**文档视图**允许常规语义 HTML 和布局 CSS 作为模型创作输入，经解析器编译为允许的展示树。它不是“把模型 HTML 直接插入聊天 DOM”。**场景视图**接受有界的几何、绘图指令、相机和材质数据，可信代码负责绘制。生成程序不能取得 DOM、Canvas 或 Three.js 对象。

### 与普通对话解耦

新增输出种类 `mini-app`，封套版本从 1 开始，不挤占现有 `intelligent-ui` 的版本号。聊天只负责输出槽、快照、通用保存门禁及当前会话身份。具体协议、编译器、状态与渲染按需加载。

当前 `AnswerOutput`、generation/server 适配层仍直接引用 Intelligent UI 类型或具体工具名。3A 先建立显式的内部适配器登记表，涵盖工具名、版本、预览、保存、fork/复制和导出；登记表只引用应用自带模块，不接受模型提供的模块路径。现有组件先通过适配器保持行为不变，再增加小程序。

建议新增模块为 `lib/mini-app/`、`components/mini-app/`、`extensions/piora-mini-app.ts`。共用输出接口留在 `lib/answer-output*`；不得在 ChatWindow/useAgentSession 中分散加入小程序分支。旧客户端、未知版本、关闭开关或加载失败统一读取快照。

### MiniAppPlan1 的最小契约

| 模型提供 | 宿主提供或决定 |
| --- | --- |
| planVersion、稳定任务 id、标题、用途和假设 | 输出身份、当前分支、发布版本与内容摘要 |
| 输入定义、状态 schema、初始值 | 有界 schema 校验器、保存版本和迁移流程 |
| document：HTML/CSS 与显式数据绑定 | 展示树编译、主题、可访问性与资源限制 |
| 可选 canvas2d / scene3d 视口声明 | 实际可用渲染器和固定依赖版本 |
| program：固定生命周期函数 | 沙箱、时钟、随机源、调度与停止 |
| 已登记动作的声明、纯文字初始快照 | 动作按钮、权限检查、执行回执 |

模型不能指定宿主版本、令牌、文件句柄、远程依赖或扩大资源上限。JSON schema 只允许有限的标量、对象、数组和数值约束，不开放外部引用、任意正则或无限递归。

## 3. 触发判断与生成稳定性

继续由当前回答模型结合上下文，在同一轮选择回答形式。组件生成调用 `piora_render_ui_plan`，小程序生成调用 `piora_render_mini_app`；直接回答和澄清不强迫走工具。不新增必经的路由模型请求，不用关键词或自报置信度代替语义判断。

判断顺序为：尊重用户指定形式；确认关键业务事实；判断操作或动态展示是否有实际收益；比较现有组件与小程序的表达能力；选择能够完整满足任务的较低成本路径。能力范围由宿主按开关、版本和设备公布，模型不能自行宣布“已支持”。

| 用户自然表达 | 期望选择与理由 |
| --- | --- |
| “两个人出去，A 和 B 哪个便宜？” | 已有价格时直接算；缺价格先询问 |
| “人数不一定，我想换着看看哪个划算。” | 组件界面，输入与比较结果联动 |
| “把这个排序过程演给我看，我想一步一步走。” | 小程序，离散步骤、播放与暂停 |
| “让我拖一下三角形，看看面积怎么变。” | 小程序，空间操作和几何结果联动 |
| “正方体转起来让我看清楚，再展开成平面。” | 三维小程序；展开规则与关系需要真实实现 |
| “做个提成计算器，但规则还没定。” | 先澄清规则，不能用编造公式做漂亮界面 |
| “只用文字解释刚才的结果。” | 读取已保存状态解释，不重复生成 |

模型说明只提供通用交互原语和少量不同领域的协议例子，不把测试任务写成触发规则。组件不能表达状态演化、空间交互或自定义运算时才选择小程序；动画也可以是理解问题的收益，不要求每个界面必须放输入框。

### 上下文与修复

追问携带已确认的输入、状态版本、简短结果和当前能力；范围有界，历史程序、说明和导入数据均作为任务数据，不升级为系统指令。沿用现有聊天上下文，不截取固定几条消息另建不一致的路由上下文。

代码语法、引用与绑定错误返回字段路径和有限诊断。两种 UI 工具共用 PromptRun 的接纳计数：初始沿用最多 3 次尝试、1 次模型纠错及首次尝试后的 60 秒活动窗口，不因切换工具、重命名输出或模型回退而重置。若较长小程序在开发样本中超时，依据数据调整宿主策略并记录新版本，不能暗中加重试。

已知状态冲突、取消、权限拒绝与不支持能力不交给模型循环重写。静态编译、试运行和发布分别记录结果；通过结构校验不等于计算正确。生成中的预览不能宣称已经保存或可执行。

## 4. 交互与视觉规则

统一使用 Piora 的主题、字号、间距、圆角和焦点样式。用户可操作的方式包括数值输入、选择、分段按钮、拖动、画布点选、键盘、播放和单步；按任务选择，滑块仅用于有意义的连续区间。

动态数值、图形和结论均来自同一帧的计算结果；标题与说明只承载不变事实。避免图表已更新而结论仍写着初始值。键盘操作、拖动的替代输入、简要文字结果、窄屏重排和减少动画偏好是基础要求。

## 5. 自由布局、流式预览与渲染

### 受控 HTML/CSS 的具体含义

模型可以组合 section、div、标题、段落、列表、表格、标准表单和 SVG 图元；用 flex/grid、有限尺寸、主题令牌与基本变换描述布局。编译器使用 HTML、CSS 和 SVG 解析器建立展示树，检查节点、属性、绑定、深度与展开成本，不用正则替代安全解析。

初始绑定形式限定为 `data-input`、`data-text`、`data-event` 和 `data-viewport` 等声明，引用显式 ID；数值、文本和重复列表由校验后的 frame 数据填充，绑定不执行表达式。程序可返回有界图元与列表，从而表达业务上未预置的新任务。不得以静默删除节点、换公式或忽略事件来修复不支持的输入。

拒绝 script、事件处理属性、iframe/object/embed、导航与表单提交、HTML 字符串注入、外部 URL、CSS import/url、SVG foreignObject、脚本链接及无限 CSS 动画。允许样式按属性和值类型验证；不提供可任意选中宿主节点的 CSS。复杂滤镜、巨大模糊与无界重复不在首版范围。

### 渲染容器

可信渲染器放在不携带宿主凭据的隔离 iframe，sandbox 仅开放运行固定渲染器所需的脚本能力，不开放 same-origin、弹窗、顶层导航、下载或表单提交。编译后的展示树通过消息发送，不能改变 iframe 的安全属性。

外壳采用拒绝默认资源的 CSP；只允许宿主固定哈希的运行脚本与所需样式，不对生成代码开放 unsafe-eval 或脚本 unsafe-inline。依赖打包、固定版本、纳入许可证清单，不使用浮动 CDN。WASM 仅在可信 Worker 装载路径获得最小所需策略。opaque-origin iframe 内如何装载固定资源与建立消息通道，是 3A 必须验证的工程点。

iframe 提供来源隔离，不承诺独立进程或 CPU/内存硬配额；限制与风险评估同时覆盖布局和 GPU。[MDN 的 iframe 说明][R5]解释 sandbox 与来源边界；桌面继续遵循 [Electron 的隔离要求][R7]。

### 渐进预览与三维

流式参数先进入限长缓冲，只对闭合且校验通过的布局块生成预览。预览使用同一编译器和资源边界，禁用交互、不启动模型程序、不读写文件；不把残缺 HTML 直接交给浏览器解析。供应商不提供可用增量时显示进度占位，不能声称已做 token 级预览。

最终计划在受限试运行完成后走持久发布；持久回执确认后建立新实例，再原子替换预览或旧实例。取消、重连和迟到片段必须检查运行身份与单调序号。

三维适配器提供基础网格、顶点数据、实例、相机、灯光和有限材质；Three.js 对象由可信代码创建并释放。交互拾取、旋转和缩放转成标准事件。纹理只能使用宿主管理的有限资源，不支持任意模型加载器、远程资源或生成着色器。无 WebGL 或资源不足时显示可读快照并明确能力缺失。

## 6. 计算运行时与资源预算

生成的 JavaScript 只在 Worker 内的 QuickJS/WASM 执行。Worker 包装器和消息桥是可信应用代码，禁止把生成字符串交给 Worker 自身的 eval/Function。QuickJS 不提供 DOM；因此参考项目中的 DOM/Three.js 代码不能原样搬入这个计算环境。

优先验证锁文件已有的 quickjs-wasi；正式采用时改成明确的直接依赖并固定版本。其文档提供运行时内存限制和中断回调，但它们不等于整个浏览器或 GPU 的总内存限制。[QuickJS/WASI 文档][R4]是选型依据，最终仍以本项目原型结果决定。

```text
init(inputs, context) -> JSON state
reduce(state, event, context) -> JSON state
advance(state, fixedDt, context) -> JSON state
project(state, inputs, context) -> Frame + 文字结果
```

程序通过固定导出函数运行，不得导入包、访问网络、宿主存储、Node/Electron 或创建线程。宿主控制固定步长、随机种子和随机序列状态；禁用或替换非确定性的 Date/Math.random，并验证所有可见时钟入口。承诺同版本同输入的可重复计算；跨平台浮点数与像素结果另设容差，不承诺逐位一致。

### 初始预算，全部待原型校准

| 资源 | 首轮约束与处理 |
| --- | --- |
| 计划与程序 | 完整计划 256 KiB；程序 64 KiB；深度 24；超限不接纳 |
| 计算内存 | 单 VM 32 MiB；另限制 WASM 可增长内存和消息复制，按实际 API 验证 |
| 计算时间 | 初始化 200 ms；单次交互/步进 8 ms；滚动 1 秒累计 200 ms；超限暂停 |
| 失联处理 | 宿主 watchdog 500 ms 无有效响应即终止 Worker；后台调度延迟另测 |
| 调度与事件 | 初始 30 fps，隐藏时暂停；指针移动合并，离散事件最多排队 128 条，溢出暂停并提示 |
| 展示与消息 | 文档 400 节点；单帧 2,000 绘图指令；frame 128 KiB；完整回复 512 KiB；30 条/秒 |
| 状态与三维 | 状态 256 KiB；三维 200 网格、50,000 三角形、32 MiB 估算纹理；超限拒绝 |
| 并行运行 | 每个聊天窗口默认仅一个小程序持续播放；其他保留暂停快照 |

以上为设计值，不是实测性能或安全保证。检查消息大小要在 VM 导出/结构复制前进行，并限制字符串、数组和对象展开；主线程在解析前再次检查序列化长度。帧序号允许丢弃过期视觉帧，不能丢失状态提交或伪造输入回放。

停止按钮由宿主绘制。先撤销运行资格、停止调度，再终止 Worker、释放渲染资源并拒绝迟到消息，不依赖生成代码清理。Worker 终止不会等待任务完成，因此从最近确认的状态恢复，不能声称保存了卡死瞬间的状态。[Worker terminate 文档][R6]

Web 平台没有统一的整应用内存硬配额。文档规模、绘制复杂度和 GPU 预算必须结合压力测试；无法保持宿主可操作的能力不开放，不能仅凭 iframe 存在宣称隔离通过。

## 7. 状态、发布、停止与动作

### 状态是协议数据，不是 DOM 或 VM 快照

持久记录包含输出 kind、session/branch/entry 身份、程序摘要、协议与运行时版本、发布 revision、stateRevision、输入、JSON state、随机序列状态、tick 和文字快照。模型只提供业务状态；身份与修订号由宿主维护。保存成功以磁盘回执为准，复用第二阶段会话锁域与冲突协调。

动画允许持续播放和后台合并保存，但不能每帧写盘。交互后防抖保存完整快照，连续播放定期检查点；刷新、暂停和追问触发有界 flush。不能依赖 beforeunload 完成写入；未确认修改保留本机耐久恢复副本。恢复显示实际检查点时间，默认暂停；崩溃可能丢失最后未保存的计算步，不能隐瞒。

用户继续追问前等待状态保存或明确恢复处理，确保模型使用已确认的参数和结果。fork、复制和祖先导航读取该分支可见的已提交版本，不从正在播放的其他分支复制瞬时内存。旧窗口与离线草稿保留独立恢复记录，过期版本禁止覆盖新状态。

新程序先成为候选，编译及试运行失败保留旧程序。涉及字段含义、单位或 schema 变化时显示差异并确认迁移；迁移输出再次校验，失败保留原稿。只允许同程序摘要与兼容运行时恢复执行；升级默认停在快照并请求明确重建，不自动运行旧任意代码。

### 生命周期

```text
生成 -> 只读预览 -> 编译/受限试运行 -> 待发布
  -> 持久提交 -> 就绪 -> 运行 <-> 暂停
                            -> 停止/异常 -> 快照 -> 明确恢复
```

初次提交成功后，可以在当前可见输出中自动播放纯本地演示；尊重减少动画偏好。历史加载、崩溃恢复、切换分支后的输出默认暂停。关闭实验功能立即撤销所有运行资格、停止计算并展示快照；再次开启不自动执行历史程序。

### 事件不等于授权

普通控件、键盘和拖动仅产生本地业务事件。文件读写、继续提问、导出等能力由外层宿主控件承载，程序只能声明支持的 actionId，不能伪造点击、提交工具参数或获取授权凭据。不得仅凭 postMessage 内容或提示词中的“必须用户点击”认定已获授权。

消息采用专用 MessageChannel；初始握手验证实际 frame/worker、宿主生成的 nonce、运行 epoch 和当前输出身份，绑定后不用全局消息总线接收业务请求。opaque origin 下不能只比较 origin 字符串。所有请求校验 schema、序号、大小、频率和取消状态。

首版复用第二阶段已登记的读取参数与保存快照动作，并适配小程序输入和快照格式；仍由服务端核实分支、版本、目标与权限，继承幂等、结果不明时核对、拒绝覆盖等规则。生成、预览、init、动画和恢复均无文件副作用。外部 URL 和任意 shell 不新增为小程序能力。

导出默认保存参数、结果和可读静态快照；HTML 会话导出不嵌入可自动运行的小程序。无执行环境的设备仍可阅读，不将静态导出描述为完整可交互移植。

### 代码与数据兼容

新增模块通过显式 adapter 接入现有 PromptRun、answer-output、状态 API 与动作授权。组件模式保留原协议和存储读取；小程序数据拥有单独 kind/schema，但共用会话写锁、磁盘确认和恢复规则。共享抽象先覆盖当前调用点，不能只改前端渲染器。

普通聊天关闭实验功能时不加载 QuickJS、Three.js 或小程序样式，不注册小程序生成工具。已存在的快照仍能读取。权限模式沿用用户当前设置，不因为开启 Beta 自动扩大权限。

本轮不安装新依赖，不修改 Next.js/Electron 配置，不启动桌面或调用真实模型。后续实现涉及 Next.js 时先阅读安装版本的相关开发文档；不在开发目录运行 next build，也不本地构建发布包。

### 优先级与可行性结论

自由布局、流式预览、独立纯计算和持久化具备明确的实现路径；主要工作是宿主编译器、运行管理及旧协议兼容。三维资源回收、复杂布局成本、模型生成稳定性属于需原型和开发数据支持的风险，当前不承诺工期或成功率。

与直接执行任意 HTML/JS 相比，该方案需要更多适配器工作。换取的是一份可检查的输入/输出契约、可恢复的业务状态与可控制的计算；表达能力边界必须写入模型说明和测试，不声称等同完整浏览器编程环境。

## 9. 验证方案与完成口径

### 模型、样本与评估

真实生成测试使用用户指定的 DeepSeek V4.1，沿用已确认的 `deepseek/deepseek-flash` 配置；每次记录服务返回的实际标识和参数，不使用 V4 Pro，不把别名当作不可变模型快照。凭据不可用时明确未测，不擅自换模型并合并数据。

建立组件和小程序混合任务，包含直接回答、需澄清、已有界面追问与不支持能力；按业务领域和交互原语组合分组。开发集与封存集按任务族隔离，测试用语不提示工具、协议或组件名称。不同表述但同一模板不能跨两边充当泛化证据。

初始建议 48 个任务：16 个小程序、12 个组件、12 个直接回答、4 个澄清、4 个能力缺口；32 个开发、16 个封存，运行前固定分组、预期与预算，每例 3 次。另设故障矩阵，不混入生成成功率。封存任务一旦参与修复即降为开发样本并补充新的封存任务。

首轮固定 DeepSeek V4.1 便于对照，不产生跨模型稳定性的结论。报告逐项保留漏触发、误触发、选错形式、首次可用、预算内最终可用、修复次数和端到端耗时。未调用、超时和文字降级仍计入相关能力内任务的失败；“两者均可”的任务单列。

### 功能正确性与交互证据

| 类别 | 自然表达例子 | 独立核对方式 |
| --- | --- | --- |
| 概率实验 | “掷很多次硬币，我想看看比例怎么变。” | 固定种子回放；预先确定样本量和二项分布容差，多种子统计 |
| 几何教学 | “拖一下三角形，看看面积怎么变。” | 独立鞋带公式；退化三角形、负坐标和边界输入 |
| 离散过程 | “把排序一步一步演给我看。” | 输出有序且多重集不变；每步操作符合指定算法 |
| 持续交互 | “做个用方向键躲障碍的小玩意。” | 固定步长、碰撞和计分规则；持续键入、暂停、重启和焦点恢复 |
| 三维关系 | “把立方体转一转，再展开看看。” | 顶点、面邻接与展开关系独立检查；拾取、GPU 资源释放与二维替代说明 |

这些是开发示例，不是预置业务模板。独立检查逻辑不能复用生成程序本身，也不能以模型自报“已验证”作为证据。结构和截图检查不能代替数学、物理或业务正确性。

桌面验证复用 `scripts/desktop-e2e/` 的隔离生命周期与报告，真正操作通过 UI 完成。接口和存储只用于准备及核对，记录夹具边界。关注输入反馈、帧耗时分位数、主聊天响应、停止耗时和长时间资源趋势；记录设备与样本，不预先声称达到性能目标。

故障矩阵至少覆盖残缺 JSON、编译错误、死循环、超大状态、渲染洪泛、CSP 绕过尝试、伪造消息、窗口卸载、关闭 Beta、取消后迟到、发布中断、两窗口冲突和旧分支写入。数据表述与动态结论一致性沿用第二阶段回归，视觉改善不能掩盖结论错误。

开发完成要求目标能力全部落地且相关开发验证有证据。CI、至少两位独立人工语义判断及分歧复核按约定在三阶段开发后完成；它们未完成时只能写“待综合验收”，不能写“已验收”或“已发布”。

## 10. 方案自审与未决验证

本节为当前方案的桌面推演，不是独立人员 Review，也不是执行测试结果。

| 发现的问题 | 本版设计处理 | 仍需验证 |
| --- | --- | --- |
| 自由 JS 与可停止、可保存要求冲突 | 生成逻辑进 VM，文档/三维由可信适配器渲染 | 导出限制、VM 中断、主线程负载 |
| 只有固定组件会限制表现和泛化 | 支持自由布局、通用图元、程序状态和事件 | 新领域任务首次生成与语义正确性 |
| 仅有 iframe 无法证明资源可控 | 计算预算、编译预算、渲染成本和宿主停止分层处理 | 极端 CSS、SVG、GPU 压力与设备差异 |
| 简单通道可能混淆旧版本或伪造用户动作 | 专用握手、epoch、服务端权威身份、宿主动作控件 | 竞态、过期令牌、取消及多窗口攻击样本 |
| 保存 JSON 不保证恢复含义一致 | 程序摘要、schema/runtime 版本、种子/tick、默认暂停 | 升级、浮点容差、迁移失败与断电恢复 |
| 通用输出层仍有具体功能引用 | 先抽显式内部 adapter，保留组件兼容测试 | 关闭开关零加载、导出/fork/回收站全路径 |
| 好看可能掩盖错误结论 | 同帧结果绑定、独立 oracle、失败保留 | 自然语言语义、数学与业务计算 |
