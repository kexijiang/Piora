# Intelligent UI：登记动作与执行边界

2026-10-29 · 2D 实施设计 v2.7。内部 Plan2 已接入动作声明、发布来源、文件适配器、权限、操作记录及按钮。默认生成协议仍为旧 Surface，真实模型到桌面的完整验收尚未完成。结果与证据见 [本次成果](verification/intelligent-ui-phase2-actions-2026-10-29.md)。

## 用户流程

第一组登记能力为读取工作区 JSON 参数，以及把当前已保存结果另存为 JSON／Markdown。用户可据此重新加载一份条件配置、保存比较方案或预算结果。能力可继续扩展，但模型只选择宿主登记的动作，不能提供 JavaScript、Shell 命令、任意工具名或 URL。

读取返回待核对参数，用户明确采用后通过原参数 CAS 保存，不能用查询响应覆盖本机未保存调整。保存内容由宿主根据当前已发布界面及已保存参数计算；文件路径固定在动作声明中，并在操作界面完整展示。首组保存动作只新建文件，已有文件返回冲突；不同名称的另存是新的明确操作。

候选、等待结构确认和已被替代的旧版都不允许动作。关闭 Beta、停止、切换分支、改变源参数或结构、改变文件目标后，旧操作凭据失效。等待批准期间不锁住参数编辑；执行前在统一 UI 锁中再次核对来源和目标。

## 声明与确定性适配器（已实现基础）

`action-contract.ts` 定义独立的 version 1 动作声明，最多 8 个动作。每个动作有稳定 ID、标签、登记种类及有界工作区相对路径。禁止路径别名、上级目录、绝对路径、隐藏及凭据路径、Windows 设备名与 ADS；保存格式和扩展名必须一致。

`action-files.ts` 解析当前工作目录的真实路径，逐层检查目录及目标，拒绝符号链接、junction、硬链接和未存在的父目录。不自动建立目录，也不访问网络。操作证据包含真实目标、根与父目录身份、文件身份及内容哈希；核对后发生变化会产生冲突。这些检查属于应用边界，不是针对恶意本地进程的操作系统沙箱。

JSON 参数读取上限 256000 字节，严格解析还受既有 JSON 结构预算约束；要求完整 UTF-8、无重复键、输入 ID 完整且没有多余字段，值符合界面类型、范围和选项。返回提案数据及证据，不修改会话参数。不能把静态或未验证数据当成已保存值。

报告使用当前参数重新计算快照。JSON 保存界面标识、结构版本、参数和可读快照；Markdown 把模型文本作为缩进代码块展示，避免将模型 HTML 当成可执行标记。输出同样限制为 256000 字节。

文件通过独占创建写入，并同步文件描述符。创建前和写入前复核宿主授权；已有文件即使内容相同也不直接当成本次成功。中断可能留下空文件或部分结果，适配器返回 UNCERTAIN，保留现场供核实，不自动删除、覆盖或重写。

## 发布来源（已实现内部入口）

Plan2 编译器 2.1.0 验证独立动作声明，声明存入 generation journal 和原工具结果的 actions 字段，参与精确工具回执验证。计算 Surface2 保持原结构，旧客户端仍可读取参数和快照。Plan2 工具 schema 与提示已开放有限 actions；普通 Surface 和 Plan1 不增加动作。生成预览仍只有计算界面，不呈现可执行按钮。

`readActionSource()` 只提供当前分支中当前已发布版本的动作、参数及摘要；候选和旧版不能获取可用来源。`withActionSource()` 在统一 UI 锁内重读，并核对会话、所选 leaf、发布位置、结构、参数版本和值、动作声明。摘要只是比较令牌，不是执行授权。分叉复制声明与值，但新的会话 ID 产生不同来源摘要，不继承父会话批准。

2026-10-30 修正：参数读写仍使用实际 leaf，但动作摘要忽略末尾无分叉的 `session_info` 标题记录，避免自动命名误使待采用参数或确认失效。遇到兄弟分支、消息或其他记录立即停止折叠；标题记录上保存的新参数仍参与版本和值校验。旧数据不会因此自动采用。

## 操作 journal 与权限连接（已接入内部 Plan2）

动作声明作为独立版本协议随候选持久化，并纳入精确工具回执验证；不把动作混入计算表达式。动作查询只从当前已提交版本读取，不从浏览器重新接收路径或正文。

准备操作捕获会话、分支 leaf、已发布 operationId、来源摘要、参数版本、动作声明、真实工作目录、文件证据及待写字节摘要。同一 journal 保存操作和参数采用回执，避免应用参数成功后丢失幂等记录。幂等键绑定来源与动作，复用同一键提交不同意图会拒绝；重复请求只返回原记录。

每次明确点击通过通用 executeAnswerAction 建立新 PromptRun，与普通模型运行互斥。权限复用当前聊天的 ToolReviewController、权限版本、独立模型审核／人工批准和停止规则。还要求会话启用 read 或 write 能力及 Plan 工具。宿主提供具体点击要求及内容，不从模型标签推断更广泛的授权；完整访问仍不跳过会话、版本、路径和执行正确性检查。普通项目读取及写入继续遵守原有安全操作豁免；严格 ask 模式的写入展示一次性批准，按钮不能修改聊天权限模式。

操作状态为 prepared、waiting_approval、executing、completed、cancelled、failed、uncertain。先写执行意图，再产生效果，最后写回执。网络断开不自动重放；服务重启后不恢复旧批准。结果不明时显式核对目标文件哈希，保持 uncertain 并报告 matching／missing／different，不将 matching 改写成“本次执行成功”，也不声称跨崩溃 exactly-once。GET 仅投影中断状态，显式核对才写恢复记录。

读取结果可以重新查询；采用结果属于独立参数更新，仍需源版本 CAS。保存结果核实为缺失或不同内容时保持未确认，让用户选择新的明确操作；禁止凭旧批准继续写入。重复点击及两窗口并发需共享同一持久意图或返回冲突。

确认期间参数变化仍使批准失效，同时取消原等待运行；拒绝不要求参数仍与点击时相同。异步来源检查前后均核对同一个待确认对象，一次确认只能由一个请求消费。安全项目文件的读取遵循现有权限豁免；读取结果的采用始终是独立的明确操作。

## 接口与独立界面

GET／POST 位于会话的 intelligent-ui/actions 路由，要求同源、Beta 开启及有限请求字段；起始请求只传来源摘要、声明 ID 和请求 ID，不能传目标路径、正文或命令。GET 不创建模型会话。启动操作恢复权威会话及能力配置，写入意图后返回 202；动作继续由宿主跟踪，浏览器可轮询或刷新。

独立 SurfaceActions 只挂载于已提交的 v2 回答，展示声明相对路径和实际操作的完整路径、批准／执行状态、读取结果、采用及核对入口。开始前保存已知参数调整；未保存草稿阻止采用，服务端 CAS 再阻止覆盖新值。请求丢失后只查询，显式重试使用原请求 ID。组件位于 Intelligent UI 模块，原 ChatWindow 不包含动作专用分支。

2026-10-30 补充：HTTP 错误和持久操作可携带独立的 `problem` 展示原因，不改变原错误码和诊断文本。前端据此显示中英文的文件已存在、文件缺失、参数格式错误、来源变化、超限或结果不明等提示；旧记录没有该字段时使用状态对应的保守说明，原诊断放在可键盘展开的技术详情中。参数格式失败不会产生可采用结果。未预期的服务端异常返回 500；只有明确的 4xx 拒绝且查询确认没有操作记录后才解除请求不明状态，网络与 5xx 失败继续保留原请求编号，等待查询或用户显式重试。

剩余验收：真实模型能否在自然表达下正确选择动作、目标及参数文件格式，模型到桌面的完整流程，以及默认协议启用决策。当前 JSON 查询要求文件键与输入 ID 完全对应，不支持任意业务 JSON 的自动映射。

按用户最新安排，CI 在三个阶段功能开发完成后统一处理；开发阶段继续做直接相关的本地验证。本次增量已输出 v2.7 报告及 PDF，第二阶段整体保持实现中。
