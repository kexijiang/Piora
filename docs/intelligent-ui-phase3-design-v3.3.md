# Intelligent UI 第三阶段方案 v3.3

2026-10-31 | 参考 OpenIntelligentUI 后重新设计 | 实施方案，非完成报告

## 1. 重新设计的结论

第三阶段交付的是能操作、能保存、能继续讨论的交互回答。参数调整、比较和筛选沿用组件模式；算法演示、空间拖动、模拟、小游戏和三维教学使用独立小程序。两者共用 Beta 开关、原有模型会话和回答输出接口，普通对话不维护任何小程序状态机。

技术路线采用 **自由 HTML/CSS 布局 + 普通 JavaScript 计算 + 可信图形渲染 + 独立持久状态**。模型写任务逻辑，Piora 提供基础外观、播放控制、运行预算、保存、恢复与动作权限。这能拓展表达能力，也能保留第二阶段已经建立的状态一致性。

### 本次调整解决什么问题

| 问题 | 设计决定 |
| --- | --- |
| 固定组件难表达复杂任务 | 新增小程序路径，允许数组、循环和普通函数；不为每个任务增加一套业务表达式 |
| 自然语言容易生成失败 | 合并形式选择原则，减少重复协议说明；用可运行契约样例和字段级诊断降低纠错成本 |
| 自由生成容易样式失控 | 宿主提供主题、字体、间距、控件和状态提示；模型只组织内容与布局 |
| 原型不少，完整流程仍没接通 | 先交付聊天中的生成、操作、保存、刷新和追问；开放工具前接好分叉、复制和静态导出 |
| “支持三维/游戏”过于笼统 | 明确拾取、相机、时间步、按键、终态与独立正确性验证，逐项验收 |

### OpenIntelligentUI 借鉴范围

本轮检查本地提交 8391a94c1c3939c679e40ddd7bfc08a9ef690e70。其 CSS 完成后预览、最终沙箱、共享设计系统和受限宿主桥接值得借鉴；但当前项目使用独立 Jev 展示决策、进程内会话检查点，任意控件状态不会自动同步给智能体。[R1]、[R2]

Piora 沿用现有 AgentSession 和同轮模型判断，补足持久状态、分支与保存回执；本方案不引入另一套聊天后端。参考项目的 HTML/JS 可直接操作浏览器环境，Piora 的生成程序只能访问明确提供的计算契约，二者能力范围并不等价。

本版替代 v3.2 作为后续实施依据，保留原型与历史报告。整体仍是三个阶段；下面的 3A 至 3E 是第三阶段内部步骤。

## 2. 如何判断用文字、组件还是小程序

同一轮回答模型结合当前请求、最近对话、已确认参数和可用能力作选择。先判断用户是否需要反复操作或观察过程，再判断哪种表达能满足目的；复杂问题和某些关键词本身不构成触发条件。

| 自然表达 | 选择及理由 |
| --- | --- |
| “六个人平分 480 块。” | 文字，直接给出 80 元即可 |
| “人数还没定，我想改着看看。” | 组件，少量参数和结果联动即可 |
| “排序怎么一步步交换？让我点着看。” | 小程序，需要显式过程、单步和高亮 |
| “拖一下三角形，看看面积怎么变。” | 小程序，需要空间操作与数值同步 |
| “提成规则还没想好，帮我算。” | 先澄清影响计算的规则 |
| “为什么刚才那个结果变了？” | 根据已确认状态解释；没有新交互需求时不重建 |

### 决策怎样落到代码

- 共用一份选择策略：用户目标、事实是否足够、交互收益、支持能力、已有输出。两个工具不各自重复一套竞争性说明。
- 组件工具保持 piora_render_ui_plan；小程序使用 piora_render_mini_app。工具 schema 给结构，短说明给约束，版本化能力清单给支持范围；示例必须通过实际编译和执行。
- 生成工具接纳后，记录所选工具、运行身份、尝试次数及失败类型；文字与澄清的准确性通过评估判断，不另设每句必经的分类模型。
- 已有输出时优先回答、调整或修订当前任务。用户说“只要文字”就遵从；关键规则缺失要澄清，颜色和一般布局可以采用默认值。

模型选择与程序接纳分工明确：模型判断是否有交互价值；程序核对 Beta、能力、结构、资源、版本和来源，不能用结构校验替代语义判断。

### 生成稳定性

原始参数在 SDK 类型转换前校验，再编译和隔离试运行。错误返回稳定代码、具体字段路径和原因，区分可修复的计划错误与取消、冲突、权限拒绝。可无歧义展开的语法简写由编译器处理；缺失公式、单位或业务规则不能猜测补齐。

先沿用同一 PromptRun 的 3 次接纳尝试、1 次模型纠错和首次尝试起 60 秒窗口。组件、小程序及模型恢复共用预算，切换工具不能重新计数。失败时保留旧输出并解释；预算调整只依据开发集证据，记录策略版本。此处是初始策略，尚未证明适合所有复杂生成任务。

## 3. 运行架构与模型创作契约

```text
AgentSession -> 形式选择 -> MiniAppPlan -> 编译 / 试运行 / 发布
                                      |
                                 MiniAppHost
                           /                 \
             文档 / SVG / Canvas / 3D     Worker + QuickJS
                  可信渲染器              显式状态与计算
                           \                 /
                          版本化事件与投影帧
                                  |
                    独立状态存储 / 追问 / 登记动作
```

模型输出用途、假设、输入含义、状态结构、HTML/CSS 和四个函数：init 创建状态，reduce 处理交互，advance 推进固定时间步，project 生成同一时刻的图形、数值和说明。普通 JavaScript 算术、数组和循环承担任务计算；project 必须纯读取，不能偷偷推进模拟。

宿主承担计时器、随机种子、依赖加载、资源清理、版本身份和保存。输入变化、时间、随机结果都进入可恢复检查点；不依赖浏览器闭包、Date.now 或 Math.random 保存隐式进度。无需时间推进的任务使用空操作 advance，由示例说明清楚。

### 展示与计算分开

HTML/CSS 通过解析与允许列表编译为可信节点和样式；SVG 绑定有限标量；Canvas 与 Three.js 只接受受限绘图指令和场景数据。固定渲染器置于隔离 iframe，模型代码在 Worker 内 QuickJS/WASM 执行，通过 MessageChannel 传递事件与帧。

这一方案便于暂停、重放、保存和故障隔离，代价是不能直接运行任意网页示例或调用完整 Three.js API。第一版支持语义 HTML、布局 CSS、SVG、有限 Canvas 指令和常用三维几何；不承诺任意 npm、远程资源、着色器或完整游戏引擎。能力不足时解释限制或提供合适的替代形式。

能力清单按协议版本维护。只冻结即将接通的事件与帧结构；后续动态列表、拾取和相机功能以明确版本扩展，不能提前在工具说明中承诺。旧版本可继续用兼容运行时读取；无法兼容时展示快照，不用新版本静默解释旧程序。

### 执行与停止边界

QuickJS/WASI 提供内存和执行中断控制，外层 Worker 提供终止机制。[R3]、[R4] 两者不能替代 DOM、GPU 和消息队列预算。原型初始上限为单步 8 ms、30 fps、堆 32 MiB、400 个文档节点与 200 个网格。它们需要目标设备校准，不代表已测得的性能。

默认暂停，每个聊天视图同一时刻只允许一个实例持续播放。隐藏页面时暂停并清除按键/拖动状态；停止时终止计算并释放图形资源。强制终止无法保证保存卡死瞬间的状态，恢复从最近确认检查点开始。

## 4. 复杂任务的实现与验收

按通用交互能力组织代码，再用不同任务验证组合能力。排序、几何和小游戏是验收样例，不成为只识别特定说法的业务模板。

| 任务能力 | 实现约定与验收重点 |
| --- | --- |
| 算法与步骤教学 | state 保存序列、步骤及高亮；单步与播放共用推进逻辑。核对顺序、元素多重集、过程和终态，不能只展示最终排序 |
| 几何拖动 | 可信渲染器统一坐标与指针捕获，程序更新点位并投影面积。支持键盘或数值替代；用独立公式核对退化、负坐标等边界 |
| 模拟与持续小游戏 | 固定时间步、显式随机源、按键状态与碰撞规则；提供暂停、复位、终态。固定输入可回放；超预算暂停，不能跳过逻辑步伪造实时性 |
| 动态列表 | 受限重复模板、稳定 key、有限字段绑定；展开后计入节点上限。更新项目保持身份，事件绑定正确行，不接受任意 HTML 片段 |
| 三维拾取与相机 | 可信渲染器射线拾取，返回对象 ID 和有限坐标；旋转、缩放、选择进入显式状态。恢复时还原视角；拒绝旧帧点击 |
| 三维关系教学 | 计算程序表达展开、旋转与空间关系；场景适配器绘制结果。展开例子核对邻接、边长、重叠和还原，展示立方体不等于完成教学 |

### 交互消息的时序

每条事件绑定实例 epoch、视口和显示帧身份。输入坐标按固定协议转换，不将 DOM、Three.js 对象或宿主引用交给生成程序。拾取仅在有效帧上使用；第一版精确选择优先在暂停或静止场景中完成，过期事件拒绝并留下诊断。

连续 pointermove 可以合并为最新位置，按下、松开、取消和点击必须保持顺序。保存前排空合并事件和 Worker 队列，不能让最后一次拖动丢在防抖计时器里。后台切换、失焦和实例卸载同样处理释放事件。

### 外观恢复到统一标准

宿主提供标题、内容边距、控件、字体、语义色板、焦点和错误状态。模型组织任务信息，不能重画一套宿主权限界面。精确输入用数字框，连续探索才用滑块；有限选项用按钮或选择器，过程用播放/单步，空间关系用拖动/旋转。

CSS 和依赖完整的布局先显示只读预览；三维预览使用占位，不创建 GPU。正式发布前不执行预览脚本。主题、字号、减少动画、窄屏重排和键盘替代同时覆盖文字、SVG、Canvas 和三维标签；图形、指标与说明来自同次 project。

## 5. 保存、追问、分支与更新

发布记录不可变，保存计划、程序摘要和工具来源；交互记录独立保存 inputs、state、rng、tick、运行版本、文字结果和 stateRevision。原始模型回执不因用户拖动而改写。

### 一次追问的完整流程

```text
暂停推进并冻结新输入
  -> iframe 发出最后一批事件并确认冻结
  -> Worker 排空已接收事件，取得同一检查点
  -> IndexedDB 持久草稿
  -> 服务端核对分支、发布身份和 expectedRevision
  -> 服务端重新 project 并原子保存，返回幂等回执
  -> 模型读取这次确认的参数、假设和结果
```

等待超时或保存失败时，保留草稿与旧版本，由用户重试、恢复或明确采用已保存状态；不能默默带旧参数继续提问。用户在追问发出后继续操作，不改变本轮已经捕获的状态；候选发布前再次核对源版本，变化后保留旧版并提示冲突。

### 需要同时满足的生命周期规则

| 场景 | 规则 |
| --- | --- |
| 刷新、崩溃、断网 | IndexedDB 按独立 draftId 保存待确认记录；本机存储失败须可见，并允许导出内存中的草稿 |
| 写入响应丢失 | 查询同一 requestId 的回执，重试沿用身份；只删除已确认的草稿。保存中产生的新修改等待前一回执 |
| 多窗口与旧草稿 | expectedRevision 检查冲突，保留双方内容；服务器校验来源分支祖先，前端标签不能代替身份检查 |
| 分支、fork、复制 | 只继承保留历史可见的已确认状态和发布来源，之后独立写入；未确认草稿明确处理，不能悄悄丢失 |
| 导出与回收站 | 导出静态结果、参数及来源，不自动执行生成代码；发布与状态一起删除、恢复和清理 |
| 新程序与结构变更 | 保留旧版本，比较字段含义、单位和约束；兼容输入可预填，内部 state 默认重新 init，不自动猜测迁移 |
| 明确的状态迁移 | 单独受限转换，重新校验和投影后由用户确认；失败保留旧程序、旧参数和草稿 |

关闭 Beta 立即停止小程序、取消未提交发布和保存，下一轮撤销工具；保留已确认数据和恢复草稿。组件路径沿用现有开关语义，避免改动普通对话的运行规则。

外部动作复用已登记的读取/另存入口，由宿主按钮发起、保存当前参数后重新校验聊天权限与目标。iframe 消息和生成程序不能授权操作；加载、定时器和参数变化也不能自动向模型发消息。“根据当前结果继续问”通过宿主入口执行上述保存流程。

## 6. 接入边界与实施顺序

lib/answer-output-* 提供通用能力目录、生成、预览、渲染、保存门禁和持久化适配。intelligent-ui 与 mini-app 是独立 kind。新增扩展、lib/mini-app/ 和 components/mini-app/ 管理小程序；ChatWindow、MessageView、useAgentSession 只调用公共接口。

Beta 关闭时不加载交互 Surface、QuickJS 或 Three.js，历史保持文字快照。服务端保存、迁移和动作仍在会话作用域复核身份。依赖固定版本并随应用分发，开发应用与发布包的资源路径分别验证。

| 步骤 | 交付与开放条件 |
| --- | --- |
| 3A 基础契约 | 核对现有编译、Worker/WASM、渲染与停止原型；最小示例可执行，真实开发应用能加载资源，旧组件回归通过 |
| 3B 第一条完整产品流程 | 登记工具、共同生成预算、预览和 Surface；连同基础保存、刷新、追问、fork/复制、静态导出与回收站一起接通。以真实聊天操作验证后才开放小程序入口 |
| 3C 完整恢复与动作 | 补齐多窗口、断网、旧草稿分页、修订确认、状态迁移与登记动作权限。每条失败路径可恢复且有回执证据 |
| 3D 复杂能力与泛化 | 逐项扩展动态列表、拾取、相机、模拟和持续小游戏；同步主题、字号、无障碍、性能与自然语言开发评估 |
| 3E 综合收尾 | 三阶段回归、封存样本、此前推迟的完整 CI 与人工语义验收，逐项审计并导出最终成果报告。发布另走既定流程 |

3B 前置基本分叉、复制和导出，是本版相对 v3.2 的关键顺序调整：这些入口在聊天中已经存在，不能开放小程序后再让用户遇到状态丢失。3C 仍负责完整故障矩阵、迁移和动作，不缩减范围。

### 现在可以复用什么

本轮源码核对基线为 Piora HEAD b41fa2ff，codex/intelligent-ui 分支包含未提交原型。已有编译器、计算与渲染隔离、发布日志、独立状态服务、草稿及 React Surface；通用 catalog 与前端 renderer 仍只登记已有组件，小程序工具尚未开放。

客户端报告记录了 62/62 相关测试、TypeScript 与修改模块 lint 通过，这些仅是报告对应快照。本轮没有复跑，也未验证真实模型或完整桌面聊天。后续复用已有代码完成接入。

本次只更新方案与文档索引、导出 PDF 并检查排版。没有新增产品功能、提交、推送或运行 CI；现有实现状态保持在进展文档中。

## 7. 验证方案与可行性

判断：可行，但风险集中在模型能否稳定遵守契约、复杂任务是否真的正确，以及完整生命周期是否一致。基础原型提供实现依据，尚不足以证明复杂任务成功率或桌面性能。

### 怎样验证泛化，而不是背熟例子

固定 48 个初始任务：16 个小程序、12 个组件、12 个文字、4 个澄清、4 个能力缺口。按任务族及交互组合分为 32 个开发、16 个封存样本，每例 3 次；同时覆盖自然表达、多轮引用、解释已有结果、明确拒绝 UI 和未支持能力。

开发集用于优化说明与实现，封存集留到综合验收。封存样本用于调试后必须转入开发集并补新样本；保存任务、策略、模型、运行版本和失败输出。测试固定使用用户指定的 **DeepSeek V4.1**，运行前核对配置与实际返回标识；不使用 V4 Pro，也不静默替换模型。

| 维度 | 验收证据 |
| --- | --- |
| 选择是否合理 | 误触发、漏触发、漏澄清和形式不合适分别统计；预先标注允许多种合理形式的任务 |
| 是否稳定生成 | 首次可运行率、预算内最终可运行率、纠错次数和耗时分开报告；所有任务保留为分母，超时和漏调用不删除 |
| 是否完成任务 | 用独立算法、公式或规则核对边界、终态和单位。结构通过、截图漂亮、模型自称正确均不足以通过 |
| 是否可靠使用 | 操作、保存、刷新、追问、分支、修订、动作、关闭 Beta 贯穿验证；静默丢失、越权或错误版本覆盖不得接受 |
| 是否适合桌面 | 记录硬件、版本、输入响应、长时间运行资源趋势、窄屏/深色/键盘表现；真实 GPU 与软件渲染结果分开 |

桌面流程复用 scripts/desktop-e2e/ 生命周期，通过 UI 进行被验证操作。接口和存储读取只用于准备与核对；明确区分固定模型夹具、真实模型、真实桌面窗口和发布包。自动快速检查继续按改动需要执行；人工语义验收与完整 CI 按用户安排放到三个阶段开发完成后。

### 方案自审的五个重点

- 契约太长：压缩公共说明、从真实编译样例生成示例，先验证不同任务而非继续堆能力。
- 沙箱限制影响表达：清楚公布可用绘图与事件，记录能力缺口；需要扩展时升级契约，避免让模型反复试不存在的 API。
- 状态正确但结论错误：服务端重投影只证明一致性；数学、物理和规则另外验证。
- 原型通过而产品未接通：开放条件绑定真实聊天流程及已有生命周期入口。
- 渲染资源与平台差异：分别量测计算、DOM、消息与 GPU；不把本地夹具数据当成发行质量。
