# Piora 用户手册

Piora 是本地优先的 AI 桌面工作台。你可以在同一窗口里与 AI 对话、处理项目文件、审阅代码改动、运行终端命令、浏览网页，以及连接远程主机和鸿蒙设备。本手册从首次安装开始，介绍日常操作、数据迁移和常见问题。

**适用范围**：以 `0.5.5-beta.36` 候选源码为基础。它不代表这些功能都已随安装包发布；已安装版本的可用功能以实际界面和对应[版本更新说明](../CHANGELOG.md)为准。较旧版本可能将“模型配置”称为“模型”，将部分设置放在“通用”中。

## 安装与启动

### 选择安装形式

从 [Piora 发布页面](https://github.com/kexijiang/Piora/releases)选择一个已发布版本，先读该版本说明，再下载适合系统的文件。不要将源码版本号当成已经可下载的版本。

| 形式 | 适用情况 | 启动方式 |
| --- | --- | --- |
| Windows x64 安装版 `setup.exe` | 日常使用，需要安装目录选择和应用内更新 | 安装后打开 Piora |
| Windows x64 单文件便携版 `portable.exe` | 希望直接运行程序 | 双击 EXE；升级时手动替换 |
| Windows x64 目录 ZIP | 希望解压后运行 | 完整解压后打开其中的 `Piora.exe` |
| Linux x64 AppImage | Linux 桌面使用 | 在文件属性中允许执行，再运行 |

Windows 桌面版支持 Windows 10/11 x64。安装包包含应用运行时，普通使用无需安装 Node.js。需要操作 Git 仓库、编译工程或运行第三方工具时，仍需安装对应的 Git、编译器或依赖。目前仓库说明不提供 macOS 安装包；各版本具体支持的平台以发布附件为准。

Windows 包尚未启用代码签名。遇到系统信誉提示时，核对下载来源和发布页提供的 SHA-256 校验文件。目录版必须完整解压，不能只复制其中一个 EXE。

**便携版不等于数据全部存在 EXE 旁边。** 会话和配置默认仍保存在用户目录；换电脑请使用[备份与迁移](#数据备份与迁移)。

### 桌面版与网页模式

本手册以桌面版为主。源码启动的网页模式可以使用聊天及许多工作区功能，但桌面窗口、系统通知、剪贴板集成、电脑控制等能力依赖桌面环境。Linux 也不包含 Windows 专用电脑控制和随包离线听写运行时。

需要自行运行源码时，参阅 [README 的开发与贡献](../README.md#开发与贡献)和[桌面开发说明](../desktop/README.md)。普通用户无需进行构建或打包。

## 第一次完成任务

第一次使用，可以先完成一个只读任务，确认模型和项目都已配置正确。

1. 打开设置，进入“模型配置”，添加服务凭据并测试连接。Piora 不提供统一模型订阅或内置 API Key。
2. 从侧边栏选择一个本地项目文件夹；只想问答或写作时，也可以新建无项目聊天。
3. 在输入框选择可用模型。如果模型支持思考等级，可一并选择。
4. 发送：**“请阅读这个项目，说明它的用途、启动方法和主要目录，先不要修改文件。”**
5. 查看工具调用和最终回复。点击引用的文件，核对 AI 的判断。
6. 继续提出具体任务，例如：**“修复刚才指出的布局问题，完成后运行相关检查，并列出修改的文件。”**

成功时，你会看到用户消息、AI 回复以及实际发生的工具调用。出现认证、额度或连接错误时，先按[模型与网络](#配置模型与网络)检查，不必反复创建新聊天。

## 认识工作区

| 区域 | 用途 |
| --- | --- |
| 左侧栏 | 选择项目、查找和切换聊天、管理工作树及协作空间 |
| 中间聊天区 | 阅读历史、查看思考和工具执行、发送任务及停止任务 |
| 输入框 | 选择模型、思考等级、附加图片或文件、引用路径 |
| 右侧工作区 | 通过加号打开文件、改动审阅、终端、浏览器、SSH、设备等面板 |
| 设置 | 管理模型、运行策略、技能、网络、外观、备份和诊断 |

面板之间可以切换，分隔线可以拖动。屏幕较窄时，先关闭暂时不用的面板或放大当前面板。

设置支持搜索。找不到某个入口时，直接搜索“重试”“备份”“语音”“快捷键”等关键词。也可以按 `Ctrl+K` 打开命令面板，搜索当前可执行的操作。

## 配置模型与网络

### 添加模型服务

1. 打开“设置 → 模型配置”。
2. 选择服务商，使用它支持的 API Key、OAuth 或设备码方式认证。
3. 自定义服务按服务商提供的信息填写地址、模型 ID 及必要配置，不要把网页聊天地址当成 API 地址。
4. 使用连接测试，确认认证和模型可用。
5. 启用需要的模型并设置默认模型；回到聊天，在输入框核对当前模型。

默认模型用于新会话的初始选择。当前聊天的实际选择以输入框为准。模型是否支持图片、思考等级及上下文长度，由服务和模型能力决定。

API Key 是访问凭据。不要把它贴到聊天、公开截图或问题报告中。模型收费和额度由服务商管理，Piora 的统计不替代服务商账单。

### 按思考等级配置采样参数（未发布）

在“模型配置”中选择自定义模型，展开“高级设置 → 采样参数”。可以编辑模型默认参数，或选择 `off/minimal/low/medium/high/xhigh/max` 设置等级覆盖。留空或清除此覆盖表示继承，不会自动填入推荐值。高级 JSON 可编辑完整参数，其他未知字段会保留。

“预览有效参数”使用当前草稿，先将请求等级收敛到模型支持的等级，再按“模型默认 → 有效等级覆盖 → 请求级覆盖”逐键合并。请求级覆盖只用于预览和测试，不随“保存”写入配置。等级键是 Pi 等级，不是“思考级别映射”里的渠道值。

这些参数仅适用于 `openai-completions`、`openai-responses` 和 `azure-openai-responses`。预览不调用模型；“测试此采样配置”会发送一条实际请求，可能产生少量费用。不同端点接受的参数不同，服务返回的拒绝错误会显示在界面中，Piora 不会自动替换成其他参数。无效 JSON 或参数值需要修正后才能保存。

### 超时重试与模型回退

在“设置 → 运行策略”调整超时、自动重试、上下文压缩和模型故障回退。

- **超时**：限制等待模型响应或后续数据的时间。网络慢时可以适当调大；不要用无限等待掩盖错误地址或失效凭据。
- **重试**：请求失败后按配置再次尝试。聊天状态行会显示相关状态。
- **模型故障回退**：默认关闭。启用后，当前服务不可用且常规重试结束时，会尝试其他已启用、已认证并满足能力要求的模型；模型切换会显示在记录中。
- **上下文压缩**：为长会话生成摘要，减少后续请求需要携带的历史。压缩后的上下文不能等同于逐字保留所有细节。

保存后的设置用于后续请求；正在执行的请求可能仍使用开始时的超时配置。工具失败、用户停止和一般任务错误不会自动变成模型切换。

“设置 → 使用量”可查看用量。费用缺失或仅部分已知时，应按界面状态理解，不能当成免费。

### 网络代理

打开“设置 → 网络代理”，选择跟随系统、手动 HTTP/HTTPS 代理或直接连接，填写需要的参数后保存。

应用代理覆盖模型请求与登录、内置浏览器、插件与资源下载、更新检查。保存后对后续请求生效；Agent 浏览器会在下一次操作时重新连接。本机服务保持直连。

如果模型和技能下载同时失败，先检查这里的代理地址、端口及代理程序是否运行。终端中自行启动的第三方程序有各自的网络设置，不应仅凭应用代理保存成功就认定它们也已配置。

## 聊天与任务管理

### 发送消息和附件

在输入框描述目标、相关材料和完成标准。需要修改项目时，说明允许修改的范围和希望执行的验证。使用 `@` 引用项目文件，或通过附件入口添加图片和文本材料。

默认 `Enter` 发送，`Shift+Enter` 换行；可在“设置 → 对话与输入”改为 `Ctrl+Enter` 发送。图片能力取决于模型；需要后续再次仔细看图时，重新附加该图片。

任务发送前会保留本地恢复副本。若看到“发送状态待确认”或“发送失败”，先核对聊天和恢复的草稿，再决定重试。连续点击发送可能形成多个独立任务；相同文字也可能是不同的提交。

### 运行中补充要求

| 操作 | 适合什么情况 |
| --- | --- |
| 引导 | 给当前正在执行的任务补充约束或纠正方向 |
| 排队 | 当前任务完成后，再处理下一条消息 |
| 停止 | 结束当前运行，先检查已经发生的操作 |

可在“设置 → 对话与输入”配置运行中默认发送行为。“引导”会补充到当前任务，但不保证打断已经开始的每一次工具调用。

停止任务不会撤销已经写入的文件、发送出去的网络请求或已生效的设备操作。停止后先看执行记录和文件差异，再决定继续、修复或回退。

### 阅读过程与结果

聊天会展示思考、工具调用、输出和执行时间。状态行中的重试、压缩、等待与执行工具代表不同阶段；长时间没有进展时，先展开最近的工具或错误。

刷新页面后，Piora 会尝试恢复仍在运行的任务状态。刷新页面不等于停止后台任务。最终应同时检查 AI 的总结、实际文件改动和验证结果。

上下文较长时，可使用“压缩上下文”。压缩期间等待完成或错误提示，避免重复点击。重要目标、约束和结论也可以明确写入项目文档，便于后续任务引用。

### 重试分叉与继续

- **重试**：在自己发送的消息上重新发送原文和附件。适合处理已经确认失败的发送或重新执行任务。
- **分叉**：从历史消息创建一个独立聊天，用另一种方案继续，原聊天仍保留。
- **继续及分支切换**：在同一个聊天的历史分支中继续或切换上下文，不等于创建新聊天。

分叉和切换聊天分支只改变对话上下文，**不会自动恢复项目文件到当时的状态**。想比较两套代码方案，应配合 Git 分支或工作树。

### 查找归档与删除

用聊天搜索查找历史内容；可重命名任务，方便以后定位。完成的聊天可以归档，之后在“设置 → 已归档的聊天”恢复。

删除聊天前请阅读确认框，尤其是连同分支删除及停止运行中的任务等影响。当前会话回收站支持在 30 天内恢复；永久删除及过期清理不可当作备份。聊天回收站与剪贴板回收站的保留规则不同。

需要保存可独立阅读的记录时，使用任务的导出入口生成 HTML。分享前检查其中的聊天内容、工具输出和路径。HTML 导出用于阅读，不是完整迁移备份。

## 项目与文件

### 选择工作目录

项目是本机文件夹，聊天围绕它开展工作。新建聊天前核对项目和工作树；打开已有聊天时，注意它原来绑定的目录。

文件面板按已允许访问的项目及工作目录提供文件浏览。某个路径打不开时，先确认文件是否存在，以及对应目录是否已作为项目加入。文件浏览范围不应理解为所有 Agent 工具的操作系统沙箱。

### 编辑和预览

1. 打开文件树或按 `Ctrl+P` 搜索文件。
2. 点击文件，在右侧标签中打开。
3. 文本文件可编辑；Markdown 和 HTML 可以查看源码及预览。
4. 手动修改后保存，查看保存状态再关闭或进行其他操作。
5. 有改动时，用“上一处改动 / 下一处改动”跳转检查。

切换标签会保留各文件的未保存草稿和浏览位置，但未保存草稿不等于磁盘文件。让 Agent 继续修改同一个文件前，先处理手动编辑，避免两边基于不同内容工作。

ArkTS、TypeScript 和 JavaScript 支持定义跳转、补全等能力；语义服务不可用时会显示基础模式。ArkTS 语义服务依赖本机 DevEco Studio。

### 检查 AI 修改

打开本轮结果或改动审阅，逐个检查修改的文件和差异。查看实际新增、删除和替换的内容；需要验证时，让 Agent 运行项目已有的相关检查，或在终端自行运行。

“AI 已回复完成”与“测试全部通过”是两件事。未执行的检查、安装验证及设备验证，应保留为未验证状态。

## Git 与工作树

### 审阅提交和推送

在 Git 仓库项目中打开改动审阅面板。

1. 核对当前目录和分支。
2. 查看每个文件或区块的差异，选择要暂存的内容。
3. 填写能说明实际改动的提交信息，提交暂存内容。
4. 推送前核对远程仓库、目标分支和认证状态。
5. 若远端已有新提交，先同步并处理冲突，再验证及推送。

提交保存在本地 Git 历史；推送才会更新远程仓库。无项目或非 Git 目录不会具备相同的审阅和分支操作。浏览器方式的 GitHub、GitLab、Gitee 授权还依赖部署方配置授权服务，详见[授权服务说明](../services/git-oauth/README.md)。

### 用工作树同时处理不同分支

工作树是同一仓库中另一个分支的独立工作目录。它适合让两个任务各自修改文件，同时仍归属于同一项目。

1. 选择 Git 仓库根目录。
2. 从工作树入口选择“新建 worktree…”，填写分支名。
3. 切换到生成的目录，再创建对应任务。
4. 完成后先确认改动已保存或提交，再移除不需要的工作树。

已有分支可复用，不存在的分支会新建。工作树默认位于仓库旁的 `<仓库名>-worktrees/` 下。移除脏工作树会提示确认；移除工作目录不等于删除分支。

多个 Agent 即使处于不同聊天，若使用同一个工作目录，也会看到和修改同一份文件。需要隔离改动时，应明确选择不同工作树。更多行为见 [Worktree 指南](worktrees.zh-CN.md)。

## 终端

右侧加号打开终端，也可使用命令面板。终端中的命令在标签对应的本机目录执行。运行前看提示符确认目录，尤其是在切换项目或工作树后。

Windows 优先选择随包或已安装的 PowerShell 7。在终端设置中可选择检测到的 Shell，也可以新建其他 Shell 的标签。更改默认 Shell 只影响新标签，已有标签保留原配置。

常用 PowerShell 操作：`↑` / `↓` 翻阅历史，`Ctrl+R` 搜索，`Tab` 补全，行尾 `→` 接受可用的历史建议，`Ctrl+C` 中断当前命令。

手动交互终端与 Agent 的命令工具分别运行。Agent 命令有超时与交互检查；需要长期运行的开发服务时，明确说明后台运行方式，或在交互终端中手动启动。修改 Agent Shell 默认超时可在设置里搜索“命令超时”。

## 浏览器

### 独立浏览

在右侧打开浏览器，输入网页地址。它适合手动检查网页和项目页面，登录资料保存在 Piora 自己的浏览器环境中，不自动继承日常 Chrome 或 Edge 的登录。

### Agent 直接操作右侧浏览器（桌面版）

桌面版默认使用内置浏览器。此时 Agent 打开网页、点击和输入，用的就是右侧这个浏览器里属于当前会话的标签页，面板不用打开，也不会自己弹出。你手动打开面板时，会直接看到 Agent 正在用的页面，之后它的每一步都能实时看到，你也可以像普通浏览器一样点击、输入和滚动。

- 你在面板里切到别的标签后，画面不会被 Agent 抢走，只在 Agent 的标签上显示“Agent 正在操作”。点这个标记、点 Agent 的那个标签，或者关掉面板再打开，就恢复跟随。
- 面板上方的提示条可以暂停 Agent。Agent 操作时你自己点一下页面，它也会自动暂停，从下一步起不再操作，点“继续”交还给 Agent。
- 遇到登录、验证码、两步验证、支付或账号安全页面时，Agent 会停下来，在对话里显示一张卡片。点“打开浏览器”在右侧完成操作，再点“我已完成，继续”；点“取消”则让 Agent 放弃这一步。最多等 15 分钟。
- Agent 不会代你输入密码。执行页面脚本前每次都要你确认；有密码框或像登录、支付、账号安全的页面会直接拒绝执行。
- 在右侧登录过的网站会保留登录状态，重启 Piora 后仍然有效。以前后台浏览器里的登录不会迁移过来，需要在右侧重新登录一次。

### 后台浏览器模式与网页版

在“设置 → 通用”打开“使用后台浏览器”，或者在网页版里使用时，Agent 仍使用独立的无头浏览器。打开“跟随 Agent 浏览器”可以查看它的只读画面；关闭跟随后回到独立浏览。这种模式下 Agent 的页面和登录状态与右侧浏览器互不联动，遇到登录时也无法在浏览器里接手，Agent 会在对话里说明。

Agent 后台浏览器需要可用的 Chrome、Edge 或相应运行环境。无法启动时先看错误提示与网络代理配置，再检查本机浏览器安装情况。

## SSH 远程工作台

### 建立连接

1. 在右侧加号选择 SSH。
2. 填写主机地址、端口、用户名，选择密码或私钥认证；加密私钥还需要口令。
3. 点击“测试连接”。测试成功只表示认证成功，不会打开终端或关联 AI 任务。
4. 正式连接，核对主机身份，再开始操作。
5. 需要重复使用时保存主机，并给它一个清楚的名称。

桌面端使用系统安全存储加密凭据。网页模式或系统加密不可用时，需要先设置主密码；忘记主密码无法恢复已有密文。

### 远程文件与 AI 任务

连接后可使用远程终端和 SFTP 文件浏览，上传或下载文件。多台主机会保留为独立标签；执行命令前检查当前主机。

让 Agent 操作主机前，在 SSH 面板核对与当前任务的关联。当前任务的活动连接可以被 Agent 的 SSH 工具使用；只保存但未连接的主机不会自动连接。**本地终端仍然执行本地命令。**

关联期间，远程终端输入由 AI 独占；想手动输入时先解除关联。“停止命令”会关闭该主机的 Shell，保留输出，之后需重新连接。服务重启后也需要重新建立连接。

界面示例及更多连接行为见 [SSH 工作台](SSH_WORKBENCH.md)。

## 多 Agent 协作

多 Agent 群聊默认是自由对话。成员可以是写作搭档、研究助手或你自定义的角色，不必先安排负责人、执行者和审查者。

1. 在“群聊”入口选择“新建群聊”，使用默认的“自由群聊”，填写成员名称；成员设定可以描述擅长领域、性格和说话风格，也可以留空。
2. 直接发消息让成员判断谁来回应，或用 `@成员名` 指定回复者，用 `@所有人` 征询全体意见。回复某条成员消息会继续交给原作者。成员会使用自定义设定和近期群聊上下文，必要时直接 @ 其他成员交接；自动交接达到轮数上限后会停止。
3. 在成员面板点击“添加成员”可直接进入成员设置。新成员共享群聊当前工作目录，不会自动创建 Git 工作树。
4. 托管成员会话只保留在群聊内，不额外占用聊天列表或生成侧边栏项目；高级选项中复用的已有聊天仍保留。
5. 需要固定分工、计划和审查时，可在创建时选择“任务编排（高级）”，或在设置中启用协调者编排。固定职责、模型和工作区策略位于高级设置。

例如，可以让一个成员实现功能、一个成员检查交互、另一个成员审查改动。职责中说明各自负责的文件，减少同时修改同一文件的冲突。

运行中的成员不能换绑会话或移除，应先停止或等任务结束。并发任务会增加模型调用量；共享目录不隔离文件，修改同一项目时需避免覆盖。高级任务模板仍可创建独立工作树；Windows 检出启用 Git 长路径支持，若文件路径仍超限，请改用共享目录或缩短项目路径。详细规则见[多 Agent 协作说明](multi-agent-collaboration.md)。

## 定时任务

定时任务让一段说明周期执行，例如每天检查项目状态或持续跟进一项工作。执行依赖本机 Piora 进程，电脑休眠、关机或应用完全退出后不会继续运行。

### 创建和验证

1. 先打开目标聊天或选择项目，再进入“设置 → 定时任务”，选择“新建”。
2. 填写名称与任务说明，明确每次检查什么、输出什么，以及需要通知的条件。
3. 选择“现有聊天”或“新建项目任务”，核对目标聊天或项目。
4. 选择重复频率，核对时区；中国大陆通常使用 `Asia/Shanghai`。
5. 设置通知方式和启用状态，保存。
6. 核对“下次运行”，用“立即运行”验证一次，再检查运行历史。

| 运行方式 | 适用情况 |
| --- | --- |
| 现有聊天 | 需要沿用当前讨论、持续跟进同一事项 |
| 新建项目任务 | 每次希望产生单独的任务记录 |

通知可选择重要更新、每次运行、仅运行失败或关闭。需要停止后续调度时暂停任务；不再需要时删除。删除调度会保留已经产生的聊天记录，处理当前运行仍应查看其状态。

建议先用界面预设频率。自定义 RRULE 适合熟悉日历重复规则的用户，保存后务必检查下一次触发时间。不要把任务说明中的“每天”误认为已经设置了执行频率。

## 技能插件与扩展

### 先分清用途

| 名称 | 作用 | 常见操作 |
| --- | --- | --- |
| 技能 Skills | 给模型提供某一类任务的说明和流程，也可能附带脚本资源 | 发现、安装、启停、更新 |
| 插件或 Pi 资源包 | 分发扩展、技能、提示词等资源 | 安装、更新、启用、卸载 |
| 扩展 | 为运行时增加工具或行为 | 查看来源、启用或禁用、重载会话 |
| 能力包 | 导出和导入一组能力配置及资源 | 在自己的环境或团队之间迁移能力 |
| 项目工具 | 管理模型在当前上下文可用的工具 | 启用工具、调整可见性和资源访问 |

安装资源不等于已安装它依赖的程序或已登录外部服务。导入的代码和脚本可以按本机运行权限工作，应先确认来源和用途。

### 发现和安装技能

1. 进入“设置 → 技能 → 发现”。
2. 搜索技能，阅读说明、原始 `SKILL.md`、文件和依赖。
3. 选择全局安装，或在有效项目下选择项目安装。
4. 在“已安装”中确认结果及对模型可见的状态。
5. 新会话会加载安装结果；已有会话等空闲后按提示重载，或使用 `/reload`。

全局技能可供多个项目使用；项目技能跟随指定项目。同一作用范围的同名技能不会直接覆盖。更新时若本地内容被修改，会阻止覆盖，应先处理这些修改。

### 添加来源和管理资源

在“来源管理”启用内置来源，或添加 Git 仓库、兼容技能市场。添加来源只让它参与搜索，不会自动安装全部技能。需要凭据的来源，填写后测试连接并保存；普通网页地址不能当作市场 API 地址。

插件在“设置 → 插件”管理；扩展在“设置 → 扩展”核对来源并启停。空闲当前会话会尽可能重载；忙碌会话应等运行结束，再按提示应用变更。

在“设置 → 能力包”导出当前能力，或预览后导入别人提供的包。能力包不替代完整应用备份。技能来源和更新规则详见[技能来源说明](skill-sources.md)。

## MCP 外部工具

MCP 用于连接外部工具服务。当前源码提供 Pi 原生 MCP，支持本地进程 `stdio` 和远程 `Streamable HTTP`。较旧安装版可能没有此入口。

### 配置连接

1. 打开普通任务，再进入“设置 → 插件”的“Pi 原生 MCP”。
2. 启用原生 MCP 连接，在“配置服务器”中填写名称与范围。
3. 按服务器提供的接入说明填写严格 JSON 定义。本地服务需要本机存在对应命令及依赖，远程服务需要正确 URL 和认证信息。
4. 保存后按提示重载当前任务，刷新服务器状态。
5. 服务需要 OAuth 时点击“登录”；连接异常时查看原因并重新连接。
6. 点击“查看项目工具”，逐项启用所需工具；访问服务器资源还需单独启用资源访问及相应辅助工具。

**连接成功并不自动授予模型调用权限。** 只显示“已配置”时也不能当作连接成功；打开常规任务后查看实际状态。

### 工具暴露与范围

| 暴露方式 | 含义 |
| --- | --- |
| 直接暴露 | 工具直接加入模型可见的工具声明 |
| 按需发现 | 通过发现机制在需要时查找工具 |
| Codemode | 通过脚本调用工具 |
| 隐藏 | 工具不可用 |

**配置范围**：从 `0.5.5-beta.20` 起，服务器卡片支持选择“全局默认”或“仅此项目”、创建项目覆盖及恢复全局继承。全局修改不会覆盖已有项目覆盖，卡片会显示当前生效值。旧安装版没有这些按钮时，请先更新到包含该功能的版本。

若项目范围不可选，按界面的 Pi 项目配置前置条件处理，或使用适合的全局配置；此页面不提供项目信任授权。旧 MCP adapter 与原生 MCP 配置独立，迁移后需要重新核对连接和工具状态。

## 语音听写

语音听写把麦克风输入转换为聊天文字。Windows 桌面包内置 SenseVoiceSmall INT8 和 sherpa-onnx；其他运行形式按语音设置显示的资源状态处理。

1. 进入“设置 → 本地语音识别”，开启本地听写，确认识别资源可用。
2. 允许系统或浏览器访问麦克风。
3. 在聊天中点击语音入口，或按默认快捷键 `Ctrl+Shift+M`。
4. 按界面提示结束录音，检查识别文本后发送。

语音识别在本机进行；发送识别文本到模型后，按所选模型服务的规则处理。聊天听写与向鸿蒙手机注入测试语音是两种功能。

## 鸿蒙设备

鸿蒙工作台支持连接 HDC 设备、观察手机画面、截图与录屏，以及通过 AI、应用和测试工具执行操作。支持程度取决于手机、系统及工具链，参阅[兼容性说明](harmony/compatibility.md)；某项软件检查通过不代表整套设备功能已通过真机验证。

### 首次连接

1. 在手机开启开发者选项和 USB 调试，连接电脑，并在手机确认授权。
2. 打开右侧设备面板，选择 HDC 和目标手机。多台设备时核对选中的设备。
3. 在“设备设置 → 连接诊断”检查状态，手动解锁手机。
4. 需要初始化投屏服务时，先准备 HarmonyOS API 26 SDK，通过 `devecocli auth login` 完成 DevEco 开发者登录。
5. 明确点击“初始化投屏服务”，等待设备调试 Profile、本地签名、验签和安装完成。缺失工具链、登录或设备绑定时，按错误提示补齐后重试。
6. 如界面要求启用实时视频，在手机上完成屏幕共享授权。

随包投屏组件需要为当前设备生成适用的签名副本；不能把 unsigned HAP 直接当作可安装文件。只打开面板观看不会自动安装服务、唤醒或解锁手机。

### 看画面和操作手机

投屏画布只读：点击、长按、拖动和键盘输入不会发送到手机。缩放和拖动只改变观看范围。需要操作手机时，从 AI、应用或测试工具发起。

截图和录屏可以在持续投屏及 AI 任务期间使用。默认 `Alt+Shift+S` 在可见且可用的设备面板截图；输入框、终端、弹窗和输入法编辑会保留原按键。

华为手机录屏时优先使用系统自带录屏：停止后 Piora 从手机图库找到这段录屏并传到电脑，手机图库里的原文件会保留。如果 Piora 无法确认系统录屏是否已开始，会提示你在手机上手动停止录屏，再点“我已停止，取回录屏”；也可以点“放弃取回”，录屏仍保存在手机图库，可以手动导出。其他设备沿用投屏视频流录屏，需要手机上的 Piora 投屏已开始共享。华为系统录屏尚未经过真机验收。

通过底部“工具”打开应用、测试、语音、日志或记录。应用可以按名称或包标识搜索；测试中先选应用和场景，核对步骤与验证内容再运行，最后在记录里查看成功、失败和未执行步骤。

已通过 HDC 连接的设备动作不再逐次请求应用范围授权或单次批准。让 AI 操作前把目标应用与允许的动作说清楚，安装、卸载、清除数据等任务尤其需要明确目标。

### 停止与恢复

设备忙碌时等待当前任务完成，或停止对应任务。若提示正在停止、恢复中或输入释放不确定，先检查手机实际状态，再按诊断提示处理。不要仅因等待了一段时间就重复执行动作。

“重试视频”用于恢复观看连接，不会替你安装组件或解锁手机。截图、录屏保存失败时，查看记录中的实际保存状态和路径。

手机语音测试需要先完成音频检查与校准，并以手机实际识别结果验证。配对信息填入专用表单，不发送给模型。进一步操作见[首次连接](harmony/quickstart.md)、[控制与停止](harmony/controls.md)、[语音输入](harmony/voice-input.md)及[故障处理](harmony/troubleshooting.md)。

## Windows 电脑控制

Windows 桌面版提供电脑控制，可让 Agent 操作本机应用。进入“设置 → 扩展”中的“电脑控制”，点击连接，分别检查 UIA 和 Windows-MCP 的状态，再在任务工具列表启用 `computer_control`。

UIA 优先使用应用控件进行读取、点击、输入和滚动。需要视觉定位的操作还依赖视觉模型和 Windows-MCP；Windows-MCP 需要本机安装 `uv`，首次连接会下载运行环境。

连接后，在任务中说明要操作的应用、目标和完成标准。需要停止时使用电脑控制的停止入口，再检查目标应用是否已发生变化。停止和超时后不会自动重放可能已经生效的操作。

该功能不能操作锁屏、UAC 安全桌面或权限高于 Piora 的应用。若某个后端未连接，先处理其具体错误，不要仅凭另一个后端就绪认为所有操作都可用。

## 随身舱与剪贴板

### 常用小工具

随身舱提供快捷访问、待办、专注时钟、JSON 工具和 Markdown 中转站。默认 `Ctrl+Space` 打开随身舱，可在快捷键设置中修改。部分界面使用“随身仓”名称，指同一功能区域。

### 常用文件、文件夹与快捷方式

工具台首页直接显示已添加的位置，包括未置顶的目录和快捷方式，并跟随快捷访问管理页的顺序；调整顺序后自动保存，不再显示成功提示条。搜索框支持按名称或完整路径查找收藏，匹配的快捷访问始终排在应用、系统设置和其他工具之前，也不受最近使用影响。左侧“快捷访问”可选择文件、文件夹、快捷方式（如 `.lnk`、`.url`），也可手动输入绝对路径；每项菜单提供打开、定位、复制路径、改名、修改路径、置顶、排序和移除。移除只删除快捷入口，原文件保留。

首次使用会提供下载、桌面、文档等默认位置，Windows 还提供 hosts。用户移除默认入口后不会自动恢复，可在列表底部重新添加。收藏独立保存在本机桌面用户数据目录的 `quick-access.json`，切换项目不影响列表；路径失效后可修改路径恢复。

目录使用系统文件管理器打开，文件交给系统默认应用，快捷方式交给系统启动并保留其目标和参数。Windows 文件选择框保留 `.lnk` 本身的路径。Windows hosts 使用记事本打开；需要保存修改时，从菜单选择“以管理员身份编辑”并处理 Windows 授权提示。取消授权可返回继续使用，Piora 的打开提示只表示已请求启动编辑器，不表示修改已经保存。网页模式不支持打开本机收藏。

Markdown 中转站支持文件标签、源码编辑、自动保存、草稿恢复、导入导出及图片插入。编辑后注意保存状态；出现草稿未保存提示时，先导出或复制需要保留的内容。

可选桌宠以独立透明窗口显示任务和专注状态。在相关设置中选择、导入兼容素材并调整显示。桌宠显示状态不替代聊天里的真实执行结果。

### 剪贴板记录

桌面剪贴板功能在开启记录后收集支持的文字、富文本、图片和文件引用。可以按类型控制记录、排除来源应用或暂停收录；数据不会自动发送给模型。

| 入口或操作 | 效果 |
| --- | --- |
| `Ctrl+Alt+V` | 打开独立快捷弹窗 |
| 随身舱中的剪贴板入口 | 打开管理界面 |
| `Enter` 或双击 | 粘贴选中内容 |
| `Shift+Enter` | 以纯文本粘贴 |
| `Ctrl+C` | 复制选中内容 |

自动粘贴只向确认过的目标窗口发送粘贴操作，不会发送回车执行命令。目标窗口失焦或输入受阻时，按提示手动粘贴。非 Windows 平台按实际能力提供功能。

管理界面支持搜索、收藏、备注、编辑副本、多选合并和屏幕暂存。未完成的正文或备注编辑可在“未完成的编辑”中恢复；确认已保留到本机后再退出。

### 容量与归档

默认内容预算为 1 GiB，达到 90% 时提醒，不足时暂停新增，不会为了腾空间自动删除历史。调整预算或清理后，再检查记录状态。剪贴板回收站保留 7 天；数据库、索引等占用另行显示，内容预算不等于全部磁盘用量。

“更多操作”支持导出历史和合并导入。独立剪贴板归档未加密，未完成编辑草稿不包含在历史归档中；完整应用备份则使用密码加密并纳入剪贴板快照。

出现“重新连接存储”时先重连，再核对最近记录。故障期间不会自动补录系统剪贴板中的旧内容。更多细节见[剪贴板说明](clipboard-history.md)。

## 外观与快捷键

在“设置 → 外观与界面”调整主题、字体、背景和透明度。背景可使用内置资源或支持的本地图片。背景影响文字阅读时，提高遮罩或降低透明度。

在“设置 → 对话与输入”调整发送方式、输出自动滚动和完成通知。通知默认需要主动开启，网页模式还需要浏览器允许通知。

“快捷回复”可从助手回复中提取选项，默认关闭，需要单独配置提取模型。点击气泡只把文字填进输入框，仍需自己发送；提取及测试会调用模型。

在“设置 → 提示词与标题”管理系统提示词、提示词优化和标题模型。辅助功能的模型选择与当前聊天模型分别保存，不应只检查输入框里的模型。

## 数据备份与迁移

### 完整备份

1. 等待运行中的任务完成，保存正在编辑的内容。
2. 打开“设置 → 数据与诊断 → 完整备份与迁移”。
3. 设置至少 8 个字符的备份密码。
4. 点击“导出全部应用数据”，等待生成 `.piora` 文件。
5. 确认文件下载完成，妥善保管文件和密码。大型语音资源可能使备份需要数分钟。

加密备份覆盖模型配置与凭据、会话、随身舱、桌面剪贴板历史与暂存、插件资源、应用设置、草稿、自定义背景和已下载语音包。**项目源码不在备份中**，需要用 Git 或文件备份单独保存。浏览器登录和系统集成在新电脑上可能需要重新授权。

### 在另一台电脑恢复

1. 安装适合的 Piora 版本，并准备需要恢复关联的项目目录。
2. 进入完整备份页面，输入原备份密码，选择“导入迁移备份”。
3. 等待密码、完整性及文件校验通过，检查备份日期和内容概况。
4. 原项目路径不同的，填写新电脑上实际存在的项目文件夹；留空会保留原路径。
5. 确认后“导入并重启”。当前应用数据会保留为独立恢复副本，备份内容在重启时恢复。
6. 重启后检查会话、模型和项目关联，并重新验证外部服务及系统集成。

若未自动重启，完全退出后再打开；网页模式需要重启服务进程。密码错误、校验失败或提示任务仍在运行时，先解决原因，不要把“备份准备好”当作恢复完成。

### 偏好导出与数据目录

同一页面中的旧版 JSON 导出只包含界面偏好，不包含凭据或会话，不能替代完整备份。

默认常见位置如下；实际目录以设置显示为准：

| 位置 | 内容 |
| --- | --- |
| `~/.pi/agent/sessions/` | 聊天记录和分支上下文 |
| `~/.pi/agent/settings.json`、`models.json`、`auth.json` | Pi 设置、模型及认证资料 |
| `~/.pi/agent/piora/` | Piora 偏好、协作、定时任务等数据 |
| Windows `%APPDATA%\Piora` | 桌面配置、浏览器资料、草稿及日志等 |

Windows 的 `~` 通常指 `%USERPROFILE%`。便携版默认也会使用用户目录。

需要调整 Pi 数据存储位置时，在数据设置中填写或选择目标目录。保持“将现有 Pi 数据复制到新位置”关闭，执行“切换并重启”，即可直接使用目标目录中的已有数据，适用于接入手动复制的数据目录；如需复制当前数据，请选择专用空目录，打开该开关，再执行“迁移并重启”。新旧目录不能互相包含，旧目录会保留。该操作调整 Pi 数据目录，不等于迁移所有桌面数据或项目源码。

如果位置由 `PI_CODING_AGENT_DIR` 环境变量管理，设置页不能覆盖，需调整该环境变量后重启。换电脑时优先使用完整备份，避免遗漏分散保存的数据。

## 更新与退出

安装版可按应用内更新提示操作，在应用行为设置中管理更新计划。先保存工作、等待任务结束，并阅读“本次更新”。便携 EXE 和目录版按发布说明手动替换程序；目录版不要混用不同版本的程序文件。

Beta 用于预览变化，功能和兼容范围可能不同于稳定版。选择版本时查看对应发布说明，不要将仓库中的未来版本或构建候选当作正式发布包。

关闭主窗口通常会收起到托盘；完全退出使用托盘菜单。完全退出、关机和休眠会影响后台 Agent 及定时任务，关闭窗口与停止任务应分别检查。

## 连接外部客户端

“设置 → 远程控制”用于给外部客户端提供受令牌控制的本机接口，与 SSH 远程主机连接是不同功能。普通聊天无需配置它。

1. 根据客户端要求创建有名称的能力令牌，选择必要权限。
2. 如需新建会话，选择允许的会话模式，填写已存在的工作目录。
3. 如需访问当前会话，显式勾选对应授权。
4. 复制只显示一次的令牌，将设置页显示的服务地址与身份信息填入可信客户端。
5. 不再使用时撤销令牌。

工作目录限制只约束新建会话，不是 Agent 文件系统沙箱。令牌可能允许读取聊天或发送任务，应按用途授予权限，不要把本机接口直接暴露到公网。详细接入方法见[外部客户端接口说明](remote-http-api.zh-CN.md)。

## 常见问题

| 现象 | 先检查什么 | 下一步 |
| --- | --- | --- |
| 模型列表为空 | 是否配置服务、完成认证并启用模型 | 测试连接，核对自定义模型 ID 与地址 |
| 认证失败或额度不足 | API Key、登录状态和服务商账户 | 更新认证或处理额度；不要持续重复发送 |
| 一直等待或频繁重试 | 最近工具、错误信息、网络代理 | 查看运行策略；必要时停止后换模型重试 |
| 压缩失败 | 当前模型的连接和上下文配置 | 保存错误，核对模型设置后重新压缩 |
| 发送后草稿消失或状态待确认 | 聊天中是否已有对应消息、草稿是否恢复 | 等状态确认，避免重复提交；保留原文 |
| 切换分支后文件没有恢复 | 切换的是聊天分支还是 Git 分支 | 用 Git 差异核对；聊天分支不回滚文件 |
| 文件打不开或路径不见了 | 当前项目、工作树和文件是否存在 | 重新选择正确项目，检查文件是否移动 |
| 技能装好但没有生效 | 安装范围、启用状态及依赖 | 等当前任务空闲后重载或新建会话 |
| MCP 已连接却不能调用 | 项目工具是否启用、是否允许资源访问 | 在项目工具中逐项检查并核对重载提示 |
| Agent 没有使用浏览器登录状态 | 是否开启了后台浏览器模式，或者在网页版里使用 | 桌面内置浏览器模式下，在右侧登录后 Agent 可直接使用；后台浏览器模式和网页版不共享右侧的登录 |
| SSH 测试成功但 AI 找不到主机 | 是否已正式连接并关联当前任务 | 核对主机标签及任务关联 |
| 定时任务没运行 | 应用是否运行、是否休眠、任务是否启用 | 核对时区和下次运行，再查看历史或立即运行 |
| 听写没有内容 | 麦克风权限、输入设备、识别资源 | 检查语音设置和系统录音输入 |
| 鸿蒙设备未授权 | 手机 USB 调试授权和解锁状态 | 在手机确认授权，再运行连接诊断 |
| 点击投屏没有反应 | 是否期望直接控制手机 | 画布只读，从 AI、应用或测试工具发起操作 |
| 投屏初始化失败 | DevEco 登录、API 26 SDK、Profile 和设备绑定 | 按诊断补齐；不要直接安装 unsigned HAP |
| 剪贴板不新增记录 | 记录开关、排除规则、容量与存储状态 | 恢复记录、调整预算或重新连接存储 |
| 备份失败 | 任务和编辑是否仍在改变数据、密码与空间 | 停止编辑后重试，确认最终文件生成 |
| 程序黑屏或无法启动 | 是否下载正确平台且完整解压 | 完全退出后重开，保存日志并反馈，勿删除会话目录 |

### 提交有效的问题报告

打开“设置 → 数据与诊断 → 运行日志”，复制实际日志路径或打开文件夹。无法进入界面时，可先检查 Windows `%APPDATA%\Piora` 下的日志目录。

向 [GitHub Issues](https://github.com/kexijiang/Piora/issues)反馈时，提供：Piora 版本、系统版本、安装形式、重现步骤、预期结果、实际结果和相关错误。设备问题另外写明机型、系统及 HDC/SDK 情况。

截图和日志发送前删除 API Key、令牌、私人路径、聊天及文件内容。涉及安全漏洞时使用[安全问题报告渠道](../SECURITY.md)。

## 常用任务示例

可以复制以下任务，并替换其中的项目、文件或主机信息。

**了解项目**

> 阅读当前项目，说明用途、启动方法和主要目录。列出判断依据，先不要修改文件。

**修改并验证**

> 修复登录页在窄窗口下按钮被遮挡的问题。先定位原因，再修改相关文件，运行已有的相关检查，最后说明改了什么及哪些内容尚未验证。

**整理资料**

> 阅读我附上的会议记录，整理决定、待办、负责人和待确认事项。未出现的负责人不要猜测。

**远程排查**

> 使用当前任务已关联的测试主机，检查磁盘和应用日志，说明可能的故障原因。先只读检查，不重启服务或删除文件。

**周期检查的任务说明**

> 检查当前项目新增的问题和上次遗留项，记录本次变化。仅在出现新问题、状态变化或需要我处理时通知；没有变化时保持安静。

最后一例填写到定时任务的“任务说明”，还需要在界面单独设置频率、时区和通知方式。
