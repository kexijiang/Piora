# 聊天工具权限

输入框底部可选择请求批准、帮我批准或完全访问，并保留“操作前询问 · 严格兼容”。请求批准与帮我批准使用相同审批边界，前者由用户审批，后者由独立模型调用审核。手动选择会同时保存为后续新聊天的默认模式，与设置 > 通用保持同步，未保存过偏好时初始为完全访问；已有的手动选择不会被覆盖；未发送首条消息时选择也会立即保存，重启后保留。保存失败会显示错误。审核流程、预算和限制见[独立审核说明](tool-review.md)。

权限记录使用 `schemaVersion: 2`，与单调递增的权限 `revision` 分开管理。旧 `auto` 保持人工审批（现称请求批准），旧 `ask` 保留严格行为；新增 `review` 只接受用户明确选择后写入的 v2 记录，未知版本失败关闭。

权限按聊天 ID 保存在 `<agentDir>/piora/tool-permissions/<sessionId>.json`，不随历史分支回退，不受 AgentSession 空闲回收影响。分叉及复制聊天使用当前的新聊天默认模式，不继承父聊天的完全访问。旧聊天没有记录时显示旧版兼容权限：普通工具保持原行为，桌面浏览器脚本仍逐次确认。用户选择任一模式后结束兼容行为。仅打开或恢复已有聊天不会修改默认值；一次批准不改变默认值，审批弹窗中明确开启完全访问并设为默认会保存选择。

统一入口在 SDK ExtensionRunner 的最终 tool_call 分发之后判断，覆盖模型直接调用和工具通过 SDK 调用的子工具；扩展对参数的修改先于判断，已有阻断不会被完全访问覆盖。运行时重载会重新安装入口。

文件读取和搜索只有在工具来源可靠、真实目标处于当前工作目录内且不属于敏感路径时才能免审；请求批准/帮我批准额外允许满足相同条件的文件修改和无凭据、无查询参数的 HTTP(S) 新页面导航。敏感配置、符号链接越界、Shell、任意脚本、页面交互及未知工具进入审批。完全访问跳过工具审批，不跳过普通扩展提问、用户接管或执行正确性检查。这是应用级审批机制，不是文件系统沙箱或恶意扩展隔离。

人工权限审批携带独立的 toolApproval 标识，并使用已有请求 ID、SSE、取消和超时机制。批准绑定具体运行、工具调用、最终参数、权限版本与关键证据，变化后重新判断。模型硬拒绝停止本轮自动执行并使待处理批准失效。脱敏审核记录持久化，重连只恢复状态，服务重启不重放旧批准。开启完全访问不回答其他普通问题，也不恢复已经停止运行的旧批准；已执行的操作不承诺回滚。

桌面浏览器执行 JavaScript 仍检查标签页归属和导航令牌。显式权限模式下由统一入口审批；完全访问可通过敏感页面脚本检查，桌面进程直接读取同一份持久化记录，模型不能提供 full 标志。密码输入、验证码及用户接管流程不自动完成。

新增工具默认按未知操作处理；需要免询问时应为其结构化动作建立明确分类并补充测试，不能仅凭工具名称推断外部副作用。
