## 1. 产品目标与调整结论

让用户用自然语言获得能操作、能恢复、能继续讨论的交互答案。简单任务沿用第二阶段组件；复杂任务生成独立小程序，承接过程演示、空间操作、动态列表、模拟、游戏和三维教学。Beta 设置仍是总入口，整个项目仍分三个阶段。

**保留已有基础，把剩余工作组织成可验证的完整任务。** 每批都要交付生成、操作、结果核对、保存、恢复和追问，不能把渲染出画面当作任务完成。本版接替 v3.6；历史方案和报告保留，不修改历史结论，也不缩减第三阶段复杂交互范围。

### OpenIntelligentUI 的价值与边界

本地参考固定为提交 8391a94c1c3939c679e40ddd7bfc08a9ef690e70。源码支持自由 HTML/CSS、共享设计系统、CSS 完成后的渐进预览和经校验的宿主桥接；最终 iframe 可以运行生成脚本。任意控件状态不会自动进入 agent，进程内检查点也不等于持久交互状态。[R1]

Piora 借鉴回答形式、视觉组织和预览流程；继续使用自己的 AgentSession、Beta 设置、状态和权限。保留“模型计算与宿主渲染分离”，不新增必需的 Jev/LangGraph 服务。相比直接运行网页脚本，这条路线需要维护图形与事件协议，代价是更多适配开发，收益是可保存、可核对和可控制的执行边界。参考项目为 MIT；本次未复制代码，后续若复制须保留许可与来源。

## 2. 独立架构与触发判断

```text
AgentSession -> 形式选择 -> MiniAppPlan -> 编译 / 试运行 / 发布
                                      |
                                 MiniAppHost
                           /                 \
                可信文档与图形渲染器       Worker + QuickJS
                           \                 /
                           版本化事件与投影帧
                                  |
                       独立状态 / 追问 / 登记动作
```

普通聊天只依赖通用输出描述、渲染入口和发送前保存接口。组件与小程序分别实现适配器；计算、事件、存储、恢复及迁移不进入 ChatWindow。复用现有会话生命周期与工具权限，不另建一套聊天或审批系统。

Beta 关闭时撤销正在生成或保存的旧请求，历史内容显示最新确认的静态结果；重新开启须重新核对发布身份和状态，旧异步回调不能重新生效。浏览器草稿继续保留，关闭功能不等于删除数据。

### 判断依据进入同一回答轮

给当前回答模型提供用户目标、已知事实、当前分支确认的参数/结果、当前可用能力。公共策略只装配一次，详细契约随相关工具提供；不为每句话额外发起分类请求，也不依赖“画图”“比较”等关键词。

| 上下文中的实际需求 | 行为与例子 |
| --- | --- |
| 一次性答案，操作没有额外价值 | 文字：“480 元六个人分”直接给出 80 元 |
| 缺少决定结果的业务规则 | 澄清：“提成怎么算”缺比例与阶梯规则，先问必要信息 |
| 改参数、比较结果，现有组件足够 | 组件：“人数和费用我想改着看”提供数字框及联动结果 |
| 推进过程、操作空间对象或自定义状态 | 小程序：“让我一步步看排序”“拖动顶点看角度” |
| 解释刚才结果或修改已有条件 | 使用最新确认状态解释；只有规则或交互改变才修订程序 |
| 缺少数据或执行能力 | 说明限制，选择可完成的部分；示例数据必须标明，不能伪装真实结果 |

实现上继续由模型选择回答或工具，宿主校验能力、来源和预算。保存实际选择、策略版本、关联输出、修订关系和错误作为评估记录；若记录选择理由，只保留简短决策标签，不索取或保存内部推理。离线判断误触发、漏触发及上下文误用，不能只统计工具调用率。尊重“只要文字”等明确偏好。

### 能力清单成为共同依据

在输出 catalog 旁增加能力 manifest：ID、契约版本、依赖、视图/事件、预算、完整示例、验证记录及相关源码摘要。ID 按通用能力命名，例如 pointer、repeat、scene-picking，不按“排序题”“倒水题”命名。

planned 仅进入路线图；implemented 可在隔离开发配置验证；verified 且环境支持的能力才向普通 Beta 会话开放。提示、编译接纳与环境检查读取同一份清单。旧程序按原版本加载，不能因新版本失去验证而破坏历史读取。证据随实际依赖摘要失效；验证范围明确区分浏览器、Windows 开发桌面、GPU 与其他平台，单项 verified 不代表每个生成程序正确。

## 3. 生成、视觉与计算契约

### 让模型专注任务内容

组件与小程序保留各自的完整示例和版本说明，全部必填字段通过真实 schema、编译和初始投影校验。宿主分配程序身份、运行时版本和回执；模型描述输入、任务状态、计算、文档与图形，不承担这些内部字段。

现有简单 const 字面量支持、多问题诊断和最多 128 状态的组件边界采样继续维护。诊断最多汇总 8 个独立问题，说明工具、版本、路径和完整重提要求；不静默改公式、单位或输入范围。所有 UI 工具共享现有 3 次接纳尝试、1 次模型纠错及首次 UI 尝试起 60 秒窗口，换工具不能刷新预算。若后续确需调整，由固定版本基线论证。

### 外观由共享设计系统兜底

宿主提供主题、字体、字号、间距、输入框、按钮、焦点、错误与保存状态。模型在受支持的 HTML/CSS 范围内自由组织布局；先有样式，再预览结构，预览不执行程序。正式发布后绑定输入及图形。

数字默认数字框，离散选择使用选项，布尔值使用复选框；仅在有合理边界且连续探索有价值时使用滑块。主要操作靠近相关对象，结果与解释来自同一状态。主题色需扩展到 Canvas/3D 的语义色，避免正文能切深色而图形仍固定浅色。语义色及新布局能力采用版本化扩展，旧字面颜色仍可读取。

### 四个入口保持明确职责

| 入口 | 职责与约束 |
| --- | --- |
| init | 从输入和显式随机源建立初态；恢复已有检查点不重新初始化业务进度 |
| reduce | 处理输入、点击、拖动、按键等有序事件，返回新状态 |
| advance | 推进一个离散步骤或固定逻辑时间步；与宿主单步和播放使用同一语义 |
| project | 把状态投影为文字、文档绑定、Canvas 命令或 3D 场景；不能偷偷推进状态 |

Worker 内 QuickJS 执行任务逻辑，iframe 内可信渲染器处理 DOM、SVG、Canvas 与受限 Three.js。随机源、逻辑时钟及状态显式保存；程序不能直接读取网络、文件、DOM 或 Electron。外部数据先由现有有权限工具获取，再带来源进入程序输入。

### 交互和性能按行为约束

事件绑定实例、显示帧、视口和对象身份。移动可合并，按下、松开、取消和点击保序；队列溢出或过期事件应明确取消手势，不能丢掉一次松开后继续拖动。隐藏、失焦、停止和卸载先释放临时输入，再暂停或结束。恢复默认暂停，不能恢复“物理按键仍按住”的假设；旧程序的 blur 清理若改变检查点，必须作为新的待保存版本，不能静默改写确认状态。

默认仅一个实例持续播放；停止、替换和卸载释放 Worker、图形资源及事件订阅。保持现有资源限额作为初始配置，8ms/步、30fps、32MiB 堆不构成帧率或设备性能承诺。记录队列、步骤耗时、帧大小和资源释放；超限保留检查点并暂停，不通过跳过逻辑步骤伪造流畅。

## 4. 复杂任务的实现办法

每个任务族依赖可复用能力，交付时同时包含真实生成、操作轨迹和独立正确性检查。不能用一个计数器证明模拟，也不能用一个立方体证明三维教学。

| 任务族 | 通用实现与验收重点 |
| --- | --- |
| 算法演示 | state 保存序列、游标、步骤和高亮；按钮与播放共用推进入口。独立核对每步、元素守恒及终态，刷新从当前步骤继续 |
| 几何拖动 | 宿主统一坐标变换、指针捕获及取消；程序保存几何坐标并计算关系。核对角度/距离，覆盖窗口缩放、边界点和键盘替代 |
| 动态列表 | 新增有界 repeat 模板与稳定 key；事件携带对象 key，新增/删除/重排后仍指向正确项目。展开节点计入预算，拒绝重复 key 和过期事件 |
| 持续模拟与小游戏 | 固定时间步、显式 rng、输入状态及碰撞/终态规则。分别验证同种子回放、长时间运行、暂停恢复与实际规则，不只观察动画 |
| 三维教学 | 宿主增加拾取和相机控制；投影中保留稳定对象 ID、场景版本与可选择属性。选中对象、相机和缩放纳入可恢复视图状态，独立核对几何及解释 |

### 需要新增的协议边界

动态列表不开放原始 HTML 拼接；模板由宿主编译，模型仅输出有界数据。列表项 key 的生命周期与任务对象一致，DOM 序号不能当对象身份。先完成普通表单/清单，再复用到带交互对象的列表。

3D 拾取由可信渲染器根据当前场景计算，事件包含对象 ID、场景版本及经校验的位置；旧帧对象不能影响新场景。相机交互由宿主控制器实现，视图状态与任务状态分开版本化并一起保存；投影、鼠标操作和恢复必须有明确优先级，避免镜头每帧被重置。

Canvas/3D 的视觉与可访问性和交互一起交付：语义颜色、文字说明、选中状态、键盘操作、减少动画。图形必须表达任务关系；装饰性动画不能替代结果或教学内容。

### 首批八个任务成为完整链路基线

沿用均分、提成澄清、出行对比、满减、排序、三角形、倒水与棋盘，每例 3 次，共 24 次。沿用原始自然表达；预期形式、轨迹和答案只供评估器使用。

文字/澄清样本核对答案及后续上下文；18 份 UI 样本逐一核对输入变化、关键步骤、终态、保存、刷新与解释追问。未发布样本也留在完整任务分母。首批需要的最小通用能力在 3B 补齐，不能借口属于 3D 而跳过；3D 再扩展到动态集合、持续运行和完整三维等更复杂要求。

八例不是生成白名单。每类检查包含不同表述、参数和边界，完整泛化集合仍为 48 个初始任务，见第 6 节。

## 5. 保存、修订与动作

发布程序不可变；交互状态独立保存 inputs、state、rng、tick、程序版本、stateRevision、视图状态和投影摘要。新字段按版本接纳，不能要求已有历史程序补填。

```text
暂停 / 冻结输入 -> 排空事件与计算 -> 一致检查点
-> 本地草稿 -> expectedRevision 与分支校验
-> 服务端重投影并原子保存 -> requestId 回执 -> 追问读取确认状态
```

| 场景 | 用户可见行为与验收 |
| --- | --- |
| 断网、超时、响应丢失 | 显示待保存并保留草稿；同一 requestId 查回执或重试，确认后只清除对应版本 |
| 保存中继续操作 | 新操作成为下一版；旧回执不能清除更新的草稿 |
| 草稿超过一页、读取失败 | 游标分页可找到全部当前作用域草稿，支持重试；刷新胜过旧分页响应，列表失败不清空本机数据 |
| 多窗口或旧分支 | 校验来源及版本，冲突保留双方供选择；不能使用最后写入覆盖正确状态 |
| fork、复制、导出、回收站 | 继承分支可见的确认状态，之后独立写入；导出静态结果并恢复关联数据 |
| Beta 切换、取消、重载 | 拒绝旧实例回调；读取确认结果并明确呈现尚未处理的本地草稿 |

恢复矩阵必须覆盖这些场景及关键组合；本机浏览器、固定模型桌面与真实模型测试分别标记。通过 UI 操作验证行为，接口或存储直接访问仅用于准备和核对。

### 参数调整与程序修订分开

改人数、速度、点位是当前状态变化；新增规则或改变交互才创建候选版本。复用第二阶段的候选/确认流程，小程序提供自己的兼容性和迁移适配器。

输入迁移检查含义、单位、类型和约束，不只比较字段名。内部 state 默认重新 init；保留进度需要明确、受限且有测试的迁移函数。候选展示保留、重置、丢弃项，用户确认时重新核对来源版本并原子切换。取消、失败或来源已更新时继续保留旧版。组件与小程序互转也遵守这个过程。

### 动作经宿主登记和既有权限执行

本地步骤、拖动和计算不产生外部副作用。继续提问、导出及已支持的真实操作分别登记动作 ID、参数 schema、执行器和结果记录。不要再造平行动作系统，应复用第二阶段 action-contract 与工具审批入口。

动作从宿主可核对的明确用户操作发起，绑定程序、状态版本与动作参数；先完成保存，再交给既有权限层。计时器、加载、模型构造的消息不能取得用户操作凭据。实际工具只执行一次，结果另存回执；失败可以重试，但不能重新执行一个已成功却丢失响应的外部操作。没有回执能力的执行器必须暴露不确定状态，不能承诺普遍“恰好一次”。

## 6. 实施顺序、验收与可行性

3A 至 3E 是第三阶段内部交付顺序，不新增第四阶段。各批提交 Markdown 和 PDF，分别记录代码变化、实际验证、失败、未覆盖和下一步。

| 批次 | 具体成果与退出条件 |
| --- | --- |
| 3A 基础维护 | 保留现有隔离计算/渲染/状态；仅因后续能力扩展升级契约，维护旧版本读取与相关回归 |
| 3B 完整任务基线 | 审查待验证的分页/生命周期增量，接入能力清单，完成八例各三次的全链路与视觉核对；用结果确定修复优先级 |
| 3C 恢复与修订动作 | 完整恢复矩阵、迁移确认、跨输出修订及登记动作；无静默数据丢失、覆盖或重复副作用 |
| 3D 复杂能力扩展 | 动态列表、持续模拟/游戏、完整 3D 拾取/相机/教学；每个能力同时有独立正确性、外观、键盘及资源证据 |
| 3E 综合验收 | 三阶段开发完成后运行完整 CI、封存集和人工语义验收，记录平台限制；发布仍走 GitHub Actions |

### 下一批从哪里开始

- 核对现有草稿分页和输入释放增量，补隐藏、失焦、停止、卸载及恢复后的残留输入验证，形成独立成果报告。
- 为现有能力补 manifest、依赖摘要和验证记录；先验证清单可驱动提示与接纳，不新增一套分类模型。
- 接续首批 24 份原始生成记录，逐份执行完整操作轨迹；代码或生成策略变化时另开固定版本批次，不混算新旧结果。
- 依据真实失败补能力和修复，再完成 3C、3D；不能把失败样本删掉、把复杂任务缩成演示，或无限增加重试。

### 泛化与质量门槛

保留 48 个初始任务：16 小程序、12 组件、12 文字、4 澄清、4 能力缺口。按任务族分成 32 开发、16 封存，每例 3 次；首批八例计入开发集。被看过并用于调试的封存样本移入开发集，同时补入新封存样本。每例包含相关多轮、反例或边界轨迹。

分别统计形式选择、首试发布、预算内发布、结果正确、操作完成、保存恢复、追问一致性、耗时与资源；每个指标声明分母。取消、超时、漏调用、失败保留原始明细。先完成开发集基线，再在封存测试前固定数值门槛；本版不从八例推导总体成功率。静默丢失、错误覆盖和权限绕过是阻断缺陷。

| 自查问题 | 修订后的处理 |
