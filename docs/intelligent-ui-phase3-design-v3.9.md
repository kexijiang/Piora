# 第三阶段可用性与第四阶段可靠性

2026-11-03 · 方案 v3.9 · 用户确认的新阶段边界

## 第三阶段交付可用的 Beta 功能

本版接替 v3.8 的阶段划分。用户明确同意：第三阶段复杂功能达到可用程度即可，系统性的可靠性和泛化放到新增的第四阶段。原有隔离运行、通用回答接口、Beta 开关和权限边界保持；旧报告保留原始结果，不把范围迁移写成缺陷已修复。

第三阶段的完成标准是：代表性任务可以完成主要操作，基本结果正确，能暂停或重置，保存后刷新继续使用；修订、迁移、登记动作和组件互转的主要流程可用。范围为 Windows 开发桌面及已注明边界的真实浏览器流程，交付开发版 Beta，不意味着发布安装包或全平台验收完成。

| 功能 | 第三阶段最低完成证据 |
|---|---|
| 动态列表 | 新增、修改、勾选、排序、删除可用；保存刷新后内容和顺序正确 |
| 算法与二维交互 | 至少一个逐步过程和一个几何拖动任务，基本结果及主要操作正确 |
| 三维交互 | 对象操作、点选、镜头变化、参数复位及保存恢复可用；代表姿态关系正确 |
| 持续模拟／小游戏 | 至少一个连续任务可玩，方向输入、碰撞、计分、扣命、暂停、终局、重新开始和刷新续用正确 |
| 状态与会话 | 普通保存、刷新、追问继续操作可用；已有关键取消、冲突和恢复检查保留 |
| 修订与迁移 | 候选预演、取消、确认及保留进度的主要流程可用 |
| 宿主动作与互转 | 参数读取后明确采用、报告保存，以及组件与小程序双向切换可用 |
| 外观与交付 | 代表任务文字和控件可读、可操作；相关快速检查、用户测试说明和 Markdown/PDF 完整 |

接球游戏若碰撞或计分不工作，仍属于第三阶段未完成。不同说法下偶发生成失败、额外解释误述、广泛任务覆盖和长时间稳定性属于第四阶段。已发现的静默丢失、权限绕过、错误覆盖或阻止主要使用流程的问题不能用阶段迁移关闭。

## 第四阶段接手的工作

| 工作组 | 范围及原有问题 |
|---|---|
| 形式选择与生成稳定性 | 自然表达下选择文字、澄清、组件或小程序；首试成功率、有限重试、不同任务与输入的泛化 |
| 业务语义与解释一致性 | 原 24 例中的排序漏试算、三角形错误建议/键盘说明、量杯提示、棋盘排他性说明；机械臂穿地附加假设和历史变化误述。量杯实例已修好仍需通用复测 |
| 复杂恢复与操作组合 | 多窗口、分支、冲突、取消、响应丢失与修订、迁移、登记动作、互转的组合；不宣称普遍恰好一次 |
| 外观、访问与资源 | 深浅主题、窄窗口、完整键盘/焦点、减少动画、长时间运行、Worker/GPU/订阅释放与性能 |
| 综合验收 | 完整 CI 及历史失败修复、开发集评估、16 个封存任务各 3 次、两人独立语义判断与分歧复核 |

原 48 个任务和失败记录继续保留：32 开发、16 封存，每例 3 次。开发集完成后、封存测试前固定指标与门槛；曾用于调试的封存题移入开发集并补题。第三阶段不再以全部任务稳定通过作为退出条件。

## 验证与文档规则

- 模型固定用户指定的 DeepSeek V4.1 Flash 配置，当前请求为 deepseek/deepseek-flash，不用 Pro 或静默回退。记录实际请求和思考设置。
- 本地按改动运行相关快速检查，保留基础类型、语法与行为验证；完整 CI、封存集和人工验收归第四阶段。既有失败不得写成通过。
- 操作验证使用真实 UI；API/存储用于准备和核对。模型新生成、旧程序重放、宿主夹具和人工验收分开记录。
- 每批记录实现、已执行检查、失败、限制及对应文档/PDF。第三阶段总报告需给出可用能力、用户测试用例和第四阶段待办。
- 禁止开发目录 next build 和本地发布打包。后续发布仍通过 GitHub Actions，仅 Windows x64 NSIS 及其更新辅助文件；本阶段完成不自动授权发布。
