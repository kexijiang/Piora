# Intelligent UI 原始任务复测

这些入口重放已经生成的合成开发样本，用独立预期核对操作和后续回答。它们不替代新生成评估、封存集或人工语义验收，也不加入默认全量测试。

## 选择入口

| 内容 | 入口 | 验证边界 |
|---|---|---|
| 计算、比较组件 | `scripts/verify-recorded-component-tasks.mjs --bindings <json>` | 独立开发桌面的实际输入、保存、刷新和真实模型追问 |
| 有任务状态的小程序 | `scripts/verify-recorded-mini-app-tasks.mjs --bindings <json>` | 实际点击、键盘、拖动、播放、保存、刷新和真实模型追问 |
| 小程序自然语言修订 | `scripts/verify-recorded-mini-app-revisions.mjs --bindings <json>` | 量杯提示修订、取消、过期核对、进度迁移、保存、刷新和真实追问 |
| 直接回答、先澄清再计算 | `scripts/verify-recorded-text-tasks.mjs --bindings <json>` | 复制原始会话后使用生产 SDK、会话包装器及扩展；不启动桌面 |

在本聊天独立 worktree 中运行。桌面重放期间保持 checkout 不变，不同时运行同一 checkout 的交互式 dev launcher，也不要写入其他脚本或文档触发开发服务编译。先等待公共 `result.json` 和进程退出，再继续编辑。临时结果缺失不代表进程已停止。

原始记录及对应的 `agent/sessions`、已发布界面存储必须存在。运行器复制开发夹具到隔离目录，检查原始结果 SHA-256；不要使用私人会话作为公开测试材料。仓库中的脱敏报告不包含完整夹具，不能直接拿报告 JSON 作为运行绑定。

## 普通回答和澄清后的追问

```powershell
node scripts/verify-recorded-text-tasks.mjs --bindings .verification/text-bindings.json
```

绑定格式如下；`source` 和 `sha256` 需要换成自己的真实生成记录与摘要，不能复制示例值作为证据。

```json
{
  "version": 1,
  "thinking": "enabled",
  "cases": [{
    "id": "direct-1",
    "source": ".verification/mini-app-live-EXAMPLE/result.json",
    "sha256": "REPLACE_WITH_SHA256_OF_SOURCE",
    "followup": "如果变成八个人呢？只给结果。",
    "expectedNumber": 60
  }]
}
```

例子的前文是总额 480 元、6 人平分。`expectedNumber` 仅保存在报告中供独立审阅，不发送给模型，也不以“回答中出现该数字”冒充语义正确。脚本要求原始记录为 `completed`、形式为 `non-ui`；测试用例 ID 唯一，追问非空且不超过 4000 字符。

运行器在进程内使用已配置的 `deepseek/deepseek-flash`，要求配置名称含 V4.1；任务请求必须是 `thinking=enabled`，不回退。它核对实际请求模型、思考参数及流中返回的模型 ID，拒绝 Pro 返回。供应商返回别名仍不能独立证明内部模型修订。认证文件不复制到临时 profile。

每例最多 4 次模型调用，单次 SDK 超时 120 秒，禁止自动重试和自动压缩；发送后的轮询截止时间为 150 秒，不能当作包含所有初始化与清理的整例硬期限。UI 工具仍对模型可见，但这组明确要求普通计算的追问必须不调用工具。输出在 `.verification/phase3-text-replay-*/result.json`。

`completed` 仅表示机械检查完成；必须继续检查原始回答和追问中的全部结论、上下文继承及多余建议。开发审阅和独立人工验收分别记录。

## 小程序误差与失败诊断

普通 `expected` 仍做精确比较；刷新 `sameAs` 仍要求整个快照相同。仅当实际输入存在可解释的坐标量化时，可为特定数值路径声明绝对误差：

```json
{
  "approximate": {
    "snapshot.state.ax": {
      "value": 85,
      "tolerance": 0.01,
      "reason": "实际鼠标坐标经过 SVG 缩放后存在亚像素量化"
    }
  }
}
```

预期值、实际值和容差必须是有限数，容差必须为正且说明不能为空。报告保存实际值、差值和容差。不要为业务计算、计数或无法解释的错误统一放宽精度；本批仅放宽平移坐标，底、高、面积和保存恢复仍保持原断言。原始失败记录不覆盖。

运行器记录当前操作编号、宿主运行/状态/动作错误码，并最多保存 50 条相关请求失败或 HTTP 错误的时间、方法和路径；不保存请求头、请求体或凭据。网络记录帮助定位，不能仅凭时间接近就断言根因。

公共场景 step 的 `passed` 只表示该回调走完。若 `task-replay.json` 的样本为 `semantic-failed`，或整批为 `failed`，仍必须按失败报告。预声明的文字问题、实际文本不符、机械中断和复测分别保留。

本轮 24 个原始样本的逐项状态、失败反例与范围见[任务矩阵报告](verification/intelligent-ui-phase3-task-matrix-2026-11-03.md)及其脱敏 JSON。桌面生命周期和隔离配置见[自动化测试说明](desktop-automated-testing.md)。

## 真实模型修订与迁移

```powershell
node scripts/verify-recorded-mini-app-revisions.mjs --bindings .verification/revision-bindings.json
```

```json
{
  "version": 1,
  "thinking": "enabled",
  "scenario": "jug-no-op-revision",
  "source": ".verification/mini-app-live-EXAMPLE/result.json",
  "sha256": "REPLACE_WITH_SHA256_OF_SOURCE",
  "cancelFirst": true,
  "staleReview": true
}
```

此入口明确绑定原始合成量杯样本，不能直接用于任意小程序。样本须使用 `j3/j5/steps/next/note/history` 状态和 `fill3/fill5/pour3to5/pour5to3/empty3/empty5/reset` 操作；预期原程序两杯为空时错误提示目标杯已满。新生成结构或状态重构应独立审阅绑定，不能修改业务预期以迎合生成结果。

运行器复制会话和界面存储到隔离 profile，先通过 UI 达到 3/4 升、6 步，再用自然语言要求修复两个方向的无效提示并保留进度。模型固定为配置名称含 V4.1 的 `deepseek/deepseek-flash`，任务开启思考、无 Pro/回退；后台标题请求单独记录。源文件摘要和 sidecar 身份在模型调用前校验，原始生成记录不改写。

两个可选开关默认不启用。`cancelFirst` 取消第一份候选、刷新并再次请求真实修订；`staleReview` 在保持核对面板挂载时，通过第二个应用视图将旧版改为 3/5 升、7 步，要求旧确认返回 409、刷新核对后迁移最新进度。第二视图由测试临时挂载为同源 iframe，使用同一个 Electron profile 内的独立 React 客户端，操作和保存通过 UI 完成；它不代表两个原生窗口验收。聊天虚拟列表会卸载屏外行，因此定位绑定会话条目并通过真实滚动寻找，不依赖第一张卡片。

随后检查四种空杯/满杯无效操作、重置、达成与失去当前目标、完整快照刷新恢复和真实模型追问。API 和存储仅用于准备与结果核对。总场景期限 15 分钟、步骤期限 4 分钟；不能将机械 `completed` 视作语义通过。原始回答、候选说明与追问仍需独立审阅，双人人工验收另行安排。

修订确认现在先执行宿主的“预演所选变化”：核对来源摘要和实际数据变化，证明预演不修改旧版。过期场景先保留一次成功预演，再从另一视图编辑来源；刷新核对后再次预演并确认。运行器记录两次预演的结果与截图，确认仍必须满足原来的 409/200、保留最新进度和完整刷新断言。不能用重新生成预演来跳过过期确认测试。

输出位于 `.verification/desktop-e2e-*/revision-replay.json` 和公共 `result.json`，含本地合成会话内容，发布前应提取脱敏摘要；不要提交模型配置、认证、完整请求或私人会话。本轮成功、三次夹具失败及复测边界见[真实修订报告](verification/intelligent-ui-phase3-real-revision-2026-11-03.md)。

## 三维任务的独立几何核对

```powershell
# 新生成一个自然表达的飞机姿态任务，并验证其预设按钮。
node scripts/verify-spatial-ui-desktop.mjs --presets

# 原样重放指定记录，按审阅过的独立预期核对几何和点选。
node scripts/verify-spatial-ui-desktop.mjs --recording .verification/desktop-e2e-ORIGINAL --presets --bindings .verification/spatial-bindings.json
```

`--prompt-file` 可替换新生成时的自然任务文字，`--followup-file` 可独立替换追问；两者均读取非空 UTF-8 文本。未指定时仍使用飞机姿态任务和追问。其他对象（例如有关节的机械臂）须明确提供对应追问，不能用飞机措辞替代该任务的解释验证。交互仍限定为数值姿态参数、对象选择、镜头和保存恢复，不是任意任务的语义评分器。`--recording` 要求源目录只有一个已提交的小程序，复制到隔离 profile 后保持原始记录摘要不变，并按原会话条目定位画布。长聊天通过真实滚动寻找原条目。

`--bindings` 必须与重放配合使用，包含 `version: 1`、准确的 `planDigest`、场景 `viewport` 和有序 `steps`。每步声明 `name`、数值 `inputs`，以及至少一项 `points` 或 `directions`；每项指定对象 `object`、局部采样点 `local`、独立预期 `expected`，可选显式 `tolerance`。例如，只有在已确认关节绕原点的 Z 轴转动、无其他变换时，局部端点 `(2,0,0)` 在 +90° 的世界坐标才应为 `(0,2,0)`；不能照抄为其他程序的预期。

根字段 `selection` 可绑定首次键盘选择的准确部件 ID；未提供时仍选第一个不同的非空对象。若程序将某对象（如工作面）定义为取消选择，应审阅后显式指定任务部件，保留首次失败记录；运行器不会不断换对象直到通过。实际鼠标点选仍由各步 `pick` 独立核对。

`spatial-oracle.mjs` 独立计算缩放、XYZ 内禀旋转、父组变换与透视投影，不调用 Three.js 或产品变换函数。位置比较默认容差为 `1e-7`，显式容差不得大于 `0.01`；方向归一化后仍比较正负。可选 `pick: {object, local, selected?}` 通过独立投影位置实际点击，并核对被选对象；不自动寻找其他点来规避遮挡或错误几何。可选 `cameraKeys` 通过原生按键改变镜头，同时检查输入、状态及选择未改变。

每个姿态通过原生数值框或滑块键盘输入，再点击保存、读取快照核对。滑块从当前值、Home 或 End 选择较短序列，每字段最多 1000 次按键，保存值仍必须精确相等。改变姿态须保留用户镜头，最后刷新恢复完整快照并发送真实追问。接口与存储读取只用于准备和核对。

任务固定 DeepSeek V4.1 Flash 配置、`deepseek/deepseek-flash`、开启思考，无 Pro 或回退。后台标题请求单独记录：生产协议可能保留工具定义、追加宿主上下文或合并消息，因此测试使用完整默认标题指令识别，不靠有无 tools、thinking 或最后一条消息分类。这只是隔离运行器的请求分类，不是产品的 UI 触发规则或权限边界。

运行前后核对来源文件、运行器和独立核对函数摘要；运行期间不得修改该 checkout。输出含原始模型与合成会话资料，发布时提取脱敏记录。机械步骤通过不代表模型解释正确，后台中继失败、语义错误、原始失败和复测必须分别记录。本轮 7 组姿态、56 项断言以及追问错误见[三维核对报告](verification/intelligent-ui-phase3-spatial-audit-2026-11-03.md)。

### 保存变化与追问范围

小程序宿主随成功保存持久化相邻检查点的结构差异。每条变化绑定前后状态版本与检查点摘要，和保存回执原子写入；精确重试、重复保存同一检查点不会产生新变化。最多保留 16 条、32000 字节，单条沿用 12 项/1200 字符的差异预算；超限、深层或大值省略必须显式计数。原有全会话存储上限保持不变。

保存变化属于该程序在当前分支上的已确认状态。编辑祖先先冻结既有后代；新分支继承新的状态与变化。复制/分叉保留可见记录，后续独立写入。旧记录没有此字段时仍可读取，但更早过程未知；修订后的新程序从自己的检查点开始记录，不能凭相同字段名拼接旧程序历史。生成程序和客户端保存请求均不能直接提交变化证据。

模型收到 `saveHistory`，在原有 11000 字符总上下文预算内最多使用 3500 字符；当前快照优先，省略条数与字段仍标明。它证明保存前后的值，不证明具体点击、两个保存之间的完整顺序、未保存动作或用户动作数量。`eventHistory: unavailable` 不等于用户没有操作。历史为空、被裁剪或当前值恰好等于初始值时，回答应明确范围，不能声称“从没改过”。

场景上下文增加宿主计算的三维欧氏距离：当前相机到目标点、当前程序默认相机到其目标点，单位为场景单位。它们不是水平半径，也不代表历史镜头；`cameraRevision` 仍只是程序复位代次。测试时可调整三个角度、保存，再归零并保存，然后问“刚才改过哪些角度？现在是多少？”；也可只换视角后问“飞机姿态变了吗？镜头距离变了吗？”。核对实际记录与回答，不能把工具完成或上下文送达记为语义正确。

三维运行器额外核对保存变化以当前版本结尾、含实际参数变化、明确缺少点击历史，并核对相机距离；最终自然语言回答仍需独立审阅。

### 当前界面计算出的文字

初次试运行回执及后续确认状态增加 `projectionText`，从已编译文档声明的 `data-text` 绑定读取当前投影值，保留完整文字和单位。同一绑定只出现一次，不混入 SVG 属性、未声明值或动态列表的行数据；列表继续使用既有独立上下文。每个应用最多 32 项、每项 1000 字符、序列化后最多 2000 字符，超限整项省略并计数，不截断数值或单位；后续上下文仍受 11000 字符总预算限制。

初次回执明确还未保存。确认上下文的文字与当前检查点同源，不能混入初始值；它们是程序计算的结果，不证明业务公式正确、元素实际可见或完整操作历史。三维运行器核对真实追问拿到的文字与已确认投影一致，回答是否准确仍单独核对。

### 参数变化的只读试算

`piora_inspect_mini_app` 继续支持原有 `actionIds`；也可改为 `inputCases: [{inputId, value}]`，两者必须二选一。一次最多八个样本，每个从同一份当前确认检查点独立执行一次实际 input 事件，包含生成程序的 reduce 逻辑。每个样本不会接着上一样本运行，也不等价于一次滑块拖动中的所有中间事件、焦点或 blur 序列。

宿主校验输入 ID、类型和声明范围，在原有隔离 Worker/QuickJS 限额下计算变化及投影文字，返回结果前重新核对来源版本。试算不保存状态、不生成修订、不执行文件动作。整个提问沿用最多十二次只读检查额度，缓存绑定准确来源并在结束时清理。模型上下文提供输入类型、范围和选项；有限样本不证明整个区间的极值或单调性。

可以自然地追问：“别改我现在的姿态，帮我看看肘部在 0、90 和 120 度时，末端分别有多高？是不是越往上折就越高？”测试必须核对实际调用、各样本结果、解释和原状态未改变，不能只检查模型说自己试算过。

三维运行器的 `--inspect-inputs` 模式只允许该只读工具，并要求 `--bindings` 文件中提供 `inspectionCases`，各项包含 `inputId`、`value` 和预期 `projectionText` 映射。运行器核对模型实际收到的样本、来源版本和准确文字，以及追问后的检查点和状态版本未变；未启用该模式时仍要求直接回答且没有工具调用。完整区间结论、场景几何与自然语言正确性需要独立审阅。
