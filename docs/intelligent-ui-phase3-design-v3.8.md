# Intelligent UI 第三阶段方案 v3.8

2026-11-02 | 结合 OpenIntelligentUI 重新设计 | 设计修订，第三阶段尚未完成

## 1. 目标与本次调整

让用户的一句自然表达得到合适的答案：可以直接阅读，也可以改参数、推进过程、操作对象，并在刷新后继续使用和讨论。项目仍分三个阶段；本版接替 v3.7，保留全部复杂任务范围，以现有实现为起点安排剩余开发。

**核心路线：语义选择回答形式，共享设计系统保证外观，独立小程序承接复杂交互，宿主持有运行与持久状态。** Beta 设置仍是统一入口；普通聊天只接入通用输出接口，不承担小程序的执行、恢复和迁移逻辑。

### 与上一版相比，具体改什么

| 调整 | 设计决定 |
| --- | --- |
| 能力清单已落地，计划不再把它当未开工事项 | 保留现有实现；补当前窗口环境协商，并逐步缩小证据失效范围 |
| 真实模型已经能够发布首批界面 | 下一批先操作这些原始界面，核对结果、保存、刷新和追问；失败驱动共性修复 |
| 三维原型不等于可用的三维教学 | 分别交付环境检测、场景绘制、对象拾取、相机控制和独立正确性验证 |
| 复杂能力需要可实现的协议 | 明确动态列表的稳定身份、视图状态归属、迁移确认及动作回执 |
| 用户曾反馈样式退步、滑块过多 | 将外观和输入适配纳入每批任务验收，不留到最后统一美化 |

### 当前基线与证据边界

代码已有通用输出适配、Worker + QuickJS、受限 HTML/CSS/SVG、Canvas、基础场景绘制、独立状态、草稿分页及输入释放。能力清单已贯通模型提示、参数接纳、执行与发布复核；当前 WebGL 条件为 false，三维尚未向普通新生成开放。动态列表、拾取/相机、登记动作和状态迁移仍列为 planned。[R2]

历史真实模型批次共 24 次：18 次 UI 请求中首试发布 13 次、预算内发布 18 次，另 6 次为文字或澄清。完整逐样本操作、恢复和追问尚未验收。能力夹具 51/51 与普通配置复测 26/26 范围重叠，不能累计，也不代表模型任务正确率。[R3]

### 借鉴 OpenIntelligentUI 的哪些部分

本地参考固定为 8391a94c1c3939c679e40ddd7bfc08a9ef690e70：借鉴自由 HTML/CSS 布局、共享设计系统、CSS 完成后的渐进预览，以及受校验的宿主桥接。其最终沙箱执行生成脚本，任意控件状态不自动回到 agent，服务端检查点使用进程内存。[R1]

Piora 继续使用自身 AgentSession、权限、会话和存储；新增能力不要求引入另一套 Python/LangGraph 服务。生成逻辑继续与 DOM/图形渲染分离。此路线的主要代价是维护事件和视图协议，收益是可核对、可保存、可恢复。参考项目为 MIT，本次未复制代码。

## 2. 架构与回答形式选择

```text
AgentSession -> 形式选择 -> MiniAppPlan -> 编译 / 试运行 / 发布
                                      |
                                 MiniAppHost
                           /                 \
                可信文档与图形渲染器       Worker + QuickJS
                           \                 /
                           版本化事件与投影帧
                                  |
                       独立状态 / 追问 / 登记动作
```

### 模块责任

| 层 | 负责什么 |
| --- | --- |
| 回答层 | 同一回答模型根据目标、已知规则、当前确认状态及可用能力，选择文字、澄清、组件或小程序 |
| 通用输出层 | 复用 answer-output catalog、renderer adapter、发送前保存接口；ChatWindow 不分叉成两套聊天 |
| 小程序层 | 承担编译、执行、事件、投影、保存、修订和恢复；组件继续使用原有独立适配器 |
| 宿主层 | 提供可信渲染、主题、输入生命周期、能力检查和已登记动作；副作用走现有权限入口 |

### 触发依据是任务收益与上下文

不新增每句话都执行的分类模型，也不使用关键词触发。公共选择策略只装配一次，工具提供相应契约；模型直接回答、提问或调用合适工具。宿主负责校验可执行性，不能把 schema 通过解释为语义判断正确。

| 用户实际需要 | 预期处理 |
| --- | --- |
| “六个人分 480 元” | 直接回答 80 元，交互没有额外收益 |
| “提成帮我算下”，但规则未知 | 先澄清必要比例或阶梯规则，不编一个默认比例 |
| “人数变了，两个方案哪个划算” | 已知价格规则时使用组件，数字框和结果联动 |
| “让我一步步看冒泡排序” | 小程序保存序列、游标和步骤，支持推进与恢复 |
| “为什么刚才 B 更便宜” | 读取当前确认参数解释；不因出现“比较”就重建界面 |
| “只要文字”或所需能力不可用 | 尊重偏好或说明限制；可降级部分明确标注，不能伪称已完成原交互 |

追问时区分调整当前状态与修改程序规则。前者更新参数，后者创建候选版本。模型只接收当前分支可见的确认状态及其来源；保存失败时提示用户处理草稿，不能把旧状态当最新状态解释。记录实际形式、策略版本、关联输出和错误；如需决策标签，保存简短类别，不要求内部推理。

## 3. 能力开放与生成可靠性

### 从“代码存在”到“当前窗口可用”

沿用 planned / implemented / verified：planned 仅为路线图；implemented 可在隔离开发配置测试；普通 Beta 新生成要求 verified、依赖满足且环境可用。历史程序按原契约读取；新生成证据失效不能删除历史记录或草稿。

当前实现把相关源码和运行资源统一纳入摘要，保守但会使多个能力一起失效。后续按公共运行时、事件、Canvas、场景等真实依赖拆分；共用 VM 或编译器变化仍使所有依赖能力失效。不能仅为减少复测而删掉实际依赖。证据继续携带版本、平台、检查范围和资源摘要。

### 三维环境协商的具体流程（待实现）

- 可信渲染器启动后检测 WebGL 上下文能否建立，报告渲染器版本、窗口实例、环境代次和可用特性；生成程序不能自行声明支持。
- 报告关联当前提交请求的窗口/会话及宿主运行资源版本。服务端把验证证据与该环境报告取交集，生成提示和接纳读取同一份快照。
- 环境报告只表示可用性，不赋予权限。缺少报告、版本失配或环境代次过期时不开放三维；无渲染端的自动任务采用已验证的其他形式。
- 发布和加载时重新核对。发生 WebGL context loss 时暂停、保留检查点并提示恢复；不能为了“可展示”静默删掉任务所需的三维关系。
- 多窗口分别管理环境；窗口关闭或切换后，旧报告不能授权新实例。每次真实绘制仍处理失败，检测成功不等于永远有 GPU 资源。

### 生成链路保持短且可诊断

沿用模型生成计划、原始参数检查、编译、有限试运行、正式发布。完整示例、版本及能力说明来自实际契约。基础完整示例始终可用；增量能力的示例按当前可用能力提供，避免能力收缩后失去全部合法参考。

继续共用 3 次接纳尝试、1 次模型纠错、首次 UI 尝试起 60 秒的窗口；更换工具不重置预算。最多汇总 8 个独立诊断，给出路径、预期和完整重提要求。不静默改公式、单位或业务范围。输入边界采样用于发现错误，不能证明所有状态或任务语义正确。

### 外观成为基础契约

统一主题、字体、间距、按钮、焦点、错误和保存状态；模型在支持范围内组织布局。先完成 CSS 再预览结构，预览不执行程序。数字默认数字框，离散项用选项，布尔值用复选框；只有合理范围内的连续探索才用滑块。Canvas/3D 增加语义色及文字替代，与浅色、深色和减少动画设置一致。

### 兼容策略

现有 v1 计划和旧运行时继续可读。动态模板、视图状态或迁移字段进入明确的新契约版本，不直接改变历史字段含义；具体版本号在协议实现时固定。新旧编译入口分别覆盖回归，旧程序原有动作不会因新能力开放而自动获得外部权限。

能力 verified 只证明记录范围内的宿主能力。新模型生成的每个程序仍需自身编译和试运行，实际任务还需结果与操作核对。浏览器证据不外推为原生窗口、其他操作系统或发布包通过。

## 4. 复杂任务怎样实现

保持四个职责明确的入口：init 建初态；reduce 处理有序操作；advance 推进一个离散或固定时间步；project 只投影视图。显式保存 state、rng 和 tick；投影不能暗中改变进度。可信渲染器执行 DOM、SVG、Canvas 和受限场景绘制，生成代码不直接访问网络、文件或 Electron。

| 任务族 | 实现方式 | 独立验证重点 |
| --- | --- | --- |
| 算法演示 | 状态保存序列、游标、比较与交换数；按钮、单步、播放复用同一推进逻辑 | 逐步序列、元素守恒、终态；播放与单步一致 |
| 几何拖动 | 宿主负责坐标换算和指针捕获；程序保存点位并计算关系，提供数值/键盘替代 | 面积和角度独立计算；缩放、边界、拖动取消 |
| 动态清单/规划器 | 有界 repeat 模板、稳定对象 key、声明式绑定；新增、删除、重排由 state 驱动 | 重排后操作仍命中原对象，键盘焦点不串项 |
| 持续模拟/小游戏 | 固定时间步、显式随机源、输入状态、碰撞和终态；视图帧与逻辑步解耦 | 相同种子与事件可重放；暂停恢复、终态不变、长时间运行 |
| 三维教学 | 可信场景渲染、稳定对象 ID、拾取及相机控制；标注与解释来自相同任务状态 | 几何关系、选中对象、镜头恢复及任务解释一致 |

### 动态列表：列表项必须有稳定身份

模板由宿主编译，模型输出有界数据，不拼接可执行 HTML。事件关联模板、对象 key、实例代次和显示帧；重复 key、已删除对象或过期事件被拒绝。展开节点、文本和事件数都计入预算。删除聚焦项时转移到合理位置，不把 DOM 序号当作业务身份。

### 三维：任务状态与视图状态分开

任务状态记录对象、角度和选择；视图状态记录用户相机、缩放及视图版本，并一起保存。程序只提供初始镜头或显式复位请求，普通重投影不覆盖用户刚转动的镜头。拾取由宿主计算，事件带对象 ID 和场景版本；删除对象后，旧点击不能作用于新对象。

先用“旋转飞机理解俯仰、横滚、偏航”等真正涉及空间关系的任务验收，再检查不同对象与参数的泛化。可绘制立方体只算渲染原型，不算完整三维任务交付。

### 输入生命周期与资源

移动可合并，按下、松开、取消和点击保序。隐藏、失焦、停止、卸载释放临时输入；恢复默认暂停，清理残留按键若改变状态则生成待保存版本。队列溢出取消手势，不能漏掉松开后继续运行。

默认只让一个实例持续播放；停止和替换释放 Worker、图形对象和订阅。沿用 8ms/步、30fps 逻辑步频、32MiB 堆等初始限额，并记录步骤耗时、帧大小和资源释放；这些是配置而非设备性能承诺。超限保留检查点并暂停，不跳过业务步骤伪造流畅。

## 5. 状态、程序修订与真实动作

### 保存是后续操作的共同边界

发布的程序不可变。独立检查点保存程序身份、输入、任务状态、随机源、逻辑步、状态版本及视图状态。保存先冻结输入、排空事件并取一致检查点，再写本地草稿、核对分支与 expectedRevision，最后由服务端重投影、原子保存并返回 requestId 回执。

| 情况 | 用户应看到的行为 |
| --- | --- |
| 超时、断网或响应丢失 | 保留草稿和待保存提示；同一请求查回执或重试，不能显示虚假的已保存 |
| 保存中继续操作 | 新操作成为下一版，旧回执只清理它对应的草稿 |
| 多窗口、分支或程序版本冲突 | 保留双方，展示选择；不以最后写入覆盖正确状态 |
| 刷新、Beta 关闭再开启 | 读取已确认结果，另行呈现未处理草稿；旧异步响应不能重新激活实例 |
| fork、复制、导出与回收站 | 继承分支可见的确认状态，之后独立写入；导出说明是静态结果还是可恢复数据 |

当前分页和输入释放已有局部证据，仍需覆盖以上场景及组合，特别是原生桌面关闭/最小化、保存中取消、冲突后修订和恢复后追问。操作通过 UI 完成；直接读 API/存储只用于准备及核对。

### 修订用候选版本，不覆盖正在使用的程序

改人数、速度或点位属于状态调整；新增规则、数据结构或交互才生成候选。复用第二阶段候选确认流程，小程序提供自己的兼容性判断和迁移适配。

候选展示哪些输入可保留、哪些进度会重置、哪些字段会丢弃。迁移检查含义、单位、类型和约束，不能仅凭同名字段复制。内部状态默认重新 init；保留过程进度必须提供受限迁移函数并试运行。确认时重新核对来源版本，冲突则重算候选；取消或失败继续保留旧版。组件与小程序互转也遵循此流程。

### 外部动作复用既有执行与权限系统

先接入继续提问和导出，再接入已有执行器支持的真实操作。沿用 lib/intelligent-ui/action-contract、action-runtime 等边界，以适配器连接小程序，不再建立另一套工具审批。

用户点击经宿主校验的登记动作后，先保存当前检查点，再绑定程序、状态版本、动作 ID 和参数进入既有权限层。加载、计时器或生成程序自行构造的消息不视为用户确认。结果持久化为回执；成功后丢失响应时查回执，不能盲目重做副作用。执行器无法查证结果时展示“不确定”，不能承诺普遍的恰好一次。

动作或候选迁移能力在实现并验证前不进入普通生成可用清单。历史读取与新动作执行分别处理，避免历史兼容路径意外绕过能力或权限检查。

## 6. 实施顺序与完整验收

3A 至 3E 仍是第三阶段内部批次。每批都交付对应代码、相关验证、Markdown 和 PDF，记录失败及未覆盖项；不以“新增一个协议”代替用户任务成果。

| 批次 | 继续开发的内容 | 退出条件 |
| --- | --- | --- |
| 3A 基础维护 | 沿用既有隔离、渲染和状态；随新契约维护版本兼容 | 变更影响的基础检查通过，历史可读 |
| 3B 完整任务 | 首批 8 例各 3 次，逐份验证生成结果、操作、恢复与追问；同步修视觉和通用错误 | 24 个样本有完整判定，失败修复并留下复测记录 |
| 3C 恢复与修订 | 完整恢复矩阵、候选迁移确认、组件/小程序互转及登记动作 | 无静默丢失、错误覆盖或重复副作用；冲突和取消可恢复 |
| 3D 复杂能力 | 动态列表、持续模拟/游戏、三维环境协商、拾取/相机及教学任务 | 每项均有完整任务、正确性、外观、键盘和资源证据 |
| 3E 综合验收 | 三阶段开发完成后进行完整 CI、封存集及人工语义验收 | 记录真实结果与平台边界，发布通过 GitHub Actions |

3B 若遇到完成任务必需的通用能力，直接补齐最小能力，不以归属 3D 为由跳过。3D 扩展复杂程度和泛化，不只重复已通过的简单演示。

### 紧接着的开发批次

复用 desktop-e2e 生命周期，在隔离配置导入原始生成记录副本。先验证六份组件和三份排序，再完成三角形、倒水、棋盘；文字与澄清也核对答案和多轮上下文。每个 UI 样本都完成实际操作、独立结果核对、保存、刷新和追问。

原始模型记录保持不变。重放旧输出只证明当前运行/恢复路径；代码或提示修复后另开固定版本真实模型批次，不能把旧生成与新运行混成一次端到端成功。固定模型回显能证明状态送达，但不能替代真实模型理解当前状态的追问验证。

| 自然表达任务 | 核心判定 |
| --- | --- |
| 均分、提成澄清 | 80 元；缺少提成规则时提出必要问题 |
| 出行对比、满减 | 人数 2/4/6 时费用分别核对；5/6/8 杯总价 90/88/124 元 |
| 冒泡排序 | [6,2,5,1] 的六次比较、五次交换和最终 [1,2,5,6] |
| 拖三角形、倒水、棋盘 | 点位对应面积；杯容量及转移量；占位、胜负、终态与重置 |

### 泛化与评价

保留 48 个初始任务：16 小程序、12 组件、12 文字、4 澄清、4 能力缺口；32 开发、16 封存，每例 3 次，包含多轮、反例和边界。首批八例属于开发集，不是生成白名单。用于调试的封存样本移入开发集并补新样本。

## 7. 可行性、改动位置与设计复核

### 可行性判断

基础方案可继续增量实施，主要难点已从“能否运行界面”转为生成语义、复杂交互一致性和可靠恢复。自由布局、共享样式、数字/表单交互已有基础；动态集合、三维交互和迁移属于明确的新工作，不能用现有局部测试宣布完成。

| 风险 | 处理及可检验证据 |
| --- | --- |
| 自然表达选错形式、界面有画面但任务错误 | 同轮语义策略加正反例，使用独立答案和操作轨迹；不会仅增加重试次数 |
| 自由布局造成外观退步 | 共享设计系统、语义控件、主题与窄窗口检查随任务交付 |
| 自定义协议增加模型负担 | 完整合法示例、能力一致的提示与接纳、多问题诊断和有限纠错 |
| 三维设备差异、资源耗尽 | 按窗口协商，真实渲染核对，失去上下文后暂停并保留状态 |
| 修订后丢失进度、动作重复执行 | 候选确认、CAS、受限迁移及执行回执，保留可恢复旧版 |

### 预计修改的边界

共享选择策略继续在 lib/answer-output-decision.ts；工具契约在 extensions/piora-intelligent-ui.ts、piora-mini-app.ts 及各自 decision-policy。环境与能力扩展进入 lib/mini-app/capability-*；事件、投影和渲染扩展进入 document、frame、events、controller、renderer-runtime。环境协商的客户端与 API 契约需新增，尚未实现。

恢复沿用 client-state、drafts、state-service/state-store；候选迁移和登记动作复用 lib/intelligent-ui 已有机制，通过小程序适配器接入。通用输出 catalog/renderer 只增加必要接点。桌面验证复用 scripts/desktop-e2e，保持独立配置、端口、输出目录和进程清理。

### 本次设计复核

- 3D 代码存在但 WebGL 仍不可用：已明确环境协商和真实绘制验证，不将原型当作已开放能力。
- 状态迁移与相机恢复不能混为一谈：前者迁移任务语义，后者保存版本化视图，均需与程序身份绑定。
- 能力证据与生成正确性不能混算：分别保留宿主能力、真实生成、旧样本重放及真实追问记录。
- 现有实现不能因重新设计被重复重写：沿用已验证边界；下一批先完成真实任务，按失败补通用能力。
- 人工验收和 CI 仍留到三阶段开发完成后，开发期间只做相关快速检查和必要桌面验证。

真实模型继续使用用户指定 DeepSeek V4.1 Flash 配置，不使用 Pro 或自动替换。当前 provider/modelId 为 deepseek/deepseek-flash；服务返回只能确认 deepseek-flash，不能独立证明 4.1 版本身份。原生 GPU、其他平台及发布包分别取对应环境证据；禁止本地发布构建。
