## 什么时候生成界面

开启功能后，当前模型在同一轮结合用户意图、交互收益、已有事实、组件能力及对话上下文，选择文字回答、澄清、创建或更新界面。没有关键词路由，也不会为每句话额外调用分类模型。一次性计算、解释和静态比较通常直接回答；反复改条件、观察联动结果才适合 UI。关键业务规则缺失时先澄清，展示细节采用合理默认值。

例如，“480 元六个人分”直接回答 80 元；“人数和费用我想自己改着看”适合界面。已有界面之后问“为什么是这个结果”只解释，要求新增比较项才考虑更新同一任务。显式“只要文字”优先，不能为生成控件而编造价格、规则或滑块范围。

这些是模型选择规则，不能保证每次选择正确。程序单独验证能力、结构和预算；评估另外记录误触发、漏触发和多轮选择，结构有效不等于任务完成。

## 使用

在设置 → 实验功能（Beta Features）开启 Intelligent UI。默认关闭，选择保存在 Pi 数据目录的 `piora/beta-features.json` 中。可请求「我们四个人出去玩，我想来回改人数和餐费，看看各项、总共和每人多少」。当前开发版本默认按需要调用 `piora_render_ui_plan`，普通问题仍用文字回答；用户无需提到工具名。

控件在本地即时计算，不为每次调整请求模型。参数保存到服务端后显示「已保存」，继续发送、编辑历史、分叉或导航前会等待待保存参数；保存失败会保留本地修改并提示重试或解决冲突。勾选和选择可通过受限条件表达式参与计算。

开关对智能体在下一轮开始时生效，已运行的一轮保留原能力。关闭时前端立即显示文字快照，不再加载交互渲染器。参数未保存成功时可以重试，也可以明确选择关闭并在本机保留未保存参数；重新开启后恢复草稿并重新核对服务端版本。已保存状态不会因关闭开关而删除。

## 模块边界

- 普通对话只识别 `answerOutput` 公共内容封套、快照和通用待保存接口。过程折叠不会隐藏已识别的回答输出。
- 独立目录 `lib/intelligent-ui/` 管理规格校验、计算和状态，`components/intelligent-ui/` 管理渲染和客户端状态，独立扩展提供模型工具。
- `AnswerOutput` 仅在开启功能且有有效输出时懒加载渲染器；关闭、历史只读视图、加载失败和未知版本保留文本。
- 运行时仍共享原有 AgentSession、SSE、消息发送、权限和持久化边界，没有第二套模型客户端或聊天数据库。加载计划在执行扩展模块前过滤关闭的功能；存量会话在新轮次重新加载能力，避免缓存旧工具。

## 协议与交互

基础节点包含 `text`、`number`、`slider`、`select`、`checkbox`、`metric`、`table` 和 `barChart`；稳定 ID 用于恢复和版本衔接。旧 Surface v1 工具直接接收 `id`、`title`、`nodes`，宿主附加协议版本和递增的界面版本，旧历史继续可读。

未设置 `PIORA_UI_INPUT_PROTOCOL` 时，开启 Beta 的新加载扩展只提供 `piora_render_ui_plan`，接收平铺输入、命名计算、结果和完整布局。UiPlanV2 编译为 Surface2，支持分组、方案卡片和本地筛选表格，并共用候选校验、准确磁盘回执、保存及恢复机制。每个节点必须恰好出现在一个布局位置；筛选不会删除源行，计算失败的行保留并标明未知。开发回退可在启动前显式设置 `surface` 或 `plan-1`；`plan-2` 等同于当前默认。环境变量在扩展加载时读取，改变后应重启服务，不承诺存量 wrapper 即时切换。

Surface2 的完整布局随参数保存、刷新、后续模型上下文、分叉、复制和文字导出保留。切回旧生成协议后可继续读取已有结果，但旧生成器不能覆盖 Surface2 的布局。模型工具只能产生受限声明，不执行生成代码。Plan2 已接入可取消的增量预览，以及 [登记动作](intelligent-ui-actions-design.md)：读取项目 JSON 参数后明确采用，或另存当前结果为 JSON／Markdown。点击使用新运行身份及当前聊天权限，保存不覆盖文件。完整桌面动作矩阵仍待验收。

动作按钮旁由宿主说明实际行为：读取后先核对再采用，保存使用点击时已确认的参数，只新建文件。模型在生成结果及后续上下文中也能读取已登记动作、目标、文件格式与当前权限模式；该说明不是执行或授权回执，实际点击仍重新检查权限。Markdown 保存为可读的纯文字快照，JSON 另含参数；批准保存也不能开启覆盖。

Plan2 自编译器 2.2 起支持原子值简写：字符串、数字、布尔值等价于对应的 `{literal: value}`，可用于表格、指标、图表和派生计算参数。输入和计算引用仍须使用明确对象，字符串不解释为公式或引用，空值不转为零。预览与最终编译采用相同解释；原始计划在 SDK 转换前校验，仍计入原运行预算。Plan1 语法保持不变。真实模型到浏览器与后续追问的开发样本见 [v2.8 报告](verification/intelligent-ui-phase2-workflow-2026-10-29.md)。

Plan2 编译器 2.3 将内部派生计算名独立于渲染节点 ID：指标 `total` 可以展示 `{derived:"total"}`。明确的 input／derived 引用分别解析，不猜测或自动更名；同类 ID 重复、输入与展示节点冲突、布局身份冲突、缺失引用和计算环仍拒绝。Plan1 保留原共享 ID 约束。对应的逐片段预览、完整 SDK 流程与两模型开发比较见 [v2.10 报告](verification/intelligent-ui-phase2-namespaces-2026-10-29.md)。

Plan2 编译器 2.4 进一步允许在计算参数、指标值、表格单元格和图表值中使用内嵌 `{op,args}`。它被精确转换成内部命名计算后，仍经过相同的类型、引用、循环、默认值和展开成本校验。例如 `{op:"divide",args:[{op:"multiply",args:[{input:"price"},2]},3]}` 不再需要模型再发一轮调用来改成平铺形式。内嵌对象只允许 `op` 与 `args`；带 `id` 的命名声明应放在 derived 列表，未定义引用、占位字段、字符串公式和错误类型不会被猜测或修复。

命名与转换产生的计算合计最多 256 项；展开结果保持深度 12、4096 表达式节点和 64000 字符限制。原始 JSON 仅在规定的表达式位置允许更深的嵌套，布局、动作等其他数据仍使用原深度边界。流式扫描、闭合片段预览和最终编译采用相同规则。内部名称会避开所有原始字符串，避免意外补上一个本来缺失的引用；诊断映射回原始索引路径。

工具 schema 保持有限结构、没有递归 `$ref`，深层操作数由必经的原始 Plan 编译器在 SDK 转换前校验。SDK schema 单独通过不代表接纳通过，预览也必须验证所有闭合计算。Plan1 的平铺协议与已保存 Surface 格式保持原样。

当前同轮决策策略为 `intent-4`。模型区分可调整的数值与计算所需的业务规则：后者尚未确定时先澄清，不能因为用户说了“做个工具”就自行选规则。用户明确要求假设试算或比较已指定的方案时可以生成；上下文已有规则时直接沿用。这个选择仍由模型理解语义，不是关键词路由，也不是正确性保证。应用通过独立接纳层约束调用次数、纠错和期限；结构验证无法代替业务事实验证。

值可以是常量、控件引用或限定的计算表达式。支持加减乘除、取整、最小最大、严格相等和条件选择。表达式经过数量、深度、引用、数据类型与数值范围校验，不使用 `eval`，不接受 HTML、JavaScript、URL、任意组件名或任意动作。

每次工具调用仍提交一份完整、经过校验的界面。Plan2 在此之前严格扫描原始参数片段，逐步显示已闭合且依赖完整的布局块。预览只读，标明尚未保存；取消、重试、分支与运行切换撤销旧预览，重连恢复当前运行快照。未校验的半截 JSON 不进入渲染器。供应商没有可验证参数增量时，仅在最终完整参数校验后展示。完整工具结果仍须经过候选和发布确认，预览不会提前获得保存能力。实现与证据见 [增量预览报告](verification/intelligent-ui-phase2-preview-2026-10-29.md)。

修改参数只保存数据。需要查询、文件或网络操作时继续通过普通对话与已有工具权限机制执行；没有能绕过权限的界面执行接口。

## 状态、分支与恢复

最终工具结果在会话中保存完整规格和文字快照。交互状态保存于 Pi 数据目录 `piora/intelligent-ui/`，文件名由会话 ID 哈希生成，不能由模型指定路径。

保存采用文件锁、界面版本和乐观并发检查。状态按会话、界面和分支节点关联；使用活动 SessionManager 读取实际选中分支。回到祖先修改参数时，已有子分支冻结原值，新建分支继承新值。分叉与复制仅拷贝所保留历史的状态，后续互不影响。版本变化保留类型、范围兼容的参数；不兼容参数使用新规格默认值。

虚拟列表卸载不会丢失待保存状态。客户端保留有限的可回收缓存，未确认的参数在本机恢复记录中保留；重载后遇到分支或版本不一致，必须明确解决冲突。后续模型请求只获得当前分支有限的已保存快照，并被标记为任务数据，不是指令或工具授权。

HTML 导出保留原始工具快照，并附加当前分支已保存参数；离线导出不运行交互控件。普通历史只读视图保留当时的输出快照。删除到回收站期间保留参数以便恢复，永久清理时清理对应服务端参数。

## 范围与验证

第一阶段聚焦「生成 → 本地操作 → 保存 → 追问」闭环。任意代码小程序、动画游戏、复杂模拟、自定义网络动作和供应商参数流式适配属于后续阶段。

回归覆盖协议限制、本地计算、保存冲突、分支与分叉、真实 SDK 扩展注册及开关生效、关闭后的快照、普通聊天路径，以及浏览器控件、焦点、刷新、窄屏和中英文。浏览器时延来自本地固定数据测试，不能代表真实模型生成速度。上线前仍需在实际模型和桌面发行包中验收；本地不构建 Next 生产包或发布包。具体命令、结果、失败复测和未覆盖范围见 [首次验证记录](verification/intelligent-ui-2026-10-28.md) 和 [同步 beta.44 验证记录](verification/intelligent-ui-rebase-2026-10-28.md)。
