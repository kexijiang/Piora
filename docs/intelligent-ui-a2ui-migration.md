# Intelligent UI：A2UI 迁移与试用指南

2026-11-09 · 本地开发版 · 工作分支 `codex/intelligent-ui`

## 本轮调整

新生成的普通交互回答采用 A2UI 1.0 消息；复杂小程序的界面也改为 A2UI 组件描述。协议处理依赖固定版本 `@a2ui/web_core@0.15.0`，组件目录 ID 为 `urn:piora:a2ui:interactive:1`。目录在应用内注册，标识不用于联网下载组件。

这是一套基于 A2UI 1.0 的 Piora 受限组件目录，不宣称实现 A2UI 的全部组件和 RPC 能力。当前入口接受完整的单界面消息批次：`createSurface`、`updateComponents`、`updateDataModel`。先完成校验，再按原有候选发布流程应用；不是逐个 JSON token 就执行动作的通用流式客户端。

普通界面保持 `piora_render_ui_plan` 工具名，参数改为 `id/title/messages`，可选文件动作和形态转换仍由宿主管理。消息中不再要求模型填写旧的 `inputs/derived/views/layout` 计划。复杂界面保持 `piora_render_mini_app` 工具名，`document` 改为 `{messages:[...]}`；显式状态、确定性程序、播放模式等仍是独立的运行约定。A2UI 不承担程序隔离或会话事务。

## 分工与兼容

| 部分 | 实现 |
|---|---|
| 布局与常用控件 | 官方 Row、Column、Card、Text、Divider、Button、Slider、CheckBox；小程序另支持 TextField |
| 数值输入与比较 | PioraNumber、PioraChoice、PioraMetric、PioraTable、PioraBarChart 扩展组件 |
| 复杂展示 | PioraSvg、PioraViewport、PioraRepeat 扩展组件；沿用 SVG、Canvas、3D、行模板的原有边界 |
| 计算与动作 | 普通回答编译成现有有界计算图；小程序继续使用隔离的 QuickJS/Worker 与可信渲染器 |
| 保存和恢复 | 复用原有发布确认、持久化回执、参数草稿、进度检查点、会话分支与迁移流程 |
| 是否使用 UI | 继续结合任务、上下文及缺失事实判断；A2UI 本身不负责形式选择 |

保存记录同时保留标准来源和宿主计算/原生布局投影。重新读取时重编译并核对两者，拒绝来源与投影不一致的数据。旧版 Surface、Plan1、Plan2 和 HTML 小程序继续按原版本读取。新默认入口为 `a2ui-1`；内部环境变量 `PIORA_UI_INPUT_PROTOCOL=plan-2` 仅供旧协议回归，不新增用户设置。

Beta 开关仍是 Intelligent UI 的统一入口，普通对话模式保持独立。启用后新启动的扩展使用新协议；已经运行的旧实例需要重启桌面或重新加载扩展。

组件 ID 与数据字段 ID 按 A2UI 绑定路径独立处理，例如控件 `peopleControl` 可绑定 `/inputs/people`。当前每个输入只挂载一个控件，数据字段仍由宿主校验和保存；同一输入挂载多个同步控件尚未开放。

## 当前边界

- Piora 使用固定、受限的目录；未注册组件、目录和函数会明确拒绝。标准组件的任意扩展字段不等于已经支持。
- 普通回答控件绑定 `/inputs/<输入字段 id>`。小程序结果文字绑定 `/frame/<投影字段>`；运行时状态是持久化依据，界面是其展示。
- Row/Column 当前使用显式子组件 ID。动态行使用 PioraRepeat；没有宣称通用 A2UI 动态列表模板已经接入。
- 当前创建/修订入口不接受 `deleteSurface` 或双向 RPC。Button 只调用目录声明的本地参数、事件或预设；文件动作仍走单独的宿主权限流程。
- 不支持组件 `checks`；约束由宿主输入声明校验。TextField 当前只支持短文本；普通回答的自由文本编辑仍使用小程序。
- 官方 SDK 限制最多五层嵌套函数（包含 concat/if），生成提示同步此限制；更复杂的计算使用隔离程序。小程序布局当前使用响应式等宽布局、默认按钮和水平分隔线，显式拒绝 weight/justify/align、其他按钮样式、垂直分隔线及 placeholder，不会默默忽略。
- 自定义部件、动画资源和模型生成质量仍需要开发。自行车和风扇样例是原创简化 SVG 示意，没有复制示例仓库资产，也不是已接入 Lottie 播放器或工程装配模型。
- 不把协议迁移等同于生成成功率、美观、语义正确性或完整互操作性通过。系统性可靠性、完整 CI 和双人人工验收继续按第四阶段安排。

## 试用前

1. 重启本工作分支的 desktop，进入设置，开启 Beta Features 中的 Intelligent UI。
2. 新建对话，模型选择 DeepSeek V4.1 Flash；不要切换为 Pro 或在失败后换模型算作同一次通过。
3. 正常说需求，不必提工具名、协议或组件名。记录是否直接成功、重试、澄清或失败。

## 自然语言用例

### 费用比较

> 周末出去玩，A 每人门票 30 元，包车一共 120 元；B 每人门票 45 元，包车一共 60 元。先按两个人算，我想改改人数看看哪个便宜。

先看两个人：A 为 180 元，B 为 150 元，应该是 B 更便宜。改成四个人，两边都是 240 元；改成六个人，A 为 300 元，B 为 330 元，应该是 A 更便宜。结果、图表和解释应一起变化。不要只看 JSON 合法或工具成功。

### 选择与开关

> 做个订阅费用比较吧。基础版每月 20 元，高级版每月 35 元；年付打八折。我想选套餐、切换年付，再改使用月数，看看总价。

应能选择套餐和年付，而不是把每个参数都做成滑块。高级版、12 个月、年付时应为 336 元。改成基础版后应为 192 元。

### 动态解释

> 在刚才的出游比较里，顺便告诉我现在两种方案差多少钱，人数变化时这句话也跟着变。

人数改回 2 时差 30 元，改到 4 时差 0 元。文字不能仍然把 A 写成更划算，也不能重新生成一份丢掉当前参数的回答。

### 拆解与泛化

> 做个自行车的拆解示意，能展开、装回去，再选一个部件看看它在哪里。

检查车轮、车架等部件是否有对应图形和交互；展开、装回及部件选择应改变实际画面。如果提供了播放/暂停，再核对动画是否停止和继续。再用新对话尝试：

> 换成一个台式风扇的拆解示意，我想看底座、支架、风叶和网罩的关系。

第二个任务需要新的部件和几何关系，不能只是换标题。图形合理性仍需人工判断；这两句不是固定资产调用口令，不保证模型每次生成相同画面。

### 保存、恢复与历史

把费用比较的人数改成 6，等待“已保存”，刷新并追问“现在两种方案各多少钱”。应恢复到 6 人并回答 300/330 元。对复杂示意操作后保存、刷新，核对实际位置和选择。关闭 Beta 时保留可读结果，再开启后恢复已确认状态。最后打开旧版本对话，确认旧界面仍可阅读和操作。

### 不需要 UI 与缺失事实

> 30 元一张票，4 个人一共多少？

应直接回答 120 元。

> 帮我比较这两个旅游方案哪个便宜，但我还不知道门票和交通费。

应先澄清价格或说明缺少数据，不能捏造数字并生成看似确定的比较。
