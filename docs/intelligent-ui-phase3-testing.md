# 第三阶段 Beta 试用说明

2026-11-03 · 对应方案 v3.9 · 系统性可靠性验证归第四阶段

打开当前开发版 desktop，在设置的 Beta Features 中开启 Intelligent UI，模型选择 DeepSeek V4.1 Flash。开启后，模型按任务决定使用文字、组件或小程序。以下是自然表达试用用例；每次新生成的外观和操作细节可能不同，当前不承诺生成成功率。

| 可以这样说 | 主要看什么 |
|---|---|
| “帮我弄个买菜清单，能勾掉买过的，也能调整顺序。” | 新增、修改、勾选、重排和删除后，保存刷新仍保留内容与顺序 |
| “冒泡排序我没看懂，拿 6、2、5、1，让我一步步看。” | 单步与播放遵循相同过程，最后为 1、2、5、6；暂停和刷新后能继续 |
| “让我拖一拖三角形，看看底和高变了面积怎么变。” | 拖动或数值操作有效，面积满足底乘高除以二，保存后点位保留 |
| “飞机的俯仰、偏航和横滚总分不清，让我转一转看看。” | 改姿态、选部件、换镜头、复位可用；单纯换镜头不应改姿态 |
| “做个能用左右键移动挡板接球的小游戏，接住加分，漏掉扣一条命，能暂停继续和重新开始。” | 点宿主“播放”，点游戏区域获得焦点，再用左右键；接球、漏球、暂停、终局和重新开始正常 |

小程序保存会暂停运行；刷新后也默认暂停，需要点宿主“播放”继续。游戏内部的暂停按钮可能只改变游戏自身状态，宿主还有独立的播放/暂停状态。不要仅凭模型一句“进行中”判断实际正在播放。

保存后可以问：“现在是多少分、还剩几条命？”或“我现在清单里还有哪些没买？”先核对当前值。复杂历史和额外解释的可靠性放在第四阶段继续改善。

需要修订时，可以说：“这个提示不太对，帮我改一下，保留我现在的进度。”新版应先显示候选，核对预演后再确认；取消后旧版继续可用。只有提供迁移的同类小程序修订支持保留进度，不能把组件与小程序互转理解成保留全部游戏进度。

宿主动作目前支持项目内 JSON 参数读取后单独采用，以及创建 JSON/Markdown 报告。可以明确指定目标文件，例如“给这个工具加一个保存报告按钮，存到当前项目的 report.json”。文件应不存在，父目录应存在，执行仍遵循会话权限；不是任意工具或网络动作接口。

组件互转可以明确提出“把这个计算界面改成一个能保存步骤的小程序”，或反向要求回到计算组件。先核对参数和损失说明，再确认；跨形式切换会重新开始任务进度，旧结果保留在历史中。

完整证据和限制见[阶段报告](verification/intelligent-ui-phase3-usable-2026-11-03.md)。本次为开发版功能交付，未生成或验收安装包。
