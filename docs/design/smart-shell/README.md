## 布局

右侧面板从上到下：终端管理、当前工作目录与 Shell、视图切换、可滚动执行记录、执行状态栏、统一输入框。只有记录区域滚动，输入框和停止按钮始终可达。每个终端保留独立草稿、模型和工作目录。

模型选择与输入模式放在输入框底栏，清空与重启放在状态栏。窄面板允许底栏换行，命令和输出换行或局部滚动，不能撑宽整个工作区。设计图中的外层聊天布局仅作为上下文，沿用 Piora 已有侧边栏与工作区框架。

## 视觉规范

- 使用应用现有 `--bg`、`--bg-panel`、`--text`、`--text-muted`、`--border`、`--accent`，同时支持浅色和深色；图中的薄荷色由当前主题强调色替代。
- 面板间距以 8px 为基准，内容左右 12–14px，设置分区 18px；圆角 8–10px。
- 普通文字 12–14px，次要信息 10–12px，命令和路径使用现有等宽字体。
- 选中的视图用底部强调线；命令块与任务卡用细边框。确认区域使用琥珀色，执行状态同时提供文字，避免仅依赖颜色。
- 按钮有键盘焦点和可访问名称，动画尊重减少动态效果偏好。

## 交互约束

1. 历史联想展示实际命令、来源与目录；缺失的信息保持未知。Tab 或点击填入，填入动作不执行命令。中文输入法确认不触发提交。
2. 自然语言与命令共用输入框，可显式切换模式。不能确定输入类型时让用户选择。
3. 运行状态、步骤、耗时和退出码必须来自运行时；不能把设计图中的示例成功状态写成固定内容。暂未提供结构化步骤时，展示真实任务响应。
4. 关键操作展示实际命令和工作目录，批准绑定此次操作。接管、停止保持可达。
5. “放入主聊天草稿”只填写草稿；图片中的“发送到对话”在实现中采用更准确的文案。
6. 模型下拉来自已配置模型目录；全局默认、Shell 默认和终端覆盖的继承关系明确。图片中未选择具体模型时的推理强度行可省略。
7. 设置页分为模型、终端、命令历史。来源只展示真实检测结果，不添加图片中的虚构同步条目。新来源表单点击添加后展开。

## 验收

检查 360px、480px、640px 右侧面板以及浅色/深色主题；验证输入框不被挤出屏幕、长路径不造成页面横向滚动、按钮可用键盘操作。对比截图应单独保存并标明是实际页面还是使用固定测试数据的组件场景。

## 按图开发的对应关系

| 设计区域 | 实现组件 | 验收重点 |
| --- | --- | --- |
| 主工作区、终端标签、任务卡 | `SmartShellPanel.tsx` | 后台终端自动出现，当前选择不跳转，相同标题可区分 |
| 固定输入区、模式和模型 | `ShellComposer.tsx`、`ShellModelSelect.tsx` | 接受联想只填入，中文输入法不误提交，失败保留草稿 |
| 全局历史与自然语言查找 | `ShellHistory.tsx` | 来源、目录和历史内容真实，选择命令后再编辑执行 |
| 原生交互终端 | `TerminalSurface.tsx` | 支持交互输入、全屏程序、Ctrl+C、重连和进程代次隔离 |
| 设置页 | `SmartShellSettings.tsx` | 继承关系明确，保存失败保留修改，模型目录复用现有设置 |
