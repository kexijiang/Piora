# 图片历史与发送可靠性

## 调研依据

- [OpenCode 的 provider transform](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/provider/transform.ts)：在发送适配层检查空图片和模型支持的输入类型，避免直接把无效图片交给渠道。
- [Cline 的历史架构](https://github.com/cline/cline/blob/main/sdk/ARCHITECTURE.md)：区分完整历史与提供给模型的上下文视图。
- [Cline 的工具图片适配](https://github.com/cline/cline/blob/main/sdk/packages/llms/src/providers/middleware/split-tool-images.ts)：校验媒体数据并控制单图及总量预算；工具图片通过多模态消息传输，避免把 Base64 当普通文本发送。
- [Claude 的图片输入文档](https://platform.claude.com/docs/en/build-with-claude/vision)：图片格式、分辨率和请求体限制都会影响是否能成功发送；连续携带 Base64 图片会增大历史请求体。

以上是这些项目的具体实现，不代表所有智能体采用同一策略。

## Piora 的实现

历史记录保留原图。继续使用已有规则：最新用户消息之前的图片在模型上下文中替换成文字占位，界面与落盘内容不受影响。当前轮用户附件和工具返回的图片仍作为图片发送。

新增的 `model-image-context` 只处理发送副本，主智能体和视觉辅助模型共用：

1. 校验 Base64，实际解码图片，根据内容确定格式，纠正 EXIF 方向并转换到 sRGB。
2. 优先保留 PNG；JPEG 输入重新编码为 JPEG。长边上限 1568 像素，超预算时逐步降低 JPEG 质量和尺寸。
3. 应用自行采用单图 3 MiB、整轮 12 MiB 的保守预算，按本轮图片数量分配单图压缩预算，不再设置统一的 20 张数量上限。这不是所有渠道的统一限制，也不能保证兼容每一个代理服务。
4. 缩放后附上原尺寸及坐标换算说明；多帧图片说明仅发送首帧。必要时将透明背景合成到白色，并说明这一变化。
5. 同一会话上下文缓存转换结果；转换失败给出中文图片序号和修复建议，取消后不继续调用模型。

Pi SDK 已有 OpenAI Chat Completions 工具图片消息适配，因此不重复实现。暂不引入绑定特定供应商的文件 ID，保持切换模型和渠道时的可用性。

代价是发送副本的细节可能减少；需要识别极小文字时可以裁剪重点区域重新附加。原图仍可从历史查看。

## 快捷回复超时是独立问题

快捷回复提取只发送最近一条助手文本，不携带图片或完整对话。原实现的初始化和模型调用共用 15 秒总期限，较慢模型容易被提前取消。现改为 60 秒，并保留最低可用推理强度、请求合并、取消和失败后重试机制。超过期限仍会结束等待，提示重试或选择更快的提取模型。

## 验证范围

使用真实图片检查格式转换、EXIF 方向、尺寸与整轮体积预算、缓存、原始记录不变、损坏数据和取消。模拟模型验证超过原有 15 秒的提取能完成、60 秒超时能取消且可以重新提取。浏览器检查取消状态中文显示及真实错误保留。

尚未获得用户失败时的模型、渠道和服务端错误，因此没有将某个具体渠道的线上故障断言为已解决，也没有调用用户付费模型作实机验证。
