# Intelligent UI：可取消的已校验增量预览方案

状态：**内部 Plan2 路径已接入，完整验收仍在进行**。日期：2026-10-29。实现、局部验证及真实模型单样例见 [v2.5 成果报告](verification/intelligent-ui-phase2-preview-2026-10-29.md)。CI 按用户要求在三个阶段开发完成后统一处理。

本文落实第二阶段 2C 中的增量预览要求，不把当前完整工具结果的只读展示当作增量生成。分组、比较卡片、筛选表格、参数保存与恢复、后续动作及第二阶段其他验收要求继续保留。相关主方案见 [第二阶段设计](intelligent-ui-phase2-design.md)；字段含义变化的确认流程见 [迁移设计](intelligent-ui-migration-design.md)，两者不合并为同一种预览状态。

## 当前代码与事件边界

- `extensions/piora-intelligent-ui.ts:registerPlan()` 在 `executePlan()` 完整返回之后才调用 `onUpdate()`。此时完整计划已经编译并建立候选；它不是模型生成参数过程中的增量预览。
- 当前 SDK 的 `toolcall_start`、`toolcall_delta`、`toolcall_end` 经 `message_update.assistantMessageEvent` 进入 AgentSession 和 `rpc-manager.ts`。服务器订阅点目前可取得原始参数增量。
- `lib/agent-event-transport.ts` 为浏览器压缩事件，将工具变化变成 `message_block`，删除 `assistantMessageEvent`。前端能够得到正在变化的参数对象，但其中可能有 SDK 的不完整 JSON 修复结果，不能据此证明某个值已经生成完毕。
- SDK 明确说明 `partial` 是共享的可变对象，不是事件发生时的快照。工具开始时的参数形态依供应商而异；部分 Responses 供应商还会在结束时以权威完整参数替换原先前缀。因此，不能异步保留 `partial` 引用，也不能一律把开始时的 `arguments` 序列化后再拼接增量。
- `AnswerOutput` 通过通用瞬态 context 接收预览，真实工具结果优先；预览边界 key 使用会话、运行、流、调用和分支，不包含 seq 或快照文本，避免追加内容时重挂界面。
- `IntelligentUiPreview` 复用纯 `SurfaceContents`，不导入参数 writer；独立的运行中协议和 store 处理取消、重连与旧事件拒绝。

## 用户可见流程

1. 原有已保存回答继续显示，当前编辑与本机草稿不受新预览影响。
2. 模型开始生成计划时显示“正在生成预览”。只有组成部分已经闭合、依赖完整且正式编译校验通过，才逐步显示相应内容；其余部分继续等待。
3. 所有预览控件只读，明确标记“生成中，内容可能调整，尚未保存”。不能把预览中的建议初始值描述成用户当前已保存参数。
4. 用户点击现有停止操作时立即停止接收该运行的新预览，显示“已停止，原回答仍保留”。该操作使用现有任务取消流程；不另造一个表面停止而后台继续发布的按钮。
5. 完整最终参数到达后，重新编译全量计划。工具执行成功后进入现有“候选，等待发布确认”；只有精确磁盘回执与发布校验完成，才能进入可编辑状态。
6. 生成失败、权限拒绝或发布冲突时说明当前状态，保留旧回答与草稿。完整候选的失败信息由现有候选生命周期负责；未形成候选的碎片不成为历史回答。

## 1. 原始增量收集与闭合判断

新增服务端功能模块，例如 `lib/intelligent-ui/preview-runtime.ts` 与 `preview-parser.ts`。通过 `bindAnswerOutputGeneration()` 绑定运行，在 `rpc-manager.ts` 的原始 SDK 事件订阅点观察事件，位于浏览器压缩传输之前。聊天公共层只转交事件和通用回答预览，不解析 Intelligent UI 计划。

每个收集器绑定宿主的会话、PromptRun、已捕获模型请求、独立流身份、工具调用及内容位置。不能只按 surfaceId 或 toolCallId 复用；模型重试、回退和新助手消息可能建立新的流。同一调用换了内容身份时，旧流先失效。

收集时必须同步复制增量字符串、工具标识及必要的原始参数信息，再进入节流或异步工作。不得保存 SDK 共享 `partial` 对象供稍后读取。

原始 JSON 采用有界的词法/结构扫描，只承认实际接收到的字符串结束符、容器结束符和合法分隔符。完成的顶层标量及 `inputs`、`derived`、`views`、`layout` 的完整数组成员才可加入已闭合集合。字符串转义、Unicode 转义、数值尚未结束、括号出现在字符串内等情况必须正确处理。拒绝重复键、危险属性名、非法分隔符和超限结构；不得通过补括号、补引号或删除字段修复流式输入。

不能只对 SDK 已修复的 `arguments` 调用 `JSON.stringify()` 来恢复原始流。供应商适配应有以下明确行为：

- 已取得完整原始前缀及后续增量：正常扫描；前缀重置必须成为显式 reset，而不是继续追加。
- 开始事件已经携带原始 JSON：先接收该原始内容，再接收后续增量；避免重复计入首块。
- 仅有结构化开始参数、无法证明其闭合性：等待可验证的原始流或结束事件，不猜测半截内容。
- 供应商不提供参数增量：保留进度提示，在最终完整参数通过校验后显示完整候选，报告该供应商没有中间预览，不能伪称已逐段生成。

现有服务器事件已经提供原始 `toolcall_delta`，通常不必修改通用 SDK 事件。若某供应商在开始或 reset 时缺少原始内容，则在该供应商适配层补充可验证的 raw snapshot/reset 信息，并按仓库的依赖补丁机制维护；不能在前端从修复结果逆推。此补充只服务预览，不改变最终工具参数或正式发布依据。

## 2. 从完整片段形成合法预览

不能将半截 Plan2 送进渲染器，也不能把正式编译器改成容忍缺失字段。`lib/intelligent-ui/preview-plan.ts` 从已闭合成员建立依赖完整的投影。实现复用同一声明解析、图类型检查及表达式编译内部函数，再用正式 `validateRichSurface()` 校验投影。专用于预览的入口允许尚无结果节点的完整控件块，不制造占位结果；正式 `compileUiPlan()` 与 `compileUiRichPlan()` 仍要求完整计划和至少一个结果。最终完整参数始终重新调用 `compileUiRichPlan()`。

Plan2 的最小展示单位为一个完整布局块。每次更新按以下规则收敛：

1. 根级 planVersion、id、title 必须完整且有效。保留原始顺序和稳定 ID。
2. group、comparison、filteredTable 本身必须完全闭合。比较卡片不能只收到第一张就伪造第二张；表格节点也必须完整，不展示正在截断的行。
3. 布局引用的 input/view 必须完整，其引用到的 derived 及其他派生依赖也必须完整。前向引用尚未到达只表示等待；闭合数据已经证明存在类型错误、循环或冲突则撤销相关预览并等待最终诊断。
4. 所有被展示计算依赖的控件都必须位于已完成的布局块。筛选表格所引用的筛选控件也必须满足该条件。逐步排除依赖未闭合块的内容，直到剩余块构成完整闭包；没有闭包时只显示进度。
5. 临时子计划只包含上述块、完整输入/展示节点及必要派生闭包。它必须独立满足引用、类型、运算、唯一 ID、完整布局归属、资源上限和默认求值等正式校验。预览投影不删除或修改最终计划，最终全量校验仍检查所有声明。
6. 后续成员暴露出重复 ID、重复归属、非法结构或超限时，立即撤销失效预览；不能继续展示为可用结果，也不能为保留预览而静默丢弃后续数据。

预览默认展示计划提出的初始值，并明确它尚未保存。若展示已有任务的已确认参数，只能从本次宿主捕获的上下文中按同一兼容规则选取，不能凭同 ID 推断字段含义相同。预览不读取或接管另一窗口未保存草稿。

生成顺序影响首次预览时间：模型将 layout 放在最后时，必须等到相关布局块闭合。可以在后续提示试验中比较更适合增量输出的字段顺序，但不能用未验证占位布局强行提前展示，也不能承诺所有供应商都有相同的首次预览延迟。

扫描总原始长度、JSON 深度、节点/块数量沿用并不放宽计划预算；另外限制每个运行的活动收集器数量和编译频率。只在闭合成员集合发生变化时编译，并合并短时间内的事件。预览限制不得重置现有 UI 尝试/纠错预算；纯预览不调用工具执行，也不把每个增量算成一次工具尝试。

## 3. 独立的瞬态传输与重连

新增通用的 `answer_output_preview` 事件及对应运行内快照。事件包含版本、kind、宿主 runId、公开的流标识、toolCallId、单调 seq、阶段，以及经过校验的临时 payload/只读说明。公开流标识不包含可提交凭据；私有 request/context 身份与来源摘要继续只留在服务器。

预览必须满足以下隔离约束：

- 不伪造 `toolResult`，不写会话 JSONL、generation journal、参数文件、恢复草稿或 IndexedDB 发送存档。
- 不放入模型后续上下文，不作为 saved 参数、已提交版本、导出内容或 fork 继承依据。
- 不携带可提交的 operationId、磁盘回执或其他出版权限。
- 正式 toolResult 到达后，以现有完整候选替代对应瞬态预览；不能把“停止流式传输”当作已发布证据。

`bindAnswerOutputGeneration()` 暴露事件观察、当前预览快照及清理接口；`rpc-manager.ts` 仅连接这些能力。`app/api/agent/[id]/events/route.ts` 连接后补发宿主当前运行的预览快照，并明确当前运行/流身份。订阅与快照之间的竞态通过同一 seq 规则处理，客户端仅接纳更高序号，删除/撤销消息也是带序号的终态。

快照只来自仍存活且来源匹配的运行内收集器，不能用历史半截 arguments 重建。服务器重启后若没有对应活动收集器，预览为空；已提交结果仍走正常历史读取。断线期间完成的工具结果、候选发布或取消，由原有运行对账与历史加载恢复，再清理瞬态记录。

## 4. 只读渲染、焦点与生命周期

新增纯展示组件，例如 `components/intelligent-ui/IntelligentUiPreview.tsx`，共享已校验节点和 `RichSurfaceLayout` 的显示代码。它不创建 `SurfaceState`、不注册 writer、不调用保存/加载/迁移接口，所有控件禁用。预览容器与已保存界面是独立实例。

`AnswerOutput` 增加独立 preview 输入或从通用预览上下文读取；`MessageView` 继续只负责回答输出位置。`useAgentSession` 或独立通用预览 hook 保存瞬态 map，不能将其混入 `messages`。`ChatWindow` 只提供当前会话/分支作用域与该通用状态。

预览根 key 使用 session/run/stream/toolCall，不含 snapshot 文本或递增 seq；布局块、卡片、节点按稳定 ID 更新。追加块不能重挂已有块、抢焦点或触发自动聚焦。原有可编辑 UI 的组件 key、writer、参数和滚动位置不因新预览更新而改变。正式候选交接时也不自动移动用户正在编辑旧界面的焦点。

| 事件 | 必须采取的行为 |
| --- | --- |
| 用户停止、运行撤销、wrapper 销毁 | 同步撤销接纳资格，清除定时编译和当前预览；迟到计算结果不得再发送 |
| 新模型请求、供应商重试或回退建立新助手流 | 建立新的流身份；旧流失效，不沿用其半截参数 |
| 分支导航、fork、会话切换 | 对原作用域清理预览；新作用域只接纳自己仍有效的宿主快照 |
| toolcall_end | 使用权威最终参数重新全量编译；与前缀不同也不能把旧预览当作依据 |
| 参数结束但工具尚未执行或等待权限 | 最多显示“校验完成，尚未执行/发布”的只读内容，不新增权限 |
| 参数校验失败、权限拒绝、工具错误 | 撤销瞬态预览，走有界诊断/失败展示；不能制造候选或成功状态 |
| 完整工具结果建立候选 | 将瞬态预览交接给候选显示；候选仍由现有 journal 回执流程决定发布 |
| 参数写入或分支状态在生成期间变化 | 保留旧参数及草稿；正式发布继续执行源版本 CAS，预览不能绕过冲突 |
| 前端关闭 Beta | 立即隐藏图形预览，保留普通进度/文字；不能由隐藏操作伪造服务器发布或取消结果 |
| 重连或刷新 | 使用当前宿主快照和正式历史恢复；过期 seq、不同 run/stream/分支的内容不复活 |

最终参数替换是正常的权威边界：无论先前预览是否完整，都必须重新检查。若只在结束时发现供应商替换，丢弃原前缀收集器并使用完整最终对象；若完整参数也非法，则报告失败。预览完成不等于工具已接纳，更不等于已保存。

## 需要修改的模块

| 模块 | 责任 |
| --- | --- |
| 新增 `lib/intelligent-ui/preview-parser.ts` | 严格闭合扫描、重复键检查、原始字节/结构预算及显式 reset |
| 新增 `lib/intelligent-ui/preview-plan.ts` | 构建依赖闭合子计划，复用正式 Plan2 编译器与 Surface 校验 |
| 新增 `lib/intelligent-ui/preview-runtime.ts` | 宿主流身份、节流、seq、撤销和运行内快照；只输出已校验预览 |
| `lib/answer-output-generation.ts`、`generation-runtime.ts` | 将收集器绑定已捕获请求与清理边界；完整结果交接，不改变候选提交条件 |
| `lib/rpc-manager.ts` | 转交原始 SDK 事件，发通用预览事件和快照，保持功能模块隔离 |
| `lib/agent-event-transport.ts`、SSE route | 保留新的预览事件与重连快照；普通文字 delta 压缩行为不变 |
| `lib/answer-output.ts` 或单独通用类型模块 | 定义与 durable answerOutput 不可混用的 preview 契约和校验 |
| `hooks/useAgentSession.ts` / 通用预览 hook、`ChatWindow.tsx` | 当前运行/分支作用域、瞬态 map、取消清理与重连对账 |
| `components/AnswerOutput.tsx`、`MessageView.tsx` | 输出位置、阶段状态及候选交接；不把半截参数直接交给渲染器 |
| 新增纯预览组件及共享内容组件 | 只读节点/布局渲染，稳定 key 与焦点；不连接参数 writer |
| 供应商适配与现有依赖补丁脚本（仅缺原始信息时） | 补充 raw snapshot/reset 的可验证事件，不用 SDK 修复值冒充原始前缀 |

generation journal 无需新增“流式碎片”状态。`candidate / committed / aborted` 继续只用于完整已编译结果；若后续字段迁移增加等待确认状态，预览也不能跳过该流程。

## 可验证场景与退出条件

1. **严格分片**：在每个字符边界切分合法计划；覆盖字符串转义、Unicode、负数/指数、空数组、括号文本。未闭合项始终不展示，分片方式不改变最终结果。
2. **结构异常**：重复键、重复 ID、非法布局归属、循环引用、错类型、超长字符串/过深结构、追加垃圾；不得由 JSON 修复器补成预览，不得继续使用已经失效的旧预览。
3. **完整依赖**：前向引用、共享 derived、惰性 if、跨组控件、比较卡片和筛选表格；只显示依赖闭合的块，默认结果与独立期望值一致。
4. **最终权威值**：供应商首块已含参数、空首块、完整单块、只在结束时有参数、最终参数重置；覆盖共享 partial 对象在异步工作前被修改的情况。正式候选必须来自最终值。
5. **真实事件链**：用 SDK 流式测试供应商驱动 wrapper → transport → decoder → AnswerOutput，验证第一批闭合块在工具结束前出现；单纯直接调用预览组件不构成该证据。
6. **取消与迟到**：在闭合前、编译排队中、预览显示后、toolcall_end 与 execute 间、候选提交前取消；在新运行中注入旧流事件。不得发布或复活旧预览，原答案与参数保持可恢复。
7. **刷新与重连**：浏览器断线时追加块、完成发布或取消，重连快照与实时事件交错；只接纳当前身份和较新 seq。服务器重启不从历史半截参数恢复生成中界面。
8. **焦点和草稿**：用户编辑旧回答、选中文字或滚动表格时不断追加预览；旧输入的 DOM 身份、焦点和本机草稿保留。预览无 GET/PUT 参数请求、无 writer、无恢复存储写入。
9. **权限与隔离**：Beta 关闭不加载图形预览；权限拒绝不生成候选；预览不会进入后续模型上下文、会话导出、fork 继承或保存成功提示。
10. **资源与退化**：最大合法计划、多工具调用及高频碎片不会无限编译或缓存；不支持增量的供应商如实显示普通进度。测量首次有效预览时间、编译次数与事件大小，不把完整候选的首次出现计为增量收益。

退出条件是上述链路和失败边界有实际测试证据，且至少一个真实支持参数流的供应商在自然请求下展示了工具结束前的有效片段。其他供应商是否支持、真实桌面及跨平台覆盖分别记录；未验证项保持未完成。不得以本设计文档、原型单测或“工具有 onUpdate 回调”代替 2C 增量预览验收。
