# Intelligent UI：组件与小应用互转

同一任务可以在组件界面和小应用之间切换。模型必须明确提出转换并引用当前保存的来源；用户核对参数并确认后，新版才成为当前答案。沿用同一个任务 ID 本身不会触发转换。

## 用户操作

候选结果显示“核对切换 / 刷新”。打开后可查看旧版参数与摘要、新版参数及变化说明。新版先显示自己的默认值，不按同名字段、相近标签或推测的单位自动复制。

用户可以逐项选取类型和取值范围兼容的旧值，也可以直接填写新值；服务器仍校验整份输入。选择旧值只表示用户明确采用该数值，不代表系统证明了两种业务含义相同。

跨形式转换重新初始化任务进度、步数、随机状态与镜头。原版的已保存状态保留在历史中。同一小应用的进度迁移是另一项能力，不能与此转换混用。

确认后，旧版在当前分支变为只读，新版恢复可编辑状态。取消、校验失败或尚未完成的确认保留原版。响应丢失后先刷新核对结果；相同请求只恢复原来的决定，不重复发布。

## 生成契约

目标小应用计划或第二版组件计划可声明 `conversion`，包含：

| 字段 | 含义 |
| --- | --- |
| `fromKind` | 来源形式，必须与目标形式相反 |
| `fromToolCallId` | 当前来源的工具调用 ID |
| `fromDigest` | 已保存上下文 `conversionSource.digest` 的准确值 |
| `description` | 变化及无法保留内容的说明 |

目标保留来源的逻辑任务 ID。来源身份包含确认的结构、参数、状态与版本；小应用还包含当前进度和视图。生成和用户确认分别复核来源。来源变化后不能悄悄套用旧方案，需要重新生成提案。

新计划分别采用 `mini-app-1.9` 或组件编译器 `2.6.0`。没有转换声明的旧计划保持原身份。`outputConversion` 能力只有在当前源码的验证证据有效、运行环境可用时才对普通生成开放。

## 持久化和权限边界

确认走同源宿主接口 `/api/sessions/[id]/answer-output/conversion`，占用会话变更权并拒绝正在执行的模型任务。Beta 关闭、取消请求或会话变更会使当前授权失效。授权是内存中的不可序列化对象，模型计划或 iframe 不能构造。

确认顺序为：校验准确来源与选择、隔离试运行目标、保存选择意图、保存目标状态、保存完成回执。只有最后一步完成，当前分支才启用目标。读取不会自动补完未完成的意图。

目标状态先写入但完成回执尚未写入时，原版仍可使用。重试相同选择核对原状态和结果；用户也可以刷新后取消。取消不删除原版，也不启用已经暂存的目标。旧分支和确认前的 fork 不继承之后的切换；确认后的 fork 继承已选择的状态，不继承执行授权。

生成、试运行和转换本身不会执行项目文件动作。目标中声明的宿主动作仍按各自的会话权限和单次操作回执执行。

## 验证范围

接口验证使用真实 SDK 文件、原有会话锁和隔离运行时；界面验证使用实际 React 组件、iframe、Worker 和生产接口。输入计划是确定性夹具。这些结果证明协议及操作流程，不代表自然语言理解正确率、原生桌面多窗口验收、其他操作系统或完整 CI 已通过。
