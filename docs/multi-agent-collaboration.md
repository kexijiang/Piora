# Piora 多 Agent 协作工作台

## 产品目标

群聊默认以直接对话和用户自定义成员为中心。成员只需名称，可选填写擅长领域、性格或交流方式；普通对话不要求固定分工，也不强制进入任务规划与审查。需要项目分工时可选择高级任务编排。房间保存成员身份、消息和公共产物；Session 是成员使用的执行载体。

## 核心模型

### Room（协作空间）

- 可修改名称与说明。
- 绑定一个项目，成员只能绑定该项目及其 worktree 中的 Session。
- 保存协调模式、协调者、并发上限和租约时长。
- 控制面数据（消息、任务、审计、产物索引）始终由 Piora 托管，用户不能误移动或破坏。

### Agent identity（稳定身份）

- `memberId` 是稳定身份；`sessionId` 是可替换绑定。
- 每个成员可配置显示名称和自由文本设定，设定、系统提示词、风格与约束都会进入群聊回复上下文。
- 普通新增成员共享当前目录，不自动创建工作树。托管会话只显示在群聊中，复用的独立聊天仍保留在聊天列表。
- 高级任务编排支持协调者、规划者、执行者、审查者和参与者；内部管理身份不要求用户预先定义角色。
- 换绑 Session 时保留 `memberId`、私有目录和团队身份；待办任务自动迁移到新 Session，运行中的任务必须先结束。

### Shared workspace（共享工作区）

- 与 Piora 控制面目录分离。
- 托管模式使用房间自己的 `workspace/` 目录。
- 自定义模式允许选择项目根目录内的任意目录，并自动创建。
- 可配置工作区名称和协作说明；这些信息会注入每个 Agent 的上下文。

### Task orchestration（任务编排）

- 任务具有执行者、优先级、依赖、重试次数、租约和产物。
- 并发受房间上限和 worktree 冲突双重约束。
- 协调者可手动分派；失败或忙碌原因必须在 UI 中可见。

## 权限与不变量

- 只有协调者可以修改房间、成员、共享工作区和编排配置。
- 房间至少保留一名成员；移除协调者时必须先转移协调权。
- 同一 Session 在一个房间内只能绑定一个 Agent 身份。
- 自定义共享工作区必须位于房间项目根目录内。
- 运行中的 Agent 不能换绑 Session 或被移除。
- 控制面消息、任务、审计和产物元数据不随共享工作区切换而移动。

## 群聊交互

参考 Grok Bot 官方的[成员资料](https://docs.x.ai/grok-bot/bots)与[群聊协作](https://docs.x.ai/grok-bot/chat-and-collaboration)说明（2026-10-20 查阅），本地实现采用以下交互：

- 用户直接发消息时由成员判断接手人；@ 指定成员，回复消息指向原作者，多人 @ 可以分别接收请求。
- 自由群聊的成员可按需直接交接，不必经过固定协调者。交接应说明已有结果、下一步和负责人，避免重复执行。
- 每次回复附带群目标、成员名单和有界的共享消息上下文；不会把其他会话的私有历史拼进群聊。
- 自动交接保留轮数上限，达到上限后停止唤起新成员；广播回复不继续自动扩散。

- 主区域保持消息流与简洁输入框。
- 顶部设置按钮打开全屏内的轻量设置面板，而不是把表单堆在聊天侧栏。
- 设置分为“概览 / Agent / 工作区 / 编排”四个清晰页面。
- 成员列表展示名称、设定与运行状态；“添加成员”直接进入成员设置。固定职责、绑定会话、工具和工作区策略收在高级设置中。
- 移动端默认显示聊天，详情与设置作为可关闭抽屉。

## 兼容迁移

- v1 房间读取时升级为 v2。
- 旧成员使用原 `sessionId` 作为稳定 `memberId`，因此原 private 目录保持可读。
- 原 `shared/` 保留为 Piora 控制面；新的 Agent 文件协作目录为 `workspace/`。
- 旧消息、任务和产物格式保持兼容。
