# 中转站写作体验补齐方案

## 目标与调研依据

以用户明确选择的“所见即所得、表格、图片”为本轮重点。中转站改用 Vditor 4.0.0，保持 Markdown 为唯一正文来源，复用现有自动保存、草稿恢复和冲突检测，无需迁移用户数据。

Typora 是商业闭源软件，[官方问题仓库](https://github.com/typora/typora-issues)不提供完整编辑器源码。可以研究它的交互方式，不能直接移植其专有实现。

## 开源方案取舍

| 方案 | 特点 | 结论 |
| --- | --- | --- |
| 继续扩展原 CodeMirror | 源码编辑成熟，但已有实现只有标记隐藏，表格与图片缺少结构化交互 | 自行维护富文本选择、表格操作、粘贴与撤销，工作量较大 |
| [Vditor](https://github.com/Vanessa219/vditor) | MIT；同一实例支持所见即所得、即时渲染、源码；内置表格、任务、HTML 粘贴转换与图片工具条 | 采用；适配现有存储，补齐图片尺寸与生命周期问题 |
| [Milkdown Crepe](https://milkdown.dev/docs/guide/using-crepe) | MIT；ProseMirror 体系，结构化编辑能力完整 | 可行，但需要引入更多编辑器与 UI 依赖，现阶段适配成本高于 Vditor |
| [Cherry Markdown](https://github.com/Tencent/cherry-markdown) | Apache-2.0；Markdown 与预览联动，表格图片能力丰富 | 可行，Vditor 的三种编辑模式更贴近本轮目标 |

对照官方文档（2026-09-09 查阅）：

- [表格编辑](https://support.typora.io/Table-Editing/)：可视化单元格、行列增删、对齐与 Tab 导航。
- [专注与打字机模式](https://support.typora.io/Focus-and-Typewriter-Mode/)：突出当前段落，在输入时保持光标居中。
- [图片](https://support.typora.io/Images/)：粘贴、拖放、文件选择和文档附件的可携带性。
- [大纲](https://support.typora.io/Outline/)：结构导航、当前位置标识与标题搜索。
- [导出](https://support.typora.io/Export/)：适合阅读和分享的 HTML、PDF 等输出。

## 现状与改进

| 工作流 | 现有问题 | 本次实现方向 |
| --- | --- | --- |
| 可视化排版 | 只隐藏部分 Markdown 标记，表格和待办交互不完整 | 默认所见即所得，可切换即时渲染或源码；可编辑表格和待办勾选 |
| 格式输入 | 按钮简单插入符号，动态组件引用还截住了操作 | 使用原生选区格式工具栏，修复动态组件的引用传递；保留撤销与重做 |
| 表格 | 只能手写竖线和分隔行 | 单元格直接编辑、Tab 导航、行列数量和插入/删除操作、对齐工具；窄窗面板限制在编辑区内 |
| 图片 | 正文拖放可能变成独立资料；尺寸不保留 | 文件选择、正文拖放、多图粘贴；说明、标题、宽度编辑；图片写入期间暂时锁定编辑位置，关闭文档等待上传结束 |
| 文件流转 | .md 内的本机 API 图片链接离开应用就失效 | 无本机图片时导出 .md，有图片时导出含相对路径图片的 ZIP，附件失败时明确报错 |
| 编辑可靠性 | 有自动保存与冲突恢复基础 | 复用现有控制器，验证格式、表格、图片同样进入保存和撤销流程 |

## 技术方案

- 通过动态加载隔离 Vditor，打开中转站文档才加载编辑器。每份打开的文档保留一个实例，切换标签或随身仓工具时保留编辑状态。
- 关闭 Vditor 自带缓存，继续使用 markdown-draft 的本机恢复副本、自动保存与版本冲突保护；打开文档本身不触发源码格式化写回。
- Markdown 不原生支持图片尺寸，使用标准 `<img width="…">` 表达，并通过小型 Lute 适配器在所见即所得中保留普通图片交互。
- 保存、复制、导出、阅读切换前同步实际编辑器内容；输入法组合完成后同步，超长文档禁止误报保存成功或关闭。
- 编辑器资源由 postinstall 和开发/打包前置脚本复制到版本化的 public 路径；无需外部 CDN。数学渲染复用项目锁定的 KaTeX，阅读模式继续使用已有 Mermaid 渲染。
- 导出仅读取文档实际引用的中转站图片，不扫描其他文件，不将资料上传至外部服务。
- 浏览器测试使用真正的 Vditor 和动态组件，覆盖表格编辑与行数撤销、待办、图片位置和尺寸往返、查找替换、窄窗面板、超长输入及失败草稿保护；导出测试检查图片去重、相对路径和附件读取失败。

## 能力边界

本次完成优先选择的编辑能力，不宣称完整复刻 Typora。图片宽度通过输入像素值调整，暂不提供拖拽缩放手柄。富文本修改会按 GFM 重新序列化 Markdown，已有文字格式空白可能规范化；源码模式可直接编辑原始文本。

研究后续项：当前段落专注、打字机定位、大纲筛选/当前位置、自包含 HTML 和打印导出。Pandoc 的 Word/EPUB/LaTeX 双向转换、主题市场和任意本地目录双向监控属于独立工程。
