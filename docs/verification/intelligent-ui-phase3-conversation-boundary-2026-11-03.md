# 第三阶段对话边界与会话生命周期

## 问题与处理

上一批桌面测试在追问后立刻操作小程序时，保存返回 409。回答文字已经出现，并不代表服务器收尾、历史重新读取和交互状态刷新已经结束；新编辑可能仍携带旧的对话位置。单独串行处理刷新与保存，只处理了检查点锁重叠，没有覆盖文字出现到状态同步结束之间的时间窗口。

本批通过公共回答输出上下文传递“暂不可操作”状态。回答生成、命令运行、压缩和历史/状态同步期间，保留已挂载的界面与草稿，暂时禁止鼠标和键盘修改；同步完成后恢复操作。小程序自动播放同时暂停，恢复可操作后保持暂停，由用户决定继续。提示为“回答和状态同步完成后，可继续操作”。

普通聊天只提供通用生命周期状态；界面模块自行处理播放，未向 ChatWindow 引入小程序计算、存储或迁移实现。组件和小程序通过同一回答容器接入，Beta 默认关闭及按需加载保持不变。服务端的分支、程序身份及版本校验未放宽，待确认草稿也不自动跨分支迁移。

## 验证方式

真实浏览器测试改为使用实际 AnswerOutput 容器、React 小程序界面、隔离运行器、IndexedDB 和生产状态接口。播放中开始对话，保存并保留原 iframe；在人为延迟状态 GET 时执行原生鼠标与键盘操作，核对没有新编辑进入。释放同步后再点击加一，确认新对话位置下保存成功。另用真实 hook 回调验证历史读取结束之后，仍需等待输出状态刷新，才解除同步标记。

这些是固定程序和确定性对话边界的开发验证，不调用真实模型。原有离线恢复、回执丢失、多窗口和兄弟分支冲突断言继续保留；没有靠修改保存协议或跳过冲突来通过测试。

实际回答容器与状态浏览器检查 19/19、按名称选择的 hook 收尾回归 5/5 通过；后者只运行了两个相关测试及其子项，不代表整个历史 hook 集成套件通过。能力验证 517/517 通过，57 个文件、14 项能力；公共回答容器及其上下文加入能力来源核对。Web 类型与修改文件 lint 通过。各组检查有重叠，不累计为模型正确率。
