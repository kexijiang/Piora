## 从最新值补到可核对的保存变化

上批飞机复测中，模型把“当前三个角度均为零”误说成“这一轮没改过角度”，并算错镜头距离。宿主原来只保留同一对话位置的最新检查点，无法向追问提供连续保存之间的变化。本批补充实际证据，不依赖飞机关键词，也不增加分类模型或生成重试。

每次确认保存，由宿主比较前后检查点，原子写入变化、状态版本、摘要和原有回执。精确重试及相同检查点不新增变化。最多保留 16 条、32000 字节；大值、深层值和旧记录的省略明确计数，不让附加摘要阻止合法保存。历史数据仍受原有全会话容量限制。

变化记录随分支隔离和复制继承，之后独立写入。旧版本没有记录时仍能读取，但更早过程未知；新程序修订从自己的检查点开始。客户端和生成程序不能直接提交这份证据。数组索引是位置，不能据此认定是同一事项被改名。

追问上下文仍限制为 11000 字符，保存变化最多占 3500 字符，当前状态优先。记录只证明两次保存之间的值，不证明具体按钮、未保存动作或完整点击顺序。镜头到目标点的三维欧氏距离由宿主计算，单位为场景单位；当前程序默认镜头也不是历史镜头。策略版本为 mini-app-intent-25。

## 实际回答：主要事实改善，语义检查仍未全部通过

最终角度为 0°/0°/0°，选中机翼。自动保存也参与记录：本轮有 131 个有差异的确认保存，保留最近 16 条，明确省略 115 条；这不是用户点击次数。末段记录包含偏航 7→0、横滚逐步 90→0，最后一条才是相机位置变化，终止状态版本为 137。最大持久历史为 5540 字节。

| 回答要点 | 独立核对 |
|---|---|
| 当前值与选择 | 三个角度为零、机翼选中，正确 |
| 改过后归零 | 引用横滚 90→84→77→…→2→0，并承认更早记录不完整；本次没有再以当前零值推断从未修改 |
| 镜头距离 | 当前与程序默认均为 11.543396…，正确；相对默认方位变化约 30°、仰角约 15°也符合独立计算 |
| 最近一次保存 | 只改变相机位置、角度仍为零，符合最后一条持久记录 |
| 复位历史 | 仍把 cameraRevision=0 解释为从未触发程序级复位；现有快照与部分保存记录不能直接证明完整历史 |

复位断言另做可复现反例：原程序将复位代次按 1000001 取模。在未修改的原程序中，以符合状态约束的 1000000 为起点，执行一次复位得到 0。这是生产 QuickJS 的构造反例，不是本轮 UI 操作，也不声称用户真的执行过这些次数。结论是零值不能独立证明“从未发生”。

开发核对曾把“最后一次角度变化”误当成最后一次保存；核对落盘顺序后已纠正，模型关于最后一次相机变化的说明应判为正确。保留这一复核过程，避免把审阅错误记作模型失败。其他附加说明不自动视为独立语义验收通过。
