## 1 失败时说清原因，并保留原请求

此前，保存目标已存在、参数文件缺失、参数内容不合法等情况，常被显示成相同的“无法确认结果”；操作记录中的错误还可能直接显示英文。用户无法据此判断该换文件名、修正参数文件，还是先查询结果。

现在错误响应与操作记录可以携带稳定的展示原因，宿主提供中英文说明与下一步操作。原诊断仍保留，放入可用键盘展开的“技术详情”；旧记录缺少新字段时，显示保守的状态说明，不要求重写历史。

| 情况 | 现在的处理 |
| --- | --- |
| 保存路径已有文件 | 明确说明不会覆盖，提示换一个文件名另存 |
| 参数文件不存在 | 显示缺失提示，引导放到已声明的项目路径后重读 |
| JSON 格式、字段或取值不符合要求 | 提示检查文件；当前参数不变，也不显示“采用”按钮 |
| 来源、参数或目标发生变化 | 提示查询最新状态，再按当前内容重新操作 |
| 写入结果不确定 | 保留核对保存结果入口，不把不确定状态说成保存成功 |
| 网络中断或服务器错误 | 查询不重发；用户主动重试时沿用同一个请求编号 |

### 恢复行为的修正

原实现把所有非成功 HTTP 响应都当成明确拒绝，包含服务器 5xx；查询尚无操作记录时可能提前解除“请求不明”。现在只对明确的 4xx 拒绝作此处理。未预期的服务器异常返回 500，浏览器继续保留原请求。即使查询暂时找不到记录，重试仍使用原编号，不自动新建保存请求。

这项修改保留原权限、目标校验、创建文件而不覆盖、明确采用参数等约束。模型生成的标题和按钮标签保持原文；本轮本地化针对宿主的状态和失败说明。

### 本地验证

服务端、文件与动作来源测试 32/32 通过；Edge 浏览器 12/12 通过，包含 11 个场景及父测试，均无跳过。覆盖已存在文件不改写、无效参数不改变当前值、错误原因重载后保留、旧记录兼容、技术详情的键盘操作，以及 500 后查询与手动重试保持同一编号。

类型检查与相关 ESLint 通过。中英文错误和无效参数的截图已查看。浏览器使用受控 API 夹具；真实路由与文件行为由服务端测试另行覆盖，没有把它们称为一条真实桌面端到端流程。本轮没有重新调用供应商模型。

### 实测模型范围

Flash 与 V4 Pro 的封存交互任务最终数值轨迹均为 29/30，属于上一轮冻结实验。Flash 有真实 Windows JSON 动作流程与一次参数流预览；Pro 尚无同等范围的桌面动作验证。其他供应商未获得本轮实测结论。

这些数字不代表所有任务可用。三次重复用于观察稳定性，不能当成三倍独立任务；已暴露封存任务若用于调优，必须转为开发集并另补未见任务。
