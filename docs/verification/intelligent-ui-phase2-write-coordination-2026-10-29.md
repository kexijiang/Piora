# Intelligent UI 第二阶段写入协调进展

版本 v2.1 · 2026-10-29 · 2B 实现中，尚未验收或发布。

本次推进生成、改参和会话变更的共同写入边界。工作位于本任务独立工作树，分支 codex/intelligent-ui；没有提交、推送或更新第一阶段 PR。完整第二阶段仍包含 2A 至 2D。

## 1 本次接入的行为

- 运行时从打开会话文件前取得写入所有权，并持有到模型、扩展启动及扩展关闭处理全部退出。另一个采用同一机制的 Piora 进程不能同时取得同一会话的写入权。
- SDK 的追加、迁移和重写在同步写入前检查所有权。打开文件时补换行的隐含写入也受保护；分支和复制在使用新会话 ID 前先取得其所有权。
- 旧参数保存与候选 journal 共用会话操作锁；删除会话先等待已接纳操作结束。已提交输出仍可读取，外部写入进程不会因为自己持有运行时而阻止另一个窗口读取快照。
- 重命名、修改系统提示词和复制会话等待旧运行时收尾结束；不会把进程内可重入的所有权误当作操作串行队列。
- 复制参数在动态加载适配器后重新检查源、目标所有权；候选发布在原子替换 journal 前再次检查。失效后保留原数据，不通过清理逻辑继续改写文件。
- 两层锁均核对真实目录身份及租约期限。旧持有者退出、释放或恢复心跳时，不会删除或续租已被另一持有者替换的锁。

同进程操作互斥、跨进程写入所有权和参数版本比较承担不同职责。锁不能替代分支及参数版本检查，读取到工具结果也不等于候选已经发布。

## 2 Review 与验证

独立 Review 发现并修复了三类遗漏：扩展启动等待用户输入时的退出死锁、离线修改与旧运行时收尾的竞争，以及旧读取锁误删替换锁。修复同时覆盖所有权冲突的 HTTP 409 返回、复制失败清理前检查，以及异步加载后重新检查写入权。

验证环境为 Windows、Node.js 22.19.0。最终 34 个测试文件、261 项全部通过，0 失败、0 跳过。相关回归包含真实 SDK、真实文件读写和两个 Node 进程，不依赖只有文字匹配的证明。原有源码断言仍保留，并更新为要求清理前先验证所有权。

重点场景包括：失败启动不泄漏所有权；关闭期间保持所有权；启动问题被取消后能完成退出；旧运行时追加的最后记录进入复制结果；复制参数独立保存；锁失效后不发布候选；同进程保存不丢更新；外部运行时允许读快照但拒绝改参；旧锁释放或进程退出不破坏新锁。

测试文件清单保留于本地 .verification/intelligent-ui-phase2-write-test-files.txt；最终合并输出为 .verification/intelligent-ui-phase2-write-tests-final.log。使用 PowerShell 读取文件清单作为数组，再执行 node --test；新增路由、清理前所有权断言和发布前失效测试均已进入本次最终合并回归。

Web 与 Desktop 类型检查通过；全仓 lint 为 0 错误、4 条既有告警。仓库卫生检查通过。当前是相关回归，不是全仓测试、桌面实机或跨平台验收；未执行 next build 或本地发布打包。

## 3 剩余工作和实际边界

这是一套协作租约。检查与文件操作不是操作系统级原子隔离，不能保证阻止外部非协作程序，或任意时刻暂停后跨过租约期限的文件操作。当前采用同步写前检查、安全释放和运行时撤销降低风险，不把 abort 当作写入保护。

尚需继续替换可能触发 SDK 文件修复的其他读取入口，并完成全部写入调用方核查。新计划工具的正式接入、磁盘回执后的发布、v1 与 v2 的完整写入兼容、fork/复制的 journal 继承和客户端旧草稿恢复仍未交付。

2A 仍需完整自然语言与泛化验收；2C 的组合布局、筛选和可取消预览，以及 2D 的受控动作、权限及端到端交付继续保留。当前改动没有把第二阶段缩减为并发保护，也不代表第二阶段完成。
