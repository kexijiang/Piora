## 1 已实现的行为

内部 Plan2 路径现在能在工具参数尚未生成完时显示已校验内容。原有回答继续保留；预览明确标记“尚未保存”，控件不可编辑。最终参数重新全量校验，仍须经过现有候选、磁盘回执和发布流程，才能成为可保存的正式回答。

| 环节 | 本轮实现 |
| --- | --- |
| 原始片段 | 服务端在 SDK 事件压缩之前同步复制参数增量；不读取 SDK 修复后的半截对象来猜测完整值。 |
| 严格解析 | 只接纳闭合字段和数组成员。拒绝重复键、非法转义、错误数值、追加垃圾和预算超限；数字在缓冲区尾部仍等待分隔符。 |
| 依赖与编译 | 分组、比较卡片、筛选表格等待完整引用及控件布局。共享正式声明和图编译逻辑，投影通过 Surface2 校验后才展示。 |
| 生命周期 | 绑定会话、运行、助手流、工具调用与递增序号。取消、重试和新请求清理旧状态；重连使用当前运行快照。 |
| 前端 | 通用瞬态 store 与独立懒加载预览组件。稳定 DOM key 保留焦点；真实工具结果优先；没有参数 GET/PUT、writer 或本机草稿写入。 |

严格上限为 64000 个原始 UTF-16 字符、深度 8、20000 个 JSON 值，同一助手消息最多 4 个收集器，80 ms 合并更新，每个调用最多 128 次片段编译。正式候选另有既有预算，预览不赋予额外执行或发布权限。

纯控件分组可以先出现，不需要伪造结果节点。正式完整计划仍要求至少一个结果；只对预览开放的片段入口不能用于工具发布。非法后续片段撤销预览，同一被撤销流不复活；合法的最终工具结果仍可走普通接纳流程。

开启内部验证需在服务启动前设置 PIORA_UI_INPUT_PROTOCOL=plan-2，并开启设置中的 Intelligent UI。默认生成协议尚未切换。没有可靠原始参数流的供应商只展示进度与最终完整结果，不声称支持中间预览。

核心单测日志位于本地 .verification/intelligent-ui-preview-unit-tests.log。SDK 测试为 lib/answer-output-preview-runtime.test.mjs；浏览器测试为 components/intelligent-ui-preview-browser.test.mjs、intelligent-ui-rich-layout-browser.test.mjs 和 intelligent-ui-browser.test.mjs。它们分别验证传输与渲染边界，尚未构成完整桌面产品的一条端到端自动化链路。

另用 DeepSeek Flash 对一个普通语言合成任务运行一次真实参数流：“周末四个人出去玩，门票每人30元，车费总共120元，吃饭每人40元。我想自己改人数和餐费，看看总共花多少、每个人出多少，也把费用明细列出来。”

首次有效预览约 12.19 秒，显示 4 个节点、1 个分组；约 12.54 秒追加为 8 个节点、3 个布局块；参数结束约 12.65 秒，最终为 9 个节点、4 个布局块。首次预览比参数结束提前约 0.46 秒。这是单模型、单样例观测，不能声称稳定提速或跨模型可用率提升。

运行采用 low reasoning、6000 输出 token、0 供应商重试、90 秒上限。只调用生成工具的模型声明，不执行工具，不写会话或保存参数；committed 为 false。默认值及人数、餐费、门票、车费变化共 35 个独立数字期望全部吻合。

Review 发现一个仍需优化的问题：门票改为 50 元后金额正确，表格公式文字仍写“单价 30 元”。因此语义验收保持 pending。证据、最终界面与源文件哈希见 docs/verification/intelligent-ui-phase2-preview-pilot-2026-10-29.json；原始探针保留于本地 .verification/intelligent-ui-preview-live-2026-10-29.json。

## 3 当前边界与接下来开发

第二阶段仍在实现中。预览不等于正式发布，不代表已有业务动作，也不能替代字段含义变化时的确认。默认协议切换、完整自然语言泛化评估及真实桌面验收仍未完成。

接下来继续完成结构变更候选的确认与取消流程，再接入已登记动作及其权限、幂等与失败恢复。真实样例中的静态说明与动态值一致性问题要加入通用策略和后续评估，不能只针对“门票”写规则。

增量预览后续验收还包括真实桌面消息链、供应商重置原始参数的适配、更多模型和字段输出顺序、切换分支/重连的完整产品路径。现有 SDK 夹具、store 和浏览器组件证据分别保留，不把它们拼称为已完成实机验收。

可用上述出游请求手测：生成时先观察只读块，继续生成时不应刷新旧回答的焦点；点击停止后预览清理；完整发布后才调整人数和餐费。快模型或字段较晚闭合时可能直接进入完整结果，不能仅凭肉眼没看到中间态判定失败。

第三阶段仍保留自定义小程序、模拟、教学演示和小游戏的隔离运行时。按最新安排先完成三个阶段功能，再统一处理 CI；当前未宣称第二或第三阶段已完成，也没有发布任何新版本。
