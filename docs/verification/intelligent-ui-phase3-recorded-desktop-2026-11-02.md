## 3. 已实现的共性修复

### 冷启动恢复沿用启动预算

恢复一个新虚拟机时，第一次 project 原先使用普通操作的 8 ms 预算，冷启动开销可能导致已保存程序停止。现在首次恢复投影可使用既有 200 ms 启动预算，仍保留累计 CPU、内存及外部超时约束；后续投影、事件和步进继续使用普通预算。失败的首次投影也会消耗启动资格，不能反复续期。

恢复不调用 init，不重置数组、计数、tick 或随机数状态。两项真实 QuickJS 测试使用可控时钟验证：复杂首次投影能恢复原状态；后续过慢投影与无限循环仍被终止。修复前失败记录和修复后桌面证据均已保存。

### 离散程序发布前最多检查 32 步

新生成的离散程序沿实际声明的步进操作试运行，逐步核对状态结构与渲染结果，到终点或 32 步即停止。连续程序仍只做原有的一步检查，纯事件程序不执行不存在的时间推进。最终发布的仍是初始状态，不会把检查进度交给用户。

错误返回步骤、字段路径和可修复标记，模型可据此纠正声明。原始 sorting-2 已复现为：第 5 步，STATE，state/swaps，repairable=true。通用递增计数器测试同样覆盖首步正常、后续越界，避免只针对排序样本修补。

历史状态读取只投影已保存检查点，不运行未来步骤，也不偷偷更改旧程序。本次没有重新生成排序样本，尚不能声称模型收到诊断后已成功修复它。

该检查只覆盖默认输入下的有界轨迹；第 33 步以后、其他输入与事件路径、公式含义、说明和颜色仍需其他验证。没有增加关键词触发、额外分类模型或无限重试。

### 可观察性与复用工具

桌面表面分别暴露运行、保存状态及动作错误码，诊断可以区分超时与状态越界。新增原始记录重放入口和真实模型内存转发模块；模型请求与后台命名分开记录，保留失败运行和最终清理结果。
