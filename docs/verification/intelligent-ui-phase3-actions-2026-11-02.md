# 第三阶段成果：小程序宿主动作

2026-11-02 | 专用 worktree：intelligent-ui/Piora | 分支：codex/intelligent-ui

## 1. 读取参数与保存报告已接通

**小程序现在可以声明项目内的参数读取和报告保存按钮，复用已有会话权限、执行及回执机制。** 按钮由宿主显示在小程序之外；生成程序、加载、投影、计时器和普通交互事件不能调用文件操作。第三阶段尚未完成。

| 操作 | 用户可见行为 |
| --- | --- |
| 读取参数 | 读取指定 JSON 文件，展示参数供核对；不会自动改变当前任务 |
| 采用参数 | 用户单独点击后，按输入声明顺序调用输入处理函数；保留当前任务状态，再由处理函数决定变化 |
| 保存报告 | 以服务端确认的参数、进度和结果创建 JSON 或 Markdown 文件；已有文件不覆盖 |
| 权限审批 | 沿用会话的读写能力和权限模式；安全读取可能直接执行，需要确认的写入等待一次性批准 |
| 重复或中断 | 同一请求读取已有记录；不能确认写入结果时显示不确定，只核对文件，不自动重做 |
| 视图恢复 | 采用参数后，两处同显视图恢复到同一新检查点；刷新页面仍保留结果 |

最多声明 8 个动作，路径限项目内、父目录必须已存在；保留原有文件身份核对、链接限制、JSON 重复键检查和大小预算。报告 Markdown 按文本引用保存，不将生成内容变成可执行标记。操作详情可展开查看，日常界面直接显示动作、目标文件和状态。

新契约为 mini-app-1.8，仅有动作声明的计划使用新身份；策略为 mini-app-intent-18。没有动作声明的历史计划保持原运行时身份。能力提示、工具字段、原始参数校验和执行继续使用同一能力清单。

## 2. 可复核的完整操作

确定性计数夹具的输入为 2，当前进度为 19，步数为 13，随机状态为 12345。保存报告前，文件不存在；批准后，磁盘报告记录上述服务端确认值。

读取参数文件得到 start=8，界面先显示建议值，当前进度仍为 19。点击“采用这些参数”后，夹具输入处理函数执行 19 + 8，得到 **27**；步数仍为 **13**，随机状态仍为 **12345**。两处实际 iframe 均显示 27，刷新后仍显示 27，并保留“已采用参数”的回执。

此例验证保留检查点并执行输入处理函数，不意味着所有程序都应按相加规则处理输入。业务状态变化仍取决于生成程序。另有崩溃夹具模拟“状态已保存、动作记录尚未标记采用”：重试读取原子保存回执，不再执行处理函数，也不会覆盖之后的新进度。
