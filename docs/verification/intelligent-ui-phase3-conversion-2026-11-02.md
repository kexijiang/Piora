# 第三阶段成果：组件与小应用互转

2026-11-02 | 专用 worktree：intelligent-ui/Piora | 分支：codex/intelligent-ui

## 1. 同一任务可以明确切换界面形式

**组件界面与小应用已支持双向转换，先核对参数，确认后再启用新版。** 模型必须引用当前已保存的准确来源并说明变化；仅沿用同一个任务 ID 不会触发切换。第三阶段尚未完成。

| 操作或情况 | 用户可见结果 |
| --- | --- |
| 核对切换 | 查看旧版参数、含义和结果，以及新版的默认值 |
| 选择参数 | 逐项选择兼容的旧值或直接填写；不按同名字段猜测映射或单位 |
| 确认 | 服务端校验并初始化新版，完成回执保存后启用；旧版成为只读历史 |
| 取消或失败 | 旧版继续可用；不会把暂存结果当成已完成的转换 |
| 响应丢失 | 刷新读取原决定，重复请求不重复发布 |
| 分支或 fork | 确认前仍使用旧版；确认后继承已确认的新版状态 |

跨形式转换重新开始任务进度、步数、随机状态和镜头，原有进度保留在旧版历史中。同一小应用的受限进度迁移仍是独立能力，不能与转换同时声明。原来的聊天模式继续通过独立输出适配器工作。

新契约为 mini-app-1.9，组件转换使用编译器 2.6.0，策略为 mini-app-intent-19。没有转换声明的历史计划保持原身份。模型上下文只暴露转换所需的公开来源引用，不携带内部操作 ID、请求 ID 或执行授权。

## 2. 实际操作核对

组件转小应用的夹具：旧组件参数为 3，新小应用默认值为 2。界面明确显示两个值；用户选取旧值并确认后，小应用从 3 开始。小应用转组件的夹具：旧输入为 7、当前进度为 19、步数为 13，新组件默认值为 3；选取旧输入后，新组件值为 7，旧进度 19 仍可从历史读取。

实际 React 控件、iframe、Worker 和生产接口完成上述两条流程。模拟确认响应截断后，刷新读取已完成的结果，只记录一次确认请求；重新加载后恢复选定参数。合成 DOM 点击不能触发确认。另有接口检查验证确认中断后重试、取消暂存新版、旧协议组件转换以及再次转回组件。
