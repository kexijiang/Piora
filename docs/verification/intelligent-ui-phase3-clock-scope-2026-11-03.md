# 第三阶段：任务进度与追问范围

2026-11-03 · 阶段性代码提交 · 第三阶段尚未完成

本批把宿主时钟与业务进度分开表达，收紧追问的证据范围，并完成新一轮 24 次真实模型生成。生成接纳率提高，但完整任务和回答语义仍存在失败；作为 upstream Draft PR #238 的开发中增量提交，不作为阶段验收通过。

## 代码变化

- 小程序上下文不再把宿主 tick 放在任务顶层，改用 runtimeMetadata 标明时钟和播放模式。任务进度从程序 state、声明结构及显示值读取，避免把引擎时钟叫作用户操作步数。
- 修订迁移仍保留原检查点的 tick/rng，持久格式和旧程序身份不变。本次没有改变小程序运行或保存逻辑。
- 公共策略更新为 answer-form-6，小程序策略为 mini-app-intent-23。单次试算只证明指定操作的影响；回答所问结果、说明未实际执行后结束，不额外推导其他操作的限制、最优路线或建议。
- SDK 回归和桌面重放同步核对实际请求里的状态摘要及独立宿主元数据，保留未来操作的试算断言。

## 保留的问题

- 三角形当前 A(0,0)、B(8,0)、C(0.5,0)，模型正确解释面积为 0，却额外建议把 C 移到 (0,4) 就恢复面积 12；实际应为 16。这一跨任务反例说明收紧提示尚未解决完整回答正确性。
- 两份排序没有调用 piora_inspect_mini_app，保留原始失败断言。当前游标和数组可支持部分下一组比较的推断，后续需区分已建立的事实与尚需试算的按钮后果；本批没有删断言或降低要求。新排序还附加了未请求的多步解释，不作为已验证路线。
- 旧排序本次没有再把宿主 tick=11 称为业务第 11 步，比较 2 次、交换 2 次的回答正确；单次改善不代表泛化已解决。
- 当前量杯和棋盘请求的数值正确，部分回答仍超出所问范围。三份明确后果回答本次没有复现此前的错误普遍性限制；这不是双人人工语义验收。

## 环境失败与恢复

上一批磁盘不足导致的失败和损坏汇总保留，未改写成成功。本批继续把已终止运行的 Next 缓存迁出 C 盘时，发现 PowerShell Move-Item 遍历嵌套 node_modules junction，导致当前 worktree 的十个依赖目录内容被移到归档位置。首次 TypeScript 和能力检查因此失败。

随后从归档恢复原文件，核对锁文件版本和逐文件内容，不跟随符号链接；十个依赖全部恢复，包清单和锁文件未改。后续能力、类型及桌面运行均在恢复后执行。另核对旧进程和端口已结束，将旧锁改名保留。缓存迁移需要检查嵌套链接，不能仅以顶层非链接判断递归移动安全。
