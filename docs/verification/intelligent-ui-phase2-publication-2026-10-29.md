## 1 本轮实现

计划协议通过内部验证开关 PIORA_UI_INPUT_PROTOCOL=plan-1 启用，每个扩展实例只提供一种生成契约。默认仍保留 Surface 协议，待真实模型与泛化验收后决定切换。本轮运行时通过不等于自然语言生成成功率已经提升。

| 环节 | 实际行为 |
| --- | --- |
| 模型请求 | 在当前轮次选择文字、澄清或 UI；冻结已保存参数、字段名称、结果摘要和来源版本，不增加分类模型请求。 |
| 生成候选 | 模型提交平铺计划，宿主校验引用、类型和复杂度；候选先只读展示，不能把结构校验当作已保存。 |
| 发布 | 观察 SDK 精确的 assistant/tool-result 磁盘记录，重新检查运行、分支和源参数版本，再一次写入已提交状态。 |
| 拒绝与取消 | 被拒候选立即记录为 aborted；下一请求得到 committed/rejected 及错误码。取消立即撤销旧运行，迟到结果不能发布。 |
| 参数保存 | 新旧协议使用共同锁域；拒绝过期版本和错分支写入，保留祖先编辑前已存在子分支的参数。 |
| 复制与导出 | 核对标签重排、原始回执和二次 fork；复制先在隐藏暂存目录准备，成功后发布。导出使用只读快照和一致的参数批量读取。 |

默认 Surface 协议也能读取 v2 已保存参数并解释结果。为保护这些参数，旧工具不能直接覆盖同 ID 的新版结构，会返回明确的不可修复诊断；已提交界面的控件仍可使用。回滚不重新解释新协议，也不删除新版数据。

生产扩展与模型评估现在复用同一份 Plan 工具说明和名称，避免评估提示与实际产品分叉。既有小样本试跑保留为历史证据，不作为本次新链路的泛化结论。

## 2 Review 与恢复验证

独立审查确认并修复：候选发布失败但仍显示等待、默认旧协议遗漏新版参数、多界面导出读取混合时点，以及复制尚未准备好的会话可能被列表提前发现。旧版参数、已提交新版和明确排除的候选分别核验；缺失或损坏的证据产生错误，不猜测成功。

草稿按独立 ID 保存，窗口刷新先恢复本机内容再请求服务器。服务器读取失败时仍显示草稿，并阻止依赖旧参数的发送。其他可恢复草稿可查看、另存或显式复制恢复；保留旧稿必须先读回确认，才能解除该稿的发送阻塞。

双窗口测试覆盖一边修改为 7、另一边修改为 8，一边保留旧稿不能清掉另一边的新稿。复制标签页还必须在恢复时建立独立副本，防止尚未编辑就选择丢弃时删除原窗口数据。旧 shared-key 草稿保留原记录，并通过经核对的归档兼容读取。
