# 第三阶段：修订前预演实际变化

2026-11-03 · Windows 开发验证 · 第三阶段尚未完成 · 本批未提交或推送

## 确认前可以看到什么

小程序修订核对页现在展示核对时已保存的进度，并提供“预演所选变化”。用户选好参数和进度模式后，先在隔离环境计算实际结果，再决定是否应用。候选的模型说明继续标记为提议，不再承担展示当前进度的唯一依据。

例如，旧计数为 19、起始参数为 7。用户将新版起始参数改为 8，选择保留相对进度，预演显示结果 20，并列出起始参数 7→8、计数 19→20；选择重新开始则显示 8。更改参数或进度模式会清除预演、停用确认按钮，重新预演后才可确认。取消不要求预演。

| 层次 | 本批实现 |
|---|---|
| 来源与结果 | 展示核对时的来源摘要、所选模式的实际投影摘要；不会改写旧版 |
| 数据变化 | 宿主比较检查点，区分新增、移除、替换和 null；超限明确未展示数量 |
| 确认绑定 | 摘要绑定候选、分支、来源核对、输入、模式和完整结果，确认时重新试运行并比对 |
| 过期与恢复 | 来源变化拒绝确认；刷新核对后再次预演；保留原有取消、幂等和回执恢复 |
| 外观与用语 | 表格沿用主题颜色与字体；区分运行时钟和任务步数 |

## 实现边界

读取核对的 GET 不执行生成代码。新增同源 POST 预演入口使用现有 Worker/QuickJS 限额和看门狗，试运行前后都核对 Beta、取消、忙碌状态、叶节点、候选及来源。预演不创建模型运行、确认意图或保存记录，不获得新的宿主文件、网络或进程权限。

确认重新试运行并检查 previewDigest，随后沿用锁内 CAS 和持久回执。旧客户端和历史回执未包含预演摘要时保留原有确认校验，新界面必须先预演。普通聊天没有新增迁移逻辑或专用判断分支。

变化详情最多 12 项、1200 字符，单值最多 256 字符；省略项不能视为未变化。结构差异不是业务语义证明，数组位置也不是业务身份。投影摘要来自生成程序，仍需任务结果核对。

## 真实模型桌面结果

运行 sBRwSc 使用原始合成量杯样本副本，固定配置名 DeepSeek V4.1 Flash，实际请求 deepseek/deepseek-flash、任务 thinking=enabled，无 Pro 或回退。共 5 次任务请求和 2 次后台标题请求，分别记录；服务别名不能独立证明内部修订。

六个任务步骤及桌面启动全部通过，完成 24 个保存检查点、3 次刷新、2 次预演和 3 轮真实对话。清理错误与页面错误均为空。

| 过程 | 独立核对结果 |
|---|---|
| 原始缺陷与进度 | 两杯均空误称目标杯已满；随后达到 3/4 升、6 步 |
| 取消第一次修订 | 返回 200；原始水量、历史和刷新状态保留 |
| 第二次修订预演 | 显示 3/4 升、6 步；结构变化 0，来源未写入 |
| 编辑旧版后确认 | 另一视图改为 3/5 升、7 步；旧确认返回 409 |
| 刷新核对并再预演 | 显示 3/5 升、7 步；结构变化 0；确认返回 200，保留 7 条记录 |
| 修订后使用 | 两方向空杯/满杯提示、重置、达成与失去当前目标、保存刷新及追问核对完成 |

两个并行视图通过测试挂载的同源应用 iframe 实现，分别持有 React 客户端，操作通过 UI 完成；API 与文件读取仅作准备和核对。不代表两个原生窗口、多设备或其他平台验收。

开发审阅核对两份修订说明与程序差异。最终候选改变 purpose、program、migration，文档/样式/状态结构保持一致。模型新增的“源杯空且目标杯满时同时说明两者”在程序分支中存在；本轮 UI 只执行既定四种无效操作，没有把额外组合写成实测通过。

第二份模型迁移描述仍写“已有 6 条记录”，而刷新后的宿主预演与实际迁移正确采用 7 条。这证明实际核对信息有必要；静态模型描述仍可能过时。最终追问的当前值及历史解释与记录一致，但额外历史说明和独立人工语义验收仍分开记录。
