# 第三阶段字段影响与追问复测

2026-11-03 | 3B 状态解释与反事实证据 | 第三阶段尚未完成

上一批量杯复测中，模型能读对当前 3 升与 4 升，却仍说“任何操作都会破坏结果”，甚至紧接着承认满杯不能接水。这属于解释错误：已确认状态和只读预演的数值正确，不足以保证模型的自然语言结论正确。本批继续使用原始程序、操作轨迹与自然追问，检验新的通用证据表达。

## 明确哪些字段保留、改变或未知

宿主增加字段影响表，将已验证的操作差异按当前状态和输入的叶字段整理。每行包含当前值、明确保留该值的操作、新值及对应操作、无法确定的操作。它只描述结构与数值，不猜测用户目标或按任务关键词匹配模板。

| 证据情况 | 表达与边界 |
| --- | --- |
| 完整差异中未改变某字段 | 将该操作列入该字段的 unchanged，而不是要求模型从遗漏推断 |
| 操作改变字段或删除其父对象 | 给出新值或 present=false；删除不等于 null 或零 |
| 差异不完整、值过大或父容器变化不足以还原 | 标为 unknown；不声称不变 |
| 按钮禁用或操作被省略 | 没有执行证据，不加入保留或改变集合 |
| 列表与新字段 | 下标仍表示位置；表只索引当前叶字段，新增字段保留在原差异中 |

例如，另一只杯子倒空时，目标杯的 4 升可以明确列为保留；提示文案或步数变化不再需要与水量变化混在一起判断。但宿主不据此宣布完成业务目标，仍需对照用户给出的规则。

字段表最多 12 行、1600 字符，单值最多 128 字符；大值和超限行计入省略数量。原有操作上下文 4500 字符、总状态上下文 11000 字符的预算不增加。空间不足时先移除补充字段行，再移除操作，避免字段表引用已删除操作，也不挤出当前状态。缓存与快照摘要绑定，重新压缩不修改缓存。旧计划身份、保存格式和 Worker 预演协议保持兼容。

共同回答策略更新为 answer-form-4：围绕被问到的具体数值或条件作答，区分“不必继续操作”和“所有操作都会破坏结果”。“所有、任意、没有、不能”等概括需要检查相关反例，证据不全时只描述已观察的备选。没有新增分类模型、额外模型调用、自动改写回复或任务白名单。

## 代码检查

新增回归覆盖实际隔离运行的量杯反例、字段删除与空值、路径转义、数组位置、父值替换、部分差异、禁用按钮、摘要绑定、预算及缓存不变性。真实 SDK 检查确认模型请求收到计数器 13→14 的字段事实，预演后磁盘状态不变。

能力验证 512/512 通过，57 个文件、14 项能力证据已更新；Web 类型检查、定向 lint 和脚本语法通过。首次直接运行定向检查为 12 通过、9 失败（含父检查）：源码变化后旧能力证明失效，生成被宿主拒绝，后续场景连带失败。通过隔离能力验证后，普通配置复测同组检查为 21/21 通过；首次失败记录保留。两组范围重叠，不能累计。

## 原始任务真实桌面复测

固定 DeepSeek V4.1 Flash 配置，实际 deepseek/deepseek-flash，开启推理、关闭回退，未使用 Pro。服务返回 ID 不能独立证明内部修订。五份原始任务完成 58 项 UI 操作（含 12 次刷新）及 5 次真实追问，原始文件摘要不变；预演和解释后保存快照、版本不变，清理无错误。

真实请求含 36 个操作，原差异与字段表按独立预期核对，其中 45 对字段前后值通过。所有操作均保留，超预算字段明确省略；产品逻辑不按任务名或字段名称分支。

| 样本 | 开发审阅观察 | 判定边界 |
| --- | --- | --- |
| 量杯第一份 | 当前 3/4 升与是否需要继续正确；正确指出倒空另一杯仍保留 4 升 | 仍主动补充操作建议；“什么都不会变”忽略提示文字变化，表述范围待收紧 |
| 量杯第二、三份 | 当前数值正确，但仍把倒空 3 升杯列为破坏结果 | 明确语义失败：字段表、原差异和隔离执行均证实 5 升杯仍为 4 升 |
| 棋盘第二份 | 正确说明中心一颗 X、轮到 O、尚无胜负 | 请求事实正确，不代替独立人工验收 |
| 排序第一份 | 正确说明比较/交换各 2 次、上一对 6/5、下一对 6/1 | 额外预测再下一步，不计入本批单步核对通过范围 |

因此，本批没有证明字段表和提示调整已经修复自然语言解释。两份失败从错误泛化变成明确错误列举，不能当作质量改善。字段表仅作为可核对的宿主事实保留，不作为语义正确性保证；不得把桌面运行器的 passed 写成五份任务均正确。

## 新发现的生成状态问题

从本批 UI 确认检查点追加只读隔离探测，三份程序的倒空另一杯结果均为 4 升，排除了该错误建议来自实际水量变化。另发现第三份原程序把 solved 当作“曾经达成”保存，却在当前状态文案中使用它：再次装满或倒空目标杯后，水量已为 5 或 0 升，界面投影仍写“5 升杯里正好 4 升水”。

这项探测执行真实隔离程序和投影，但不是新增 desktop 点击，也没有修补原始生成记录。需在后续生成与验收中明确区分历史成就和当前条件，并加入“达成后再改变条件”的独立轨迹。它与本批倒空另一杯时的错误解释是两个问题，不能互相归因。
