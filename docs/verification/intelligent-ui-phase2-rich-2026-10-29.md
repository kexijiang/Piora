工作位于本聊天独立 worktree，分支 codex/intelligent-ui。基线 HEAD 62c7401c、upstream/main 4ba01185（beta.59）。本轮延续 v2.3，未提交、推送或更新第一阶段 PR #238。

## 1 本轮实现

### 丰富布局接入生成、保存和追问

分组、方案卡片与筛选表格已从独立原型接入内部 Plan2 路径。模型提交平铺输入、命名计算、结果及完整布局，宿主编译为 Surface2，再经过已有候选、准确磁盘回执和发布检查。主聊天使用完整 Surface2 渲染，参数保存、刷新、追问、连续分叉、复制和导出均保留布局与当前参数。

| 能力 | 实际行为 |
| --- | --- |
| 分组与对比 | 同组可排一至三列；卡片复用原控件与结果，窄面板自动换行。每个节点恰好放置一次。 |
| 筛选表格 | 支持相等、包含和数值上下限，多条件同时满足；保留所有源行及稳定行索引，空结果与计算未知分别显示。 |
| 历史兼容 | 旧 Surface1 保持严格校验；版本适配保留完整 Surface2。旧生成器不能覆盖新版布局。 |
| 保存与恢复 | 沿用参数版本、分支和操作回执检查；草稿迁移保存完整布局，候选未发布时保持只读。 |
| 快照预算 | 发布前估算所有合法参数状态的完整文字快照，限制为 128000 字符，防止换选项后历史输出失效。 |

### 开启方式与边界

在启动服务前设置 PIORA_UI_INPUT_PROTOCOL=plan-2，并开启设置中的 Intelligent UI。新加载的扩展只提供 piora_render_ui_plan；一个实例不会同时暴露多个生成契约。仅开启 Beta 设置仍使用默认 Surface 路径，不能据此判断已启用丰富布局。

这是内部验证入口，默认生成协议尚未切换。Plan2 仍是受限声明，不执行模型生成的 HTML 或 JavaScript，也没有额外模型客户端或聊天数据库。模型判断回答形式，宿主校验能力、结构和预算；结构有效不等于任务语义正确。

### Review 修复

发现底层 SDK 会把 Integer 类型的小数列号自动取整。schema 改为 Number 加 multipleOf:1，实测拒绝 0.5、1.9、-0.5、11.1，合法整数保持原值；编译器继续独立检查列索引。快照上界另外覆盖最长选项、条件分支、计算错误、换行和行标记；独立复核未发现当前集合中低估长度的路径。

## 2 真实模型试跑

### 固定条件与初次结果

使用 4 个开发任务族、2 个真实配置模型，每任务每模型 1 次，共 8 次。任务为出游方案对比、课程筛选、一次性分账和缺少计费规则时澄清；均为合成数据。模型为 DeepSeek Flash 与 DeepSeek V4 Pro，low reasoning、6000 输出 token、每轮最多 3 次模型请求、2 次工具尝试、供应商重试为 0、适配器 90 秒及外层 95 秒超时。生产运行预算不同，不混为同一上限。

首轮采用 Plan2 与 intent-1：8 次均完成，4 次交互任务各调用工具 1 次并生成有效结构，另外 4 次直接回答或澄清未调用 UI。独立程序复算 4 个生成界面、12 个参数场景全部通过：出游默认 120/180，6 人加餐 240/330；课程初始四行，运动类上限 100 只剩篮球，文艺类上限 100 只剩摄影，上限 0 为空。

### 结构通过后仍发现的问题

Flash 的课程标题固定写入“全部 4 门、费用上限 200 元”，改变筛选后标题与表格不一致。两个模型都设置了未提供的人数或费用上限，Flash 还使用任意范围的滑块。部分出游说明没有明确基础单价或加餐条件；澄清问题偏多，包含仅为控件范围服务的提问。

因此将通用策略修订为 intent-2：开放数值默认使用数字输入，只有明确事实或数值含义支持时才添加约束；初始值不是最大值，不为滑块追问范围。标题、标签和普通说明是静态内容，变化中的值应通过指标或表格绑定显示；固定费用标明基础含义，条件说明保持条件句。澄清只问影响结果的必要业务信息，不加入业务关键词路由。

同样条件下使用 intent-2 另跑 8 次，全部完成；4 次交互任务仍各首次生成有效结构，另外 4 次直接回答或澄清未调用 UI。指定 12 个计算与筛选场景全部通过；再用原始课程数据作独立期望值，66 组类别/费用边界检查及 Flash 新增课程计数的 33 组检查全部通过。它们是程序检查次数，不是新增独立用户任务。

本次样本不再出现任意上限、费用步长或滑块；201 人和 1001 元上限均可正常调整，固定“200 元”的标题已消失。Pro 的出游卡片仍写固定“每人 30/45 元”，与加餐后的动态单价存在文案歧义；Flash 澄清仍列四项并提前承诺拖动、分档明细。不能把本轮改善写成这些问题全部解决。

复测后的独立 Review 还将定价措辞收窄为“区分基础单价、一次性固定费和当前总价”，避免把所有固定费用误标为单价。该最后修订有本地检查，未追加第三轮真实模型试跑。每轮保存完整提示词及源码哈希，原始证据不覆写。

### 证据的适用范围

这些试跑仅连接真实模型与隔离编译器；所有输出 committed=false，保存和浏览器交互均标记 not-tested。程序计算检查和代理文字评审分开记录，没有填写人工验收通过。样本属于开发集、每组合仅一次，不能证明跨领域泛化、稳定成功率或完整产品体验，也不能与旧 36 次试跑直接合并计算改善。

原始证据位于 .verification/intelligent-ui-rich-pilot/results，派生复算位于其上一层 derived-review.json。修订复测使用 .verification/intelligent-ui-rich-pilot-v2。可审阅摘要与原始证据哈希见 docs/verification/intelligent-ui-phase2-rich-pilot-2026-10-29.json。
