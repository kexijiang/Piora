## 2 最后增量与实际验证

### 动作说明与实现保持一致

此前模型把保存说成“生成时的值”，或建议批准覆盖同名文件。本次在工具结果和后续上下文中加入宿主提供的动作事实：实际目标、格式、点击时已确认的参数、只新建文件，以及当前权限模式。按钮旁也显示固定中英文说明，减少对模型文案的依赖。

权限模式只是当前观察，不是授权。生成 UI 不执行动作；点击时仍重新检查。full 无额外人工对话，review 可能自动通过或转人工，auto／ask 依现有策略处理；读取到的参数只有明确采用才改变当前值。权限设置损坏时标记未知，不推断为完全访问。

## 3 验收安排、限制与第三阶段交接

### 后置验收仍需执行

按用户最新安排，两位独立人工语义评判、分歧复核与 CI 留到三个阶段开发完成后。届时核对回答形式、澄清是否问到关键规则、业务计算与文案、权限组合和平台兼容；跨平台发行包验证及发布状态也需据实际结果记录。当前这些项目均为待完成，不计通过。

### 已知限制

- 生成与触发由模型选择，仍可能误解业务、生成失败或需要纠错；有界协议和技术评估不能保证所有自然语言输入正确。
- 动态说明可跟随参数更新，但模型仍可能在普通静态文字中写死结果。除零、条件与成本有相关检查，不代表覆盖所有业务边界。
- 本轮初次回答误称 Markdown 为“表格 + 合计”，实际为缩进的纯文字快照。最后已补充明确格式事实并通过本地检查，尚未再做真实模型复测，不能宣称这条文案问题已实测消失。
- 真实桌面证据来自选定 Windows 场景，不等于全部平台、模型和权限组合。恢复流程最终截图处于参数加载中，不用它证明完整刷新已稳定；状态和动作结论来自脚本断言及实际文件。

### 第三阶段工作边界

接下来是自定义小程序、模拟、教学和小游戏：先确定专用组件与隔离代码的选择条件，再实现受限运行环境、窄消息桥、资源预算、停止与回收、状态恢复和导出降级。至少完成一个模拟／教学案例和一个持续交互案例，验证正确性、输入与资源限制。

第三阶段复用第二阶段的开关、状态身份及受控动作，不让生成代码直接访问宿主、Node、凭据或高权限桥接。本报告只完成第二阶段交接，未将第三阶段计为已实现。
