## 1 本轮实现与使用方式

### 已接入：旧草稿迁入已提交的新版本

旧界面被新版替代后，可以选择“核对字段后迁移”。界面对照旧字段和新字段，显示名称、类型、数值范围、可选值及当前参数；每项默认保留目标的已保存值。用户明确选择哪些旧值要复制，再确认保存。

即使字段 ID 相同，也不自动认为含义一致；不会自行换算单位、截断数值或替换不合法选项。未选择字段继续使用目标已保存值。参数必须通过目标协议的类型、范围及选项检查；step 沿用现有协议的调节步长语义，没有另加仅针对迁移的数值网格限制。

| 环节 | 实际行为 |
| --- | --- |
| 核对来源 | GET 校验旧稿锚点位于当前分支；不能通过指定历史 leaf 绕过检查。 |
| 核对目标 | 保存前重新读取最新版，比较任务、结构、参数版本和分支；目标变化时要求重新核对。 |
| 保留原稿 | 先建立并读回确认独立归档，再创建带关联记录的目标草稿。失败保留原稿和目标草稿。 |
| 已有编辑 | 当前窗口目标未保存内容不能被迁移覆盖；其他恢复副本需明确保留后再处理。 |
| 保存确认 | 使用现有服务端版本比较写入；准确回执到达后才标记迁移完成，原稿继续保留。 |

本入口仅处理“旧草稿 → 已提交的新界面”。模型生成的候选若改变已有字段含义，当前服务端仍返回 MIGRATION_REQUIRED；不会把被拒绝或已取消的候选重新发布。后续用户确认方案另见 docs/intelligent-ui-migration-design.md，明确标为尚未实现。

### 独立原型：分组、方案卡片与筛选表格

新增严格的 Surface v2 数据契约与布局渲染组件，复用原有八类节点。分组支持一至三列，窄面板自动纵向排列；方案卡片可放置已有控件与结果；筛选表格由明确引用的输入控制，支持相等、包含及数值上下限，多条件按“同时满足”处理。

每个节点必须恰好放置一次，不能因布局遗漏输入或结果。筛选保留原始完整行数据和稳定行索引；无法计算的行标为未知并保留显示，空结果明确提示。文字快照包含全部明细及显示/筛除标记。原型限制节点、容器、行数、筛选数、表达式和 JSON 大小。

Surface v2 与 answerOutput 的封套版本是不同概念。新原型尚未接入模型工具、持久化及主聊天渲染链路；默认产品路径仍使用原 Surface 协议，不能把独立浏览器演示视为正式开放了这三种布局。

## 2 Review、验证与剩余工作

### 本轮 Review

审查发现迁移回执不能假设“版本恰好加一”，也不能在服务端允许同一分支单线前进时要求返回原叶节点；否则已经写盘的成功结果会被误报为失败。已改为核对实际结构、操作身份、精确参数及递增版本，并采用服务端验证后的分支结果。

另两项问题也已修复：关闭功能后不再新发参数写入，也不能仅因 flush 空操作返回就宣称迁移成功；已明确保留且内容完全一致的外部恢复副本不再永久阻塞迁移。原记录不删除，内容变化会重新阻塞。独立复核未发现这四项修复中剩余的可操作问题。
