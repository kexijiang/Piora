# 第三阶段恢复与修订交叉验证

2026-11-03 | 3C 保存、冲突与候选 | 第三阶段尚未完成

此前保存冲突、候选取消和进度迁移分别有局部检查。本批将它们组合为实际用户路径，并发现新一轮对话结束后，旧实例继续编辑会被误判为分支冲突。已补充公共状态刷新接口及回归验证；新增桌面场景复用原有生命周期和报告入口。

## 修复对话继续后的保存边界

服务端原本就要求保存绑定当前分支位置，不能拿旧位置静默覆盖新分支。问题在客户端：完成普通追问或生成下一份候选后，干净的旧小程序未重新读取位置，后续保存仍携带旧 leafId，因而得到 409。

现在会话结束并完成历史读取后，宿主通过公共输出接口通知当前会话的模块刷新；旧运行或已切换会话的迟到结束不触发刷新。小程序冻结输入并核对本机状态，仅在没有待确认写入和待处理草稿时读取新的保存边界。未确认草稿不自动换分支，也不被删除。刷新失败保留在交互界面，不把已完成的普通回答改成失败。

此实现不让聊天层依赖小程序内部类，不放宽服务端分支/版本校验，也不增加模型调用。相关浏览器回归覆盖普通对话后再编辑成功，以及有未确认草稿时保留原内容和分支、重试仍被正确拒绝。

## 两视图中的完整流程

浏览器验证使用实际 React 界面、生产 API、真实 SDK 会话文件、IndexedDB 和 QuickJS。两个视图共享同一会话及浏览器存储，编辑、保存、候选选择、刷新和导出全部经过 UI；API 只读取最终状态核对预期。计划由确定性计数器夹具提供，不验证模型生成质量，也不是两个原生桌面窗口。

| 流程 | 独立预期 | 验证结果 |
| --- | --- | --- |
| 两视图先后保存 | 第一份保存 8，第二份尝试保存 9，旧版本请求被拒绝 | 服务器仍为 8，第二份草稿保留 |
| 冲突后取消候选 | 旧核对摘要失效，需刷新后再取消 | 只有一次取消确认写入，原程序仍可编辑 |
| 刷新与草稿导出 | 不自动运行未处理草稿，可导出被拒绝的输入 9 | 导出包含原输入与状态；选择服务器 8 后再加一，输入仍为 8、结果为 9 |
| 核对后继续编辑 | 原程序改为起点 10、完成一步，结果 11、逻辑步 14 | 旧确认被拒绝；刷新后建议值为 10 |
| 显式保留进度 | 新起点 12，保留相对进度一，结果应为 13 | 逻辑步 14 和随机状态保留；旧版确认结果不变 |

## desktop 交叉场景

入口为 `npm run test:desktop:e2e -- --scenario intelligent-ui-recovery`。场景通过聊天生成计数器，模拟已成功保存但响应丢失，再经刷新查回执恢复；随后取消一次候选，再次修订，在核对期间修改原程序，验证过期确认被拒绝，重新核对并迁移进度，最后刷新、继续编辑和追问。

模型为确定性本地 HTTP 夹具，不使用用户凭据，不是 DeepSeek V4.1 质量评估。故障只发生在真实认证请求完成后的响应交付，不直接注入保存状态或回执。读取 API 用于核对；被验证的变更由 UI 发起。

修复后两次完整桌面复测均通过，最终版本共 10 个步骤（含启动和夹具安装）。成功保存 9 的回执在刷新后被找回，版本仍为 1，未重复 PUT。取消候选后旧程序继续到 11；再次修订期间继续到 12，过期确认返回 409。重新核对后将起点从 9 改为 12 并保留进度，结果为 15，逻辑步及随机状态不变。刷新后编辑到 16，追问读取 16 且不改写状态；追问结束后继续编辑到 17 并保存成功。最终三次候选决策状态依次为 200、409、200，清理无错误。

## 验证范围与失败记录

桌面首次执行在响应丢失步骤失败：Playwright 转发请求没有携带 Electron 的认证头，生产接口返回 403，服务器正确地仍保留初始值 2。此失败属于夹具边界错误，不是成功保存丢失。已将故障注入改为在渲染器中保留原始 fetch 请求，仅在其成功返回后损坏响应内容。没有放宽认证或直接写入检查点。

第二次桌面运行在 600 秒预算耗尽后失败，清理无错误。终态报告确认启动实际已在约 24 秒完成，随后停在未单独标记的场景准备阶段；原记录的 failedStep 仍为 launch，不能据此认定应用启动失败。改用普通网络响应观察及单次渲染器故障注入，移除额外跨进程绑定，并将夹具安装记录为独立步骤。后续运行结果单独记录，不改写失败。

第三次桌面运行已完成真实保存，但测试等待未消费的响应体而超时；改为先读完真实响应再损坏应用收到的 JSON，网络观察只记录方法、请求 ID 和状态。第四次进入再次修订后，发现本批实际产品问题：旧实例的 leafId 未更新，保存返回 409，后续确认尚未执行。该失败与之前三次夹具失败分别保留。

修复后，客户端及公共刷新回归 18/18、会话结束定向检查 6/6、服务端检查 21/21、测试框架检查 19/19 已通过；最新能力检查为 57 个文件、509/509，通过并更新 14 项能力证据。各范围重叠，不能累计。Web 类型与定向 lint 通过。类型检查首次误用不存在的入口，未实际执行；随后使用仓库 tsc 入口通过。会话测试只运行相关选择项，不能据此把历史整组失败全部改为通过。
