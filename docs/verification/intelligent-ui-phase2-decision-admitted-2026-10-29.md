v2.11 · 2026-10-29 · 接纳规则与触发决策。第二阶段继续开发，尚未整体验收。CI 按用户安排，在三个阶段功能开发后统一处理。

## 1 实现与本地验证

离线评估已接入应用使用的 bindAnswerOutputAdmission 与 SDK runToolCall，不再直接绕过运行预算。每个合成用户回合拥有独立预算，同回合中的模型请求共享最多三次接纳、一次纠错及从首次 UI 尝试起计的 60 秒窗口。原始 Plan 在 SDK 类型转换前验证；不可修复错误停止继续生成，第二次被拒调用以 admission-stopped 结束，明确计为失败。

运行前验证 SDK 补丁；取消、过期、重复调用和错误修复都经相同接纳路径处理。只有接纳完成的结构才替换评估内存中的前一版本。合成失败参数最多保留 64000 字符并标明截断，包含此前遗漏的 Plan 校验失败；原参数不进入模型诊断反馈，也未加入生产日志。

当前策略为 intent-4：由同一个模型结合上下文判断文字、澄清或交互，没有关键词路由或额外分类模型请求。必要的业务规则、费率、系数尚未确定时先问清，即使将其做成可编辑字段，也不能凭空填初值；用户已提供的数值应保留。用户明确要求假设试算或比较已指定方案时可以生成，上下文已给定规则时直接沿用。

## 2 两模型的决策边界比较

预先固定 12 个开发任务，每任务每模型重复两次；比较 intent-2、intent-3、intent-4，共 144 次运行。六类信息不足任务包含既有失败和新场景；另用明确假设、指定规则比较、已知多轮上下文、普通文字和缺少展示边界的请求检查过度澄清。每模型每策略包含 12 个澄清回合、8 个应交互回合、6 个文字回合；多轮任务使回合数多于任务数。

三个版本使用同一 Plan2 编译器 2.3、相同模型设置和已接入的运行预算。脚本核对了非策略依赖哈希、模型设置及适配器一致性；有效提示和工具声明分别冻结。表内顺序均为 intent-2 → intent-3 → intent-4。

| 观察值 | Flash | V4 Pro |
| --- | --- | --- |
| 完成任务 | 24 → 24 → 24 / 24 | 22 → 23 → 24 / 24 |
| 澄清回合中尝试 UI | 5 → 1 → 0 / 12 | 5 → 2 → 0 / 12 |
| 文字回合中尝试 UI | 0 → 0 → 0 / 6 | 0 → 0 → 0 / 6 |
| 应交互回合中未尝试 UI | 0 → 0 → 0 / 8 | 0 → 0 → 0 / 8 |
| 完成且首次结构有效 | 3 → 7 → 7 / 8 | 8 → 6 → 8 / 8 |

| 最终数值轨迹匹配 | 6 → 8 → 8 / 8 | 8 → 7 → 8 / 8 |

Pro 的旧版有两次超时，中间版有一次超时；均保留在分母，不能将其记为成功澄清。当前版本两模型各 24 次任务均结束；Flash 有一次格式错误后纠正，Pro 应交互样本首次结构均有效。

数值检查沿同一表达式改变输入，覆盖租金规则比较、1:2:3 分摊、明确授权的积分假设、纸袋数量计算。该检查在查看部分旧版输出后补充，只核对数值轨迹，不验证所有标签、边界、实际点击或持久化。

这组任务参与了调整，不能作为封存验收或泛化证明。两次重复不等于两倍独立任务；供应商波动与顺序采样也限制因果解释。没有执行两人独立语义评判。未调用 UI 本身不能证明澄清问题理解正确。

证据文件：intelligent-ui-phase2-decision-admitted-2026-10-29.json 保留前两版结果；intelligent-ui-phase2-decision-refined-2026-10-29.json 包含三版比较、逐回合答案、数值轨迹与文件哈希。原始冻结运行保存在 .verification/intelligent-ui-decision-admitted-v1 下六个独立目录。

## 3 剩余问题与试用方式

### 已确认的剩余问题

intent-3 中，两个模型仍曾把“积分规则未定”变成自填默认分值的工具。intent-4 在本轮同类请求中停止了直接生成，但 Pro 有一条澄清把“各做了 5 次”误读为“每次 5 分”，询问用户是否这样试算。这是事实理解缺陷，不能因为没有调用 UI 就记录为语义通过。

Flash 的规则比较请求仍出现一次 PLAN_SHAPE 后修复。已保存完整合成参数，后续应区分真实复杂度超限与可无歧义规范化的表达，处理不必要的格式重试；不能猜测缺失业务公式或放宽计算类型、安全和成本约束。

当前 intent-4 尚未在原 40 项开发集、扩充后的封存集以及完整桌面动作矩阵上完成复测。原有首次成功率目标、权限边界、取消、旧参数恢复、静态标题语义和跨平台验证仍需逐项证明。没有因本轮结果将第二阶段标为完成，也没有开始第三阶段任意代码运行。

### 用口语化请求检查

重新加载当前开发版本，开启 Beta 的 Intelligent UI 后，在新会话测试以下请求；模型可能仍有波动，应同时看问题理解与最终结果。

- “做个房租分摊工具，我们三个人分法不一样，具体怎么算还没定。总租金 6000。”应先问分法，不能擅自按均摊或权重生成。
- “租金 6000，我们已经定好按 1:2:3 分。弄个能改租金的工具。”应生成；初始为 1000、2000、3000，租金改为 9000 后为 1500、3000、4500。
- “积分政策还没定，不过我明确想先试每天签到给 10 分，先 5 天，弄个能改这两个数的小工具。”应生成并标为假设试算；初始 50 分，改为每天 12 分、7 天后为 84 分。
- “活动预算 9000，已经花了 6800，还剩多少？”直接回答 2200，无需交互界面。

下一步继续改进自然语言生成与澄清语义，再补齐正式泛化及完整产品链路证据。所有已知失败、超时和未覆盖项继续保留；CI 按用户安排后置。
