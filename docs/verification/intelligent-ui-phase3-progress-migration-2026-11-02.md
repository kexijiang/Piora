# 第三阶段成果：受限任务进度迁移

2026-11-02 | 专用 worktree：intelligent-ui/Piora | 分支：codex/intelligent-ui

## 1. 参数与任务进度分别处理

**修改小程序后，用户可以明确选择是否保留任务进度。** 默认仍为“重新开始”。候选声明受限迁移函数、准确来源摘要及影响说明后，核对页才提供进度迁移选项。迁移失败保留旧版，不自动换成重新初始化。第三阶段尚未完成。

| 层次 | 本批实现 |
| --- | --- |
| 来源绑定 | 同一 app ID、准确旧程序摘要及当前确认检查点；来源变化要求重新核对 |
| 输入参数 | 继续使用上一批语义与约束比较，允许用户修改确认值 |
| 任务进度 | migrate(previous, inputs, ctx) 只返回新版状态，接受新版结构校验 |
| 步数与随机状态 | 候选声明 preserve 或 reset，核对页展示对应影响 |
| 镜头与按键 | 镜头不传入迁移函数；新版收到 blur 释放旧按键和拖动，镜头重新开始 |
| 用户选择 | 默认重新开始；另行选择迁移后才执行，不由模型自行授权 |
| 确认与恢复 | 沿用来源 CAS、独立宿主运行、持久回执、取消、旧分支和 fork 边界 |

新增契约版本 mini-app-1.7；未声明迁移的旧程序保留原身份。普通浏览器 VM 没有迁移入口。迁移只在服务端 Worker 的新 QuickJS 实例中运行一次，仍受原有 200ms 启动、堆/栈、JSON 节点/深度/字节及 Worker 看门狗约束；不能重复请求启动额度。

来源检查点被冻结，修改它会失败。迁移结果须通过新版状态及投影检查，并继续接受已有的有界步骤与交互试运行；最终只提交迁移后的起始结果。请求仍有 512KiB 总限制，大来源明确失败，不默默丢字段。

模型上下文提供完整但有大小限制的 progressSource：程序摘要、状态结构、输入、内部状态、步数和 RNG。超限明确 complete:false，提示不得猜测缺失状态。迁移说明是模型提议，结构合法不能替代业务语义验收。

## 2. 可核对的界面结果

旧计数演示的起始输入为 7，当前计数 19，步数 13。用户将新版起始输入改为 8，再显式选择保留“已走过的距离”；迁移函数计算 19 + 8 - 7，新计数为 **20**，步数仍为 **13**，输入为 **8**。原旧版仍保留 19，刷新后新版完整检查点不变。

同一候选若不选择迁移，则走默认 init，计数变为 8、步数归零。试运行失败时旧版仍可写，用户可以重新明确选择 init。没有静默丢失进度，也不把保存参数误称为保留整个任务。

## 4. 三维回归中的竞态修复

首次合并验证为 **240 通过、1 失败**：既有三维测试在快速键盘选择后等待目标对象超时。记录显示无运行时错误，但选择仍停在旧对象；单独复测通过，不能删除首次失败。

排查发现选择框可能被较早返回的投影写回旧值。本批让三维选择与动态行共用有序事件回执：最新用户选择未被处理时，旧画面不覆盖控件；过期事件拒绝和任务重置也会完成回执。传给模型程序的选择事件仍只包含对象身份，不暴露宿主序号。

原断言保留，并扩展为连续六轮 End、Home、两次方向键及确认，检查最终状态与原生控件都选择 X 轴。相关定向复测通过，随后合并验证通过。首次失败目录 mini-app-capabilities-Z0FUVc，记录不会被后续成功覆盖。
