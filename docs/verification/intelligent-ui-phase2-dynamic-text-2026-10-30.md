# Intelligent UI 第二阶段：随参数更新的说明

2026-10-30 · v2.16 · 实施增量，第二阶段整体尚未验收。

## 能力与实现

v2.15 实测中，用户将票价从 3500 分改成 4500 分后，动态指标已显示 270 元，但静态说明和导出文件仍保留 210 元。本次增加可绑定参数和计算结果的说明，解决这一类由固定文字造成的新旧数值并存问题。

### 文字与计算共同更新

Plan2 编译器升级到 2.5.0，新增 dynamicText 展示项。模型提供一串文字片段和明确引用，宿主按当前参数求值后拼接。一次说明最多 12 个片段，支持输入、派生计算和已有的条件表达式。

例如“按【人数】人、每人【分价】分计算，合计【总额】元”，其中括号里的值都绑定计算。修改控件后，界面说明、保存快照、Markdown/JSON 导出和后续模型上下文使用同一份当前值。条件说明可绑定 if 的文字分支。

这不是字符串公式或任意代码。文字始终按普通文本显示，HTML 不执行；缺失引用、类型错误、深度和计算量超限仍会拒绝。除零等交互错误显示明确的不可计算提示，不静默替换成零。

### 模块边界与兼容

新增能力仅在 Plan2 / Surface2 中提供，原 Plan1 / Surface1 和已有固定文字继续可读。聊天公共层无新路由分支，功能仍由 Beta 开关控制。

编译时借用现有图编译器验证表达式，再还原为动态文字节点；预览使用同样的转换和依赖检查，缺少依赖时等待，完整无效数据直接拒绝。动态文字不会被当作可筛选表格或输入控件。

相关源码：`rich-plan.ts`、`plan2-expressions.ts`、`rich-protocol.ts`、`preview-plan.ts`、`SurfaceContents.tsx`。数值轨迹检查同步识别动态文字里的绑定值，固定的“80、60”不能冒充随输入变化的结果。

## V4.1 实测与边界

### 原自然表达流程复测

仍使用 **DeepSeek V4.1 Flash（deepseek/deepseek-flash）**，没有调用 Pro。独立 Windows Electron 测试配置，Beta 默认 Plan2，真实供应商与权限入口；原自然语言提示未加入组件名或动态文字协议指导。

| 步骤 | 实测结果 |
| --- | --- |
| 创建门票工具，再修改人数和票价 | 一次 UI 调用生成；保存 6 人、35 元，总额 210 元 |
| 要求票价改按分填写 | 一次 UI 调用生成待核对稿；旧参数保持，刷新后仍可核对 |
| 明确确认 4500 分 | 动态说明显示 6 人、4500 分、27000 分及折合 270 元；快照不再含 210 |
| 保存 Markdown | review 模式自动审核通过；文件中的计算说明也为 270 元，无旧总额 |
| 继续追问与 Beta 切换 | 回答 6 人、45 元、270 元；关闭显示快照，开启恢复控件与参数 |

新版包含一个动态文字节点，旧版也使用了动态文字。保存文件的摘要哈希及实际产物记录在机器可读证据中。测试实例已退出，临时凭据已清理。

### 不能据此宣称的结论

这是一个已暴露的开发回归样例，不是新的封存集或泛化验收。它证明本次结果与绑定机制一致，不能证明模型以后一定不会在标题或固定说明中写入变化值，也不能保证业务计算规则本身正确。历史聊天消息仍保留生成时的描述，不会随控件编辑重写。

本轮模型仍笼统描述“保存会经过权限确认”，并建议已有文件可以“允许覆盖”；登记保存动作实际只支持新建，权限审核可能自动通过。静态保存说明中“生成时的数值”也不如“点击保存时的数值”准确。这些文案问题尚未解决，不计作语义验收通过。

独立人工语义评判、尚缺的真实取消与权限组合继续待完成。CI 仍按用户安排，在三个阶段开发完成后统一处理。本轮没有提交、推送或发布。
