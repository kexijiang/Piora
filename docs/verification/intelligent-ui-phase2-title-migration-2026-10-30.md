## 本次修复与实测结果

后续真实模型测试统一使用 **DeepSeek V4.1 Flash**，供应商/模型 ID 为 `deepseek/deepseek-flash`。这是用户本次明确指定的配置；此前 Pro 数据保留为历史证据，本次新实测没有调用 Pro。

### 修复自动标题导致的生成冲突

此前单位迁移试跑发现：模型已经提出新版 UI，但后台自动命名恰好插入在模型请求和工具调用之间，宿主将其误判为上下文变化并返回 CONFLICT。旧参数未损坏，新版却无法进入核对流程。两项回归在修复前复现失败。

生成宿主现在允许这段路径中出现有限的 session_info 标题记录，并保存逐条磁盘回执。请求时的参数、来源叶子和原始调用哈希保持冻结；真正的消息、分支变化与参数冲突仍会拒绝提交。运行时直接采用宿主验证过的调用身份，避免重复使用过严的直接父子判断。

标题证据随历史复制保留，并验证 SDK 分叉移除标签时的对应关系；已提交历史和未提交候选都覆盖两次分叉。修复范围是请求捕获至助手调用之间的自动标题，不是任意放宽所有记录的时序要求。

### 真实 Windows 桌面流程

使用独立测试配置、Electron 开发实例和真实 V4.1 服务。Beta 默认 Plan2，无协议覆盖。会话日志中 6 条助手消息的模型均为 deepseek-flash；交互共 4 轮用户输入，另有一次保存动作自动审核。

| 操作 | 观察到的结果 |
| --- | --- |
| 自然表达创建门票工具 | 4 人、每票 30 元，计算 120 元；一次 UI 调用生成 |
| 用户调整参数 | 6 人、每票 35 元，保存后计算 210 元 |
| 要求票价改按分填写 | 沿用任务 ID，一次 UI 调用进入待核对；旧版仍是 35 元 |
| 刷新并核对新版 | 待核对状态保留；明确输入 4500 分，确认后计算 270 元 |
| 保存 trip.md | review 模式自动审核通过，真实文件包含 4500 分及 270 元，无人工兜底 |
| 继续追问数字 | 回答 6 人、每票 45 元、总计 270 元，无 UI 调用 |
| 关闭再开启 Beta | 关闭后显示保存的快照，普通算术回答 60；重新开启恢复 4500 分及 270 元 |

“确认新版”与“保存文件的权限审核”是两个不同步骤，本次均实际执行。临时凭据已清理，测试实例已退出。

## 验证边界与后续事项

### 本地验证

- 78 项相关测试通过，无失败或跳过：生成宿主、运行时、真实 SDK/wrapper、历史复制和结构迁移。包含自动标题插入、证据篡改、参数冲突、迁移就绪、分支历史和两次分叉。
- TypeScript 检查、定向 ESLint 通过。没有运行全量 CI、next build 或本地发行构建；未提交或推送。
- 真实桌面是一个门票流程样本，不是新的泛化基准，也不能将 78 项局部测试解读为全产品通过。独立人工语义评判仍未完成。

### 实测仍暴露的文案问题

数值计算和追问正确，但模型添加的静态说明仍写着“总费用保持 210 元不变”；用户确认 4500 分后，真正的动态总额已是 270 元。该旧值说明也进入 Markdown 快照。当前没有修复此语义问题，不能把文件写入成功等同于报告全文正确。

模型还把内部迁移状态名直接告诉用户，并笼统声称保存总会弹出权限确认；实际本次 review 模式是自动审核通过。这两类文案仍需优化并验证，宿主的核对与权限行为不以这段模型说明为准。
