# 第三阶段：可编辑动态列表

2026-11-02 · 对应方案 v3.8 的复杂交互增量 · 第三阶段尚未完成。

## 1. 本批交付

小程序现在可以把显式状态中的数组渲染成可编辑列表。用户可以修改名称、勾选、增删和调整顺序；宿主保留每项身份、输入与键盘焦点，并沿用既有保存、恢复和后续追问路径。此能力通过原有 Beta 开关和能力清单开放，不要求普通聊天维护另一套列表状态。

| 用户操作 | 已实现的行为 |
| --- | --- |
| 编辑列表项 | 支持文字、勾选、数字、滑块和选择框；输入写入该项状态，不污染顶层参数 |
| 增删与重排 | 固定模板接收数组数据；按稳定 key 更新和移动行，不能按当前 DOM 序号寻找对象 |
| 连续打字 | 按输入确认序号应用计算结果，旧帧不会覆盖刚输入的新文字 |
| 键盘与焦点 | 按钮可用键盘操作；重排保留焦点与选区，删除聚焦行后移到相邻控件，空列表回到容器 |
| 保存和追问 | 检查点保存列表值与顺序；追问上下文含行 key、显示位置和当前绑定值，明确说明被省略的行 |

自然表达探测使用：“给我做个可调整的采购清单。先放牛奶、鸡蛋、面包，能改名称、勾选买好了、增删和上下调整顺序，刷新以后不要丢。”模型固定为配置中的 DeepSeek V4.1 Flash；实际服务返回 deepseek-flash，未独立确认版本号，未使用 Pro 或回退模型。

当前实现适用于平面列表，不包含嵌套列表、跨列表拖放或大型虚拟滚动。新增样式支持有限的原生 input[type=...] 选择器及列表标记，用于区分文本框和勾选框、调整列表外观。完整契约与示例见 docs/intelligent-ui-dynamic-lists.md。

## 2. 协议、状态与资源边界

### 固定模板和有界数据

一个 data-repeat 容器包含一个行模板；project 返回 repeats 中的数组，每项是 key 与标量 bindings。行内 data-text、SVG data-bind 和 data-field 使用行绑定。模型程序不拼接执行期 HTML，也不直接访问 DOM。

字段使用可访问标签和固定约束。重复 key、缺失绑定、非法值与超限展开会报错，不截断用户数据。最多 8 个非嵌套列表，每个最多 50 行；实际展开共同受 400 节点、64000 字符和 128 交互目标限制。容量需结合模板复杂度说明，不能把 50 当作所有模板都能达到的数量。

### 事件必须仍指向原来的对象

可信渲染端为事件附带显示帧与序号，独立控制器维护行对象代次和最近 32 帧的身份历史。已删除、删除后重建或过期帧的事件不再生效。仍存在对象上的排队输入可正常完成，重排不会误改相邻行。宿主把核对后的 item-input / item-click 业务事件交给 reduce。

同一控件的连续输入可合并，不跨行合并；拒绝事件也按队列顺序确认。渲染端按 key 复用节点，保留焦点、选区和尚未确认的输入。停止或替换实例时，原有 MessagePort 与虚拟机生命周期继续负责隔离旧实例。

### 持久化与兼容

生产状态服务在写盘前用 QuickJS 重新投影。保存回执可重放，列表身份与顺序随检查点恢复。模型上下文每个小程序最多摘录 3000 字符的完整行值，保留原位置及总行数/省略行数；省略不代表初始值或空值。静态快照导出包含保存的行数据。

使用动态列表或本批新增 CSS 语法的计划采用 mini-app-1.3。未使用这些能力的旧计划保持原版本；注释里提到新语法不会改变计划身份。能力清单记录 repeat 的实现和验证状态，证据失配时不开放新生成，旧记录读取仍独立。
