# 第三阶段成果：修订确认与参数保留

2026-11-02 | 专用 worktree：intelligent-ui/Piora | 分支：codex/intelligent-ui

## 1. 用户现在可以做什么

**新版小程序不再只停留在“需要确认”。** 用户可以核对参数变化、修改建议值，然后确认或取消。旧版继续保留；来源状态变化时要求重新核对。当前保留输入，明确重新开始任务进度，第三阶段尚未完成。

| 操作 | 实际结果 |
| --- | --- |
| 核对变化 | 先暂停并保存旧实例，再显示当前来源参数与新版建议值 |
| 参数相容 | 含义、类型、标签和约束一致才建议保留；仅默认值变化不覆盖已保存值 |
| 含义或约束变化 | 使用新版默认值，允许用户修改；不按同名字段转换单位 |
| 确认 | 服务器试运行新版，用确认的参数重新初始化状态、步数、随机状态及镜头 |
| 取消或初始化失败 | 旧版继续可用，其参数和进度不被覆盖 |
| 来源在其他窗口变化 | 拒绝旧确认，刷新核对最新来源 |
| 响应丢失或重复点击 | 核对同一次持久回执；不能盲目再次初始化 |
| 切回旧分支 / fork | 新版只在确认所在分支生效，副本只继承可见的已确认结果 |

确认入口复用第二阶段的会话所有权、公共锁和不可序列化宿主授权。旧模型运行、生成程序、合成 DOM 点击不能代替真实用户点击。普通聊天只读取通用输出，不承担确认和执行逻辑。

程序身份及原工具结果保持不变：确认后的初始结果另有持久记录与摘要，保留原候选内容。新确认使用独立宿主运行。内部状态默认重新 init；有进度保留需要的任务仍需后续受限迁移函数，不能把同名状态字段直接复制。

## 2. 一次真实界面流程

固定计数夹具的旧输入为 7，已运行到 19，步数为 13。新版核对页建议保留输入 7；用户先填入越界值 999，被拒绝后刷新核对，再改为 8 并确认。新版输入和初始计数均为 8，步数归零；旧版仍显示原来的 19，并变为历史只读。刷新后新版仍为 8。

成功响应被截断时，页面显示未确认；点击刷新读取已保存决定，不再发送第二次确认。另一场景取消候选后，旧版仍可操作且计数仍为 19。以上通过原生点击、生产 API、真实 SDK 文件和 QuickJS 执行。

## 3. 开发验证与证据

相关能力验证 **230/230 通过**，33 个测试文件，证据目录 mini-app-capabilities-wAnG3T。本批迁移服务有 10 项检查，浏览器测试包含 3 个场景与外层检查；其余为相关发布、继承、保存、运行时和既有能力回归。它们与此前 182 项有重叠，不能累计为模型成功率。TypeScript 与本批 16 个模块/脚本 lint 通过。

服务端覆盖来源变化、同源与 Beta 门禁、运行冲突、错误参数、取消、精确幂等、旧分支/fork、回执篡改和初始化失败。中断恢复通过重建“确认项已落盘、发布日志尚未提交”的持久状态测试；读取不自动激活，明确重试只产生一条确认项。该场景不是实机断电测试。

浏览器使用无头 Edge、正式 React Surface、IndexedDB、真实 Worker 和生产路由，HTTP 外壳及计数程序为确定性夹具。覆盖合成点击拒绝、无效输入后的重新核对、用户修改建议值、确认后恢复、旧版保留、取消及响应截断。未运行本批原生 Electron 窗口或真实模型。

## 4. 失败记录与范围限制

首次服务端测试因迁移已经持有会话 mutation 所有权，又使用普通锁而被拒绝；改用现有 mutation 专用锁后复测通过。浏览器夹具首次调用运行时准备函数的参数有误；后续漏提供 Worker 的动态文件，导致界面等待超时。补全夹具后真实界面复测通过，未降低原有断言。

夹具曾在子测试失败后错误写入 passed：原始测试日志明确为失败，结果文件已加说明改正，并将报告改为只有全部场景完成才能通过。随后增加对无效确认输入的浏览器回归，修复被拒绝选择仍冻结编辑的问题。首次失败、修复和最终合并验证均保留。

完整 stateMigration 能力仍为 planned：保留任务过程进度的受限迁移函数、组件与小程序互转、登记外部动作尚未接通。真实模型开发/封存评估、复杂任务独立正确性、完整恢复与多窗口矩阵继续推进。已实现的 11 项生成能力没有借本批新增未验证授权。

完整 CI 与两人独立语义验收按此前约定留到三个阶段开发完成后。安装包、其他平台和真实 GPU 未验证；本批未提交或推送。源码、检查日志与本批报告摘要记录在配套 JSON 中。
