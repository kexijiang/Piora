## 1 实现与本地验证

Plan2 编译器升至 2.3。内部派生计算使用独立名称空间，指标 total 可以直接展示 derived:total，不再仅因同名要求模型重试。输入引用和计算引用明确区分，不自动更名、不猜测引用；同类重复、输入与展示节点冲突、布局冲突、缺失引用和计算环仍拒绝。Plan1 保留原共享 ID 规则。

预览与最终编译同步采用该规则。测试覆盖不同字段顺序的每个流式边界、前向引用、输入与计算同名、布局与计算同名，以及变参后的独立期望值。真实 SDK、持久化及浏览器追问夹具使用同名计算与指标完成单次生成。

桌面原始失败参数已保存为合成回归样例。去掉无歧义 ID 冲突后，原样例仍因未定义的 ticketShare 等计算报错；不会替模型补业务公式。使用已补全计算的样例，并保留同名指标后，总费用正确从 400 变为 600 元。初始“4人”标题仍是已知语义问题，本轮没有用数字替换规则伪装修复。

窄窗口新增验证复现：连续长文件名会撑宽操作区。已补换行、最小宽度和按钮最大宽度约束，以及键盘焦点与禁用样式。指标、图表输出通过可访问名称关联其标签。320 像素英文界面可以用 Tab、Enter、Space 完成单次授权，权限等待期间原按钮保持禁用。

## 2 两模型候选比较

以相同 40 个开发任务、每任务 3 次、相同请求设置比较旧基线与当前 Plan2。每个版本共 240 次，累计 480 次。20 个封存任务未用于本轮。模型分别统计，三次重复仍只属于同一个任务族。

| 观测值：旧基线 → 候选 | Flash | V4 Pro |
| --- | --- | --- |
| 任务回合完成 | 73/120 → 120/120 | 95/120 → 120/120 |
| 完成且首次结构有效 | 20/60 → 44/60 | 38/60 → 56/60 |
| 首次数值轨迹匹配 | 16/60 → 43/60 | 37/60 → 56/60 |
| 隔离重试后数值轨迹匹配 | 32/60 → 59/60 | 44/60 → 60/60 |
| 应交互却未尝试 UI | 3/60 → 0/60 | 6/60 → 0/60 |
| 文字回合中尝试 UI | 3/48 → 0/48 | 3/48 → 0/48 |
| 澄清任务中尝试 UI | 3/9 → 3/9 | 1/9 → 2/9 |
| 不支持任务中尝试 UI | 5/9 → 1/9 | 1/9 → 0/9 |

离线核对器根据原任务预先写出的检查值，对同一个结果表达式连续修改输入，避免两个无关联常量冒充联动结果。它不向模型发送检查信息，也不修改原始运行记录。控件无法唯一对应时保留为 unmapped：例如 Flash 最终一例用勾选表达黑白／彩色，核对器无法按下拉选项关联，未记成功，也未直接判业务错误。

Flash 首次还有一例明确错误：用户要求不带导览，模型默认包含导览，初值 190 元而非 160 元；后续调用纠正。这个差异证明结构有效不能代替初始条件与计算正确。

比较存在重要限制：旧基线共有供应商错误与超时，当前候选没有同类失败，不能把全部差异归因于编译器或提示词。数值轨迹是本轮补做的离线核对，非事前注册的语义验收，也不验证标签含义、浏览器、保存和追问。没有人工双审或封存集结论。

证据位于同目录 intelligent-ui-phase2-candidate-2026-10-29.json，包含逐任务终态、轨迹、错误与文件哈希；本地完整记录位于 .verification/intelligent-ui-development-candidate-2.3。前向开发目标另存为 intelligent-ui-phase2-evaluation-targets-2026-10-29.json。

## 3 没有达到的门槛与下一步

Flash 首次结构有效为 44/60，低于本轮前向目标 80%；17/60 使用了多次 UI 尝试，高于目标 20%。Pro 对应为 56/60 和 4/60。候选端到端任务耗时 P95 分别约 18.1 秒和 25.4 秒；这是隔离生成耗时，不能代表首次可操作界面或桌面总延迟。

### 评估器还需要对齐真实接纳预算

当前隔离评估器允许最多三次工具执行，但没有接入真实宿主的“最多一次纠错”、不可修复错误与活动时间限制。Flash 有 7 个应交互回合、Pro 有 1 个回合，是在已知真实预算不允许继续的错误之后才首次生成有效结构。这些不能算实际产品成功。

已保留并单列这些冲突，不改变生产预算来迎合评估。下一步应让候选评估使用真实接纳逻辑，再按新的冻结配置运行；既有结果保留为孤立编译观察，不能覆盖或重命名为生产验收。

### 触发选择和生成语义仍需改进

“三人分房租，具体规则未定”的三个开发重复中，Flash 都先生成界面，Pro 两次先生成界面；其中有回答自行选择权重分摊。虽然文字回合没有误触发，这不能掩盖应先澄清的场景失败。不新增关键词路由，后续加强通用的业务规则缺口判断，并再次检查跨任务迁移。

生成失败仍集中在平铺计划中混入嵌套公式、引用未定义计算、重复布局和原始 JSON 深度超限。应先保留可复现参数、区分真正复杂度超限和可无歧义规范化的表达，再决定是否扩展输入表示；不能自动补公式或简单放宽所有限制。标题残留初始数值也仍在未完成项中。

封存验收、人工语义判断、完整桌面动作和跨平台矩阵仍缺证据。关闭 Beta、权限、取消、参数恢复等硬约束继续保留。当前进展不能证明第二阶段完成，也不会提前开始第三阶段任意代码运行。
