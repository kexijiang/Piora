## 参数变化先试算，再解释结果

当前读数已经可以直接进入追问上下文；解释“改成另一个值会怎样”还需要实际执行程序。现有 piora_inspect_mini_app 新增 inputCases，与按钮 actionIds 二选一。一次最多 8 个参数样本，每个都从同一份已确认检查点开始，执行真实 input 事件和生成程序的 reducer，再返回变化与计算文字，不修改用户界面或保存新版本。

宿主先校验参数 ID、类型与声明范围；每个样本在受限 Worker/QuickJS 中独立运行。沿用每轮最多 12 次检查的预算，缓存绑定应用版本、状态版本和检查点摘要，执行前后均复核来源，拒绝过期、跨分支或已取消的请求。只读试算不会获得文件、网络或进程操作权限。

回执按整项裁剪并明确省略，当前应用上下文仍限制在 11000 字符内。策略版本为 mini-app-intent-27。试算只证明指定的单次输入结果，不等于完整拖动、聚焦/失焦、同时编辑或连续操作，也不凭有限样本证明整个区间的极值。

## 真实追问：三个角度分别有多高

测试原样重放 Fc48Tc 生成的两节机械臂，没有修改原程序，也不是本批重新生成。用户问：“别改我现在的姿态，帮我看看肘部在 0、90 和 120 度时，末端分别有多高？是不是越往上折就越高？”

模型一次调用只读工具查询三个角度，收到全部结果后回答。两次模型请求均为 Flash、思考开启并返回 200。工具来源绑定 stateRevision=33；追问后运行器严格核对整个检查点和状态版本不变。当前仍为底座 0°、肘部 0°，选中夹爪。

| 肘部角度 | 独立预期高度 | 工具与回答 |
|---|---|---|
| 0° | 0.88 米 | 一致 |
| 90° | 2.53 米 | 一致 |
| 120° | 2.31 米 | 一致 |

回答正确指出 120° 比 90° 低约 0.22 米，足以反驳“角度越大始终越高”。它同时给出 0.88 + 1.65 × sin(肘部角) 的关系；该公式与原程序及先前独立关节尺寸核对一致。公式结论的依据与三个采样结果应分开，不能把有限试算包装成通用极值证明。

本例的三个数值、反例及不改动状态要求通过开发核对。未做双人人工验收，不据此声明所有自然表达都会选择正确工具，或新生成的程序普遍正确。原机械臂的穿地假设、上一追问的最近镜头变化与“同时归零”误述仍保留，当前批次未重新验证这些问题。
