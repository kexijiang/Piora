### 下一候选的连接与控制准备修复

设备面板持有按引用计数共享的元数据流；媒体观察者只复用本渲染进程已有消息，不自行开启长连接，独立浮窗沿用两秒状态轮询。实际 HTTP/1 夹具同时维持四个其他长流，两个生产媒体 hook 的健康请求与状态更新可完成；临时还原旧媒体 hook 后同一场景按预期排队超时，恢复修复源码并核对字节一致，未降低断言或放宽请求预算。

坐标校验在途 Promise 不再因 300 ms 过期而重复请求，成功后再开始计算缓存。沿用已有鼠标进入触发的只读准备，不新增被动打开画面的自动 SDK 操作；冷准备中明确提示，不取 lease、不接纳手势。超过三秒的冷准备完成后不会重放早已松开的点击，只接受新的动作；同一帧身份已就绪后的后台校验继续接纳手势，不要求每次移动都等待。真正已接纳的手势仍保留三秒 setup 和设备切换释放保护。

共享订阅生命周期、连接预算、指针顺序/切换/迟到拒绝及完整镜像 UI 定向场景通过。上游合入提交的 CI 首轮历史下载等待超时，原样重跑后该场景通过，但镜像尺寸比较在浮窗样式尚未生效时执行而失败。镜像测试现增加准备状态的等待，并等待真实浮窗样式生效后继续严格比较恢复前后尺寸；原失败保留，未把旧提交 CI 写成成功。新安装版的控制与并发日志验收仍待下一候选发布。
