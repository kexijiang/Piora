# Piora Intelligent UI

第二阶段增量 v2.6：结构变更确认 · 2026-10-29

## 1 本轮交付

内部 Plan 路径现已接通“核对变更后使用新版”。字段单位、类型、范围、选项或含义变化，以及移除字段时，旧版继续生效；新版先作为只读提案显示，原任务正常完成后才允许确认。第二阶段整体仍在实现中，本报告不是阶段完成或发布声明。

| 用户操作或场景 | 当前行为 |
| --- | --- |
| 模型提出结构变化 | 展示原字段及已保存值、新字段和建议值；不按相同 ID 猜测单位换算。 |
| 原任务仍在运行 | 提案为 provisional；只读核对，确认与取消按钮尚不可用。 |
| 原任务正常完成 | 提案成为 ready；变化或新增字段可填写新值，完全兼容字段保留旧值。 |
| 点击确认 | 等待本窗口已知参数保存，再验证提案、分支与源参数；满足条件才发布新版。 |
| 点击取消 | 取消这次变更，继续使用旧版；不提交或删除本机草稿。 |
| 中断、失败、源版本改变 | 不发布；已保存的旧版仍可用，冲突时根据最新参数重新生成。 |

确认使用独立同源接口和新的宿主运行身份，原模型工具不能携带 force 参数绕过核对。POST 绑定提案摘要、完整选择和幂等键，先落盘确认记录，再原子写入发布状态。确认结果未知时，客户端只查询状态；用户重新点击才会重试同一选择，不自动再次提交。

发布位置使用独立用户确认条目。原工具结果仍作为内容证据，浏览确认前的历史时，新版保持未发布；确认前的分叉不会继承确认权限，确认后的分叉保留已验证回执。SDK 移除标签并重建父链、再次分叉也保留这项边界。

启用内部验证需在启动服务前设置 PIORA_UI_INPUT_PROTOCOL=plan-2，并在设置中开启 Intelligent UI。Plan1 同样支持结构确认，丰富布局与增量预览属于 Plan2。默认生成协议仍未切换；单独打开 Beta 不代表已切到 Plan2。

## 3 手测方式与未完成项

可以先说：“周末四个人出去玩，每人门票 30 元，车费一共 120 元。让我自己改人数和票价，看看总共多少钱。”确认第一份界面可用并保存参数后，接着说：“票价改成按分填写，其他条件先保留。”这是普通表达的手测示例，不保证模型每次都选择同一字段 ID 或结构。

如果模型提出同一界面的单位变更，应出现新旧字段核对。检查原票价仍按元保留、新值按分显示；系统不应擅自把原数值解释成新单位。填写明确的新值，点击确认后新版可用；选取消则旧版保持可用。运行中停止、核对后改旧参数、确认时断网，再刷新，均不应静默覆盖旧版或丢弃草稿。

本实现采用保守的结构／语义比较：显示名称调整也可能需要核对；只有新增字段时仍允许兼容发布。它不能自动理解业务语义，也不能证明模型选择正确的任务 ID。已 aborted 的历史候选不会复活，需要新运行生成候选。

尚未完成：完整桌面实机链路、跨平台验收、更多字段与真实模型组合、触发选择和语义泛化的完整对比、已登记业务动作及权限／幂等闭环，以及默认协议选择。上一轮真实样例中“数值变化但静态说明仍写旧值”的问题仍保留，不能以本轮结构确认测试替代其修复。

第三阶段仍为隔离的小程序、模拟、教学演示和小游戏能力。按最新安排继续推进功能，每个阶段记录成果并输出 PDF；三个阶段开发完成后统一处理 CI。现有本地测试结论只覆盖已列明范围。
