# 第三阶段原生窗口恢复

2026-11-03 | 基于提交 219d4b7b 的开发增量 | 第三阶段尚未完成

## 本批结果

Windows 开发桌面的最小化、关闭隐藏、同实例恢复、保存、刷新和追问流程连续两次完整通过。恢复后小程序保持暂停，原先按住的方向键不会继续推进；后续追问读取已保存的位置。本批处理桌面窗口可见性，不修改 Intelligent UI 的生成协议、保存格式或对话耦合边界。

## 定位与修复

历史失败中，原生窗口已经恢复，页面却仍报告 hidden，动画帧停止，按钮等待稳定超时。本机 Electron 45.0.0 / Chromium 156.0.8078.48 的独立窗口再次复现；不加载 Piora、不连接 CDP、不依赖模型也能观察到此现象。

五组串行对照均使用独立配置和置顶窗口，每次操作后采集四次原生状态、页面状态与动画帧数。结果如下：

| 对照 | 观察 |
| --- | --- |
| 默认隐藏启动 | 最小化后仍 visible，恢复后变为 hidden。 |
| 关闭初始隐藏绘制 | 同样出现不一致，不能解决恢复问题。 |
| 创建时直接显示 | 最小化能变 hidden，但恢复后仍 hidden。 |
| 关闭 GPU 加速 | 不一致仍存在，不能据此归因于 GPU。 |
| 关闭 Windows 遮挡计算 | 最小化/隐藏变 hidden，恢复/显示变 visible；帧交付随之停止和恢复。 |

在 Electron ready 之前，仅对 Windows 合并禁用 CalculateNativeWinOcclusion，保留已有 Chromium feature 设置。没有关闭整个后台节流，没有模拟页面可见性，也没有给 renderer 增加特权。显式最小化与隐藏仍停止帧交付；被其他窗口完全遮住、但仍显示的窗口可能继续绘制，这是本处理的性能取舍。它是经过本机验证的兼容处理，不能据此宣称已查明 Chromium 内部根因。

独立原生回归直接加载实际配置函数，连续两轮验证最小化/恢复、隐藏/显示；共记录九个状态，逐项核对页面可见性、原生状态、隐藏时帧计数不增长、恢复时帧计数增长，并确认 backgroundThrottling 始终为 true。窗口含隔离 iframe，无 CDP 连接。

## 真实 Piora 桌面验证

复用 intelligent-ui-window 场景，通过 UI 创建固定持键程序、播放、按住方向键、保存和追问。原生操作仅针对本次 launcher 所属且端口/标题匹配的窗口；恢复调用生产单实例激活路径，并核对原进程和窗口身份。先证明隐藏期间输入已释放、进度已暂停，再清理测试端的按键记录。保持 noDefaults CDP 连接、页面 hidden/visible 与焦点断言，不使用强制点击。

| 运行 | 结果与范围 |
| --- | --- |
| sbTmee | 可见性和按键释放已通过，但恢复后保存进入错误状态，等待已保存超时。保留截图及日志；当时未采集具体错误码，原因尚未确定，不归类为误报。 |
| y85I5f | 增加保存错误码采集与失败即报后，完整五步通过。最小化后 x=55，关闭恢复后 x=82；刷新和追问保持 82。 |

两次成功运行均记录五个检查点。最终 stateRevision=4；关闭后、刷新前后及追问后检查点完全一致，held=false、drag=false。按键实际持续时间不同，位置不要求跨运行相等。两次第二实例激活均正常退出且恢复同一主窗口；页面及清理错误均为空。已检查失败、关闭恢复和追问完成截图；它们不代表完整视觉验收。
