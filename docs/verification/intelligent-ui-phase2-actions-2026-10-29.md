# Intelligent UI 登记动作成果

2026-10-29 · v2.7 · 第二阶段实施增量，尚未完成整体验收或发布。

## 1 本次可用流程

内部 Plan2 已连通动作声明、已发布界面、宿主运行、当前聊天权限、操作记录与按钮。第一组动作只包含读取项目 JSON 参数，以及另存当前结果为 JSON／Markdown；模型不能提交任意代码、工具名或网络地址。

### 读取参数

点击后读取已声明的项目文件，严格验证输入 ID、类型、范围与选项，并显示待核对值。用户点击“采用这些参数”后才更新界面。未保存草稿会阻止采用，服务端再次核对原来源版本；若参数、结构或分支已变化，保留当前值并拒绝旧结果。采用记录和参数一起落盘，同一次请求不会覆盖后来修改的值。

### 保存结果

按钮使用当前已提交参数重新计算报告，展示目标文件，遵守聊天中启用的 read／write 能力及权限模式。保存采用独占新建，不覆盖已有文件；保存过一次后，如要另存，需要新文件名和新的明确操作。

### 取消、重复请求与断网

每次点击建立独立运行身份，和普通聊天任务互斥，可通过动作按钮或任务停止取消。相同请求 ID 只返回原记录，不再执行。丢失响应后查询状态，刷新也能读取记录；结果不明时核对文件，只报告内容匹配、缺失或不同，不把内容匹配伪装成本次成功。

当前默认仍使用旧 Surface 生成协议。以上能力只在内部 Plan2 路径使用，未切换默认协议，也未提交、推送或更新第一阶段 PR。

## 2 实现边界与复核

| 边界 | 本次实现 |
| --- | --- |
| 模型输出 | 独立 version 1 动作声明，最多 8 个，只接受登记的读取或保存适配器 |
| 发布来源 | 只允许当前已发布版本；会话、分支、结构、参数及动作摘要共同绑定点击 |
| 宿主与权限 | 新 PromptRun、既有 ToolReviewController、当前能力和权限版本；一次性批准不改变权限模式 |
| 文件效果 | 项目内真实路径，拒绝链接及凭据路径；保存独占创建，不覆盖、不自动删改恢复 |
| 持久记录 | 执行前保存意图，效果后保存回执；参数采用与其回执原子保存 |
| 界面独立性 | SurfaceActions 位于 Intelligent UI 模块，通用宿主接口连接任务；原对话组件不含动作专用逻辑 |

权限等待不占用 UI 文件锁。执行时重新核对来源、文件证据、报告字节和授权版本；等待期间修改参数或文件会阻止旧操作。关闭 Beta、停止任务、运行失效、能力未开启也不能继续执行。

本轮自查修复了三个问题：权限结果返回前后的配置变化必须使授权失效；失效批准请求统一返回冲突状态；参数采用等待锁时再次核对实时选中分支。路由仅接受声明 ID、来源摘要及操作 ID，不接受浏览器指定路径或正文。

文件检查属于应用边界，不是防御恶意本地进程的操作系统沙箱。跨崩溃不承诺 exactly-once；执行记录未完成时只核对效果，不恢复旧批准。

回归包括文件效果、发布来源、动作运行、真实路由与权限入口、Plan2 编译、预览、结构确认、复制和 wrapper 普通会话行为。浏览器使用真实组件及受控 API，验证等待批准、刷新不重放、明确采用和新参数冲突保留；文件与权限效果另由后端测试覆盖。这不是完整桌面端到端验收。

首次联动浏览器检查有两项超时，暴露动作区未校验响应形状及旧夹具缺少新接口。已限定 Surface2 挂载、校验响应并更新夹具，保留原断言重跑通过；随后新增无效响应恢复测试，未用减少断言绕过失败。

内部 Plan2 的人工试用可以从这句话开始：“做个聚餐分摊器，人数和总价都能改，算完让我保存一份 JSON 结果。”检查保存内容是否使用修改后的参数，再重复点击验证已有文件不被覆盖。读取测试需准备键与实际输入 ID 一致的 JSON；当前不支持任意业务 JSON 自动映射。

第二阶段仍需完整自然语言、多轮与跨领域评估，解决已发现的静态说明随参数变化后失真问题，决定默认生成协议，并完成桌面完整验收。第三阶段尚未因本轮动作接入而完成。按照用户安排，CI 留到三个阶段功能开发完成后统一处理。
