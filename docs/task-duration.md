# 任务总用时

运行时在聊天输入框上方固定显示一行轻量计时，不随消息滚出视野。文案由用户选定为「凝思求解中」，搭配「已用时 2:34」和当前阶段。回复完成后，准确的任务「总用时 2:34」显示在该回复底部，替换原来的「响应耗时」，输入框上方的完成计时收起。停止、失败但没有可承载计时的回复，或异常中断缺少可靠结束时间时，保留输入框上方的状态兜底。使用主题变量、等宽数字，长阶段文本省略，计时本身不触发屏幕阅读器逐秒播报。

模型生成期间，同一状态栏右侧显示 `≈42.5 t/s`；窄窗口允许换行，折叠消息过程不影响显示。直接使用当前流式助手消息携带的服务端 `streamingMetrics.tokensPerSecond`，按最近 5 秒的字符量估算，包含思考和工具参数；不以任务总用时做除数，也不将其视为精确账单用量。尚未形成有效采样时隐藏，合法的零速率显示 `≈0.0 t/s`；消息结束、任务停止、重试或压缩时不保留上一段输出的速度。

一次任务从服务端开始派发到任务终态，包含模型等待、工具、自动重试、压缩和交互等待，排队时间不计入。运行中的引导消息归属原任务，不替换计时。下一次独立执行重新开始，历史回复保留各自的总用时；这不是整个对话的累计时长，也不是模型推理耗时估算。

`SessionCommandRecord.taskTiming` 随已有命令日志持久保存，通过命令 SSE 与 submissions 的独立 `taskTiming`、`taskTimings` 字段恢复。历史计时按用户消息的 `clientPromptId` 和命令的 `idempotencyKey` 关联，每轮仅最终回复显示；不会用相同文本或最新计时套到其他回复。历史普通任务的完成事件不会因此重新触发。旧记录无精确时间时不补造；进程异常中断没有可靠结束时间时显示「用时未记录」。后台页根据时间戳重算，停止后保持最终数值。

验证：计时纯函数、路由派发/队列/日志重载、submissions 恢复，以及真实 TaskDuration 组件的浏览器交互。浏览器夹具用按钮模拟任务生命周期，用本地存储模拟重载数据，主题使用与应用一致的变量；截图不代表完整桌面端或真实模型任务验收。

设计概念图由内置 imagegen 生成，提示词要点：Piora 中性灰白界面、蓝色强调，输入框上方轻量单行计时，运行/完成/停止三态及深色示例，阶段切换不清零、刷新恢复、结束保留。概念图早于最终文案选择；以实际组件「凝思求解中」为准。概念图与组件截图保存于 `.verification/task-duration/`。

运行标记使用 24px 内联 SVG「流光 π」，周期 2.4 秒，包含环绕光点、笔画流光与轻微呼吸。渐变使用每个组件独立 ID，支持多个对话同时挂载；`prefers-reduced-motion` 改变时立即静态降级，任务结束后卸载动效。

运行阶段文字后附三个固定占位的呼吸圆点，1.8 秒一轮，逐个延迟 0.2 秒亮起并上浮 1px；文字不变、不额外播报，减少动态效果时静止，任务结束后卸载。

实时速度以纯文字显示在状态整行中央：数字 15px、字重 600，单位 12px，使用正文色，不加底色、边框；左侧依次显示任务、耗时、阶段和呼吸圆点，右侧留空。容器不超过 640px 时左侧摘要独占首行，速度在次行保持整行居中。
