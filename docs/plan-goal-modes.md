# Plan 与 Goal 模式

Plan 与 Goal 是默认关闭的实验室功能。先打开“设置 → 实验室”，开启“Plan / Goal 模式”；开启后，新会话和已有普通会话的输入区才显示 Agent、Plan 和 Goal 选择器。Agent 按当前消息执行；Plan 先研究并提交计划；Goal 围绕同一目标持续推进，具体模式和预算随本次提交保存。群聊、定时任务及多代理任务编排不属于这次模式入口的范围。

关闭实验室开关会隐藏模式选择器，并阻止新建 Plan/Goal、确认或修改计划、继续目标和调整目标预算。已保存的目标、计划与证据仍可查看，暂停、取消和退出仍可操作。正在执行的 Goal 完成当前轮后停止自动继续；需要立即停止时使用暂停或取消。进行中的 Plan 仍保持只读，可以保存计划供以后查看。重新开启只恢复入口，不自动继续任务。

## Plan

1. 选择 Plan，发送需要规划的任务。
2. Agent 可以读取和检索项目、询问需求，提交包含目标、范围、步骤和验证方式的完整计划。
3. 查看计划后选择执行、继续修改或退出。继续修改后在输入区发送意见；新计划作为新版本保存，先前版本仍可回看。
4. 执行计划使用当前会话和已确认的计划内容。执行结束、停止或失败分别记录，不依赖刷新页面来推进任务。

规划阶段在工具执行前检查模式。内置读取和搜索工具、用户提问以及浏览器的指定观察动作可以执行；文件编辑、写入、Shell 和未声明的工具调用被阻止。特别是 Shell 命令不能仅凭命令名称证明没有副作用，因此 Plan 不开放任意 Shell。计划保存由宿主工作流完成，不需要 Agent 用写文件工具创建计划。

计划确认是从规划进入实施的用户操作，与逐工具权限审批无关。它不会新增审核模型，也不会改变普通 Agent 的直接执行机制。重复确认和旧版本操作由运行标识、状态及修订号校验；已确认内容不会被迟到的界面请求替换。

## Goal

选择 Goal 后可设置本次目标的轮次预算，范围为 1–100，默认 10。一个 SDK Agent 执行轮次可能包含多个模型请求和工具调用，因此预算并非 token 数、HTTP 请求数或工具调用次数。

目标记录保留原始用户目标。Agent 用工作流工具声明可检查的验收条件、更新进度和证据。已声明的条件不能在执行中被删掉或改写；更改目标范围时应结束旧目标并创建新目标。只有每个条件都有已验证标记和非空证据时，工作流才接受完成状态。

证据仍是 Agent 的报告。应用检查记录完整性，不会自动证明所有用户目标已经实现；用户应结合实际文件、命令结果及行为核对。未运行的检查和意图不能当作完成证据。

普通一轮响应结束时，目标如果仍在运行且预算允许，宿主会在同一会话中继续下一轮。目标达到预算、连续多轮没有新进度或工具证据、执行失败、需要用户输入时会停止，并展示对应状态或原因。

- **暂停**：停止当前执行，保留目标和证据，等待明确恢复。
- **继续**：在原目标上恢复；预算不足时先提高预算。仅保存更大的预算不会自动开始执行。
- **取消**：终止当前目标，保留历史记录并返回普通 Agent 模式。

## 状态与兼容性

模式、当前工作流及历史计划/目标保存到 Pi agent 目录下的 `piora/workflows/`，以会话标识隔离。读取历史不会创建 AgentSession 或调用模型。浏览器刷新和 SSE 重连以服务端状态为准；进程重启后，未完成的执行暂停，用户检查当前工作区后再继续，宿主不会重放旧模型请求或工具调用。重启前已经确认、尚在队列中的执行或恢复操作也会中断，需要用户重新决定。

每轮模型上下文会重新包含当前目标、计划及验收记录，以便上下文压缩后保留工作依据。分叉会话使用新的会话标识，不自动继承旧会话的运行中工作流。

内置工具使用 `piora_submit_plan` 和 `piora_update_goal` 名称，不注册第三方扩展常用的 `/plan`、`/goal` 命令。现有 Pi 工作流扩展仍可安装和使用；内置模式只在用户明确选择后启用。在内置 Plan / Goal 下运行扩展 `/command` 或 `!` Shell 快捷命令前，应先选择 Agent。这样不会通过命令入口绕过当前工作流的状态与工具边界，第三方命令本身的名称和行为保持不变。
